# 12.3. SKOS 의미계통도: 계층적 관계(broader/narrower)와 연관 관계(related)

## 1. 도입: 단어장은 똑똑하지 않다, '관계'가 지능을 만든다

앞선 12.2장까지 우리는 `skos:Concept`과 다국어 라벨링(`prefLabel`, `altLabel`)을 통해 표기 변이의 혼돈을 잠재우고 완벽하게 통제된 '시맨틱 단어장'을 구축했습니다. 하지만 이것만으로는 아직 기계가 진정한 지능(Intelligence)을 가졌다고 말할 수 없습니다.

일반적인 검색 엔진에 "사림(士林)"을 검색한다고 가정해 보십시오. 지능이 없는 시스템은 텍스트나 라벨에 정확히 '사림'이라고 적힌 문헌만 찾아옵니다. 
하지만 역사학을 배운 인간의 머릿속에는 거대한 **'의미계통도(Hierarchy)'**가 자리 잡고 있습니다. 인간 학자는 "동인(東人)과 서인(西人)은 사림에서 갈라져 나온 하위 분파니까, 사림을 검색하면 당연히 동인과 서인에 관한 데이터도 싹 다 긁어와야지!"라고 생각합니다.

기계는 이 역사적 족보를 스스로 깨우치지 못합니다. 우리가 엑셀로 만든 평면적인 단어장들을 거대한 트리(Tree) 구조의 십진분류표나 지식망으로 직접 엮어주어야만 합니다. 단어와 단어 사이에 상하좌우의 '관계(Relation)'를 맺어주는 순간, 기계는 비로소 문맥을 이해하고 똑똑한 **'확장 검색(Query Expansion)'**을 수행하게 됩니다.

## 2. 해결책 제시: SKOS의 3대 시맨틱 관계 속성

SKOS는 개념(`Concept`)과 개념을 엮어 입체적인 지식 조직체계를 만들기 위해, 직관적이고 강력한 3가지 관계 속성을 제공합니다.

### 1) 계층적 관계 (Hierarchical Relations)
도서관의 십진분류표(KDC, DDC)나 조선시대 문헌의 경사자집(經史子集) 체계처럼, 상위 개념과 하위 개념을 수직으로 연결합니다.

* **`skos:broader` (더 넓은 개념 / 부모):** 현재 개념보다 의미가 더 포괄적인 상위 개념을 가리킵니다. (예: '동인'의 `broader`는 '사림'이다.)
* **`skos:narrower` (더 좁은 개념 / 자식):** 현재 개념보다 의미가 더 구체적인 하위 개념을 가리킵니다. (예: '동인'의 `narrower`는 '남인'과 '북인'이다.)

### 2) 연관 관계 (Associative Relation)
수직적인 상하 관계는 아니지만, 횡적으로 깊은 연관성을 맺고 있어 "이 개념을 찾은 사람은 저 개념도 관심 있을 것"이라고 기계에게 넌지시 알려주는 횡적 연결망입니다.

* **`skos:related` (관련된 개념 / 형제 또는 연관어):** (예: '동인'과 '서인'은 서로 `related` 관계이다. 또는 '동인'과 '기축옥사(사건)'는 서로 `related` 관계이다.)

## 3. 실전 적용: 조선시대 붕당 정치 시소러스 맵핑 (Turtle)

이 3대 관계 속성을 활용하여 조선시대의 복잡한 붕당(Faction) 계보도를 기계 가독형 시소러스로 코딩해 보겠습니다.

```turtle
@prefix skos: [http://www.w3.org/2004/02/skos/core#](http://www.w3.org/2004/02/skos/core#) .
@prefix 국학: [http://aks.ac.kr/vocabulary/](http://aks.ac.kr/vocabulary/) .

# --- [1] 최상위 개념: 사림 ---
국학:concept/사림 a skos:Concept ;
    skos:prefLabel "사림(士林)"@ko ;
    skos:inScheme 국학:scheme/조선_정치세력 ;
    skos:narrower 국학:concept/동인 ; # 내 밑에 동인이 있다
    skos:narrower 국학:concept/서인 . # 내 밑에 서인이 있다

# --- [2] 하위 개념: 동인 ---
국학:concept/동인 a skos:Concept ;
    skos:prefLabel "동인(東人)"@ko ;
    skos:inScheme 국학:scheme/조선_정치세력 ;
    skos:broader 국학:concept/사림 ; # 내 부모는 사림이다
    skos:narrower 국학:concept/남인 ; # 내 밑에 남인이 있다
    skos:narrower 국학:concept/북인 ; # 내 밑에 북인이 있다
    skos:related 국학:concept/서인 ;  # 서인과 나는 라이벌 관계(연관)이다
    skos:related 국학:concept/기축옥사 . # 기축옥사 사건과 깊은 연관이 있다

# --- [3] 최하위 개념: 남인 ---
국학:concept/남인 a skos:Concept ;
    skos:prefLabel "남인(南人)"@ko ;
    skos:inScheme 국학:scheme/조선_정치세력 ;
    skos:broader 국학:concept/동인 ;  # 내 부모는 동인이다
    skos:related 국학:concept/북인 .  # 북인과는 갈라진 형제(연관)이다
```

이렇게 계보도를 짜두면, 글로벌 시맨틱 검색 엔진은 사용자가 "사림"을 검색했을 때, `narrower` 속성을 타고 내려가 동인, 서인, 남인, 북인에 맵핑된 모든 고문헌 데이터를 한 번에 쓸어 담아 사용자에게 제공합니다. 지식 그래프가 스스로 '지식의 맥락'을 추론하는 짜릿한 순간입니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

관계 모델링을 시작하면, 초보 아키텍트들은 인간의 직관과 기계의 엄격한 논리 사이에서 빈번하게 충돌을 일으킵니다. 다음 두 가지 치명적인 함정을 반드시 피해 가야 합니다.

**함정 1. "남인의 부모는 동인이고, 동인의 부모는 사림이니, 기계가 알아서 남인을 사림의 자식으로 인식하겠지?" (이행성의 함정)**

**시맨틱 아키텍트의 경고: "기본 `broader`와 `narrower`는 이행성(Transitivity)을 갖지 않습니다."**
인간의 논리로는 A가 B의 자식이고 B가 C의 자식이면, A는 C의 손자(하위 개념)입니다. 하지만 W3C의 표준 `skos:broader`는 오직 **'직속 부모'**만을 가리키도록 엄격하게 설계되었습니다. 즉, 추론 엔진은 남인을 사림의 하위 개념으로 자동 확장하지 않습니다.
만약 여러분이 족보를 몇 단계든 끝까지 타고 올라가며 추론하는 시스템을 만들고 싶다면, 일반 속성이 아니라 **`skos:broaderTransitive`**와 **`skos:narrowerTransitive`**라는 특수한 이행성 속성을 사용하도록 서버를 세팅해야 합니다. (이 부분은 고도의 추론 엔진 설계 영역입니다.)

**함정 2. "관계는 많을수록 좋으니, 부모-자식 관계이면서 동시에 연관 관계로도 묶어둬야지!" (배타성의 붕괴)**

```turtle
# [치명적인 논리 오류 코드]
국학:concept/동인 a skos:Concept ;
    skos:broader 국학:concept/사림 ; # 동인은 사림의 하위 개념이다.
    skos:related 국학:concept/사림 . # 동시에 동인은 사림과 연관된 개념이다?
```

**시맨틱 아키텍트의 무관용 원칙: "계층 관계(상하)와 연관 관계(좌우)는 철저히 배타적(Disjoint)입니다."**
나의 직속 상사이자 부모인 사람과, 나란히 어깨를 맞대는 형제나 친구 관계를 동시에 맺을 수는 없습니다. SKOS 논리 구조에서 `broader/narrower`와 `related` 속성을 두 개념 사이에 동시에 부여하면 심각한 **논리적 모순(Inconsistency)** 에러가 터지며 지식 그래프가 붕괴합니다. 상하 관계면 상하로만, 횡적 관계면 횡적으로만 단호하게 하나만 선택하십시오.

## 5. 요약 및 다음 단계

* 기계에게 개념의 맥락을 가르치고 똑똑한 확장 검색을 구현하기 위해, 우리는 개념들을 **상하 관계(`broader`, `narrower`)**와 **횡적 연관 관계(`related`)**로 엮어야 합니다.
* 이 관계 속성들을 활용하면 파편화된 단어들이 거대한 계보도(Tree)나 십진분류표와 같은 입체적인 시맨틱 시소러스로 진화합니다.
* 실무에서는 `broader/narrower`의 이행성(Transitivity) 한계를 명확히 인지해야 하며, 계층 관계와 연관 관계를 동시에 부여하는 배타성 위반 오류를 철저히 차단해야 합니다.

이제 우리 연구소 내부의 시소러스 체계는 그 어떤 도서관의 십진분류표보다 정교하게 완성되었습니다. 

하지만 지식의 바다는 우리 연구소 밖에도 끝없이 펼쳐져 있습니다. 우리가 만든 '조선시대 붕당' 시소러스를 전 세계 학자들이 알아보기 위해 미국의 의회도서관 주제명 표목(LCSH)이나 위키데이터(Wikidata)의 거대한 지식망과 엮어낼 수는 없을까요?

다음 장인 **[12.4. 글로벌 어휘 매핑: exactMatch, closeMatch를 활용한 외부 권위 데이터 연결]**에서, 닫힌 연구실의 문을 열고 글로벌 LOD 생태계와 우리의 시맨틱 사전을 우아하게 동기화시키는 '크로스워크'의 최종 비기를 전수해 드리겠습니다.
