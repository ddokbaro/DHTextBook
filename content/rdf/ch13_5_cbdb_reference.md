# 13.5. 시맨틱의 거울: CBDB (China Biographical Database) 관계 모델의 참조와 응용

## 1. 도입: "동양의 인물 관계를 바닥부터 발명하지 마십시오"

13.4장에서 우리는 서양의 FOAF가 가진 한계를 극복하기 위해 한국학(동양학) 특유의 사승, 붕당 관계를 로컬 온톨로지로 직접 설계해야 한다고 배웠습니다. 

하지만 시맨틱 아키텍트 여러분, 이 로컬 속성(`국학:hasMaster`, `국학:politicalEnemy` 등)을 수백 개씩 바닥부터 전부 상상해서 만들어야 할까요? 만약 여러분의 프로젝트가 수만 명의 역사적 인물이 얽힌 거대한 지식망을 목표로 한다면, 인간관계의 경우의 수는 기하급수적으로 늘어납니다. "처남의 아들", "같은 해 과거 급제 동기(同榜)", "나를 탄핵한 대립 세력" 등 이 복잡한 족보와 사회망을 온톨로지로 어떻게 체계화할 수 있을까요?

우리는 굳이 바퀴를 다시 발명할 필요가 없습니다. 비록 시맨틱 웹(RDF) 기술이 아닌 전통적인 관계형 데이터베이스(RDB)로 구축되었지만, 전 세계에서 가장 위대하고 정교하게 동양 인물의 관계를 분류해 놓은 선행 모델이 존재합니다. 바로 하버드 대학교, 대만 중앙연구원, 베이징 대학교가 공동 구축한 `"**CBDB (China Biographical Database Project)**"`입니다.



## 2. 해결책 제시: CBDB의 2대 관계망 분류 체계

CBDB는 수십만 명에 달하는 중국 역사 인물들의 데이터를 RDB 테이블로 관리합니다. 이 중에서 인문학 데이터 아키텍트가 반드시 훔쳐와야(?) 할 보물 창고는 바로 사람과 사람을 엮는 **'관계 코드북(Codebook)'**입니다. 

CBDB는 동양의 인물 관계를 크게 두 가지 거대한 기둥으로 나눕니다.

### [1] 친족 관계 (Kinship)
단순히 FOAF의 "가족(`foaf:knows`의 일종)" 수준이 아닙니다. CBDB의 `KINSHIP_CODES` 테이블은 동양 특유의 가부장적, 혈연적, 혼맥적 네트워크를 무려 **500여 개의 세밀한 촌수와 족보 코드**로 분류합니다.
* 예: `K-111` (B는 A의 친아버지이다)
* 예: `K-134` (B는 A의 처부(장인)이다 - 혼맥 네트워크의 핵심)
* 예: `K-243` (B는 A의 증조부이다)

### [2] 사회적 연망 (Association)
혈연을 제외한 지식인 사회의 모든 공적, 사적 관계를 다루는 `ASSOC_CODES` 테이블입니다. 이 분류 체계야말로 우리가 설계할 로컬 온톨로지의 완벽한 청사진입니다. CBDB는 사회적 관계를 다시 세부 범주로 쪼갭니다.
* **정치적 관계 (Political):** "A가 B를 천거(추천)했다", "A가 B를 탄핵했다", "A와 B는 정파적 대립 관계이다".
* **학술/사승 관계 (Academic):** "A는 B의 학문을 이었다", "A는 B의 문인(문하생)이다".
* **문학/예술 관계 (Literary):** "A가 B의 묘지명을 써주었다", "A와 B가 시(詩)를 주고받았다".
* **사회적 관계 (Social):** "A와 B는 같은 해 과거에 급제한 동기(同榜)이다".

## 3. RDB에서 RDF로: CBDB 코드의 시맨틱 응용

CBDB의 이 훌륭한 분류 체계는 RDB의 숫자 코드(예: `Assoc_code = 432`)로 되어 있습니다. 시맨틱 아키텍트인 우리는 이 숫자 코드에 담긴 인문학적 통찰을 뽑아내어, 기계가 연산할 수 있는 **'RDF 속성(Property)'**으로 번역(Translation)하는 작업을 수행해야 합니다.

* **[RDB 방식 (CBDB)]**
  테이블: `ASSOC_DATA` / 주어 ID: `1762`(왕안석) / 목적어 ID: `8008`(소식) / 관계 코드: `0605`(정치적 반대파)
* **[RDF 방식 (우리의 아키텍처)]**
  `국학:person/왕안석 국학온톨로지:opposedBy 국학:person/소식 .`

우리는 CBDB의 엑셀 코드북을 다운로드하여, 우리 연구실의 온톨로지 명세서(DCAP)를 짤 때 그대로 차용하면 됩니다. 동양학의 깊은 맥락이 이미 검증된 글로벌 표준 분류를 우리 지식 그래프의 뼈대로 삼는 것입니다.

## 4. 실전 적용: 북송(北宋) 신구법당 대립의 모델링 (Turtle)

CBDB의 관계 코드를 로컬 온톨로지(`cbdb-ont:`)로 차용하여, 북송 시대 왕안석(신법당)과 소식(구법당), 그리고 구양수의 학문적, 정치적 대하드라마를 FOAF와 융합하여 코딩해 보겠습니다.

```turtle
@prefix foaf: [http://xmlns.com/foaf/0.1/](http://xmlns.com/foaf/0.1/) .
@prefix rdfs: [http://www.w3.org/2000/01/rdf-schema#](http://www.w3.org/2000/01/rdf-schema#) .
@prefix 국학: [http://aks.ac.kr/data/](http://aks.ac.kr/data/) .
# CBDB의 관계 코드를 바탕으로 설계한 우리의 로컬 온톨로지 네임스페이스
@prefix cbdb-ont: [http://aks.ac.kr/ontology/cbdb/](http://aks.ac.kr/ontology/cbdb/) . 

# --- [CBDB 기반의 정밀 관계 속성 선언] ---
cbdb-ont:hasPatron rdfs:subPropertyOf foaf:knows ;
    rdfs:label "과거 시험의 좌주(채점관)이자 후원자이다"@ko . # CBDB Assoc Code 참조

cbdb-ont:politicalOpponent rdfs:subPropertyOf foaf:knows ;
    rdfs:label "정치적 반대파(정적)이다"@ko . # CBDB Assoc Code 참조

# --- [인물 데이터 및 관계 맵핑] ---
# 1. 구양수 (문단의 영수이자 좌주)
국학:person/구양수 a foaf:Person ;
    foaf:name "구양수" .

# 2. 소식 (소동파, 구양수의 제자이자 구법당)
국학:person/소식 a foaf:Person ;
    foaf:name "소식" ;
    # 사승/후원 관계: 구양수가 과거 시험에서 소식을 발탁함
    cbdb-ont:hasPatron 국학:person/구양수 . 

# 3. 왕안석 (신법당의 영수)
국학:person/왕안석 a foaf:Person ;
    foaf:name "왕안석" ;
    # 정치적 대립 관계: 소식과 왕안석은 신구법당으로 치열하게 대립함
    cbdb-ont:politicalOpponent 국학:person/소식 .
```

이렇게 CBDB의 분류표를 참고하여 RDF 속성을 설계하면, "정적"이라는 명확한 붉은 선(Edge)과 "후원자"라는 든든한 푸른 선(Edge)이 지식 그래프에 선명하게 그려집니다. RDB의 견고한 인문학적 토대가 시맨틱 웹의 무한한 확장성을 만나 만개하는 순간입니다.

## 5. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 딜레마: "CBDB의 숫자 코드를 그대로 URI로 써도 됩니까?"**

CBDB의 방대한 데이터를 우리의 LOD로 변환(ETL)할 때 초보자들이 자주 하는 치명적인 실수가 있습니다.
`국학:person/왕안석 <http://cbdb.fas.harvard.edu/code/0605> 국학:person/소식 .`

"교수님, 어차피 CBDB 코드북에 `0605`가 '정치적 대립'이라고 적혀 있으니, 속성(Predicate) 자리에 저 숫자 코드를 그대로 URI로 만들어 넣으면 안 됩니까?"

**시맨틱 아키텍트의 실무 가이드: "RDB의 암호(Code)를 시맨틱의 언어(Meaning)로 해방시켜라"**

절대 안 됩니다. 관계형 데이터베이스(RDB)에서 숫자로 된 코드(`0605`, `K-111`)를 쓰는 이유는 오직 하드디스크의 저장 용량을 아끼고 SQL 조인(JOIN) 속도를 높이기 위한 **'기계공학적 꼼수'**일 뿐입니다. 

시맨틱 웹은 '의미(Semantic)'의 웹입니다. 기계와 인간이 주소를 보는 순간 그 뜻을 직관적으로 유추할 수 있어야 합니다. 숫자 코드는 그 코드북 엑셀 파일을 잃어버리는 순간 아무도 해독할 수 없는 암호(Silo)로 전락합니다.

1. **나쁜 예:** `cbdb:relation/0605` (의미 불명)
2. **좋은 예:** `cbdb-ont:politicalOpponent` (인간도 기계도 직관적으로 이해 가능)

따라서 CBDB 데이터를 참조할 때는, 그들의 **'분류 철학'**은 적극적으로 수용하되, 데이터를 변환할 때는 반드시 Python 스크립트를 짜서 `0605`라는 숫자를 영문 카멜 표기법(CamelCase)이 적용된 우아한 시맨틱 URI(`politicalOpponent`)로 치환하여 데이터베이스(Triple Store)에 부어 넣어야 합니다.

## 6. 요약 및 [13장. 인물 관계망의 시맨틱 표현] 최종 마무리

* 동양 인물 관계의 복잡성을 온톨로지로 설계할 때, 관계형 데이터베이스(RDB)인 **CBDB(China Biographical Database)**의 '친족 관계(Kinship)'와 '사회적 연망(Association)' 코드북은 가장 완벽한 참조 모델이 됩니다.
* RDB에 축적된 인문학적 잣대(스승, 정적, 동방 급제 등)를 우리의 로컬 RDF 속성(`rdf:Property`)으로 번역해 오면, 수고로운 개념 설계 과정을 혁신적으로 단축할 수 있습니다.
* 단, RDB 특유의 숫자 코드(`0605`)를 그대로 시맨틱 URI로 사용하는 것은 의미적 단절을 초래하므로, 반드시 사람이 읽고 이해할 수 있는 명시적인 영문 단어(`politicalOpponent`)로 치환하여 아키텍처를 설계해야 합니다.

사물(10장~12장)과 인물(13장)을 모두 아우르는 거대한 지식망 구축의 이론과 실전이 마침내 완성되었습니다. 여러분은 동서양의 데이터 모델을 자유자재로 융합하는 진정한 시맨틱 아키텍트로 거듭났습니다.

이제 이 웅장한 지식의 성전에서 원하는 데이터를 마음껏 추출하고 분석하는 마법의 주문, **[14장. SPARQL: 지식 그래프의 언어로 묻고 답하다]**로 본격적인 여정을 떠나보겠습니다.
