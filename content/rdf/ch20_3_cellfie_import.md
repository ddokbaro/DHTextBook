# 20.3. 엑셀 사일로의 탈출: Cellfie 플러그인을 활용한 대량의 방목(榜目) 데이터 자동 변환(Import)

## 1. 도입: 수만 번의 클릭이 불러오는 대학원생의 절망

우리는 Protégé의 **"Individuals by class"** 탭에서 보라색 마름모(+) 버튼을 눌러 **"민영환"**과 **"조병세"**라는 인스턴스를 만들고, 그들에게 속성을 하나하나 정성껏 부여했습니다. 뼈대를 세우고 논리적 정합성을 테스트하는 소규모 샘플링 단계에서는 이 장인 정신이 반드시 필요합니다.

하지만 한국학중앙연구원이나 국사편찬위원회의 거대한 실무 프로젝트로 넘어가면 이야기가 완전히 달라집니다. 여러분의 하드디스크에는 조선시대 문과 급제자 수만 명의 명단이 빼곡히 기록된 **"문과방목(文科榜目) 엑셀 파일"**이 있습니다. 이 수만 명의 인물 노드를 Protégé에서 마우스 클릭으로 하나씩 만들고, 급제 연도 포스트잇을 붙이고, 본관 화살표를 잇는 작업을 수동으로 한다면 어떻게 될까요? 아마 논문을 쓰기도 전에 마우스 클릭만 하다가 손목 터널 증후군으로 쓰러지고 말 것입니다.

엑셀(Excel)이라는 거대한 데이터 사일로(Silo)에 갇힌 방대한 양의 인문학 데이터를 구출하여, 우리가 정교하게 짜놓은 지식 그래프의 무대 위로 폭포수처럼 쏟아부을 자동화 파이프라인이 절실하게 필요합니다.

## 2. 해결책 제시: 엑셀과 온톨로지를 잇는 마법의 다리, "Cellfie(셀피)"

Protégé는 엑셀 파일의 표(Grid) 구조를 읽어 들여, 우리가 설계한 온톨로지 뼈대(Class, Property)의 빈칸에 데이터를 일괄적으로 쏘아주는 **"Cellfie(셀피)"**라는 위대한 내장 플러그인을 제공합니다.

Cellfie는 **"MappingMaster DSL"**이라는 고유의 문법(변환 규칙)을 사용합니다. 이 문법은 기계에게 다음과 같은 지시를 내립니다.

| 엑셀 데이터 (문과방목.xlsx) | Cellfie의 변환 규칙 (Mapping Rule) | Protégé에 생성되는 결과물 (OWL) |
| :--- | :--- | :--- |
| **A열:** 인물 식별자 (p0001) | A열의 텍스트로 **"인스턴스"**를 만들어라. | `joseon:p0001` 개체 자동 생성 |
| **B열:** 이름 (이순신) | B열의 텍스트를 A열 인물의 **"이름(hasName)"** 속성에 문자열로 붙여라. | `joseon:p0001 joseon:hasName "이순신"^^xsd:string` |
| **C열:** 급제 연도 (1576) | C열의 숫자를 A열 인물의 **"급제연도(passedYear)"** 속성에 정수로 붙여라. | `joseon:p0001 joseon:passedYear "1576"^^xsd:integer` |

연구원이 이 규칙을 단 세 줄만 작성하고 **"변환(Transformation)"** 버튼을 누르면, 엑셀에 있는 수만 명의 데이터가 단 몇 초 만에 완벽한 지식 그래프로 조립되어 Protégé 캔버스 위에 등판합니다.

## 3. 실전 적용: 문과방목 1만 명의 데이터 자동 임포트 (Cellfie Rules)

Protégé에서 Cellfie 플러그인을 구동하여 엑셀 데이터를 지식 그래프로 쏟아부어 보겠습니다.

**[작업 1: Cellfie 창 열기와 엑셀 파일 불러오기]**
1. Protégé 상단 메뉴에서 **"Window ➔ Views ➔ Ontology views ➔ Cellfie"**를 클릭하여 빈 공간에 패널을 추가합니다.
2. 추가된 Cellfie 패널 하단의 **"Browse"** 버튼을 눌러 준비된 엑셀 파일(`bangmok_data.xlsx`)을 불러옵니다. 화면 하단에 엑셀의 시트 모양이 그대로 나타납니다.

**[작업 2: 변환 규칙(Transformation Rules) 작성하기]**
Cellfie 패널 중간의 **"Rules"** 탭에서 **"Add"** 버튼을 눌러 규칙을 작성합니다. (엑셀의 2행부터 마지막 행까지 변환한다고 가정합니다.)

```text
# 1. 개체(Individual) 생성 선언
# 기계여, 엑셀 A열(2행부터 끝까지)의 값을 주소로 삼아 인스턴스를 창조하라!
Individual(@A2*)

# 2. 소속 클래스(Type) 할당
# 그 인스턴스는 반드시 "문과급제자(Civil_Exam_Passer)" 클래스에 속한다.
Types(joseon:Civil_Exam_Passer)

# 3. 구체적인 사실(Facts) 부여 - 객체 속성과 데이터 속성 매핑
# 그 인스턴스에 B열의 텍스트를 이름으로, C열의 숫자를 연도로 붙여라!
Facts(
    joseon:hasName @B2*^^xsd:string,
    joseon:passedYear @C2*^^xsd:integer
)
```

**[작업 3: 마법의 실행 (Run)]**
규칙 작성이 끝나면 하단의 **"Generate Axioms"** 버튼을 클릭합니다. 
기계가 엑셀의 행을 빛의 속도로 훑으며 내부 논리 검사를 마친 뒤, 무결점의 시맨틱 데이터 수만 건을 생성해 냅니다. 이제 **"Individuals by class"** 탭을 열어보십시오. 빈 무대였던 공간에 수만 명의 조선시대 급제자들이 도열해 있는 웅장한 광경을 목격할 수 있습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 재앙: "빈칸(Null)"이 불러오는 논리적 파산과 한글 주소 에러**

대학원생들이 Cellfie의 위력에 환호성을 지르다가, 5분 뒤 시스템이 뻗어버리며 절망에 빠지는 두 가지 고질적인 실무 에러가 있습니다.

**재앙 1: 엑셀의 "빈칸(Empty Cell)"을 방치하는 만용**
문과방목 엑셀 파일에 어떤 인물의 "급제 연도(C열)"가 기록이 없어서 빈칸으로 비워져 있다고 가정해 보겠습니다. Cellfie 규칙에 `@C2*`라고 적어두었는데 엑셀 셀이 비어있으면, 기계는 없는 데이터를 억지로 파싱하려다가 심각한 에러(Transformation Error)를 뿜고 멈춰버립니다.
**[해결책]** Cellfie를 돌리기 전, 엑셀에서 빈칸 필터링을 완벽하게 수행해야 합니다. 연도를 모르는 인물들은 따로 시트(Sheet)를 분리하여 "연도 입력 규칙"이 빠진 별도의 Rule을 적용하거나, 엑셀 빈칸에 **"9999"** 같은 더미(Dummy) 데이터를 임시로 채워 넣고 변환한 뒤 후처리하는 것이 실무의 정석입니다.

**재앙 2: 식별자(IRI)에 한글을 쏟아붓는 대참사**
19.1장에서 강력하게 경고했던 **"인스턴스 주소(IRI) 한글 사용 금지 규칙"**을 무시하고, 엑셀 A열에 인물들의 한글 이름("이순신", "류성룡")을 그대로 적은 뒤 `Individual(@A2*)` 명령을 내려버리는 끔찍한 실수입니다. 수만 개의 한글 주소가 생성되면서 URL 인코딩이 산산조각 나고, 동명이인 데이터가 서로를 마구잡이로 덮어쓰기(Overwriting)하며 전체 데이터베이스가 돌이킬 수 없이 파괴됩니다.
**[해결책]** 엑셀 작업을 할 때, 반드시 A열(식별자 열)에는 `p0001`, `p0002`와 같은 영문+숫자 조합의 고유 ID를 부여하십시오. 인간이 읽을 한글 이름은 B열로 빼두고, `Facts(joseon:hasName @B2*^^xsd:string)`으로 포스트잇(데이터 속성)을 붙여주는 것이 수만 건의 데이터를 다루는 아키텍트의 절대 철칙입니다.

## 5. 요약 및 다음 단계

* 엑셀 파일에 갇힌 방대한 인문학 데이터를 수작업 없이 온톨로지로 자동 변환하려면 Protégé의 **"Cellfie"** 플러그인을 사용해야 합니다.
* **"MappingMaster DSL"** 문법(`Individual`, `Types`, `Facts`)을 사용하여 엑셀의 열(Column)과 지식 그래프의 속성(Property)을 매핑하는 규칙만 작성하면 수만 건의 데이터가 단숨에 생성됩니다.
* 이 강력한 파이프라인이 에러 없이 작동하려면, 엑셀 파일 내부의 **"빈칸(Null)"**을 완벽하게 전처리해야 하며, 개체를 생성하는 기준 열(A열)에는 절대 한글을 쓰지 말고 **"고유 영문 ID"**를 사용해야 합니다.

드디어 우리는 거대한 엑셀 사일로를 부수고 방목의 수만 명 데이터를 쾌적하게 쏟아부었습니다. 
뼈대를 설계하고, 추론기로 숨겨진 지식을 찾아내고, 수만 건의 실제 데이터까지 완벽하게 적재한 여러분의 Protégé 화면은 이제 100% 완성된 웅장한 우주입니다.

하지만 이 우주는 아직 여러분의 로컬 PC(노트북) 안에만 갇혀 있습니다. 이 찬란한 지식망을 전 세계 연구자들과 공유하고, 고도의 질의어(SPARQL)를 던질 수 있는 그래프 DB 서버(예: GraphDB, Blazegraph)로 안전하게 이사시켜야 합니다.
