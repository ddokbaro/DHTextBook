# 5.2. 영구 식별자(PID) 대격돌과 w3id의 승리: 100년의 지식을 담는 중계소

## 1. 도입: 한국학중앙연구원 서버는 100년 뒤에도 살아있을까요?

우리는 앞선 장에서 변하지 않는 주소, `"**쿨한 URI**"`의 중요성을 뼈저리게 느꼈습니다. 그래서 여러분은 소속 기관인 한국학중앙연구원(AKS)의 전산 시스템을 활용하여 `http://aks.ac.kr/person/P123`이라는 아주 깔끔하고 훌륭한 주소를 설계했습니다. 

하지만 역사학자로서 아주 냉정하고 거시적인 질문을 하나 던져보겠습니다. **"여러분의 대학교나 연구소의 도메인(`aks.ac.kr`)이 과연 50년, 100년 뒤에도 지금의 철자와 시스템을 그대로 유지하며 살아있을 것이라고 확신하십니까?"**

전쟁, 화재, 기관의 통폐합, 혹은 정부의 예산 삭감 등 수많은 물리적, 행정적 변수가 존재합니다. 만약 50년 뒤 기관의 도메인이 `korea-studies.go.kr`로 바뀐다면, 전 세계 학자들이 50년간 인용해 온 수백만 개의 `aks.ac.kr` 기반 지식 그래프 링크는 그날로 전부 증발해 버립니다. 

우리가 구축하는 조선시대의 지식은 반만년을 이어온 문화유산입니다. 이 영구적인 지식을 고작 수십 년 수명의 특정 웹 서버나 도메인에 종속시키는 것은 디지털 인문학자의 직무 유기입니다. 기관의 흥망성쇠를 초월하여, 우주가 멸망할 때까지 내 데이터의 위치를 안내해 줄 `"**불멸의 중계소**"`가 절실하게 필요합니다.

## 2. 해결책 제시: 영구 식별자(PID)와 리졸버(Resolver) 아키텍처

컴퓨터 공학은 이 철학적 난제를 해결하기 위해 `"**영구 식별자(PID, Persistent Identifier)**"`라는 거대한 우체국 중계소(Resolver) 시스템을 창안했습니다.

원리는 아주 단순하고 강력합니다. 전 세계의 학자들은 여러분의 연구실 서버 주소를 직접 가리키지 않습니다. 대신 글로벌하게 합의된 `"**공용 우체국(PID 중계소)**"` 주소를 가리킵니다. 우체국장(중계 서버)은 거대한 장부를 가지고 있다가, 누군가 P123번 인물을 찾으면 "아! 그 데이터는 지금 한국학중앙연구원의 3번 클라우드 서버에 있습니다!"라고 실시간으로 연결(`"**리다이렉트, Redirect**"`)해 줍니다.

만약 기관의 서버가 불타서 아마존 클라우드(AWS)로 이사를 갔다면? 여러분은 전 세계의 링크를 수정할 필요 없이, 공용 우체국 장부의 도착지 주소 딱 한 줄만 최신으로 업데이트하면 됩니다. 이것이 데이터 영속성의 궁극적인 마법입니다.

그렇다면 인문학 지식 그래프를 위해 어떤 우체국(PID 서비스)을 선택해야 할까요? 학계와 산업계에서 격돌하고 있는 4대 PID 서비스를 철저하게 해부해 보겠습니다.

## 3. 실전 적용: 4대 영구 식별자(PID) 서비스 대격돌

### 1. 학술 논문의 절대 강자: DOI (Digital Object Identifier)
* **주소 형태:** `https://doi.org/10.1234/joseon.5678`
* **특징:** 논문과 출판물 시장을 완벽하게 장악한 표준입니다. 크로스레프(Crossref) 같은 등록 대행사를 통해 강력하게 관리됩니다.
* **한계 (LOD 부적합):** 발급받을 때마다 **비용(돈)**이 듭니다. 논문 한 편에 돈을 내는 것은 괜찮지만, 조선시대 인물 10만 명, 전투 3천 개마다 각각 DOI를 발급받으려면 연구소 기둥이 뽑힙니다. 또한 시맨틱 웹의 기계 간 통신(LOD)을 위한 유연한 설정이 매우 제한적입니다.

### 2. 도서관 사서들의 든든한 친구: PURL (Persistent Uniform Resource Locator)
* **주소 형태:** `https://purl.org/joseon/person/P123`
* **특징:** 인터넷 아카이브(Internet Archive) 등에서 관리하며, 초창기 시맨틱 웹 프로젝트들이 가장 많이 사랑했던 무료 서비스입니다. 더블린 코어(Dublin Core) 같은 유명 온톨로지가 PURL을 사용합니다.
* **한계:** 시스템이 다소 노후화되었고, 대규모 데이터를 일괄적으로 맵핑하고 관리하는 최신 웹 개발 친화력이 떨어집니다.

### 3. 기록학과 박물관의 거인: ARK (Archival Resource Key)
* **주소 형태:** `https://n2t.net/ark:/12345/joseon/P123`
* **특징:** 캘리포니아 대학(CDL)이 주도하여 만들었으며, 박물관, 도서관, 기록관(GLAM) 생태계에서 매우 강력한 지지를 받습니다. "이 데이터는 문화유산이다"라는 철학적 선언이 담겨 있습니다.
* **한계:** 주소 중간에 `ark:/` 라는 이질적인 기호가 들어가서 URL이 다소 못생겨지고 길어지는 단점이 있습니다.

### 4. 시맨틱 웹의 구세주이자 최종 승자: w3id.org
* **주소 형태:** `https://w3id.org/joseon/person/P123`
* **특징:** W3C의 시맨틱 웹 커뮤니티가 링크드 오픈 데이터(LOD)를 위해 작정하고 만든 최강의 무료 PID 서비스입니다.
* **압도적 강점:** 1. 마이크로소프트의 깃허브(GitHub)를 기반으로 작동하여 서버가 다운될 확률이 제로에 가깝습니다.
  2. 서버 유지비가 **완전 무료**이며, 인물 100만 명의 주소를 단 한 줄의 정규식 코드로 한 번에 리다이렉트할 수 있습니다.
  3. 앞선 장에서 예고했던 기계와 인간을 구분하는 마법, `"**콘텐츠 협상(Content Negotiation)**"`을 네이티브로 가장 완벽하게 지원합니다.

| 비교 항목 | DOI | PURL | ARK | w3id.org |
| :--- | :--- | :--- | :--- | :--- |
| **주요 타겟** | 출판된 논문, 서적 | 초기 웹 자원, 도서관 | 아카이브, 박물관 유물 | **지식 그래프, LOD 개체** |
| **발급 비용** | 유료 (건당 과금) | 무료 | 무료 | **완전 무료** |
| **유지보수 도구** | 전용 대행사 시스템 | 웹 UI 관리자 | 전용 시스템 | **GitHub (개발자 친화적)** |
| **시맨틱 웹 호환성** | 낮음 | 중간 | 높음 | **최상 (콘텐츠 협상 지원)** |

디지털 인문학 지식 그래프 파이프라인의 표준은 의심의 여지 없이 `"**w3id.org**"`입니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

"좋습니다, 교수님. 우리 연구실 데이터도 전부 w3id.org 주소로 연결하겠습니다. 그런데 이 우주적인 중계소 장부에 우리 주소를 올리려면 W3C 본부에 복잡한 영문 공문이라도 보내야 합니까?"

많은 인문학 연구원들이 글로벌 W3C 커뮤니티의 벽을 높게 느끼고 지레 겁을 먹습니다. 하지만 w3id의 장부에 여러분의 조선시대 데이터베이스를 등록하는 과정은 놀랍도록 단순하며, 현대적인 오픈소스 철학을 따릅니다. 공문은 필요 없습니다. 오직 `"**깃허브(GitHub)**"` 계정만 있으면 됩니다.

**[w3id.org 영구 주소 획득 실무 3단계]**
1. GitHub의 `perma-id/w3id.org` 공식 저장소(Repository)를 내 계정으로 포크(Fork)하여 복사해 옵니다.
2. 복사한 폴더 안에 우리 프로젝트 이름(예: `joseon`)으로 새 폴더를 만들고, 그 안에 `.htaccess` 라는 텍스트 파일을 딱 하나 생성합니다. 이 파일 안에 **"w3id.org/joseon/ 으로 들어오는 모든 접속은 aks.ac.kr/db/ 로 보내라"**라는 아파치 리다이렉션 코드를 두세 줄 적어 넣습니다.
3. 원본 저장소에 `"**풀 리퀘스트(Pull Request, PR)**"`를 날립니다. "우리가 조선시대 인물 데이터를 개방하려 하니 장부에 추가해 주십시오"라고 메모를 남기면, 며칠 내로 전 세계의 관리자들이 코드를 확인하고 승인(Merge)해 줍니다.

단 세 줄의 코드와 깃허브 PR 한 번으로, 여러분의 데이터는 팀 버너스리가 꿈꾸었던 불멸의 웹 생태계 한가운데에 영원히 아로새겨지게 됩니다.

## 5. 요약 및 다음 단계

* 기관의 서버나 도메인은 영원하지 않으며, 이를 방치하면 전 세계의 지식 링크가 깨지는 `"**링크 부패**"`가 발생합니다.
* 이를 방지하기 위해 우리는 도착지 주소를 영구적으로 중계해 주는 `"**영구 식별자(PID)**"` 우체국을 활용해야 합니다.
* 비용이 무료이고 깃허브 기반으로 투명하게 관리되며 시맨틱 웹에 완벽하게 최적화된 `"**w3id.org**"`가 디지털 인문학 데이터베이스의 최종 해답입니다.

자, 이제 우리의 주소는 `https://w3id.org/joseon/person/P123`이라는 우주적인 불사신이 되었습니다. 

그런데 앞서 우리가 `w3id.org`의 가장 위대한 기능이라고 극찬했던 `"**콘텐츠 협상(Content Negotiation)**"`이란 대체 무엇일까요? 똑같은 `P123` 주소를 구글의 인공지능 로봇이 클릭할 때와, 대학원생이 크롬 브라우저로 클릭할 때 서버가 어떻게 귀신같이 상대방의 정체를 알아채고 서로 다른 형태의 데이터(Turtle vs HTML)를 우아하게 던져주는 것일까요?

다음 장인 **[5.3. 콘텐츠 협상(Content Negotiation): 기계와 인간을 동시에 만족시키는 통신 규약]**에서 시맨틱 웹 서버 기술의 가장 아름다운 응답 방식을 완벽하게 해부해 보겠습니다.
