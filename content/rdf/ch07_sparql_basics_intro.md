# 7장. SPARQL 1.1 문법과 데이터 질의의 기초

## 1. 도입: 거대한 지식의 바다에 그물을 던지는 방법

지난 6개의 장을 거치며 우리는 엑셀의 답답한 표(Table)를 찢어버리고, 세상의 모든 역사적 지식을 주어, 술어, 목적어라는 세 조각(`"**트리플**"`)으로 해체하여 우주적인 지식 그래프를 서버에 구축했습니다. 

이제 여러분의 수장고에는 수십만 명의 조선시대 인물, 그들이 쓴 문집, 참여한 과거 시험과 붕당의 관계망이 거대한 거미줄처럼 아름답게 얽혀 있습니다. 그런데 여기서 아주 현실적인 문제가 발생합니다. 이 거대한 점과 선의 바다에서 **"16세기에 태어난 서인(西人) 계열의 문신 중, 임진왜란에 참전한 사람의 이름과 저서 목록만 뽑아달라"**고 컴퓨터에게 지시하려면 어떻게 해야 할까요?

엑셀이라면 수많은 시트에서 필터를 걸고 `VLOOKUP` 함수를 쓰느라 밤을 새워야 할 것입니다. 관계형 데이터베이스(RDB)라면 `"**SQL**"`을 사용하여 인물 테이블, 당파 테이블, 직업 테이블, 참전 테이블, 저서 테이블이라는 5개의 표를 억지로 이어 붙이는 끔찍한 `"**조인(JOIN) 연산**"` 코드를 길게 짜야 합니다. 

복잡하고 유기적인 인문학 데이터를 검색하는 데 최적화된, 직관적이고 경이로운 검색 언어는 없는 것일까요?

## 2. 해결책 제시: 패턴 매칭의 마법, SPARQL(스파클)

시맨틱 웹의 창시자들은 이 복잡한 지식 그래프를 우아하게 검색하기 위해 W3C 국제 표준 질의어인 `"**SPARQL(스파클, SPARQL Protocol and RDF Query Language)**"`을 창안했습니다.

SQL과 SPARQL은 겉모습은 비슷해 보이지만, 데이터를 찾는 `"**철학(Philosophy)**"`이 완전히 다릅니다.
* **SQL의 철학 (조회와 결합):** "A번 서랍(테이블)을 열어서 조건에 맞는 것을 찾고, B번 서랍을 열어서 A와 공통된 열(Column)을 찾아 테이프로 이어 붙여라."
* **SPARQL의 철학 (패턴 매칭):** "내가 찾고 싶은 데이터의 빈칸(변수)이 뚫린 `"**도면(Pattern)**"`을 줄 테니, 거대한 거미줄 전체를 훑어서 이 도면의 모양과 정확히 일치하는 퍼즐 조각들을 모두 뜯어와라."

이 패턴 매칭 방식은 마치 도장이나 쿠키 틀로 반죽을 찍어내는 것과 같습니다. 여러분이 세 조각(주어-술어-목적어)의 트리플 문법으로 도면을 그리고, 모르는 부분에 `"**물음표(?)**"`만 달아주면, SPARQL 엔진이 거미줄을 타고 돌아다니며 조건에 맞는 데이터를 순식간에 건져 올립니다. 끔찍한 JOIN 연산의 폭발 없이, 오직 관계(선)를 따라 물 흐르듯 탐색하는 것입니다.

## 3. 실전 적용: 마법의 뼈대, SELECT와 WHERE

SPARQL 쿼리는 크게 두 가지 핵심 블록으로 구성됩니다. **무엇을 가져올 것인가(`SELECT`)**와 **어떤 패턴을 찾을 것인가(`WHERE`)**입니다.

조선시대 데이터베이스에서 **"서인(西人) 당파에 속한 사람들의 이름과 출생 연도를 찾아라"**라는 질문을 SPARQL 코드로 작성해 보겠습니다.

```sparql
# 1. 접두사(PREFIX) 선언: 지루한 인터넷 주소를 짧게 줄여줍니다. (Turtle 문법과 동일)
PREFIX 조선: [http://조선.kr/ontology/](http://조선.kr/ontology/)
PREFIX 인물: [http://조선.kr/person/](http://조선.kr/person/)

# 2. SELECT: 기계가 최종적으로 화면에 출력해 주었으면 하는 "변수(Variable)"를 지정합니다.
# SPARQL에서 변수는 항상 물음표(?)로 시작합니다.
SELECT ?이름 ?출생연도

# 3. WHERE: 기계가 그래프에서 찾아야 할 "도면(트리플 패턴)"을 중괄호 { } 안에 그립니다.
WHERE {
  # 패턴 1: 어떤 사람(?사람)의 당파가 "서인"이다.
  ?사람 조선:당파 "서인" .
  
  # 패턴 2: 그 사람(?사람)의 이름은 ?이름 이다.
  ?사람 조선:이름 ?이름 .
  
  # 패턴 3: 그 사람(?사람)의 출생 연도는 ?출생연도 이다.
  ?사람 조선:출생연도 ?출생연도 .
}
```

**작동 원리 해부:**
1. 기계는 `WHERE` 블록 안으로 들어가 첫 번째 패턴을 봅니다. 지식 그래프 전체를 뒤져서 목적어가 "서인"인 트리플을 모두 찾아내고, 그 주어 자리에 있는 URI(예: `인물:P00123`)를 `?사람`이라는 빈칸(변수)에 꽂아 넣습니다.
2. 이제 `?사람`에는 `인물:P00123`(이이)이 들어있습니다. 기계는 두 번째 패턴으로 넘어가 이이의 이름을 찾아 `?이름` 빈칸에 "이이"를 채웁니다.
3. 세 번째 패턴으로 넘어가 이이의 출생 연도를 찾아 `?출생연도` 빈칸에 "1536"을 채웁니다.
4. 퍼즐이 완벽하게 맞춰지면, `SELECT`의 명령에 따라 `?이름`과 `?출생연도`만 모니터 화면에 예쁜 표로 출력해 줍니다.

| 비교 항목 | SQL (관계형 DB) | SPARQL (시맨틱 웹) |
| :--- | :--- | :--- |
| **작동 원리** | 여러 테이블을 `JOIN`으로 강제 결합 | 그래프에서 트리플 `"**패턴 매칭(Pattern Matching)**"` |
| **미지수 표현** | 특정 테이블의 Column 이름 호출 | `?` 기호가 붙은 `"**변수(Variable)**"` 활용 |
| **검색의 확장성** | 스키마 구조를 완벽히 알아야 쿼리 가능 | 구조를 몰라도 선(Edge)을 따라가며 직관적 탐색 가능 |

## 4. 실무 트러블슈팅 (Street-smart Tips)

SQL에 익숙한 연구원들이 처음 SPARQL을 배울 때 모니터 앞에서 머리를 쥐어뜯게 만드는, 너무나도 사소하지만 100% 확률로 발생하는 뼈아픈 실수가 하나 있습니다. 바로 `"**마침표(.)의 누락**"`입니다.

위의 `WHERE` 블록 안을 자세히 보십시오. `?사람 조선:당파 "서인" .` 처럼 각각의 트리플 패턴 끝에는 반드시 마침표(`.`)가 찍혀 있습니다. 이 마침표는 **"이 조건 하나가 끝났고, 그다음 조건과 교집합(AND)으로 묶어라"**라는 절대적인 문법적 기호입니다.

* **흔한 초보자의 실수:**
    ```sparql
    WHERE {
      ?사람 조선:당파 "서인"   # 마침표가 빠짐!!
      ?사람 조선:이름 ?이름 .
    }
    ```
만약 이렇게 마침표를 빼먹으면, SPARQL 엔진은 첫 줄과 두 번째 줄을 하나의 거대한 문장으로 잘못 인식하여 파싱(Parsing) 에러를 뿜어내거나, 결과를 아예 출력하지 않고 입을 닫아버립니다. 

SQL에서는 문장 끝의 세미콜론(`;`)을 빼먹어도 똑똑한 클라이언트 프로그램이 대충 알아서 처리해 주는 경우가 많지만, SPARQL에서 `WHERE` 절 내부의 마침표 누락은 기계의 논리를 붕괴시키는 치명타입니다. 코드가 작동하지 않는다면 십중팔구 마침표가 빠졌기 때문이니 가장 먼저 마침표부터 점검하십시오.

## 5. 요약 및 다음 단계

* SPARQL은 복잡한 조인(JOIN) 연산 없이, 빈칸(변수)이 뚫린 트리플 도면을 제시하여 데이터를 찾는 `"**패턴 매칭(Pattern Matching)**"` 질의어입니다.
* 원하는 결괏값을 선언하는 `"**SELECT**"`와, 데이터가 만족해야 할 트리플 패턴을 그리는 `"**WHERE**"` 블록이 쿼리의 가장 핵심적인 뼈대입니다.
* `WHERE` 블록 안에서 각각의 트리플 패턴은 반드시 `"**마침표(.)**"`로 끝나야 기계가 문맥을 정확히 파악할 수 있습니다.

자, 이제 기계에게 질문을 던지는 가장 기본적인 뼈대(SELECT, WHERE)를 장착했습니다. 그런데 문제가 하나 있습니다. 
만약 우리가 '서인'들의 이름과 '호(號)'를 찾으라고 패턴을 주었는데, 평생 호를 갖지 못한 사람은 어떻게 될까요? 기계는 조건이 100% 일치하지 않으므로 가차 없이 그 사람을 검색 결과에서 통째로 날려버립니다.

기록이 없는 사람은 없는 대로 너그럽게 품어 안고 검색 결과를 출력하게 만드는 방법은 없을까요? 다음 장인 **[7.1. 기본 구문: SELECT, WHERE, OPTIONAL, FILTER, BIND]**에서 엑셀의 필터 기능을 아득히 뛰어넘는 SPARQL의 필수 고급 문법들을 완벽하게 해부해 보겠습니다.
