# 25.2. 지식 그래프 임베딩(KGE)과 BERTMap 활용

## 1. 도입: 기계의 눈을 멀게 하는 "동의어"와 "별칭"의 미궁

앞선 25.1장에서 우리는 기계에게 고문헌을 읽히고 명사를 추출해내는 파이프라인을 구축했습니다. 하지만 실제로 사료를 분석하다 보면, 디지털 인문학자들을 절망에 빠뜨리는 거대한 언어적 장벽에 부딪히게 됩니다.

우리의 지식 그래프(온톨로지)에는 관직명이 "**수군절도사**"라는 엄격한 표준어로 정의되어 있습니다. 하지만 《조선왕조실록》 원문을 읽어보면, 사관들은 "수군절도사"라는 긴 단어 대신 "**수사**", "**통제사**", 혹은 "**주진장**"이라는 다양한 별칭과 축약어를 섞어 씁니다. 인간 사학자는 문맥을 보고 이 단어들이 모두 같은 직책을 지칭한다는 것을 단숨에 알아챕니다. 

하지만 전통적인 컴퓨터 프로그램에게 "수사"와 "수군절도사"는 완전히 다른 문자열일 뿐입니다. 기계는 글자의 형태가 정확히 일치(`==`)하지 않으면 이 둘을 연결하지 못하고, 결국 이순신 장군의 위대한 전공 기록은 지식 그래프에 편입되지 못한 채 허공으로 흩어지고 맙니다. 우리는 어떻게 기계에게 표면적인 글자를 넘어 "**맥락(Context)**"과 "**의미(Semantics)**"를 가르칠 수 있을까요?

## 2. 해결책 제시: 의미의 은하수를 그리는 "**지식 그래프 임베딩(KGE)**"과 "**BERTMap**"

이 인문학적 난제를 돌파하기 위해 컴퓨터 공학자들은 "**임베딩(Embedding)**"이라는 혁명적인 철학을 고안해 냈습니다.

임베딩이란, 인간의 언어와 개념을 기계가 이해할 수 있는 수학적인 "**벡터 공간(Vector Space)**"의 좌표로 변환하는 작업입니다. 밤하늘의 은하수를 상상해 보십시오. 기계는 수백만 장의 사료를 미리 읽으면서, "수사"라는 단어와 "수군절도사"라는 단어가 항상 '바다', '전투', '판옥선', '이순신'이라는 단어들과 함께 등장한다는 사실을 깨닫습니다. 기계는 이 두 단어의 수학적 좌표를 은하수의 같은 별자리에 가깝게 배치합니다. 

이러한 임베딩 철학을 지식 그래프 간의 연결(Mapping)에 극대화한 최첨단 딥러닝 기술이 바로 "**BERTMap(버트맵)**"입니다. BERTMap은 두 온톨로지나 사료 텍스트 사이에서 "글자는 다르지만 의미가 같은 개념"을 수학적 거리를 계산하여 귀신같이 찾아냅니다.

| 매칭 방식 | 컴퓨터의 판단 기준 | 인문학적 사료 분석 시의 결과 |
| :--- | :--- | :--- |
| **전통적 문자열 매치** | "수사" == "수군절도사" | **매칭 실패 (False)**. 지식의 단절 발생. |
| **BERTMap 임베딩 매치** | "수사"의 좌표 ≒ "수군절도사"의 좌표 | **매칭 성공 (유사도 92%)**. 숨겨진 문맥 복원 완료. |

## 3. 실전 적용: BERTMap으로 이본(異本) 간의 개념 통합하기

실무에서 여러분이 《선조실록》의 추출 데이터와 기존의 "한국학중앙연구원 관직 온톨로지"를 서로 병합(Mapping)해야 하는 임무를 맡았다고 가정해 보겠습니다.

문자열이 달라도 의미가 같다면 서로 연결해주기 위해, 파이썬(Python) 환경에서 BERTMap의 논리 구조를 어떻게 활용하는지 살펴보겠습니다.

```python
# 1. 딥러닝 기반의 BERT 임베딩 모델을 불러옵니다.
# (이 모델은 조선시대 역사 텍스트를 미리 학습하여 문맥을 이해하고 있습니다.)
model = load_bert_embedding_model("joseon-history-bert")

# 2. 사료에서 추출한 단어와, 우리의 표준 온톨로지 단어를 준비합니다.
source_text = "전라좌수사"
target_text = "전라좌도수군절도사"

# 3. 모델을 사용하여 두 단어를 수학적 좌표(벡터)로 변환합니다.
vector_source = model.embed(source_text)
vector_target = model.embed(target_text)

# 4. 두 좌표 사이의 수학적 거리(코사인 유사도)를 계산합니다.
similarity_score = calculate_cosine_similarity(vector_source, vector_target)

# 5. 유사도가 90%를 넘으면, 기계가 이 둘을 같은 개념(owl:sameAs)으로 매핑합니다.
if similarity_score > 0.90:
    print("매칭 성공! 두 단어는 문맥상 동일한 관직입니다.")
    print(f"유사도: {similarity_score * 100}%")
```

위 코드가 실행되면, 기계는 글자 수가 다름에도 불구하고 두 단어의 좌표가 거의 일치함을 파악해 냅니다. 이를 통해 파편화된 수백 가지의 별칭과 이본(異本)들이 하나의 거대한 지식의 축으로 정렬되는 기적을 맛볼 수 있습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 치명적 위기: "기계가 이순신과 원균을 동일 인물로 묶어버렸습니다!"**

이것은 임베딩(KGE) 기술을 다루는 인문학자들이 100% 마주하게 되는 가장 무섭고 기괴한 에러입니다. 
분명히 "**이순신**"과 "**원균**"은 철천지원수이자 완전히 다른 두 인물입니다. 그런데 임베딩 공간에서 이 두 단어의 유사도를 계산해 보면 무려 95%가 넘게 나옵니다. 왜 그럴까요?

**[승리하는 아키텍트의 수학적 통찰과 임계값(Threshold) 방어술]**
딥러닝 모델은 단어의 뜻을 사전에서 찾는 것이 아니라, "주변에 어떤 단어가 자주 나타나는가(분포 가설)"로 뜻을 유추합니다. 사료를 보면 이순신과 원균은 항상 "임진왜란", "선조", "수군", "일본군", "전투"라는 완벽하게 똑같은 맥락(Context) 속에서 등장합니다. 기계의 눈에는 이 두 단어가 거의 완벽한 쌍둥이 좌표로 보일 수밖에 없습니다.

이러한 "**치명적인 오탐(False Positive)**"을 막으려면 다음 두 가지를 명심해야 합니다.
1. 임베딩 모델의 매칭 유사도 컷오프(Threshold)를 98% 이상으로 극도로 높게 설정하여 함부로 병합되지 않도록 방어해야 합니다.
2. 사람 이름(Person) 객체에 대해서는 딥러닝 모델의 판단을 맹신하지 말고, 앞서 배운 문자열 일치나 생몰년도 비교 등 "**엄격한 전통적 규칙(Rule-based)**"을 함께 섞어 쓰는 하이브리드 아키텍처를 도입해야만 역사의 왜곡을 막을 수 있습니다.

## 5. 요약 및 다음 단계

* 표면적인 글자가 달라도 기계가 그 의미를 이해하도록 가르치기 위해, 단어를 수학적 좌표로 바꾸는 "**지식 그래프 임베딩(KGE)**" 기술을 사용합니다.
* 최첨단 모델인 "**BERTMap**"은 문맥의 유사성을 바탕으로 "수사"와 "수군절도사" 같은 별칭들을 하나의 온톨로지 개념으로 융합해 줍니다.
* 맥락이 비슷하다는 이유로 라이벌이나 반대 개념을 동일하게 취급하는 딥러닝의 맹점을 방어하기 위해, 매칭 임계값 조절과 엄격한 규칙 교차 검증이 필수적입니다.

이제 우리는 기계에게 단어의 숨은 뜻과 맥락까지 수학적으로 이해시키는 경지에 올랐습니다. 
하지만 딥러닝 모델을 처음부터 학습시키고 벡터 거리를 일일이 계산하는 과정은 코딩 지식이 부족한 인문학자에게 너무나 가혹한 벽입니다. 만약, 챗GPT(ChatGPT)처럼 우리 말을 알아듣는 거대 인공지능에게 "네가 읽고 알아서 온톨로지로 좀 짜줄래?"라고 말로 지시할 수 있다면 어떨까요?
