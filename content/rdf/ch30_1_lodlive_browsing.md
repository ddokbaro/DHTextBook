# 30.1. 점진적 브라우징: LodLive와 방사형 탐색

## 1. 도입: 지식의 바다에 홀로 떨어진 탐험가

앞선 30장의 도입부에서 우리는 수백만 건의 데이터를 화면에 한 번에 쏟아부었을 때 발생하는 끔찍한 "**헤어볼(Hairball)**" 현상과 브라우저의 붕괴를 경고했습니다. 

인문학 연구자나 일반 대중이 지식 그래프를 탐험하는 방식은 컴퓨터가 전체 데이터를 스캔하는 방식과 다릅니다. 인간의 인지 구조는 "**관심 있는 단 하나의 주제**"에서 출발하여, 그 주변으로 가지를 뻗어 나가는 방식을 선호합니다. 

예를 들어, 사용자는 "이순신"이라는 인물 하나에 먼저 호기심을 가집니다. 이순신을 클릭하면 그제야 그가 참여한 "한산도 대첩"이 보이고, 한산도 대첩을 클릭하면 함께 싸운 "원균"이나 "권율"이 나타납니다. 
우리는 거대한 조선시대의 지도를 한 번에 들이밀어 사용자를 질리게 만드는 대신, 캄캄한 지식의 동굴 속에서 사용자가 "**마우스라는 손전등**"을 비추는 곳만 순차적으로 밝혀주는 아주 세련된 시각화 아키텍처가 필요합니다.

## 2. 해결책 제시: 어둠 속의 손전등, "**LodLive**"와 "**방사형 탐색**"

이러한 "손전등" 철학을 웹 브라우저 위에서 가장 완벽하게 구현한 오픈소스 자바스크립트(JS) 라이브러리가 바로 "**LodLive(로드라이브)**"입니다. 

LodLive의 핵심 철학은 "**점진적 브라우징(Progressive Browsing)**"과 "**방사형 탐색(Radial Exploration)**"입니다.
화면 중앙에는 오직 "이순신"이라는 동그라미 하나만 떠 있습니다. 사용자가 이 동그라미를 클릭하는 순간, LodLive는 남몰래 백엔드 서버(Virtuoso)로 짧은 SPARQL 쿼리를 던집니다. 
**"이순신과 직접 연결된 데이터만 딱 10개만 가져와!"**
서버가 응답하면, 이순신 동그라미 주변으로 10개의 작은 동그라미가 꽃잎처럼 방사형으로 우아하게 펼쳐집니다. 

| 시각화 방식 | 전통적인 전체 렌더링 | LodLive의 점진적 브라우징 |
| :--- | :--- | :--- |
| **초기 화면** | 수만 개의 노드가 얽힌 끔찍한 머리카락 뭉치 | **단 1개의 깔끔한 중심 노드 (예: 이순신)** |
| **데이터 호출** | 브라우저 로딩 시 전체 데이터를 한 번에 다운로드 | **마우스 클릭(이벤트) 시 필요한 만큼만 실시간 호출** |
| **브라우저 부하** | 메모리 폭발 및 화면 멈춤 발생 | **가볍고 부드러운 애니메이션 유지** |

이 아키텍처를 도입하면 서버와 브라우저 모두 연산의 부담에서 완벽하게 해방되며, 사용자는 미지의 세계를 스스로 개척해 나가는 엄청난 탐험의 희열을 느끼게 됩니다.

## 3. 실전 적용: 우리 서버(Virtuoso)에 LodLive 나침반 연결하기

LodLive를 여러분의 지식 그래프에 연결하는 과정은 거창한 백엔드 코딩을 요구하지 않습니다. 브라우저에서 돌아가는 자바스크립트 설정 파일(`lodlive.profile.js`)에 우리의 "**SPARQL 엔드포인트 주소**"와 "**온톨로지 접두어**"만 살짝 적어주면 끝납니다.

프론트엔드 환경에서 LodLive의 나침반을 세팅하는 핵심 코드를 살펴보겠습니다.

```javascript
// lodlive.profile.js 설정 파일 내부

$.extend(true, $.lodlive.profile, {
    // 1. 우리가 만든 조선시대 지식 그래프 서버의 주소를 기재합니다.
    endpoints: {
        "joseon_endpoint": {
            description: "조선시대 인물 지식 그래프",
            endpoint: "http://localhost:8890/sparql" // Virtuoso 서버 주소
        }
    },

    // 2. SPARQL 쿼리에서 사용할 네임스페이스(접두어)를 친절하게 알려줍니다.
    prefixes: {
        "joseon": "[http://dh.aks.ac.kr/joseon/](http://dh.aks.ac.kr/joseon/)",
        "core": "[http://dh.aks.ac.kr/ontology/core/](http://dh.aks.ac.kr/ontology/core/)"
    },

    // 3. 화면에 동그라미가 예쁘게 그려지도록 규칙을 정합니다.
    defaultSettings: {
        // Person 클래스는 '파란색' 동그라미로 그리고, 안에는 '사람 모양 아이콘'을 넣습니다.
        "[http://dh.aks.ac.kr/ontology/core/Person](http://dh.aks.ac.kr/ontology/core/Person)": {
            nodeLabel: "인물",
            color: "#3498db",
            icon: "fa-user"
        },
        // Post 클래스는 '노란색' 동그라미로 그립니다.
        "[http://dh.aks.ac.kr/ontology/core/Post](http://dh.aks.ac.kr/ontology/core/Post)": {
            nodeLabel: "관직",
            color: "#f1c40f",
            icon: "fa-briefcase"
        }
    }
});
```

이 간단한 세팅을 마치고 `index.html`을 실행하여 검색창에 `joseon:이순신`을 입력하면, 화면 중앙에 파란색 동그라미가 뜹니다. 동그라미를 클릭하는 순간 애니메이션과 함께 이순신의 궤적이 우아하게 펼쳐지며 진정한 의미의 "시각적 디지털 인문학"이 시작됩니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 분노: "이순신을 검색했는데 화면이 하얗게 멈추고 콘솔에 빨간 에러가 뜹니다!"**

LodLive를 처음 설치한 연구실에서 100% 발생하는 가장 악명 높은 통신 에러입니다. 
분명히 엔드포인트 주소(`http://localhost:8890/sparql`)를 정확히 적었는데, 동그라미가 나오지 않습니다. 개발자 도구(F12)를 열어보면 시뻘건 글씨로 "**CORS (Cross-Origin Resource Sharing) Error**"라는 문구가 여러분을 비웃고 있습니다.

**[승리하는 아키텍트의 CORS 방화벽 해제술]**
이것은 LodLive의 잘못이 아니라, 현대 웹 브라우저의 엄격한 "보안 정책" 때문입니다. 
웹 브라우저는 포트 번호 80번(일반 웹사이트)에서 실행 중인 LodLive 스크립트가, 포트 번호 8890번(Virtuoso 서버)이라는 "다른 동네(Cross-Origin)"로 몰래 데이터를 가지러 가는 것을 해킹 시도로 간주하고 강력하게 차단해 버립니다.

이 방화벽을 뚫으려면 클라이언트(JS)를 고치는 것이 아니라, 서버(Virtuoso)의 주방장에게 "누가 오든 문을 열어주어라"라고 지시해야 합니다. 
Virtuoso 관리자 터미널(Conductor)에 접속하여 `[Web Application Server] -> [Virtual Domains & Directories]` 메뉴로 들어갑니다. `/sparql` 경로의 설정을 편집하여, **"Cross-Origin Resource Sharing (CORS)"** 옵션 칸에 **`*` (별표, 모두 허용)**를 입력하고 저장하십시오.

이 별표(`*`) 하나를 넣는 순간 굳게 닫혔던 서버의 문이 열리고, 하얗게 멈췄던 브라우저 화면에 수많은 조선시대 인물들이 화려한 방사형으로 쏟아져 나오는 마법을 경험하게 될 것입니다.

## 5. 요약 및 다음 단계

* 복잡한 SPARQL 쿼리 결과를 직관적인 노드와 링크로 보여주기 위해, 우리는 "**LodLive**"라는 오픈소스 경량 시각화 도구를 사용합니다.
* LodLive는 모든 데이터를 한 번에 그리지 않고, 사용자의 클릭에 따라 하나의 중심 노드에서 주변으로 뻗어 나가는 "**점진적 브라우징**"과 "**방사형 탐색**" 철학을 통해 브라우저의 부하를 막습니다.
* 프론트엔드 시각화 도구가 백엔드 지식 그래프 서버(Virtuoso)에서 데이터를 문제없이 퍼오려면, 반드시 서버 단에서 보안 정책인 "**CORS**"를 허용(별표 `*` 입력)하는 아키텍트의 조치가 선행되어야 합니다.

이제 우리는 "이순신"이라는 하나의 돋보기를 들고 데이터의 숲을 점진적으로 탐험하는 훌륭한 나침반을 얻었습니다. 
하지만, "나는 개별 인물 탐험 말고, 이 지식 그래프 전체의 뼈대(온톨로지)가 어떻게 생겼는지 그 조감도를 한눈에 내려다보고 싶다!"라고 요구하는 학술 연구자들에게는 LodLive가 너무 국소적입니다.
