# 6.2. 데이터 무결성의 수호자: 폐쇄 세계 가정(CWA)의 한계와 필요성

## 1. 도입: 기계가 너무 너그러우면 벌어지는 끔찍한 참사

앞선 장에서 우리는 기계가 인문학 데이터를 다룰 때, 알 수 없는 것을 "거짓"으로 단정 짓지 않고 영원한 가능성으로 열어두는 `"**열린 세계 가정(OWA)**"`의 위대함을 찬양했습니다. 하지만 연구실에서 수십만 건의 데이터를 실제로 입력하다 보면, 이 숭고하고 철학적인 OWA가 곧바로 끔찍한 공학적 재앙으로 돌변하는 순간을 맞이하게 됩니다.

연구를 돕는 조교가 피곤한 나머지 실수로 치명적인 오타를 냈다고 상상해 보십시오.
**"이순신의 출생 연도는 '한양'이다."**

만약 과거의 깐깐한 관계형 데이터베이스(SQL)였다면, 기계는 0.1초 만에 시뻘건 에러 창을 띄우며 "출생 연도 칸에는 숫자(Integer)만 들어와야 하는데 문자열이 들어왔다! 저장 거부!"라고 소리를 질렀을 것입니다. 이것이 바로 `"**닫힌 세계 가정(CWA)**"`의 장점이자 데이터 무결성을 지키는 강력한 방패입니다.

하지만 우리의 고상한 시맨틱 웹(OWA) 추론 엔진은 이 엉터리 데이터를 보고 어떻게 반응할까요? 
*"음, 내 수장고에는 '한양'이 도시 이름이라고 되어 있지만, 내가 모르는 우주 어딘가에는 '한양'이 숫자 1545를 의미할지도 몰라. 우주의 무한한 가능성을 열어두어야 하니, 일단 에러를 내지 않고 맞다고 치고 저장해 주지!"*

기계가 에러를 뿜어내지 않고 이 쓰레기 데이터를 덜컥 삼켜버립니다. OWA의 무한한 자비로움이 사실은 데이터베이스를 오타와 논리적 모순이 넘쳐나는 `"**쓰레기장(Garbage In, Garbage Out)**"`으로 만들어 버리는 주범이었던 것입니다. 

## 2. 해결책 제시: 철학(OWA)과 검문소(CWA)의 완벽한 분리

전 세계의 시맨틱 아키텍트들은 이 혼란을 극복하기 위해 아주 명쾌하고 현실적인 타협안을 도출했습니다. 바로 지식의 `"**발견(추론)**"`과 데이터의 `"**검증(입력)**"`을 완벽하게 분리하는 전략입니다.

우리가 새로운 지식을 추론하고 외부 세계와 데이터를 연결할 때는 한없이 너그러운 `"**OWA(열린 세계)**"`의 철학을 유지합니다. 
하지만 누군가 우리 연구실 서버에 데이터를 새로 밀어 넣으려 할 때만큼은, 입구에 아주 깐깐한 `"**CWA(닫힌 세계)**"` 경찰관을 세워두고 엄격한 검문을 실시하는 것입니다.

*"잠깐! 지금부터 이 서버에 들어오는 모든 '출생 연도'는 무조건 4자리 숫자(Integer)여야만 한다. 내 검문소 규칙에 없는 것은 전부 튕겨낸다!"*

시맨틱 웹의 세계에서 이 깐깐한 CWA 경찰관 역할을 수행하는 최신 국제 표준 기술이 바로 `"**SHACL(Shapes Constraint Language, 샤클)**"`입니다. 우리는 SHACL이라는 검문소 도면을 그려서, OWA의 유연함을 누리면서도 동시에 엑셀이나 SQL에 버금가는 완벽한 `"**데이터 무결성(Data Integrity)**"`을 지켜낼 수 있게 되었습니다.

## 3. 실전 적용: 에러를 처리하는 두 세계의 차이

데이터를 입력하고 검증할 때, 철저한 닫힌 세계(RDB)와 열린 세계(순수 시맨틱 웹), 그리고 이 둘을 결합한 하이브리드 아키텍처(SHACL)가 어떻게 다르게 작동하는지 한눈에 비교해 보겠습니다.

| 비교 항목 | 전통적 RDB (SQL) | 순수 시맨틱 웹 (OWL) | 하이브리드 지식 그래프 (SHACL) |
| :--- | :--- | :--- | :--- |
| **적용 철학** | 순도 100% CWA | 순도 100% OWA | **입력은 CWA, 추론은 OWA** |
| **출생연도에 "한양" 입력 시** | 즉시 에러 발생 (저장 거부) | "한양이 숫자인가 보다" 라며 오판함 | **SHACL 검문소가 즉시 에러 발생** |
| **새로운 속성 추가 시** | 스키마 수정 전까지 에러 발생 | 자유롭게 추가 가능 | **사전 정의된 형태(Shape) 검증 후 수용** |
| **인문학적 평가** | 융통성이 없어 확장이 불가능함 | 쓰레기 데이터가 섞여 신뢰도 하락 | **데이터의 품질과 지식의 확장을 동시 달성** |

우리는 18장(SHACL을 활용한 온톨로지 무결성 기계 검증)에 도달했을 때, 이 위대한 경찰관을 여러분의 데이터베이스 입구에 직접 배치하는 코딩 실무를 아주 깊이 있게 다룰 것입니다. 지금은 "시맨틱 웹도 엄격한 통제가 가능하다"는 구조적 안도감만 가지시면 충분합니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

"교수님, 굳이 새로운 SHACL이라는 기술을 배울 필요가 있습니까? 기존에 온톨로지 규칙을 만드는 `"**OWL(웹 온톨로지 언어)**"`에도 제약 조건(Restriction)을 거는 기능이 있다고 들었는데요?"

시맨틱 웹을 조금 공부한 대학원생들이 100% 빠지는 가장 무서운 함정입니다. **절대로 데이터 검증(Validation) 목적으로 OWL을 사용해서는 안 됩니다.**

OWL은 뼈속까지 `"**OWA(열린 세계)**"` 철학으로 만들어진 추론의 도구입니다. 
만약 여러분이 OWL을 이용해 "출생 연도는 반드시 숫자여야 한다"라고 규칙을 짰다고 해봅시다. 그리고 조교가 실수로 출생 연도에 `"한양"`이라고 입력했습니다.

* **여러분의 기대:** 기계가 "삐빅! 한양은 숫자가 아닙니다! 에러!"라고 경고해 주겠지?
* **실제 OWL의 끔찍한 행동:** 기계는 에러를 뿜지 않습니다. 대신 이렇게 추론합니다. *"주인님이 출생 연도는 무조건 숫자라고 하셨어. 그런데 방금 '한양'이 출생 연도로 들어왔네? 아하! **'한양'이라는 글자는 지금부터 숫자(Integer)구나!**"* 기계가 스스로 우주의 법칙을 뜯어고쳐 버리는 경악스러운 사태가 벌어집니다. 검증과 추론을 혼동하면 데이터베이스의 논리가 완전히 붕괴합니다. 

**시맨틱 아키텍트의 황금률:** 새로운 지식을 생성하고 연결할 때는 `"**OWL(추론 엔진)**"`을 쓰고, 들어오는 데이터의 멱살을 잡고 에러를 뿜어내게 할 때는 무조건 `"**SHACL(검증 엔진)**"`을 분리해서 사용하십시오.

## 5. 요약 및 다음 단계

* 시맨틱 웹의 너그러운 `"**OWA(열린 세계 가정)**"`은 인문학적 진리 탐구에는 적합하지만, 오타나 잘못된 데이터까지 수용하여 데이터 품질을 망가뜨리는 치명적인 약점이 있습니다.
* 이를 해결하기 위해 우리는 데이터의 입구에 `"**CWA(닫힌 세계 가정)**"`의 철학을 띤 엄격한 경찰관, `"**SHACL**"`을 배치하여 엑셀 수준의 데이터 무결성을 확보합니다.
* 데이터의 검증(Validation)에 추론용 언어인 OWL을 사용하면 기계가 논리를 왜곡해 버리므로, 검증과 추론은 반드시 시스템적으로 분리되어야 합니다.

이제 여러분의 머릿속에는 시맨틱 웹의 완벽한 철학적 뼈대가 세워졌습니다.
