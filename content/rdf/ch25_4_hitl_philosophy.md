# 25.4. 한계와 철학: Human-in-the-Loop(HITL) 체계

## 1. 도입: 기계의 오독이 만들어낸 끔찍한 대체 역사

우리는 앞선 25장의 파이프라인들을 통해 딥러닝과 거대 언어 모델(LLM)이라는 압도적인 무기를 손에 넣었습니다. 이제 텍스트 파일로 된 《조선왕조실록》 500년 치를 서버에 올려두고, 실행(Run) 버튼만 누른 채 퇴근하면 기계가 밤새 수백만 건의 지식 그래프를 쏟아낼 것입니다. 디지털 인문학자로서 꿈에 그리던 궁극의 자동화입니다.

하지만 다음 날 아침, 연구실에 출근하여 기계가 만들어낸 지식 그래프를 열어본 여러분은 경악을 금치 못하게 됩니다.
사료에 기록된 **"원균이 모함하여 이순신이 백의종군하게 되었다"**라는 복잡한 정치적 맥락을 인공지능이 오독하여, **"원균이 이순신을 백의종군이라는 관직에 임명하였다"**라는 끔찍한 시맨틱 트리플로 변환해 버린 것입니다. 기계는 반어법이나 은유, 고도로 꼬인 당파 싸움의 행간을 읽어내지 못합니다. 

이러한 기계의 환각(Hallucination)이 필터링 없이 우리의 완벽한 저장소(Virtuoso, Wikibase)에 쏟아져 들어가는 순간, 지식의 거미줄은 치명적인 독에 감염됩니다. 오염된 1만 건의 트리플을 사후에 찾아내어 지우는 것은, 처음부터 수작업으로 데이터를 입력하는 것보다 수백 배의 고통을 수반합니다. 기계는 결코 역사의 최종 판관이 될 수 없습니다.

## 2. 해결책 제시: 기계와 인문학자의 완벽한 동업, "**Human-in-the-Loop(HITL)**"

이 재앙을 막기 위해 디지털 인문학의 데이터 파이프라인은 반드시 "**Human-in-the-Loop(HITL, 인간 참여형 루프)**"라는 철학적 아키텍처 위에서 설계되어야 합니다.

인문학적으로 비유해 보겠습니다. 인공지능은 하루에 책 만 권을 읽고 요약해 내는 천재적이지만 매우 덤벙대는 "**수습 연구원**"입니다. 그리고 여러분은 이 편찬 사업의 최종 책임을 지는 "**총괄 편찬 책임자(인문학자)**"입니다. 
수습 연구원이 텍스트에서 뽑아낸 인물과 관직 데이터는 결코 곧바로 정식 사전에 등재되지 않습니다. 반드시 "**임시 보관소(Draft)**"에 머물러야 하며, 총괄 책임자인 여러분이 눈으로 확인하고 "**승인(Approve)**" 도장을 찍었을 때만 비로소 지식 그래프(RDF)로 편입되어야 합니다.

| 파이프라인 철학 | 작동 방식 | 인문학적 결과 |
| :--- | :--- | :--- |
| **완전 수작업 (100% Human)** | 연구자가 원문을 다 읽고 엑셀에 입력 | **실패.** 속도가 너무 느려 평생 실록의 1%도 못 봄. |
| **완전 자동화 (100% AI)** | 기계가 원문을 읽고 DB에 즉시 적재 | **실패.** 기계의 오독으로 지식망이 오염되고 대체 역사 창조. |
| **인간 참여형 루프 (HITL)** | **기계가 99%를 추출하고, 인간이 최종 승인** | **성공.** 압도적인 속도와 인문학적 무결성을 동시에 달성. |

## 3. 실전 적용: 기계의 확신도(Confidence Score)를 이용한 승인 시스템

그렇다면 기계가 뽑아낸 수백만 건을 사람이 결국 다 읽어야 할까요? 그렇지 않습니다. 파이프라인 코드 내부에 "**확신도(Confidence Score)**"라는 밸브를 장착하여, 기계 스스로 헷갈리는 데이터만 인간에게 토스하도록 설계할 수 있습니다.

다음은 파이썬(Python) 환경에서 LLM의 결과를 필터링하는 실무 로직입니다.

```python
# 1. LLM이 추출한 결과물에는 기계 스스로 평가한 "확신도(confidence)" 점수가 포함되어 있습니다.
extracted_data = [
    {"subject": "선조", "predicate": "appoints", "object": "이순신", "confidence": 0.98},
    {"subject": "원균", "predicate": "appoints", "object": "백의종군", "confidence": 0.45} # 기계가 문맥을 헷갈려 합니다.
]

# 2. 데이터를 저장할 임시 창고(리스트)를 준비합니다.
approved_triples = []
review_needed = []

# 3. 확신도 임계값(Threshold)을 90%로 설정하고 데이터를 분류합니다.
for item in extracted_data:
    if item["confidence"] >= 0.90:
        # 확신도가 90% 이상이면 기계를 믿고 즉시 지식 그래프로 변환(승인)합니다.
        approved_triples.append(item)
    else:
        # 확신도가 90% 미만이면 "보류" 상태로 두고 인간 전문가의 리뷰 창으로 보냅니다.
        item["status"] = "REVIEW_NEEDED"
        review_needed.append(item)

# 4. 인간 인문학자는 'review_needed' 목록만 확인하여 기계의 오독을 교정합니다.
print(f"자동 승인된 데이터: {len(approved_triples)}건")
print(f"인간의 검토가 필요한 데이터: {len(review_needed)}건")
```

이 코드를 통해 인문학자는 1만 건의 데이터 중 기계가 헷갈려 하는 단 500건만 눈으로 확인(QC)하면 됩니다. 이는 노동력의 95%를 절감하면서도 데이터의 무결성을 100% 지켜내는 궁극의 파이프라인 설계입니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 치명적 위기: "기계가 틀린 답을 내놓고 확신도를 99%라고 우깁니다!"**

이것이 인공지능의 가장 교활하고 위험한 점입니다. 이를 "**과잉 확신(Overconfidence)**"이라고 부릅니다. 거대 언어 모델(LLM)은 때때로 전혀 존재하지 않는 가상의 조선시대 관직을 만들어내고는, 그것이 100% 진실이라고 뻔뻔하게 높은 점수를 매깁니다. 단순한 점수(Score) 기반의 필터링만 믿었다가는 지식 그래프가 붕괴합니다.

**[승리하는 아키텍트의 교차 검증(Cross-Validation) 방어술]**
기계의 주관적인 점수를 맹신하지 마십시오. 파이프라인의 마지막 문지기는 반드시 우리가 만든 "**표준 온톨로지 사전**"이 되어야 합니다. 

코드를 짤 때, 기계가 추출한 목적어(Object)가 우리의 데이터베이스(예: 한국학중앙연구원 관직명 DB)에 실제로 존재하는 단어인지 텍스트를 대조(String Matching)하는 로직을 반드시 추가해야 합니다. 기계가 99%의 확신도로 "우주방위사령관"이라는 관직을 추출했더라도, 우리 사전에 그 단어가 없다면 확신도와 무관하게 무조건 "**인간 검토(REVIEW_NEEDED)**" 상태로 강제 전환시켜 버리는 것이 실무 인프라의 철칙입니다.

## 5. 요약 및 대단원 마무리

* 압도적인 인공지능 기술조차 사료의 복잡한 맥락 앞에서는 치명적인 환각(Hallucination)과 오독을 만들어냅니다.
* 데이터 파이프라인의 폭주를 막고 역사적 무결성을 지키기 위해, 인간이 최종 결정권자로 참여하는 "**Human-in-the-Loop(HITL)**" 아키텍처가 필수적입니다.
* 확신도(Confidence Score)에 의존하는 것을 넘어, 기존 사전(Dictionary)과의 엄격한 "**교차 검증**"을 통해서만 진정한 디지털 인문학 지식 그래프를 완성할 수 있습니다.

축하합니다! 여러분은 이제 단순한 코딩 학습자를 넘어, 데이터를 지식으로 빚어내고 인공지능을 조련하며, 인문학적 철학으로 파이프라인을 통제하는 진정한 의미의 "**디지털 인문학 아키텍트(DH Architect)**"로 거듭났습니다.

온톨로지의 뼈대를 세우던 첫 모듈부터, 서버를 구축하고, 딥러닝과 LLM으로 사료의 바다를 항해한 이 위대한 여정은 여기까지입니다. 여러분이 구축한 이 거대한 지식의 거미줄 위에서, 앞으로 펼쳐질 수백만 가지의 새로운 역사적 상상력과 융합 연구의 찬란한 미래를 기대합니다.
