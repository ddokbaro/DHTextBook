# 29장. 검색엔진 최적화(SEO)와 JSON-LD 임베딩 파이프라인

## 1. 도입: 지식 그래프를 만들었는데 왜 구글 검색에 안 나올까?

우리는 지난 7개의 모듈을 거치며 엄청난 시간과 예산을 들여 완벽한 《조선왕조실록》 지식 그래프 서버(Virtuoso)를 구축했습니다. 이제 대중에게 이 위대한 성과를 알리기 위해 멋진 웹사이트를 만들고, 화면에 이순신 장군의 생애와 관직 이력을 텍스트로 예쁘게 디자인해서 올렸습니다.

연구 책임자인 여러분은 부푼 마음으로 구글에 접속하여 "이순신 전라좌수사 임명 연도"라고 검색해 봅니다. 하지만 구글의 최상단에는 여러분의 공식 웹사이트가 아니라, 누군가 개인 블로그에 대충 적어놓은 부정확한 글이나 위키백과만 덩그러니 뜹니다.

도대체 왜 이런 일이 벌어졌을까요? 구글의 검색 로봇(Crawler)은 시각적으로 예쁘게 꾸며진 HTML 웹페이지를 읽을 때, 인간처럼 "아, 이 사람이 이순신이고 이 직책을 이때 받았구나"라고 논리적으로 이해하지 못합니다. 로봇에게 웹페이지는 그저 의미 없는 글자들의 무작위적인 나열일 뿐입니다. 우리가 뼈 빠지게 만든 완벽한 시맨틱 지식망(RDF)은 우리 서버의 깊은 터미널 창(SPARQL) 안에만 갇혀 있을 뿐, 넓은 인터넷 세상으로는 단 한 발자국도 나가지 못한 것입니다.

## 2. 해결책 제시: 구글 봇을 위한 비밀 초대장, "**JSON-LD**"

이 고립을 타개하고 우리의 웹사이트를 구글 검색의 최상단("**지식 패널**")에 노출하기 위해, W3C와 구글이 강력하게 권장하는 최신 시맨틱 웹 표준이 바로 "**JSON-LD(JavaScript Object Notation for Linked Data)**"입니다.

인문학적으로 비유하자면, 이것은 박물관의 쇼윈도와 수장고의 관계입니다. 
일반 관람객(인간)은 박물관의 앞문으로 들어와서 예쁘게 전시된 유리관(HTML 웹페이지 화면)을 감상합니다. 하지만 매우 깐깐한 학예사(구글 검색 로봇)는 앞문으로 들어오지 않습니다. 그는 박물관 뒷문으로 들어와서 유물의 정확한 출처와 제원이 적힌 "**보증서**"를 요구합니다.

우리는 웹페이지의 소스 코드(HTML) 뒷면에 인간의 눈에는 보이지 않지만 기계가 너무나도 사랑하는 포맷인 "**JSON-LD**" 보증서를 몰래 끼워 넣어야 합니다. 이 보증서 안에는 우리가 앞서 고생해서 짰던 시맨틱 트리플(주어-서술어-목적어)이 완벽하게 담겨 있습니다. 구글 로봇은 이 보증서를 발견하는 순간, 여러분의 웹사이트를 "최고급 신뢰도를 가진 지식의 원천"으로 분류하고 검색 최상단으로 끌어올립니다.

| 정보 제공 방식 | 인간을 위한 앞문 (HTML 텍스트) | 기계를 위한 뒷문 (JSON-LD 임베딩) |
| :--- | :--- | :--- |
| **형태** | 시각적 디자인, 굵은 글씨, 이미지 | `<script type="application/ld+json">` 태그 |
| **타겟 독자** | 일반 웹사이트 방문자 | **구글 검색엔진 크롤러 봇** |
| **결과** | 독자가 글을 읽고 파편적으로 이해함 | **구글이 검색 결과 우측 '지식 패널'에 구조화된 데이터를 띄워줌** |

## 3. 실전 적용: 웹페이지 뒷면에 조선시대 인물 지식 심어두기

만약 여러분이 "이순신 장군"을 소개하는 웹페이지(`index.html`)를 만들었다고 가정해 봅시다. 
이 페이지가 구글 검색엔진에 완벽하게 걸려들게 하려면, 웹페이지의 `<head>` 태그나 `<body>` 태그 하단에 다음과 같은 "**JSON-LD**" 코드를 심어주어야 합니다.

거북이(Turtle) 문법의 투박함을 버리고, 현대 웹 개발자들이 가장 사랑하는 중괄호 `{ }` 형태의 JSON으로 진화한 시맨틱 트리플의 아름다운 모습을 감상해 보십시오.

```html
<html>
  <body>
    <h1>이순신 장군</h1>
    <p>조선 중기의 무신으로 1591년에 전라좌수사에 임명되었다.</p>
  </body>

  <script type="application/ld+json">
  {
    "@context": "[http://schema.org](http://schema.org)",
    "@type": "Person",
    "name": "이순신",
    "birthDate": "1545-04-28",
    "deathDate": "1598-12-16",
    "jobTitle": "전라좌수사",
    "memberOf": {
      "@type": "Organization",
      "name": "조선 수군"
    },
    "url": "[http://dh.aks.ac.kr/joseon/person/이순신](http://dh.aks.ac.kr/joseon/person/이순신)"
  }
  </script>
</html>
```

이 코드가 심어진 웹페이지가 인터넷에 발행되면, 며칠 뒤 구글의 크롤러 봇이 방문합니다. 봇은 화면의 한글 텍스트 디자인을 대충 훑어보고는, 직행으로 `<script type="application/ld+json">` 블록을 파싱합니다. 그리고 "아! 이 페이지는 조선 수군 소속의 '이순신'이라는 사람(Person)의 엄격한 지식을 담고 있구나!"라고 100%의 정확도로 이해하며, 구글 검색망 중앙에 여러분의 데이터를 꽂아 넣습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 피눈물: "웹 프론트엔드 개발자가 거북이(Turtle) 파일을 보고 프로젝트를 탈주했습니다!"**

디지털 인문학 센터에서 웹사이트를 외주 개발할 때 100% 벌어지는 참사입니다. 
인문학자가 웹 개발자에게 "우리 서버에 있는 `.ttl(거북이)` 파일이나 `RDF/XML` 파일 데이터를 읽어서 화면에 띄워주세요"라고 요구하면, 자바스크립트(JS)에만 익숙한 일반 프론트엔드 개발자들은 생전 처음 보는 기괴한 문법에 경악을 금치 못하고 프로젝트를 포기해 버립니다.

**[승리하는 아키텍트의 JSON-LD 브릿지 전술]**
이 언어의 장벽을 허무는 평화협정 문자가 바로 "**JSON-LD**"입니다.
JSON-LD는 지식 그래프의 고도화된 철학(Linked Data)을 담고 있으면서도, 그 껍데기는 철저하게 현대 웹 표준인 "**JSON**"의 형태를 띠고 있습니다. 

총괄 아키텍트인 여러분은 백엔드 서버(Virtuoso)의 SPARQL 쿼리 결과를 `.ttl`이 아니라 무조건 **`application/ld+json`** 포맷으로 출력하도록 API를 설계해야 합니다. 프론트엔드 개발자는 이 JSON 데이터를 받는 순간 안도의 한숨을 내쉬며 화면을 유려하게 그려낼 수 있습니다. JSON-LD는 단순한 구글 검색용(SEO)을 넘어, "시맨틱 웹 세계"와 "현대 웹 개발 생태계"를 이어주는 가장 완벽하고 유일한 다리(Bridge)입니다.

## 5. 요약 및 다음 단계

* 우리가 구축한 지식 그래프를 구글 검색엔진에 노출(SEO)하기 위해서는, HTML 화면의 텍스트가 아니라 기계가 명확히 읽을 수 있는 보증서인 "**JSON-LD**"를 웹페이지에 심어주어야 합니다.
* "**JSON-LD**"는 트리플의 시맨틱 철학을 유지하면서도 웹 개발자에게 친숙한 JSON 형태를 띠고 있어 프론트엔드 개발과의 협업을 매끄럽게 만듭니다.
* 구글 로봇은 이 숨겨진 JSON-LD 블록을 분석하여 우리 웹사이트를 신뢰도 높은 데이터 원천으로 인식하고 검색 결과의 최상단 지식 패널에 올려줍니다.

이제 우리는 구글에게 초대장을 보내는 강력한 무기를 얻었습니다. 
하지만 웹페이지에 시맨틱 데이터를 심는 방법이 역사적으로 JSON-LD 하나뿐이었을까요? 과거의 학자들은 화면의 HTML 태그 안에 직접 속성을 욱여넣는 "마이크로데이터(Microdata)"라는 고통스러운 방식을 사용했습니다. 왜 구글은 그 방식을 버리고 JSON-LD라는 "데이터 아일랜드(Data Island)" 방식을 채택했을까요?
