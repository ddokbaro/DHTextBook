# 27장. SHACL을 활용한 온톨로지 무결성 기계 검증

## 1. 도입: 거대한 지식의 성채를 무너뜨리는 단 하나의 "오타"

우리는 모듈 6과 26장을 거치며, 더러운 원시 데이터를 세탁하고 인공지능(LLM)을 조련하여 수백만 건의 역사 데이터를 지식 그래프로 변환하는 경이로운 파이프라인을 구축했습니다. 이제 여러분의 서버에는 《조선왕조실록》과 《승정원일기》에서 추출된 트리플(Triple)들이 초당 수천 건씩 폭포수처럼 쏟아져 들어오고 있습니다.

하지만 이 웅장한 자동화의 이면에는 디지털 인문학자를 밤잠 설치게 만드는 끔찍한 공포가 도사리고 있습니다.
만약 피곤에 지친 연구 보조원이나, 텍스트를 잘못 읽은 인공지능이 다음과 같은 데이터를 서버에 밀어 넣는다면 어떻게 될까요?
* 이순신의 출생 연도를 숫자 "1545"가 아니라 한글 "**명종 원년**"으로 입력해 버렸다.
* 전라좌수사라는 관직에 사람(Person)이 아니라 "**거북선(Artifact)**"을 임명해 버렸다.
* 이순신의 사망 연도를 "1598년"이 아니라 오타를 내어 "**1958년**"으로 적어버렸다.

기존의 전통적인 RDF 데이터베이스는 너무나도 관대해서 이런 끔찍한 시대착오적 쓰레기 데이터들을 아무런 저항 없이 모두 받아들입니다. 1,000만 건의 데이터 속에 섞여 들어간 100건의 치명적인 오류를 인간 사학자가 일일이 눈으로 찾아내는 것은 불가능합니다. 무결성이 무너진 데이터베이스는 학술적 가치를 상실합니다. 우리는 기계에게 **"이 규칙에 맞지 않는 불량품은 입구에서부터 쳐내라"**고 명령할 아주 엄격한 문지기가 필요합니다.

## 2. 해결책 제시: 지식의 국경을 지키는 무자비한 세관원, "**SHACL**"

이 거룩한 지식의 성채를 오염물질로부터 지켜내기 위해 W3C가 제정한 최신 글로벌 표준이 바로 "**SHACL(Shapes Constraint Language, 샤클)**"입니다.

인문학적으로 비유하자면, "**SHACL**"은 지식 그래프 서버의 입구에 서 있는 아주 무자비하고 깐깐한 "**세관원**"입니다. 
연구자인 여러분은 이 세관원에게 "**형태(Shape)**"라고 불리는 엄격한 검사 매뉴얼을 쥐여줍니다. 매뉴얼에는 이렇게 적혀 있습니다.
* "사람(Person) 노드는 반드시 정수형 숫자(Integer)로 된 출생 연도를 가져야 한다."
* "관직 임용(hasPost) 화살표의 끝에는 반드시 관직(Post) 노드만 와야 한다. 사물(Artifact)이 오면 즉시 폐기하라."

세관원(SHACL 엔진)은 파이프라인을 타고 들어오는 수백만 건의 데이터를 이 매뉴얼이라는 틀(Mold)에 하나씩 끼워봅니다. 만약 "1958"이라는 오타가 나서 사망 연도가 미래로 가 있거나, "명종 원년"이라는 글자가 들어와 틀에 맞지 않으면, 세관원은 즉시 입국을 거부하고 여러분의 모니터에 "**빨간색 에러 보고서(Validation Report)**"를 띄워 경고합니다. 인간의 노동이 기계의 자동 검증으로 대체되는 기적의 순간입니다.

## 3. 실전 적용: 이순신 데이터의 무결성을 검증하는 SHACL 코드

여러분에게 누군가 이순신 장군의 데이터를 작성하여 제출했습니다. 그런데 사망 연도에 치명적인 오타("1958")가 포함되어 있습니다. 이를 잡아내는 "**SHACL**" 코드를 작성해 보겠습니다.

```turtle
# 1. 네임스페이스 선언
@prefix sh: <http://www.w3.org/ns/shacl#> .
@prefix joseon: <http://dh.aks.ac.kr/joseon/> .
@prefix core: <http://dh.aks.ac.kr/ontology/core/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

# 2. 세관원의 매뉴얼, "사람 형태(PersonShape)"를 정의합니다.
joseon:PersonShape a sh:NodeShape ;
    sh:targetClass core:Person ;   # 이 검사소는 'Person' 클래스만 심사합니다.

    # 3. 사망 연도(deathYear)에 대한 엄격한 규칙을 세웁니다.
    sh:property [
        sh:path core:deathYear ;          # 검사할 화살표(속성) 지정
        sh:datatype xsd:integer ;         # 반드시 숫자여야 합니다. "명종 원년" 불가능.
        sh:maxCount 1 ;                   # 사망 연도는 인생에서 단 1번뿐이어야 합니다.
        sh:maxInclusive 1897 ;            # [핵심] 조선시대 인물이므로 대한제국 선포(1897년) 이후에 죽을 수 없습니다!
        sh:message "치명적 오류: 조선시대 인물의 사망 연도가 범위를 벗어났거나 숫자가 아닙니다."
    ] .
```

이 코드를 서버에 등록해 두면, 누군가 "이순신의 사망 연도는 1958년이다"라는 데이터를 넣으려 시도하는 순간 서버는 이를 차단합니다. **"1958은 1897보다 크므로 조선시대 인물일 수 없다"**는 논리적 위반을 기계가 스스로 찾아낸 것입니다. 우리는 이 기술을 통해 1,000만 건의 데이터 전체를 단 1초 만에 논리적으로 전수 조사할 수 있습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 착각: "규칙에 없는 속성을 넣었더니 SHACL이 통과시켜 버렸습니다!"**

이것은 시맨틱 웹의 철학을 처음 접하는 인문학자들이 100% 당황하는 "**열린 세계의 가정(Open World Assumption)**" 문제입니다.
만약 여러분이 이순신 데이터에 온톨로지 규칙에도 없는 `core:좋아하는음식 "국밥"`이라는 정체불명의 화살표를 추가해서 넣었다고 해봅시다. 놀랍게도 깐깐하다던 "**SHACL**" 세관원은 이를 에러로 잡지 않고 무사통과시킵니다!

**[승리하는 아키텍트의 폐쇄형(Closed) 통제술]**
기본적으로 RDF 생태계는 "우리가 모르는 지식도 어딘가에는 존재할 수 있다"는 열린 철학을 가집니다. 그래서 매뉴얼에 없는 속성이 들어오면 "위반이 아니라, 내가 모르는 새로운 지식인가 보다" 하고 관대하게 받아들입니다.

하지만 실무에서 이런 관대함은 데이터베이스를 정체불명의 쓰레기 속성(`favoriteFood`, `test1234` 등)으로 가득 차게 만듭니다. 이를 원천 차단하려면, SHACL 코드 안에 반드시 **`sh:closed true ;`** 라는 마법의 주문을 추가해야 합니다. 
이 한 줄이 들어가는 순간, 세관원은 매뉴얼(Shape)에 명시되지 않은 그 어떤 사소한 화살표도 전부 에러로 간주하고 무자비하게 폐기 처분합니다. 엄격한 국가 표준 지식 그래프를 구축할 때 이 "**폐쇄형 검증**" 옵션은 선택이 아닌 필수입니다.

## 5. 요약 및 다음 단계

* 데이터베이스에 시대착오적 오류나 오타가 유입되는 것을 막기 위해, 기계가 스스로 데이터를 검증하는 W3C 표준 "**SHACL(샤클)**"을 도입해야 합니다.
* "**SHACL**"은 세관원처럼 작동하며, 데이터가 우리가 설계한 엄격한 매뉴얼인 "**형태(Shape)**"의 조건(데이터 타입, 최댓값 등)에 맞는지 기계적으로 심사합니다.
* 불필요한 가짜 데이터 유입을 막기 위해서는 시맨틱 웹의 "열린 세계의 가정"을 극복하고, **`sh:closed true`** 옵션을 통해 승인되지 않은 화살표를 원천 차단하는 아키텍트의 결단이 필요합니다.

이제 우리는 기계에게 "무엇이 옳고 그른지" 논리적으로 판단하는 법을 가르쳤습니다. 
하지만 방금 우리가 만든 것은 "사람"이라는 단일 클래스에 대한 간단한 규칙일 뿐입니다. 수백 개의 클래스와 속성이 얽혀 있는 거대한 국가 단위의 지식망 전체를 어떻게 체계적으로 통제할 수 있을까요?

다음 장인 "**27.1. 형태 그래프(Shapes Graph)를 통한 거버넌스 통제**"로 진입하여, 개별 규칙들을 하나로 묶어 거대한 헌법과도 같은 "형태 그래프"를 구축하고, 대규모 편찬 사업에서 다수의 연구자들이 생산하는 데이터를 통제하는 최상위 아키텍처 거버넌스를 완벽하게 마스터해 보겠습니다!
