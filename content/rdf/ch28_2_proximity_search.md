# 28.2. 공간 추론 실전 1: 반경 내 객체 탐색

## 1. 도입: 텍스트의 바다에 "공간 레이더"를 켜다

우리는 앞선 28.1장에서 텍스트로 이루어진 "한산도"와 "전라좌수영"에 위도와 경도(WKT)를 부여하고, 기계에게 두 점 사이의 거리를 계산하게 만들었습니다. 기계가 둥근 지구의 곡률을 이해하고 "58.3km"라는 정답을 내놓는 것을 보며 우리는 전율했습니다.

하지만 역사학자의 질문은 단편적인 거리 계산에 머물지 않습니다. 
임진왜란 당시 한산도에 머물던 이순신 장군은 위급 상황 발생 시 당일 내로 지원군을 보낼 수 있는 인근 수군 진영들이 어디인지 파악해야 했습니다. 판옥선의 속도를 고려할 때, 지원 가능한 한계선은 대략 "**반경 50km**"입니다.

디지털 인문학자로서 여러분의 임무는 이것입니다.
**"한산도를 중심으로 반경 50km의 원을 그리고, 그 안에 들어오는 모든 조선 수군 진영(鎭營)의 이름과 거리를 지식 그래프에서 모조리 뽑아내어라!"**

기존의 엑셀이나 텍스트 검색으로는 절대 불가능한 질문입니다. 우리는 텅 빈 허공에 점을 찍고, 보이지 않는 원을 그리며, 그물망에 걸려드는 역사적 사실들을 건져 올리는 고차원적인 "**근접성 탐색(Proximity Search)**"을 시작해야 합니다.

## 2. 해결책 제시: 반경 탐색의 수학적 마법, "**FILTER와 거리 함수의 결합**"



컴퓨터 공학에서 반경 내의 객체를 찾는 근접성 탐색은 복잡해 보이지만, 그 철학적 원리는 매우 단순합니다. 

인문학적으로 비유해 보겠습니다. 한산도 통제영의 산봉우리에 거대한 **"봉수대(Beacon Fire)"**를 세우고 불을 지핍니다. 이 불꽃은 사방 50km까지 보입니다. 이제 기계라는 전령을 전국 방방곡곡의 수군 진영으로 보냅니다. 전령은 각 진영에 서서 봉홧불이 보이는지 확인하고, 보인다면(50km 이내라면) 그 진영의 이름을 수첩에 적어 돌아옵니다.

이 과정을 SPARQL 코드로 구현하려면, 이전에 배운 거리 계산 사투리 함수인 "**bif:st_distance**"를 "**FILTER**"라는 거름망과 결합하기만 하면 됩니다. 

| 추론 논리 단계 | 인문학적 작동 원리 | SPARQL/GeoSPARQL 구현 |
| :--- | :--- | :--- |
| **1단계: 타겟 고정** | 한산도의 봉수대 위치(좌표)를 파악한다. | `joseon:한산도 geo:asWKT ?center_wkt` |
| **2단계: 전수 조사** | 전국의 모든 진영(좌표)을 순회한다. | `?base a joseon:NavalBase ; geo:asWKT ?target_wkt` |
| **3단계: 레이더 거름망** | 두 좌표의 거리를 재어 50km 이내만 남긴다. | **`FILTER (bif:st_distance(?center, ?target) <= 50)`** |

## 3. 실전 적용: 한산도 반경 50km 내의 지원군 목록 추출하기

이제 가상의 공간 레이더를 가동하여, 한산도 인근에서 이순신 장군을 도울 수 있었던 진영의 목록과 그 거리를 가까운 순서대로 정렬해 보겠습니다.

```sparql
# 1. 공간 추론을 위한 네임스페이스 선언
PREFIX geo: [http://www.opengis.net/ont/geosparql#](http://www.opengis.net/ont/geosparql#)
PREFIX joseon: [http://dh.aks.ac.kr/joseon/](http://dh.aks.ac.kr/joseon/)
PREFIX core: [http://dh.aks.ac.kr/ontology/core/](http://dh.aks.ac.kr/ontology/core/)

# 2. 결과로 출력할 진영 이름(?name)과 거리(?dist)를 요청합니다.
SELECT ?name ?dist
WHERE {
    # 3. 기준점(한산도)의 좌표를 가져옵니다.
    joseon:한산도 geo:asWKT ?center_wkt .
    
    # 4. 전국의 모든 수군 진영(?base)을 찾고, 그 이름과 좌표를 가져옵니다.
    ?base a joseon:NavalBase ;
          core:hasName ?name ;
          geo:asWKT ?target_wkt .
          
    # 5. [핵심] 공간 레이더 거름망 가동! 
    # 한산도와 대상 진영 사이의 거리가 50(km) 이하인 데이터만 통과시킵니다.
    FILTER (bif:st_distance(?center_wkt, ?target_wkt) <= 50)
    
    # 6. 통과된 진영들의 정확한 거리를 ?dist 변수에 담아줍니다.
    BIND(bif:st_distance(?center_wkt, ?target_wkt) AS ?dist)
}
# 7. 가장 가까운 진영부터 오름차순(ASC)으로 정렬하여 출력합니다.
ORDER BY ASC(?dist)
```

이 쿼리를 실행하면, 기계는 0.1초 만에 "미륵도(5km), 거제도(15km), 가덕도(45km)" 등 50km 반경 안에 들어온 진영들을 거리순으로 깔끔하게 정렬하여 보여줍니다. 우리는 텍스트 더미 속에서 공간의 숨결을 완벽하게 복원해 냈습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 대참사: "반경 50km를 검색했는데, 저 멀리 함경도의 진영까지 검색됩니다!"**

이것은 공간 질의를 돌리다 보면 갑자기 등골이 서늘해지는 최악의 버그입니다. 분명히 거름망(`FILTER <= 50`)을 걸었는데, 남해안에 있는 한산도로부터 수백 킬로미터 떨어져 있는 북한 함경도의 수군 기지가 결과 목록에 당당하게 섞여 나옵니다. "기계가 미친 것일까?"라는 탄식이 절로 나옵니다.

**[승리하는 아키텍트의 공간 인덱스(Spatial Index) 방어술]**
기계는 미치지 않았습니다. 원인은 28.1장에서 강조했던 "**좌표계(SRID)**"의 누락, 혹은 서버의 "**공간 인덱스(Spatial Index)**" 미설정에 있습니다.

만약 여러분이 엑셀에서 데이터를 넣을 때 `geo:asWKT` 앞에 지구 형태 번호(`SRID=4326`)를 붙이지 않았다면, 서버는 거리를 킬로미터(km)가 아니라 평면의 **"도(Degree)"** 단위로 계산해 버립니다. 
위도 1도는 약 111km입니다. 즉, 기계의 눈에 `FILTER (distance <= 50)`이라는 명령은 **"반경 50km"**가 아니라 **"반경 50도(약 5,500km)"**로 해석된 것입니다! 5,500km면 함경도를 넘어 러시아의 블라디보스토크까지 쓸어 담고도 남는 거대한 원입니다.

이 대참사를 막기 위해서는 다음 두 가지 실무 원칙을 절대 잊어서는 안 됩니다.
1. 모든 WKT 좌표 텍스트 앞에 반드시 **`<http://www.opengis.net/def/crs/OGC/1.3/CRS84>`** 라는 SRID 헤더를 부착할 것.
2. 대량의 데이터를 넣은 직후에는 Virtuoso 서버의 관리자 터미널에 접속하여 **`DB.DBA.RDF_GEO_FILL();`** 명령어를 실행하여 둥근 지구 모양의 "**공간 인덱스**"를 갱신해 줄 것. 이 인덱스 갱신을 까먹으면 레이더는 영원히 고장 난 채로 작동합니다.

## 5. 요약 및 다음 단계

* 단순한 텍스트 검색을 넘어, 특정 장소를 중심으로 반경 N km 이내의 역사적 객체를 찾아내는 "**근접성 탐색(Proximity Search)**"은 디지털 인문학 지리 분석의 꽃입니다.
* SPARQL 쿼리 내부에 공간 계산 함수(`bif:st_distance`)와 조건문(`FILTER`)을 결합하면, 기계가 가상의 봉수대를 켜고 거리 조건에 맞는 데이터만 완벽하게 필터링해 냅니다.
* 거리 단위가 킬로미터(km)가 아닌 도(Degree)로 잘못 계산되어 대륙 단위의 오탐이 발생하는 것을 막으려면, SRID의 엄격한 선언과 서버의 공간 인덱스 갱신이 필수적입니다.

이제 우리는 점과 점 사이의 거리를 재고 반경을 그리는 마법을 자유자재로 다룰 수 있게 되었습니다. 
하지만 역사 속의 공간은 단순히 바늘로 콕 찌른 "점(Point)"으로만 존재하지 않습니다. 전라좌수영의 관할 구역은 수많은 섬과 해안선을 품고 있는 거대한 "**다각형(Polygon)**"입니다. 

만약 이순신 장군의 함대가 이동한 경로(Line)가 경상우수영의 관할 구역(Polygon) 안으로 침범했는지(교차했는지)를 기계에게 묻고 싶다면 어떻게 해야 할까요?

마지막 장인 "**28.3. 공간 추론 실전 2: 다각형 교차 판별 (Polygon Overlay)**"로 진입하여, 점과 선, 면이 서로 부딪히고 겹치는 고차원적인 기하학적 추론의 궁극을 완성해 보겠습니다!
