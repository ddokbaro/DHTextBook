# 16.2. 캔버스 해부: Active Ontology, Entities, Individuals 탭의 유기적 이해

## 1. 도입: 비행기 조종석에 앉은 역사학자의 당혹감

엑셀(Excel)에 익숙한 인문학도들이 처음 **"Protégé"**(프로테제)를 실행하면 엄청난 당혹감에 휩싸입니다. 화면 상단에는 수십 개의 알 수 없는 메뉴가 나열되어 있고, 화면은 여러 개의 작은 창으로 쪼개져 있으며, 엑셀처럼 직관적으로 글자를 입력할 수 있는 표(Grid)는 어디에도 보이지 않습니다. 

마치 자전거만 타던 사람이 수백 개의 버튼이 달린 보잉 747 여객기의 조종석에 앉은 것과 같은 막막함입니다. 엑셀의 평면적인 감옥을 탈출하기 위해 켰지만, 이 복잡한 메뉴판 앞에서 연구원들은 길을 잃고 맙니다. 조선시대 문무백관의 데이터를 입력해야 하는데, 대체 어디를 클릭해야 이순신이라는 인물을 만들고 전라좌수사라는 관직을 부여할 수 있을까요?

두려워할 필요 없습니다. Protégé의 수많은 메뉴와 탭들은 사실 단 3개의 핵심 공간으로 귀결됩니다. 이 3개의 공간이 서로 어떻게 유기적으로 연결되어 조선시대라는 거대한 세계관을 렌더링하는지, 그 직관적인 구조를 해부해 보겠습니다.

## 2. 해결책 제시: 세계관을 렌더링하는 3단계 연극 무대

Protégé의 화면 상단에 있는 수많은 탭 중에서, 인문학 아키텍트가 세계관을 설계할 때 오가는 공간은 크게 3가지입니다. 이 탭들의 역할을 거대한 역사 연극을 무대에 올리는 과정에 비유해 보겠습니다.

| Protégé 핵심 탭 | 인문학적 연극 무대 비유 | 디지털 인문학 아키텍처 역할 |
| :--- | :--- | :--- |
| **"Active Ontology"** | **[기획]** 극장의 이름과 규칙을 정하는 무대 기획실 | 온톨로지의 절대 주소(**"IRI"**)와 접두사(**"Prefix"**)를 선언하는 환경 설정 공간 |
| **"Entities"** | **[대본]** 배역(왕, 신하)과 그들의 관계(충성하다)를 짜는 대본 집필실 | 우주의 뼈대인 클래스(**"Classes"**)와 속성(**"Properties"**)을 트리 구조로 설계하는 공간 |
| **"Individuals by class"** | **[공연]** 실제 배우들이 의상을 입고 무대 위로 등판하는 공연장 | 뼈대 안에 구체적인 역사적 인물과 사물(**"Instances"**)을 생성하고 데이터를 입력하는 공간 |

엑셀은 대본과 배우가 하나의 표 안에 뒤엉켜 있는 난장판이었습니다. 하지만 Protégé는 추상적인 뼈대(**"Entities"**)와 구체적인 데이터(**"Individuals"**)를 공간적으로 완벽하게 분리합니다. 대본이 명확하게 짜여 있어야만, 그 규칙에 따라 배우들이 무대 위에서 오류 없이 연기할 수 있기 때문입니다.

## 3. 실전 적용: 3대 캔버스를 오가며 이순신 등판시키기

앞선 장에서 선언한 우리의 공식 주소 `http://aks.ac.kr/ontologies/joseon/`을 바탕으로, 이 3개의 탭을 순서대로 오가며 이순신이라는 인물에게 관직을 부여하는 시각적 맵핑 과정을 살펴보겠습니다.

1. **"Active Ontology"** 탭의 작업:
   * 온톨로지 IRI 칸에 `http://aks.ac.kr/ontologies/joseon/`을 입력하여 우주의 중심을 세웁니다.
   * **"Prefixes"** 메뉴에서 **"joseon"**이라는 접두사를 등록합니다.

2. **"Entities"** 탭의 작업 (뼈대와 관계 만들기):
   * **"Classes"** 탭을 열고, 최상위 개념 아래에 **"무반(Military_Official)"**이라는 배역을 만듭니다.
   * **"Object Properties"** 탭을 열고, 인물과 관직을 잇는 **"관직을_역임하다(hasOffice)"**라는 관계의 규칙(동사)을 생성합니다.

3. **"Individuals by class"** 탭의 작업 (배우 등판시키기):
   * 방금 만든 **"무반"** 클래스를 선택하고, 우측 하단의 플러스 버튼을 눌러 **"이순신(Yi_Sun_sin)"**이라는 실제 개체를 생성합니다.
   * 이순신의 속성 입력창(Property Assertions)을 열고, **"관직을_역임하다"**라는 동사를 선택한 뒤 **"전라좌수사"**를 연결합니다.

우리가 마우스로 클릭하고 이동한 이 모든 행위는, 백그라운드에서 기계가 이해할 수 있는 완벽한 코드로 동기화됩니다.

```turtle
# 우리가 3개의 탭을 오가며 마우스로 클릭한 결과는 
# 아래와 같은 완벽한 지식 그래프 논리 구조로 자동 번역됩니다.

@prefix joseon: [http://aks.ac.kr/ontologies/joseon/](http://aks.ac.kr/ontologies/joseon/) .

# Entities 탭에서 설계한 뼈대 (배역과 대본)
joseon:Military_Official a owl:Class .
joseon:hasOffice a owl:ObjectProperty .

# Individuals 탭에서 생성한 실제 데이터 (무대 위 배우)
joseon:Yi_Sun_sin a joseon:Military_Official ;
    joseon:hasOffice joseon:Jeolla_Left_Navy_Commander .
```

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 미아 사태: "Individuals 탭이 감쪽같이 사라졌습니다!"**

Protégé 실습 첫날, 연구실에서 가장 많이 터져 나오는 비명은 바로 탭의 실종 사건입니다.

**"교수님! 대본(Entities)까지는 잘 짰는데, 실제 데이터를 입력하려니 상단 메뉴에 Individuals 탭이 아무리 찾아도 없습니다. 프로그램이 고장 난 것 같습니다!"**

Protégé의 특정 버전이나 운영체제 환경에서는 초보자의 화면 복잡도를 줄이기 위해 **"Individuals by class"** 탭을 기본적으로 숨겨놓는 만행을 저지릅니다. 혹은 연구원이 실수로 탭의 **"X"** 버튼을 눌러 창을 날려버리는 경우도 허다합니다.

당황하여 프로그램을 지우고 다시 깔지 마십시오. Protégé는 자유롭게 창을 조립할 수 있는 모듈형 UI를 채택하고 있습니다. 사라진 무대를 되찾는 방법은 다음과 같습니다.

1. 프로그램 최상단의 글로벌 메뉴 바에서 **"Window"**를 클릭합니다.
2. **"Tabs"** 항목에 마우스를 올립니다.
3. 나타나는 목록 중에서 **"Individuals by class"**를 찾아 체크(Click)합니다.

이 간단한 조작만으로 사라졌던 데이터 입력 캔버스가 상단 탭에 화려하게 부활합니다. Protégé의 모든 UI 창(Views)과 탭(Tabs)은 **"Window"** 메뉴 안에 고스란히 보관되어 있으니, 창이 꼬이거나 닫혔을 때는 언제나 이 메뉴로 달려가 복구해야 함을 명심하십시오.

사실 Protégé는 설계툴입니다. 새로운 사실인가요? 설계툴이에서 개별적인 Individuals은 테스트일 뿐입니다. 

## 5. 요약 및 다음 단계

* 복잡해 보이는 Protégé의 화면은 기획(**"Active Ontology"**), 뼈대 설계(**"Entities"**), 데이터 입력(**"Individuals by class"**)이라는 3단계의 직관적인 연극 무대 구조로 이해할 수 있습니다.
* 데이터베이스의 구조(Class)와 실제 데이터(Instance)를 물리적인 탭으로 완벽하게 분리하여 작업함으로써, 우리는 하향식 설계의 무결성을 지킬 수 있습니다.
* 작업 중 탭이나 창이 사라졌을 때는 당황하지 않고 상단의 **"Window"** 메뉴를 통해 언제든 UI를 복구하고 재조립할 수 있어야 합니다.

이제 우리는 Protégé라는 훌륭한 목공소의 모든 장비 사용법과 동선을 익혔습니다.
