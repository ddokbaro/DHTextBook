# 12.2. 한자/한글 표기 변이의 통제: prefLabel, altLabel의 다국어 라벨링

## 1. 도입: "이황을 검색했는데 퇴계가 안 나옵니다!"

디지털 인문학 연구소의 랩 미팅에서 가장 빈번하게, 그리고 가장 짜증스럽게 터져 나오는 불만이 있습니다. 

"교수님, 우리 데이터베이스 검색 엔진이 고장 난 것 같습니다. 분명히 '이황' 문집 데이터를 수만 건이나 구축했는데, 사용자가 검색창에 '퇴계'라고 치거나 한자로 '李滉'이라고 치면 결과가 '0건'으로 나옵니다!"

고문헌을 다루는 한국학 아키텍트에게 이는 결코 검색 엔진 소프트웨어의 잘못이 아닙니다. **데이터 모델링의 실패**입니다. 역사적 인물이나 사건은 시대와 맥락에 따라 무수히 많은 이름(이명, 자, 호, 시호)으로 불리며, 한글, 번체 한자, 간체 한자, 로마자 등 표기법의 변이가 극심합니다. 

단순한 관계형 데이터베이스(RDB)나 엑셀에서는 이 모든 경우의 수를 처리하기 위해 지저분한 `LIKE` 검색이나 수십 개의 동의어 열(Column)을 만들어야 하는 극도의 비효율을 강요받습니다. 효율성에 미쳐있는 시맨틱 아키텍트라면, 이 지저분한 텍스트의 혼돈을 기계가 단 한 번의 연산으로 우아하게 처리하도록 만들어야 합니다. 

그 완벽한 해답이 바로 12.1장에서 만든 `skos:Concept` 뼈대 위에 입히는 `"**SKOS 어휘 라벨(Lexical Labels)**"`입니다.

## 2. 해결책 제시: 기계 가독형 사전의 3대 라벨링 무기

SKOS는 인간의 복잡한 언어 습관을 기계에게 가르치기 위해, 라벨(이름표)을 철저하게 세 가지 등급으로 나누어 관리합니다.

### 1) `skos:prefLabel` (우선 라벨: Preferred Label)
* **의미:** 이 개념을 대표하는 **'공식적이고 가장 권위 있는 단 하나의 명칭'**입니다. 박물관 전시 캡션이나 웹사이트 UI의 굵은 제목으로 표시될 때 쓰이는 이름입니다.
* **절대 규칙:** 하나의 개념은 **특정 언어당 오직 하나의 `prefLabel`**만 가질 수 있습니다. (한국어 1개, 한문 1개, 영어 1개 등)

### 2) `skos:altLabel` (대체 라벨: Alternative Label)
* **의미:** 대표 명칭은 아니지만, 이 개념을 지칭하는 **모든 동의어, 유의어, 약어, 별명(자, 호, 시호)**입니다. 
* **규칙:** 개수 제한이 없습니다. 무한대로 달아두면 검색 엔진이 사용자의 다양한 검색어(Query)를 모조리 낚아채는(Catch) 강력한 그물이 됩니다.

### 3) `skos:hiddenLabel` (숨김 라벨: Hidden Label)
* **의미:** 웹사이트 화면(UI)에는 절대 노출되면 안 되지만, **검색 매칭을 위해서만 몰래 숨겨둔 텍스트**입니다.
* **용도:** 대중들이 자주 틀리는 '오타(Typo)', 혹은 지금은 폐기된 '구형 로마자 표기법'을 처리할 때 사용하는 정보학의 숨은 비기입니다.

## 3. 실전 적용: 표기 변이의 늪, '퇴계 이황' 모델링 (Turtle)

앞서 배운 3대 라벨과 **언어 태그(Language Tag, `@`)**를 결합하여, 역사 인물 '퇴계 이황'을 완벽한 글로벌 시소러스 데이터로 변환해 보겠습니다.

고문헌을 다룰 때, 한글(`@ko`)과 한문(`@lzh`, Literary Chinese)을 기계적 수준에서 분리하여 태깅하는 것은 선택이 아니라 필수입니다. 영어(`@en`)는 썩 내키지 않더라도 글로벌 상호운용성을 위해 구글이 긁어갈 수 있도록 하나쯤 달아두는 것이 효율적입니다.

```turtle
@prefix skos: [http://www.w3.org/2004/02/skos/core#](http://www.w3.org/2004/02/skos/core#) .
@prefix 국학: [http://aks.ac.kr/vocabulary/](http://aks.ac.kr/vocabulary/) .

# 12.1장에서 만든 인물 개념(URI) 뼈대 위에 다국어 라벨을 입힙니다.
국학:concept/person_yi_hwang a skos:Concept ;
    skos:inScheme 국학:scheme/조선_인물 ;
    
    # [1. 우선 라벨 (prefLabel)] - 언어별로 화면에 보여줄 공식 대표 이름 (딱 1개씩만!)
    skos:prefLabel "이황"@ko ;
    skos:prefLabel "李滉"@lzh ;
    skos:prefLabel "Yi Hwang"@en ; 
    
    # [2. 대체 라벨 (altLabel)] - 호, 자, 이명 등 (무한대 허용)
    skos:altLabel "퇴계"@ko ;
    skos:altLabel "退溪"@lzh ;
    skos:altLabel "경호"@ko ;     # 자(字)
    skos:altLabel "景浩"@lzh ;
    skos:altLabel "Toegye"@en ;
    
    # [3. 숨김 라벨 (hiddenLabel)] - 잦은 오타 및 구형 표기 (UI 노출 금지)
    skos:hiddenLabel "이항"@ko ;      # 사용자들이 '이황'을 칠 때 자주 내는 오타
    skos:hiddenLabel "Yi Hwng"@en .   # 로마자 오타
```

이 코드가 서버에 적재되면, 지식 그래프는 마법처럼 작동합니다.
사용자가 검색창에 "경호", "退溪", 심지어 오타인 "이항"을 치더라도, 시스템 백엔드는 이 모든 텍스트 라벨들이 결국 `국학:concept/person_yi_hwang`이라는 단 하나의 URI 노드에 묶여있음을 즉각 추론합니다. 그리고 사용자 화면(UI)에는 가장 권위 있는 대표 이름인 **"이황(李滉)"**을 우아하게 띄워줍니다. 이것이 시맨틱 웹이 자랑하는 100% 검색 재현율(Recall)의 정체입니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 무관용 원칙: "언어당 prefLabel은 절대 1개다"**

데이터 구축 현장에서 가장 빈번하게 발생하는 SHACL 검증(Validation) 에러가 바로 이 `prefLabel` 규칙 위반입니다. 연구원들은 종종 선의로 다음과 같은 참사를 빚어냅니다.

```turtle
# [치명적인 에러 코드]
국학:concept/person_yi_hwang a skos:Concept ;
    skos:prefLabel "이황"@ko ;
    skos:prefLabel "퇴계"@ko . # 치명적 에러 발생!
```

"교수님, 이황도 공식 이름이고 퇴계도 너무 유명한 공식 호(號)라서 둘 다 대표 이름으로 대우해주고 싶었습니다."

인문학적인 존경심은 이해하지만, 기계에게 이런 모호함은 독약입니다. 웹사이트가 이 데이터를 읽어들여 제목을 출력하려고 할 때, 기계는 둘 중 어떤 것을 제목으로 써야 할지 결정하지 못하고 패닉에 빠져 렌더링을 멈춰버립니다. 

`skos:prefLabel`은 학문적 위상을 평가하는 자리가 아니라, **"시스템이 UI에 출력할 단 하나의 텍스트 변수(Variable)"**를 엄격하게 지정하는 시스템 설정값임을 연구원들에게 각인시켜야 합니다. 나머지는 모두 얄짤없이 `altLabel`로 강등시켜야 시스템이 평화를 유지합니다.

## 5. 요약 및 다음 단계

* 텍스트의 표기 변이와 다국어 문제를 해결하기 위해 SKOS는 인간의 언어를 **우선 라벨(`prefLabel`)**, **대체 라벨(`altLabel`)**, **숨김 라벨(`hiddenLabel`)** 3단계로 정밀하게 제어합니다.
* 특정 개념(`skos:Concept`)은 각 언어(예: `@ko`, `@lzh`)당 오직 하나의 `prefLabel`만 가져야 하며, 이 규칙을 어기면 UI 렌더링 시스템이 붕괴합니다.
* 이 3대 라벨링 무기를 잘 활용하면, 수십 개의 이명과 동의어, 심지어 오타까지 단 하나의 URI로 응집시켜 검색의 누락(Missing)을 완벽하게 근절할 수 있습니다.

이제 우리는 기계 가독형 시소러스의 '단어장'을 완벽하게 만들었습니다. 
하지만 진짜 지능(Intelligence)은 단어의 나열이 아니라, 단어와 단어 사이의 **'관계(Relation)'**에서 나옵니다. "동인(東人)은 사림(士林)의 하위 개념이다", "이황의 학문은 영남학파와 관련이 있다"라는 입체적인 지식망을 기계에게 어떻게 가르칠 수 있을까요?

다음 장인 **[12.3. SKOS 의미계통도: 계층적 관계(broader/narrower)와 연관 관계(related)]**에서, 평면적인 단어장들을 거대한 트리(Tree) 구조의 십진분류표와 지식망으로 엮어내는 시맨틱 릴레이션의 핵심 기술을 해부해 보겠습니다.
