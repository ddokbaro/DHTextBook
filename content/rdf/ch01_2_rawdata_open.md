# 1.2. 1차 가공물(기계가독형 원시 데이터 RAWDATA) 전면 개방의 당위성

## 1. 도입: “검색”의 환상과 복사-붙여넣기의 늪

국사편찬위원회나 한국학중앙연구원의 통합 검색 포털에 접속해 본 적이 있으실 겁니다. 검색창에 `"**류성룡**"`을 입력하면 수백 건의 관련 사료가 깔끔한 표와 예쁜 폰트로 화면에 나타납니다. 우리는 이 훌륭한 시스템을 보며 "와, 조선시대 데이터가 완벽하게 개방되었구나!"라며 감탄합니다.

하지만 여러분의 연구 주제가 단순히 류성룡 한 사람의 전기를 쓰는 것이 아니라, `"**임진왜란 시기 전라좌수영과 경상우수영 소속 무관 500명의 승진 패턴과 혈연 네트워크 분석**"`이라고 상상해 보십시오.

여러분의 비극은 이때부터 시작됩니다. 500명의 이름을 일일이 검색창에 치고, 마우스로 드래그하여 복사한 뒤, 엑셀 시트에 붙여넣는 작업을 수만 번 반복해야 합니다. 손목은 시큰거리고 눈은 침침해집니다. 분명 디지털 시대인데, 우리의 연구 방식은 종이 책을 베껴 쓰던 조선시대의 `"**필사(筆寫)**"`와 전혀 다를 바가 없습니다. 

왜 이런 고통스러운 노동을 해야 할까요? 그것은 우리가 마주한 화려한 웹페이지가 진정한 데이터 개방이 아니라, 단지 눈으로 읽기 좋게 포장된 `"**2차 가공물(Secondary Product)**"`이라는 거대한 감옥이기 때문입니다.

## 2. 해결책 제시: 식당의 메뉴판(Web UI)과 식재료 창고(RAWDATA)

이 고통을 컴퓨터 공학적 개념으로 해결하려면, 데이터의 형태를 인간의 눈(Human-eye)을 위한 것과 기계(Computer)를 위한 것으로 엄격하게 분리하여 인식해야 합니다.

우리가 웹 브라우저에서 보는 화면은 식당의 `"**메뉴판**"` 혹은 `"**조리된 요리**"`와 같습니다. 식당 주인(데이터 제공 기관)이 정해준 레시피(검색 조건)대로만 요리를 맛볼 수 있습니다. "류성룡이 임진왜란 때 쓴 글만 보여줘"라는 메뉴는 주문할 수 있지만, "16세기 후반 안동 지역 출신이면서 이황의 문인인 사람들의 관직 이동 경로를 전부 다 보여줘"라는 복잡한 맞춤형 요리는 주문할 수 없습니다. 메뉴판에 없기 때문입니다.

진정한 디지털 인문학 연구를 수행하려면, 다 만들어진 요리가 아니라 날것의 식재료가 가득한 창고의 열쇠를 요구해야 합니다. 이것이 바로 `"**1차 가공물**"`, 즉 파이썬(Python)이나 R, SQL과 같은 프로그래밍 언어가 직접 읽고 연산할 수 있는 `"**기계가독형 원시 데이터(Machine-Readable RAWDATA)**"`입니다.

기계가독형 데이터는 특정한 소프트웨어나 웹사이트 화면에 종속되지 않은 순수한 텍스트 형태의 데이터 덩어리입니다. 대표적으로 `"**CSV**"`, `"**XML**"`, `"**JSON**"`, 그리고 우리가 곧 배우게 될 `"**RDF**"` 포맷이 있습니다. 원시 데이터를 통째로 내려받을 수 있다면, 우리는 수만 건의 엑셀 복사-붙여넣기 노동에서 해방되어, 파이썬 코드 단 몇 줄만으로 500명의 무관 네트워크를 단 1초 만에 분석해 낼 수 있습니다.

## 3. 실전 적용: 데이터 주권(Data Sovereignty)의 회복

실제 조선시대 관직 데이터를 예로 들어, 웹 서비스(2차 가공물)와 기계가독형 원시 데이터(1차 가공물)의 차이를 시각적으로 비교해 보겠습니다.

| 비교 항목 | 2차 가공물 (웹 서비스 UI) | 1차 가공물 (기계가독형 RAWDATA) |
| :--- | :--- | :--- |
| **제공 형태** | HTML 웹페이지, 깔끔한 게시판 | CSV, JSON, XML, RDF 형식의 파일 |
| **분석 주체** | 인간의 눈과 마우스 | 파이썬, R, SQL 등 컴퓨터 알고리즘 |
| **데이터 접근** | 한 번에 한 페이지씩(10~20건) 열람 가능 | 수백만 건의 전체 데이터를 한 번에 다운로드 |
| **연구의 자유도** | 기관이 만들어둔 검색창의 옵션에 종속됨 | 연구자가 스스로 알고리즘을 짜서 무한대로 조작 가능 |

이러한 기계가독형 데이터의 전면 개방은 대한민국 `"**공공데이터법**"`에도 명시된 국민의 권리입니다. 하지만 현실의 많은 인문학 기관들은 저작권 보호, 데이터 오용 방지, 서버 부하 등의 핑계를 대며 원시 데이터를 내어주기를 꺼립니다. 정제되지 않은 날것의 데이터가 외부로 나갔을 때 자신들의 학문적 권위가 흔들릴 것을 염려하는 `"**문헌 권력**"`의 방어 기제입니다.

우리가 `"**RAWDATA**"`를 요구하는 행위는 단순한 편의성을 넘어서는 철학적 의미를 지닙니다. 그것은 기관의 검색창에 갇혀 있던 인문학적 상상력을 해방시키고, 데이터를 내 마음대로 쪼개고 결합할 수 있는 `"**데이터 주권(Data Sovereignty)**"`을 연구자들의 손으로 되찾아오는 가장 강력한 실천입니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

기관에 공문을 보내거나 공공데이터포털을 뒤져서 마침내 꿈에 그리던 조선시대 방목(과거 급제자 명부) `"**CSV**"` 원시 데이터를 다운로드 받았다고 해보겠습니다. 기쁜 마음에 엑셀로 파일을 여는 순간, 글자가 "웱뛟궯"처럼 외계어로 깨져 나오는 공포를 100% 마주하게 될 것입니다.

이것은 윈도우(Windows) 운영체제와 공공기관 데이터베이스 간의 `"**인코딩(Encoding)**"` 충돌 때문입니다. 기관의 데이터는 전 세계 표준인 `"**UTF-8**"`로 작성되었는데, 여러분의 오래된 엑셀은 한국어 전용인 `"**EUC-KR(CP949)**"`로 억지로 읽으려다 발생한 참사입니다. 

절대 당황하여 데이터를 지우지 마십시오. 메모장으로 해당 CSV 파일을 연 다음, `"**다른 이름으로 저장**"`을 누르고 인코딩 옵션에서 `"**UTF-8 (BOM 포함)**"`을 선택하여 덮어쓰기만 하면 엑셀에서 조선시대 선비들의 이름이 마법처럼 온전하게 나타납니다. 원시 데이터를 다루는 연구자는 이처럼 시스템의 언어(인코딩)를 맞추는 기초적인 엔지니어링 소양을 반드시 갖추어야 합니다.

## 5. 요약 및 다음 단계

* 화면에 보이는 웹페이지는 인간을 위한 요리(2차 가공물)일 뿐, 대규모 분석을 위해서는 컴퓨터가 읽을 수 있는 날것의 식재료인 `"**기계가독형 원시 데이터(RAWDATA)**"`가 필수적입니다.
* 데이터를 파일 형태로 다운로드 받아 내가 직접 알고리즘으로 분석하는 것은, 기관의 통제에서 벗어나 `"**데이터 주권**"`을 회복하는 지적 쾌감의 시작입니다.
* 기계가독형 데이터를 다룰 때는 글자가 깨지는 `"**인코딩(Encoding)**"` 문제에 항상 대비해야 합니다.

자, 이제 우리는 싸워서 얻어낸 수십만 건의 기계가독형 원시 데이터를 손에 쥐었습니다. 이 데이터를 깔끔하게 정리하기 위해 전통적인 표(Table) 형태의 데이터베이스에 밀어 넣으려 합니다. 그런데, 과연 이 전통적인 엑셀과 표의 구조가 조선시대의 그 복잡다단한 인간관계를 온전히 담아낼 수 있을까요?
