# 7.2. 고급 데이터 제어: UNION 병합, CONCAT 문자열 조립, 집계 함수 적용

## 1. 도입: 인물 검색을 넘어 거시적 역사 통계로

이전 장까지 우리는 `SELECT`, `WHERE`, `OPTIONAL` 등을 활용하여 거대한 지식 그래프에서 특정 인물의 이름과 출생 연도를 매우 정교하게 낚아채는 법을 배웠습니다. 이것만으로도 엑셀을 뒤지는 것보다는 훨씬 강력합니다.

하지만 디지털 인문학의 진정한 목적은 개별 인물의 프로필을 검색하는 데 그치지 않습니다. 역사학자들은 파편화된 사료를 모아 **"거시적인 통계와 패턴"**을 읽어내기를 원합니다. 

여러분이 조선시대 당쟁을 연구하며 컴퓨터에게 다음과 같이 복잡한 주문을 던졌다고 상상해 보십시오.
**"기호학파이거나 영남학파인 사람들을 모두 찾아서, 그들의 '이름'과 '호'를 괄호로 묶어 보기 좋게 출력하고, 각 학파별로 총 몇 명의 인물이 속해 있는지 인원수 통계를 내림차순으로 정렬해 다오!"**

이 질문에는 논리적 합집합(OR), 문자열 가공, 그리고 수학적 통계 연산이 모두 섞여 있습니다. 이 복잡한 인문학적 요구사항을 단 한 번의 쿼리로 우아하게 처리해 내는 것이 바로 SPARQL의 고급 데이터 제어 문법입니다.

## 2. 해결책 제시: 지식을 주무르는 3대 고급 문법

SPARQL은 데이터를 단순히 찾는 것을 넘어, 데이터를 묶고, 자르고, 계산하기 위해 강력한 함수들을 제공합니다.

1. **병합의 마법, UNION (논리적 OR):**
   기본적으로 `WHERE` 블록 안의 조건들은 모두 교집합(AND)으로 묶입니다. 하지만 "동인이거나(OR) 서인인 사람"을 찾고 싶을 때는 두 개의 서로 다른 도면(패턴)을 그려서 결합해야 합니다. 이때 사용하는 것이 `"**UNION**"`입니다. 완전히 다른 두 개의 검색 결과를 하나의 표로 매끄럽게 합쳐줍니다.

2. **문자열 조립, CONCAT:**
   데이터베이스에는 `이름: "이이"`, `호: "율곡"`처럼 데이터가 쪼개져 저장되어 있습니다. 이를 모니터 화면에 출력할 때 엑셀처럼 텍스트를 이어 붙여 `"**이이 (율곡)**"`이라는 예쁜 하나의 문자열로 가공하고 싶을 때 사용하는 함수입니다. 앞서 배운 `BIND`와 완벽한 짝을 이룹니다.

3. **거시적 통계, 집계 함수 (GROUP BY, COUNT, SUM):**
   가장 중요한 통계 기능입니다. 수만 명의 인물 데이터를 특정 기준(예: 당파, 가문, 합격 연도)으로 묶어주는 `"**GROUP BY**"`와, 그 묶인 그룹 안에 몇 명이 있는지 세어주는 `"**COUNT**"`, 값을 더해주는 `"**SUM**"`, 그리고 결과를 보기 좋게 정렬하는 `"**ORDER BY**"`가 결합하여 강력한 빅데이터 분석을 수행합니다.

## 3. 실전 적용: 학파별 세력 통계와 명단 출력기 만들기

위에서 배운 3가지 고급 문법을 하나로 결합하여, 조선시대 학파의 세력을 분석하는 완벽하고 아름다운 SPARQL 쿼리를 작성해 보겠습니다. 

```sparql
PREFIX 조선: [http://조선.kr/ontology/](http://조선.kr/ontology/)
PREFIX 속성: [http://조선.kr/prop/](http://조선.kr/prop/)

# 3. SELECT & 집계: 학파 이름과, 계산된 통계값(인원수)을 출력합니다.
# 인원수를 셀 때는 반드시 COUNT 함수를 쓰고, 새로운 변수명(?인원수)을 지정해야 합니다.
SELECT ?학파 (COUNT(?인물) AS ?인원수)
WHERE {
  # 1. UNION: 기호학파이거나 영남학파인 사람을 모두 가져옵니다.
  # 중괄호 { }로 각 패턴을 묶고 그 사이에 UNION을 선언합니다.
  { ?인물 속성:소속학파 "기호학파" . }
  UNION
  { ?인물 속성:소속학파 "영남학파" . }

  # 공통 패턴: 찾아낸 ?인물의 학파 이름을 ?학파 변수에 담고, 이름과 호를 찾습니다.
  ?인물 속성:소속학파 ?학파 .
  ?인물 속성:이름 ?이름 .
  OPTIONAL { ?인물 속성:호 ?호 . }

  # 2. CONCAT: 이름과 호를 예쁘게 합쳐서 ?출력용이름 이라는 새 변수를 만듭니다.
  # COALESCE는 호가 없는 사람을 위해 빈칸 처리를 방지하는 고급 안전장치입니다.
  BIND (CONCAT(?이름, " (", COALESCE(?호, "호 없음"), ")") AS ?출력용이름)
}
# 4. GROUP BY: 데이터를 ?학파 기준으로 묶어줍니다. (이것이 없으면 COUNT가 작동하지 않습니다)
GROUP BY ?학파
# 5. ORDER BY: 인원수가 많은 학파부터 내림차순(DESC)으로 정렬하여 출력합니다.
ORDER BY DESC(?인원수)
```

**[기계가 출력한 결과 화면]**

| 학파 | 인원수 |
| :--- | :--- |
| 영남학파 | 1,245 |
| 기호학파 | 980 |

수십만 건의 트리플 데이터를 훑어서 학파별 세력 분포를 단 0.1초 만에 완벽한 통계표로 뽑아냈습니다. 인문학자가 코딩을 배워야 하는 이유가 바로 이 한 줄의 쿼리에 담겨 있습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

집계 함수(`COUNT`, `SUM` 등)를 처음 사용하는 연구원들이 100% 확률로 직면하게 되는 가장 악명 높은 에러가 있습니다. 코드를 실행하자마자 화면이 새빨개지며 `"**Non-group key variable in SELECT**"` (SELECT 절에 그룹 키가 아닌 변수가 있습니다)라는 끔찍한 에러가 뜨는 현상입니다.

* **초보자의 치명적인 실수 예시:**
    ```sparql
    # 에러 발생! ?이름 변수는 GROUP BY 기준도 아니고, 통계 함수로 묶이지도 않았습니다.
    SELECT ?학파 ?이름 (COUNT(?인물) AS ?인원수) 
    WHERE { ... }
    GROUP BY ?학파
    ```

**오류의 원인:**
컴퓨터의 입장이 되어 보십시오. 여러분이 `GROUP BY ?학파`를 명령했기 때문에, 컴퓨터는 기호학파 980명을 단 하나의 줄(Row)로 압축해 버렸습니다. 
그런데 `SELECT` 절에서 갑자기 압축된 980명의 `"**?이름**"`을 함께 보여달라고 떼를 씁니다. 컴퓨터는 "980명의 이름 중 도대체 누구의 이름을 이 한 칸에 적어달라는 말인가?!"라며 논리적 패닉에 빠져 에러를 뱉어내는 것입니다.

**시맨틱 아키텍트의 해결책 (황금률):**
`GROUP BY`를 사용할 때, `SELECT` 절에 적을 수 있는 변수는 딱 두 종류뿐입니다.
1. `GROUP BY`의 기준이 된 변수 (예: `?학파`)
2. `COUNT`, `SUM`, `AVG`, `GROUP_CONCAT` 등의 집계 함수로 묶어낸 변수

만약 학파별 인원수 통계와 함께, 그 학파에 속한 980명의 이름 명단도 한 칸에 쉼표(,)로 이어서 다 보고 싶다면 어떻게 해야 할까요? 이때는 단순한 `?이름` 대신, 여러 문자열을 하나로 뭉쳐주는 집계 함수인 `"**GROUP_CONCAT**"`을 사용해야 완벽하게 작동합니다.

```sparql
# 완벽한 해결책: 이름을 쉼표로 뭉쳐서(GROUP_CONCAT) 하나의 거대한 텍스트 덩어리로 만듭니다.
SELECT ?학파 (COUNT(?인물) AS ?인원수) (GROUP_CONCAT(?출력용이름; SEPARATOR=", ") AS ?명단)
```

## 5. 요약 및 다음 단계

* 서로 다른 조건의 검색 결과를 하나로 합치고 싶을 때는 논리적 OR 연산인 `"**UNION**"`을 사용합니다.
* 텍스트 데이터를 시각적으로 예쁘게 가공하거나 이어 붙일 때는 `"**CONCAT**"`과 `"**BIND**"`를 결합하여 사용합니다.
* 데이터를 특정 기준(가문, 학파, 연도)으로 묶어 거시적인 통계(인원수, 합계)를 낼 때는 `"**GROUP BY**"`와 `"**COUNT**"` 집계 함수를 반드시 세트로 사용해야 합니다.

자, 여기까지 오셨다면 여러분은 우리 연구실 서버(Local DB) 안에 갇혀 있는 데이터를 검색하고 분석하는 데 있어서 이미 상위 1%의 전문가가 되었습니다.

그런데 시맨틱 웹과 링크드 오픈 데이터(LOD)의 진정한 묘미는 "내 서버"를 벗어나는 데 있습니다. 만약 내가 가진 조선시대 인물 데이터와, 저 멀리 미국에 있는 위키데이터(Wikidata) 서버의 인물 데이터를 SPARQL 하나로 실시간으로 엮어서(JOIN) 검색할 수 있다면 어떨까요?
