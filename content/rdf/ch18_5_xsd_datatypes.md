# 18.5. 데이터 타입의 해부학: XSD 표준과 인문학적 시간/공간의 정밀 제어

## 1. 도입: 종묘배향공신의 순국일은 텍스트인가, 숫자인가?

"고문헌자료정보화연구"나 "시맨틱웹과한국학자료" 수업에서 대학원생들이 지식 그래프를 구축할 때 가장 빈번하게 무너지는 지점이 바로 **"시간(Time)"**과 **"공간(Space)"**의 처리입니다.

최근 디지털인문학연구소에서 진행 중인 **"한국근대인물LOD - 종묘배향공신을 대상으로 -"** 프로젝트를 떠올려 보십시오. 고종과 순종 대의 종묘배향공신인 민영환(閔泳煥)이나 조병세(趙秉世)의 데이터를 구축할 때, 우리는 수많은 형태의 데이터와 마주합니다.
민영환이 을사늑약에 항거하여 자결한 **"1905년 11월 30일"**이라는 구체적인 날짜, 대은(大隱)이라는 **"호(號)"**, 그리고 이 인물의 기록이 담긴 국사편찬위원회 한국사데이터베이스의 **"웹 주소(URI)"**까지.

엑셀은 이 모든 것을 그저 '텍스트'라는 하나의 통에 쓸어 담았습니다. 하지만 시맨틱 웹에서는 **"1905년 11월 30일에 순국한 인물과 1907년 헤이그 특사 파견 시점 사이의 기간(Days)을 계산하라"**는 질의가 가능해야 합니다. 이를 위해 우리는 엑셀의 게으름을 버리고, 기계가 데이터의 재질을 정확히 인식하여 수학적/논리적 연산을 수행할 수 있도록 **"XSD(XML Schema Definition)"**라는 위대한 표준 사전을 도입해야 합니다.

## 2. 해결책 제시: W3C가 제정한 데이터 분리수거의 마스터키, XSD

Protégé의 **"Data Properties"** 탭에서 목적어의 자격(**Ranges**)을 설정할 때, 우리가 사용할 수 있는 XSD 타입은 수십 가지가 넘습니다. 그중 디지털 인문학 아키텍트가 한국학 데이터를 다룰 때 밥 먹듯이 사용하는 **"핵심 6대 XSD 타입"**을 직관적으로 해부해 보겠습니다.

| XSD 데이터 타입 | 인문학적 용도 및 비유 | 근대인물 LOD (종묘배향공신) 입력 예시 | 기계의 연산 능력 |
| :--- | :--- | :--- | :--- |
| **"xsd:string"** | 이름, 호, 본관 등 서술형 텍스트 | **"민영환"**, **"여흥(驪興)"** | 단순 문자열 검색 및 필터링 |
| **"xsd:integer"** | 나이, 자녀 수 등 딱 떨어지는 정수 | **"44"** (순국 당시 나이) | 덧셈, 뺄셈, 대소 비교 정렬 |
| **"xsd:decimal"** | 생가나 묘소의 정밀한 GPS 좌표 | **"37.5796"** (위도) | 공간 지리(GIS) 연산 및 지도 맵핑 |
| **"xsd:boolean"** | 예/아니오로 판별되는 논리 스위치 | **"true"** (문과 급제 여부: 참) | 참과 거짓의 명제 필터링 |
| **"xsd:date"** | 연-월-일이 명확한 구체적 역사 날짜 | **"1905-11-30"** (ISO 8601 표준) | 두 날짜 사이의 **"기간(Days)"** 자동 계산 |
| **"xsd:anyURI"** | 한국사데이터베이스 등 외부 사료 링크 | **"http://db.history.go.kr/..."** | 클릭 시 외부 웹사이트로 연결되는 식별자 |

이 섬세한 XSD 사전을 활용하면, 기계는 1905가 단순한 사과 1,905개가 아니라 역사적인 **"시간의 단위"**임을 완벽하게 깨닫게 됩니다.

## 3. 실전 적용: 종묘배향공신 데이터의 다차원적 XSD 맵핑 (Turtle)

Protégé에서 민영환이라는 구체적 인물(Instance)이 가진 다양한 속성들을 각기 다른 XSD 타입으로 정밀하게 제어하여 코딩해 보겠습니다. 

```turtle
@prefix rdfs: [http://www.w3.org/2000/01/rdf-schema#](http://www.w3.org/2000/01/rdf-schema#) .
@prefix xsd: [http://www.w3.org/2001/XMLSchema#](http://www.w3.org/2001/XMLSchema#) .
@prefix joseon: [http://aks.ac.kr/ontologies/joseon/](http://aks.ac.kr/ontologies/joseon/) .

# 민영환이라는 실재하는 종묘배향공신(Instance)에 6가지 다른 재질의 포스트잇을 붙입니다.
joseon:Min_Yeong_hwan a joseon:Meritorious_Subject ;
    
    # 1. 본관은 단순한 텍스트(string)입니다.
    joseon:hasClanName "여흥(驪興)"^^xsd:string ;
    
    # 2. 순국 당시의 나이는 수학적 연산이 가능한 정수(integer)입니다.
    joseon:hasAgeAtDeath "44"^^xsd:integer ;
    
    # 3. 대과(문과)에 급제했는가? 기계가 판별할 수 있는 참(boolean) 스위치를 켭니다.
    joseon:passedCivilExam "true"^^xsd:boolean ;
    
    # 4. 순국한 구체적 날짜는 기간 계산이 가능한 날짜 포맷(date)입니다.
    joseon:dateOfDeath "1905-11-30"^^xsd:date ;
    
    # 5. 동상이나 묘소의 위도 위치는 소수점을 포함하는 십진수(decimal)입니다.
    joseon:hasLatitude "37.5759"^^xsd:decimal ;
    
    # 6. 고종실록 원문 데이터베이스로 연결되는 외부 식별자 주소(anyURI)입니다.
    joseon:linkToSillok "[http://sillok.history.go.kr/id/kza_14211017_001](http://sillok.history.go.kr/id/kza_14211017_001)"^^xsd:anyURI .
```

텍스트 뒤에 붙은 `^^` 기호는 기계에게 **"이 데이터의 재질은 이것이다"**라고 명시적으로 선언하는 시맨틱 웹의 약속입니다. 이렇게 정밀하게 제어된 데이터는 향후 **"문과에 급제한(true) 공신 중, 1900년(date) 이후에 순국한 사람을 나이순(integer)으로 정렬하라"**는 복잡한 다차원 SPARQL 질의어를 완벽하게 소화해 냅니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 고뇌: "음력(Lunar Calendar) 날짜는 어떻게 입력합니까?"**

한국학 데이터, 특히 고문헌자료정보화 실무를 진행하다 보면 XSD의 **"xsd:date"** 타입 앞에서 깊은 절망에 빠지게 됩니다. 

**"실록에 적힌 '고종 42년 11월 4일(음력)'을 그대로 `1905-11-04^^xsd:date`로 입력하면, 기계가 이를 서양의 양력 11월 4일로 인식하여 기간 계산이 완전히 엉켜버립니다. 영어권에서 만든 XSD 표준을 동양의 역사에 어떻게 끼워 맞춰야 합니까?"**

이것은 영미권 중심의 웹 표준이 가진 치명적인 한계이자, 동양 인문학 데이터를 다루는 아키텍트들이 반드시 돌파해야 할 벽입니다. 

**[승리하는 한국학 아키텍트의 이원화 전략]**
이 문제를 해결하는 가장 효율적이고 완벽한 실무 철칙은 **"기계의 연산용 시간과 인간의 열람용 시간을 분리하는 것"**입니다.

1. **기계의 연산용 (양력 변환 - xsd:date):** 시스템의 기간 계산과 순서 정렬을 담당하는 속성(예: `hasSolarDate`)에는 반드시 한국천문연구원의 데이터를 참고하여 양력으로 변환한 값을 넣습니다. (예: **"1905-11-30^^xsd:date"**)
2. **사료적 증거용 (음력 보존 - xsd:string):** 서지학적 원문의 가치를 훼손해서는 안 됩니다. 별도의 속성(예: `hasLunarDateString`)을 만들어, 사료에 적힌 그대로 **"고종 42년 을사 11월 4일^^xsd:string"**이라고 문자열로 보존하십시오.

수학적 연산은 양력(`xsd:date`)에 맡겨 기계의 지능을 100% 활용하고, 사료적 증거는 음력 텍스트(`xsd:string`)로 병기하는 이 이원화 전략이야말로, 기술의 한계를 인문학적 지혜로 극복하는 최고의 데이터 모델링입니다.

## 5. 요약 및 다음 단계

* 인문학 지식 그래프의 수학적, 논리적 연산을 극대화하기 위해서는 엑셀처럼 문자와 숫자를 섞어 쓰지 말고 **"XSD 표준 데이터 타입"**을 목적에 맞게 세분화하여 적용해야 합니다.
* 참과 거짓은 **"xsd:boolean"**, 연산이 필요한 날짜는 **"xsd:date"**, 공간 좌표는 **"xsd:decimal"**, 외부 사료 링크는 **"xsd:anyURI"**로 엄격하게 분리수거해야 합니다.
* 동양의 음력 날짜를 다룰 때는, 기계의 연산을 위해 양력으로 변환한 **"xsd:date"** 값과 사료 원문 보존을 위한 음력 **"xsd:string"** 값을 이원화하여 관리해야 학문적 무결성을 지킬 수 있습니다.

이로써 텅 빈 무대(클래스)를 짓고, 배역(관계)을 설정하며, 세밀한 데이터 포스트잇 규칙(XSD 타입)까지 제정하는 하향식(Top-down) 뼈대 설계의 거대한 챕터가 완전히 막을 내렸습니다.

이제 설계도는 완벽합니다. 다음 장인 **"19장. 개체 할당과 심화 논리 제약 (Individuals & Restrictions)"**으로 진입하여, 우리가 만든 무결점의 뼈대 안에 실제 역사적 개체(Instance)들을 대량으로 생성하고, 동명이인을 기계적으로 식별해 내는 짜릿한 데이터 입력의 세계로 도약해 보겠습니다!
