# 25.3. LLM 프롬프팅 최적화: 온톨로지 하위 집합 주입 기법

## 1. 도입: 기계 학습의 지옥과 천재적이지만 통제 불능인 조수

우리는 앞선 장들에서 고문헌에서 지식을 추출하기 위해 딥러닝 모델(NER, RE)을 설계하고 수학적인 임베딩 공간을 구축했습니다. 하지만 이 전통적인 인공지능 파이프라인에는 치명적인 단점이 있습니다. 기계를 똑똑하게 만들기 위해서는 수만 건의 역사 문장에 연구자가 일일이 정답을 매기는, 뼈를 깎는 학습 데이터 구축 노동(Labeling) 과정이 선행되어야 한다는 점입니다. 코딩과 통계학에 지친 인문학자들에게 이는 너무나 거대한 진입 장벽입니다.

최근 챗GPT(ChatGPT)와 같은 "**거대 언어 모델(LLM)**"이 등장하면서 새로운 희망이 생겼습니다. 우리는 그저 자연어로 "이 실록 문장 읽고 이순신의 관직을 뽑아줘"라고 부탁만 하면 됩니다. 하지만 기쁨도 잠시, 챗GPT에게 실록을 던져주면 지식 그래프 생태계에 엄청난 재앙이 벌어집니다. 

기계는 자신이 이해한 대로 임의의 화살표(관계)를 무한정 창조해 냅니다. 우리가 온톨로지에서 관직 임용을 `core:hasPost`로 엄격하게 정의해 두었음에도 불구하고, LLM은 제멋대로 `worked_as`, `was_appointed_to`, `job_title` 같은 수십 개의 새로운 서술어를 남발하며 데이터를 엉망진창으로 만들어버립니다. 이 천재적이지만 통제 불능인 조수를 어떻게 인문학적 규율 안에 가둘 수 있을까요?

## 2. 해결책 제시: 1쪽짜리 커닝 페이퍼, "**온톨로지 하위 집합(Subset) 주입**"

이 통제 불능의 조수를 정밀하게 다루는 기술을 컴퓨터 공학에서는 "**프롬프트 엔지니어링(Prompt Engineering)**"이라고 부릅니다. 

인문학적으로 비유해 보겠습니다. 수백만 권의 책이 쌓인 규장각을 정리하라고 엄청나게 똑똑한 신입 학자(LLM)를 고용했습니다. 그에게 아무 지시 없이 정리를 맡기면, 그는 자기 마음대로 새로운 분류 체계를 발명해 버립니다. 그렇다고 수백 페이지에 달하는 "규장각 전체 분류 매뉴얼(전체 온톨로지)"을 한 번에 던져주면, 정보량이 너무 많아 학자는 혼란에 빠져 매뉴얼을 잊어버리고 환각(Hallucination)을 일으킵니다. 

가장 현명한 방법은, 그 학자가 오늘 정리할 서가의 내용에 딱 맞는 "**1쪽짜리 요약 매뉴얼(하위 집합)**"을 쥐여주는 것입니다. 이것이 바로 "**온톨로지 하위 집합 주입(Ontology Subset Injection)**" 기법입니다. 수백 개의 클래스와 속성 중, 현재 텍스트(예: 관원 임명 기사)를 분석하는 데 필요한 단 3~4개의 규칙만 발췌하여 프롬프트(명령어)에 주입하는 것입니다.

| 지시 방식 (Prompting) | LLM의 행동 패턴 | 인문학적 데이터 추출 결과 |
| :--- | :--- | :--- |
| **규칙 없는 단순 지시** | 자신이 아는 모든 영단어를 동원하여 임의로 관계를 생성함 | **실패.** `worked_as`, `job` 등 파편화된 쓰레기 데이터 양산. |
| **전체 온톨로지 주입** | 수백 개의 규칙에 압도되어 환각(Hallucination)을 일으킴 | **실패.** 관계를 헷갈리거나 처리 속도가 극심하게 느려짐. |
| **하위 집합(Subset) 주입** | 주어진 3개의 클래스와 2개의 속성 안에서만 완벽하게 사고함 | **성공.** `core:Person`, `core:hasPost` 등 표준화된 지식 연성. |

## 3. 실전 적용: LLM에게 조선시대 관역 지식 그래프 뽑아내기

우리에게 《선조실록》의 한글 번역본 텍스트가 주어졌습니다. 
> "선조가 원균을 경상우수사로 삼고, 이순신을 전라좌수사로 삼았다."

이 텍스트에서 챗GPT API를 이용해 완벽한 표준 트리플(JSON 포맷)을 뽑아내는 파이썬(Python) 프롬프트 엔지니어링 코드를 살펴보겠습니다.

```python
# 1. LLM에게 주입할 "온톨로지 하위 집합(Subset)"을 문자열로 정의합니다.
# 인물, 관직에 대한 규칙만 엄격하게 제한하여 1쪽짜리 커닝 페이퍼를 만듭니다.
ontology_subset = """
[허용된 클래스 (Class)]
1. "Person": 사람 (예: 이순신, 원균, 선조)
2. "Post": 관직명 (예: 전라좌수사, 경상우수사)

[허용된 속성 (Predicate) - 반드시 아래 2개만 사용할 것]
1. "hasPost": Person이 Post를 역임함 (Domain: Person, Range: Post)
2. "appoints": Person이 다른 Person을 임명함 (Domain: Person, Range: Person)
"""

# 2. 텍스트 원문을 준비합니다.
text_data = "선조가 원균을 경상우수사로 삼고, 이순신을 전라좌수사로 삼았다."

# 3. 거대 언어 모델에게 내릴 최종 명령서(Prompt)를 조립합니다.
# 시스템 역할 부여와 출력 형식(JSON)을 강제하는 것이 핵심입니다.
prompt = f"""
너는 조선시대 역사 문헌을 분석하여 지식 그래프를 추출하는 최고 수준의 사학자이다.
아래 제공된 [온톨로지 하위 집합]만을 엄격하게 사용하여, [원문]에서 시맨틱 트리플을 추출하라.
절대로 새로운 속성이나 클래스를 창조하지 마라.
출력은 반드시 컴퓨터가 읽을 수 있는 "JSON" 형식으로만 답변하라.

[온톨로지 하위 집합]
{ontology_subset}

[원문]
{text_data}
"""

# 4. LLM API(예: OpenAI)에 프롬프트를 전송하여 결과를 받습니다. (API 호출 코드 생략)
```

이 명령을 받은 거대 언어 모델은 허튼짓을 멈추고, 여러분이 주입한 1쪽짜리 커닝 페이퍼의 엄격한 규율에 순응하여 다음과 같은 기적적인 데이터를 뱉어냅니다.

```json
[
  {"subject": "선조", "predicate": "appoints", "object": "원균"},
  {"subject": "원균", "predicate": "hasPost", "object": "경상우수사"},
  {"subject": "선조", "predicate": "appoints", "object": "이순신"},
  {"subject": "이순신", "predicate": "hasPost", "object": "전라좌수사"}
]
```

복잡한 딥러닝 모델 학습(Training) 과정이나 고도의 코딩 기술 없이, 오직 잘 짜인 자연어 명령어(Prompt) 하나만으로 비정형 텍스트를 기계가 읽을 수 있는 지식 그래프로 변환하는 데 성공했습니다!

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 분노: "JSON 형식으로 달라고 했는데, 자꾸 인사말을 섞어서 파이프라인이 터집니다!"**

프롬프트 엔지니어링 실무에서 100% 마주하는 가장 짜증 나는 에러입니다. 분명히 명령서에 "JSON 형식으로만 답변하라"고 지시했는데, 친절한 LLM 조수는 꼭 결과물 앞뒤에 `"네, 분석해 드리겠습니다!"`라거나 `"이상으로 조선시대 관역 지식 그래프 추출을 마칩니다."`라는 쓸데없는 인간의 언어를 덧붙입니다. 이 답변을 파이프라인의 다음 단계 코드가 파싱(Parsing)하려다 "**JSON Decode Error**"를 뿜으며 서버가 그대로 뻗어버립니다.

**[승리하는 아키텍트의 강제 구속술: JSON Mode]**
LLM의 이 쓸데없는 친절함을 원천 차단하려면, 기계적인 족쇄를 채워야 합니다.
최신 API 환경에서는 호출 설정값에 **`response_format: { type: "json_object" }`**라는 파라미터를 강제로 주입할 수 있습니다. 만약 이 기능이 지원되지 않는 모델이라면, 명령어(Prompt)의 맨 마지막 줄을 **`[JSON 출력 시작]: {`** 라고 일부러 괄호를 열어둔 채로 끝맺으십시오. 이렇게 시스템 단에서 강제하면, 기계는 인사말을 완벽하게 생략하고 오직 중괄호 `{ }` 로 이루어진 깨끗한 데이터만을 뱉어내어 자동화 파이프라인의 안정성이 극대화됩니다.

## 5. 요약 및 다음 단계

* 복잡한 딥러닝 학습 없이 비정형 텍스트에서 지식을 추출하기 위해, 챗GPT와 같은 "**거대 언어 모델(LLM)**"과 이를 조련하는 "**프롬프트 엔지니어링**"을 활용합니다.
* LLM이 제멋대로 관계를 창조(환각)하는 것을 막기 위해, 전체 규칙이 아닌 텍스트 분석에 꼭 필요한 단 1쪽짜리 "**온톨로지 하위 집합(Subset)**"만을 프롬프트에 주입하여 기계의 사고를 완벽하게 통제합니다.
* 자동화 파이프라인이 에러 없이 돌아가기 위해서는 LLM의 답변에서 인간의 언어를 배제하고 완벽한 "**JSON Mode**"로만 출력하도록 강제하는 기술이 필수적입니다.

이제 우리는 기계의 압도적인 독해력(LLM)과 인간의 엄격한 인문학적 규칙(온톨로지)을 결합하는 최상의 무기를 손에 넣었습니다. 하지만 이 강력한 기계조차 사료에 숨겨진 깊은 은유나 고도로 복잡한 당파 싸움의 정황 앞에서는 엉뚱한 결론을 내리곤 합니다. 기계는 훌륭한 조수일 뿐, 역사의 최종 판관이 될 수는 없습니다.
