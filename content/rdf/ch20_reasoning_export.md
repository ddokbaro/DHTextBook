# 20장. 기계의 뇌를 깨우다: 추론기(Reasoner) 실행과 지식 내보내기(Export)

## 1. 도입: 인간이 입력한 데이터, 기계가 찾아낸 진실

**"한국근대인물LOD - 종묘배향공신을 대상으로 -"** 프로젝트를 진행하며 연구원들이 수만 건의 데이터를 Protégé에 정성껏 입력했습니다. 민영환이 조병세와 동료라는 사실(A-B), 조병세가 최익현과 동료라는 사실(B-C)을 입력했고, 관직 계층도와 역속성(Inverse), 이행성(Transitive) 같은 복잡한 헌법(T-box)도 모두 세팅했습니다.

하지만 화면을 가만히 들여다보면 무언가 허전합니다. 우리는 분명 **"동료 관계는 연쇄적으로 이어질 수 있다(이행성)"**라고 헌법에 명시했지만, 민영환의 화면을 클릭해 보면 최익현과 연결된 화살표는 어디에도 보이지 않습니다. 기계가 헌법을 무시한 것일까요? 

아닙니다. 여러분이 지금까지 설계한 것은 거대한 **"잠재력"**일 뿐, 기계는 아직 뇌를 가동하지 않고 휴면 상태에 있습니다. 엑셀은 저장 버튼을 누르는 순간 작업이 끝나지만, 시맨틱 웹은 저장 버튼을 누른 직후부터가 진짜 마법의 시작입니다. 

잠들어 있는 기계의 뇌를 깨워, 우리가 입력한 단편적인 힌트들(명시적 지식) 사이에서 인간이 미처 입력하지 않은 숨겨진 역사적 진실(암묵적 지식)을 스스로 찾아내게 만들어야 합니다.

## 2. 해결책 제시: 셜록 홈즈를 고용하다, "추론기(Reasoner)"



Protégé 상단 메뉴에는 **"Reasoner(추론기)"**라는 신성한 탭이 존재합니다. 이 추론기는 단순한 검색 엔진이 아닙니다. 여러분이 16장부터 19장까지 뼈 빠지게 제정한 논리 규칙(도메인, 레인지, 상하 관계, 역함수 등)을 무기로 삼아 데이터베이스 전체를 스캔하는 논리학자이자 디지털 셜록 홈즈입니다.

추론기를 실행(Start Reasoner)하는 순간, 다음과 같은 기적이 일어납니다.

| 인문학적 설계 (우리가 기계에게 준 힌트) | 추론기의 논리적 연산 과정 | 최종적으로 찾아낸 숨겨진 지식 (Inferred) |
| :--- | :--- | :--- |
| **상하 관계:** 수군절도사는 무반이다.<br>**데이터:** 이순신은 수군절도사이다. | A ⊂ B 이고, x ∈ A 이면, x ∈ B 이다. | **"이순신은 무반이다"**라는 화살표 자동 생성 |
| **역속성:** A가 B를 천거하면, B는 A에게 천거받은 것이다. | `recommends`의 Inverse는 `isRecommendedBy`이다. | 류성룡이 이순신을 천거했다고만 쳤는데, 이순신의 화면에 **"류성룡에게 천거받음"** 자동 생성 |
| **논리 제약:** 양반과 천민은 섞일 수 없다. | `disjointWith` 규칙 검사 수행. | 누군가 양반과 천민을 동시에 넣었다면, **"붉은색 에러창"**을 띄우며 시스템 방어 |

우리가 데이터를 절반만 입력해도, 추론기는 0.1초 만에 데이터베이스의 빈 공간을 수학적 논리로 꽉꽉 채워줍니다.

## 3. 실전 적용: HermiT 추론기 실행과 "노란색"의 마법

직접 잠든 뇌를 깨워보겠습니다. 세계적으로 가장 널리 쓰이는 시맨틱 웹 추론 엔진인 **"HermiT"**을 사용할 것입니다.

1. Protégé 상단 메뉴에서 **"Reasoner"**를 클릭합니다.
2. 여러 엔진 중 **"HermiT"** (또는 Pellet)을 선택합니다.
3. 다시 **"Reasoner"** 메뉴를 누르고 **"Start reasoner"**를 클릭합니다. (데이터가 많을 경우 수 초에서 수십 초의 연산 시간이 걸립니다.)

잠시 후, 캔버스 곳곳에 아주 놀라운 시각적 변화가 생겨납니다. **"Individuals by class"** 탭에서 특정 인물(예: 민영환)을 클릭해 보십시오. 우측 패널의 속성 창에 여러분이 직접 입력한 텍스트들 사이사이로 **"노란색 배경(Highlight)"**이 칠해진 데이터들이 무수히 쏟아져 나온 것을 볼 수 있습니다.

이 **"노란색 데이터"**가 바로 기계가 논리를 바탕으로 스스로 생각하여 창조해 낸 **"추론된 지식(Inferred Knowledge)"**입니다. 여러분이 엑셀에서 수십 시간에 걸쳐 수작업으로 채워 넣었어야 할 데이터들을, 기계가 단 한 번의 클릭만으로 100%의 정확도로 완성해 낸 것입니다. 인문학 아키텍트가 느끼는 최고의 카타르시스가 바로 이 노란색 화면을 마주하는 순간입니다.

## 4. 실무 트러블슈팅: 추론된 지식(Inferred)을 영구히 박제하여 내보내기(Export)

**시맨틱 아키텍트의 피눈물: "저장하고 서버에 올렸더니 노란색 지식이 다 날아갔습니다!"**

추론기가 만들어낸 노란색 마법에 감동한 초보 연구원들은 곧장 **"File ➔ Save"**를 누르고, 완성된 온톨로지 파일(`.owl` 또는 `.ttl`)을 그래프 데이터베이스(Graph DB) 서버에 업로드합니다. 그리고 절망에 빠집니다.

**"교수님! 분명히 Protégé에서는 이순신이 무반으로 자동 분류되었고 역속성도 전부 생겼는데, 서버에 올려서 질의어(SPARQL)를 던지니 검색이 하나도 안 됩니다! 노란색으로 떴던 지식들이 공중분해 되었습니다!"**

이것은 Protégé 실무에서 가장 치명적이고 빈번하게 일어나는 끔찍한 저장 실수입니다. 
명심하십시오. 여러분이 단순히 **"Ctrl+S (Save)"**를 누르면, Protégé는 여러분이 마우스와 키보드로 **"직접 입력한 데이터(Asserted)"**만을 저장합니다. 기계가 뇌를 굴려 임시로 화면에 띄워준 **"노란색 데이터(Inferred)"**는 파일 용량을 줄이기 위해 쏙 빼놓고 껍데기만 저장해 버립니다. 

그래프 DB 서버 자체가 자체적인 추론기를 내장하고 있다면 문제가 없지만, 대부분의 인문학 프로젝트 환경에서는 우리가 눈으로 확인한 그 완벽한 형태 그대로를 영구적으로 텍스트 코드로 박제해서 서버에 올려야 합니다.

**[승리하는 아키텍트의 완벽한 Export 철칙]**
임시 기억 장치에 떠 있는 노란색 지식들을 거북이 문법(Turtle)으로 영구히 굳혀서 내보내려면 다음의 특수 기능을 사용해야 합니다.

1. **"Reasoner ➔ Start reasoner"**가 켜져 있는지 반드시 확인합니다. (노란색이 떠 있어야 함)
2. 상단 메뉴에서 단순 Save가 아니라, **"File ➔ Export inferred axioms as ontology..."**를 클릭합니다.
3. 어떤 종류의 지식을 박제할 것인지 묻는 창이 뜹니다. 클래스 분류, 속성 제약 등 필요한 항목을 체크합니다. (실무에서는 안전하게 모두 체크하는 것을 권장합니다.)
4. 저장 형식(Format)을 묻는 창이 나오면, 인문학자가 읽기 가장 편하고 직관적인 **"Turtle"** 형식을 선택합니다.
5. `joseon_inferred_final.ttl` 이라는 이름으로 저장합니다.

이제 이 파일을 텍스트 에디터로 열어보십시오. 여러분이 입력한 적 없는 지식들이 완벽한 거북이 코드로 빽빽하게 인쇄되어 영원한 생명을 얻었습니다. 이 파일이야말로 여러분이 그래프 DB 서버에 떳떳하게 업로드할 수 있는 궁극의 무결점 데이터베이스입니다.

## 5. 요약 및 다음 단계

* 우리가 입력한 뼈대(T-box)와 사실(A-box)을 바탕으로 숨겨진 논리를 연산해 내는 엔진이 바로 **"추론기(Reasoner)"**입니다.
* Protégé에서 HermiT 같은 추론기를 켜면, 기계가 연쇄 작용과 역속성을 계산하여 만들어낸 방대한 양의 **"노란색(추론된) 데이터"**를 화면에서 확인할 수 있습니다.
* 이 위대한 추론의 결과물을 서버에 올리기 위해서는 단순 저장이 아니라, 반드시 **"Export inferred axioms as ontology"** 기능을 사용하여 거북이 문법(Turtle)으로 영구히 박제해 주어야 합니다.

드디어 상향식(Bottom-up) 데이터 입력의 고통을 끝내고, Protégé를 활용한 하향식(Top-down) 지식 그래프의 설계와 대량 데이터 임포트(Import), 그리고 추출(Export)까지 거대한 산맥을 완벽하게 등반했습니다. 

로컬 PC에서의 작업은 이것으로 모두 끝났습니다. 여러분이 정제해 낸 `modern_figures_lod_v1.ttl` 파일은 이제 좁은 연구실의 하드디스크를 벗어나 세상을 향해 개방될 준비를 마쳤습니다.

하지만 이 텍스트 파일 자체만으로는 어떠한 서비스도 제공할 수 없습니다. 이 찬란한 지식망을 전 세계 연구자들과 공유하고, 고도의 SPARQL 질의를 실시간으로 처리하며, 외부의 수많은 시스템과 연동하기 위해서는 이 데이터를 안전하게 담아낼 튼튼한 물리적 '그릇', 즉 **서버 인프라(Infra)**가 절대적으로 필요합니다.

이제부터는 개인의 PC 화면을 벗어나 실제 웹 생태계에 지식 그래프를 띄우는 본격적인 엔지니어링의 세계로 도약합니다.
