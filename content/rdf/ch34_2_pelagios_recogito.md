# 34.2. Pelagios Network: 공간 인문학 철학과 어노테이션

## 1. 도입: "지도 위에 '콘스탄티노플'을 찍어라"의 악몽

우리는 34.1장에서 생몰년도가 없는 고대 인물들을 1차원 타임라인 위에 세우는 '시간의 제국(CBDB)'을 탐험했습니다. 이제 우리는 2차원 공간, 즉 '지도' 위로 시선을 옮깁니다.

디지털 인문학 아키텍트에게 역사적 공간을 다루는 이른바 "**공간 인문학(Spatial Humanities)**"은 지독한 악몽과도 같습니다.
여러분이 로마 제국의 무역로를 연구하기 위해 고문헌을 디지털화하고 있다고 가정해 봅시다. 문헌에는 "론디니움(Londinium)"이나 "루테티아(Lutetia)"라는 지명이 수없이 등장합니다. 이 텍스트들을 현대의 구글 지도 위에 예쁜 빨간 핀(Pin)으로 꽂아 웹 서비스로 만들고 싶습니다.

하지만 기계는 "론디니움"이 현재의 영국 "런던(London)"이고, "루테티아"가 프랑스 "파리(Paris)"라는 사실을 전혀 모릅니다. 설령 여러분이 파이썬 코드로 `if text == "론디니움": return "런던"`이라고 하드코딩하려 해도, 수천 년간 국가의 경계가 바뀌고 지명이 수십 번씩 덧칠해진 유럽의 역사를 일일이 매핑하는 것은 불가능합니다. 심지어 문헌에는 등장하지만 현재는 바닷속으로 가라앉아 정확한 위도와 경도(좌표)조차 알 수 없는 전설 속의 항구 도시들은 어떻게 지도에 표현해야 할까요?

## 2. 해결책 제시: 텍스트와 지도의 융합, "**가제티어(Gazetteer)**"와 "**Pelagios**"

이 거대한 지리적 혼돈을 시맨틱 웹의 철학으로 정복한 전설적인 연합체가 바로 유럽 연합(EU)의 지원으로 탄생한 "**Pelagios Network(펠라기오스 네트워크)**"입니다. (Pelagios는 고대 그리스어로 '바다'를 의미합니다.)

Pelagios 연구진은 이 문제를 해결하기 위해 자신들이 직접 거대한 세계 지도를 새로 그리는 멍청한 짓을 하지 않았습니다. 대신 그들은 전 세계에 흩어진 역사 지명 사전, 즉 "**가제티어(Gazetteer)**"들을 LOD(Linked Open Data)로 묶어내는 거대한 '항구'를 건설했습니다.

인문학적으로 비유하자면, 가제티어는 과거의 지명과 현대의 좌표, 그리고 그 장소가 겪은 역사를 몽땅 담아놓은 "**시공간 등기부등본**"입니다. 고대 지중해 세계를 다루는 가장 유명한 가제티어인 **Pleiades(플레이아데스)**가 그 대표적인 예입니다.

Pelagios의 철학은 아주 단순하고도 강력합니다. **"텍스트에 위도와 경도를 직접 박아 넣지 마라. 대신 텍스트의 단어를 가제티어의 고유 주소(URI)에 연결(Link)만 해두어라!"**

| 개념 | 전통적 GIS 방식 (하수) | Pelagios/가제티어 방식 (고수) |
| :--- | :--- | :--- |
| **데이터 구조** | `{"지명": "론디니움", "lat": 51.5, "lon": -0.1}` | `{"텍스트": "론디니움", "URI": "https://pleiades.stoa.org/places/79574"}` |
| **좌표가 수정될 때** | 텍스트 DB의 모든 좌표를 개발자가 수동으로 수정해야 함 | **가제티어(Pleiades) 서버에서 좌표가 수정되면, 연결된 모든 텍스트가 자동으로 최신 지도를 반영함** |
| **장소가 불확실할 때** | 좌표가 없으면 지도에 띄울 수 없어 에러 발생 | **좌표계가 없어도 '개념적 장소(URI)'로서 네트워크 분석(SNA) 가능** |

## 3. 실전 적용: 기적의 어노테이션 도구, "**Recogito(레코기토)**"

철학은 훌륭하지만, 코딩을 모르는 일반 역사학자들이 문헌의 단어를 찾아 일일이 가제티어의 URI 식별자로 매핑하는 것은 끔찍한 노동입니다. 이를 해결하기 위해 Pelagios가 개발하여 전 세계에 무료로 배포한 오픈소스 웹 플랫폼이 바로 "**Recogito(레코기토)**"입니다.

Recogito는 문서 이미지나 텍스트를 브라우저에 업로드한 뒤, 마우스로 드래그하여 지식 그래프를 엮어내는 기적의 **어노테이션(Annotation, 주석 달기)** 도구입니다.

**[Recogito의 마법 같은 실무 파이프라인]**
1. **업로드:** 라틴어로 쓰인 고문서 스캔본을 Recogito에 업로드합니다.
2. **자동 인식 (NER):** 내장된 인공지능이 텍스트를 훑고 지나가며 "이 단어는 장소(Place)인 것 같습니다"라며 회색 음영을 칠해줍니다.
3. **인간의 검수 (Alignment):** 학자가 회색으로 칠해진 "Lutetia"라는 단어를 클릭합니다. 그러면 Recogito가 뒤에서 몰래 Pleiades 가제티어에 검색을 날려, "혹시 이 단어가 `[프랑스 파리의 고대 지명, URI: .../109126]`이 맞습니까?"라고 제안합니다. 학자가 "Confirm(확인)" 버튼을 누릅니다.
4. **WADM 추출:** 이 클릭 한 번으로, 단순한 텍스트 쪼가리였던 "Lutetia"는 W3C의 국제 표준인 **Web Annotation Data Model (WADM)** 규격의 완벽한 JSON-LD 데이터로 승화됩니다.

```json
// Recogito가 뱉어내는 완벽한 시맨틱 어노테이션 (JSON-LD)
{
  "@context": "[http://www.w3.org/ns/anno.jsonld](http://www.w3.org/ns/anno.jsonld)",
  "type": "Annotation",
  "target": {
    "source": "[http://my-domain.com/document/roman_text.txt](http://my-domain.com/document/roman_text.txt)",
    "selector": {
      "type": "TextPositionSelector",
      "start": 105,
      "end": 112 // 텍스트 문서의 105번째~112번째 글자 (Lutetia)
    }
  },
  "body": {
    "type": "SpecificResource",
    "purpose": "identifying",
    "source": "[https://pleiades.stoa.org/places/109126](https://pleiades.stoa.org/places/109126)" // 가제티어(파리)의 URI로 완벽하게 꽂힘!
  }
}
```

이 데이터가 쌓이면, 학자는 단 한 줄의 지도 프로그래밍(GIS)을 하지 않고도, 업로드한 문헌의 모든 장소가 현대의 지도 위에 인터랙티브하게 펼쳐지는 경이로운 시각화 화면을 얻게 됩니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 절망: "문헌에 나오는 '이어도'의 정확한 위도와 경도를 몰라서 에러가 납니다!"**

전통적인 공간 데이터베이스(PostGIS 등)를 다루던 공학자들이 디지털 인문학에 뛰어들었을 때 겪는 가장 큰 멘탈 붕괴입니다. 지도 프로그램은 점을 찍기 위해 반드시 `X, Y (위도, 경도)` 좌표를 요구합니다. 그런데 역사 문헌에는 "남쪽으로 사흘을 항해하여 닿은 환상의 섬" 같이 좌표를 도저히 특정할 수 없는 추상적 장소들이 수두룩합니다.

엔지니어들은 시스템이 뻗는 것을 막기 위해 지도 한가운데(예: 바다 한가운데 위도 0, 경도 0)에 임의로 가짜 핀을 박아 넣습니다. 그리고 이는 학자들의 거센 분노("역사적 사실의 왜곡이다!")를 불러옵니다.

**[승리하는 아키텍트의 '개념적 장소(Conceptual Place)' 수용술]**
Pelagios의 철학을 완벽하게 이해한 아키텍트는 장소(Place)를 "물리적 좌표"로만 보지 않습니다. 
시맨틱 웹에서 장소란 **"이야기가 교차하는 논리적 노드(Node)"**입니다.

가제티어(Gazetteer) 내부에 '이어도'라는 장소를 등록할 때, 억지로 Geometry(WKT 위경도) 속성을 넣지 마십시오. 좌표 속성은 비워두고, 오직 `URI`와 `이름`만 부여하십시오. 
이렇게 하면 비록 구글 지도 위에는 핀이 찍히지 않지만, 지식 그래프 상에서는 "이순신 ➔ (방문하다) ➔ 이어도 ➔ (전설에 등장하다) ➔ 홍길동"이라는 완벽한 인문학적 **네트워크 관계망**이 훼손되지 않고 살아남습니다. 

나중에 고고학적 발굴을 통해 정확한 좌표가 밝혀지면, 그때 가제티어의 URI 원본 데이터에 위경도 딱 한 줄만 추가하면 됩니다. 그러면 전 세계에서 이 URI를 바라보고 있던 모든 문헌과 웹 서비스의 지도 위에, 수백 개의 핀이 동시에 마법처럼 솟아오르게 될 것입니다. 이것이 위대한 공간 인문학의 시맨틱 아키텍처입니다.

## 5. 요약 및 다음 단계

* 고문헌에 등장하는 모호한 옛 지명들을 현대의 지도와 연결하기 위해, 유럽 연합의 **Pelagios** 프로젝트는 개별 문헌을 "**가제티어(역사 지명 사전)**"의 URI 식별자와 연동하는 LOD 철학을 확립했습니다.
* 일반 학자들은 복잡한 코딩 없이, 오픈소스 플랫폼인 **Recogito**를 사용하여 문헌의 텍스트를 마우스로 드래그하고 가제티어에 매핑(Annotation)함으로써 완벽한 WADM JSON-LD 데이터를 생성해 냅니다.
* 좌표(위도/경도)가 불확실한 전설 속의 장소라도, 억지로 가짜 좌표를 찍지 않고 독립된 '개념적 URI'로 남겨두면 훌륭한 인문학적 네트워크 분석(SNA)의 허브로 기능할 수 있습니다.

이제 우리는 시간(CBDB)과 공간(Pelagios)의 불확실성을 시맨틱 웹의 철학으로 우아하게 통제하는 글로벌 스탠다드를 모두 마스터했습니다. 

하지만 기록 관리와 도서관학의 세계로 넘어가면, 또 다른 차원의 거대한 공포가 아키텍트를 덮칩니다.
**"A 도서관의 문서에 적힌 '김대건'과 B 박물관의 문서에 적힌 '김대건'이 동명이인인지, 아니면 동일 인물인지 기계가 도대체 어떻게 확신할 수 있는가?"**

대망의 마지막 글로벌 사례이자 이 교재의 마침표가 될 "**34.3. SNAC: 기록학 인물 관계망과 '확률적 매칭' 알고리즘**"으로 진입하여, 수천 개의 기관에 흩어진 파편화된 기록들을 하나로 꿰어내는 신원 식별(Identity Resolution)의 궁극적 아키텍처를 해부해 보겠습니다!
