# 3장. 지식 그래프 아키텍처 대격돌: W3C RDF vs 산업계 Neo4j

## 1. 도입: 그래프의 세계에 도착하자마자 마주한 두 갈래 길

우리는 드디어 답답했던 엑셀과 관계형 데이터베이스(RDB)의 네모 반듯한 표(Table)를 찢어버리고, 조선시대 지식인들의 거대한 인물망을 점과 선으로 자유롭게 이어내는 `"**지식 그래프(Knowledge Graph)**"`의 세계로 넘어왔습니다.

이제 이 원대한 지식 그래프를 담아낼 컴퓨터 서버(데이터베이스)를 구축하려 합니다. 그런데 인터넷을 검색하거나 전산소의 IT 개발자에게 자문을 구하면, 여러분은 시작부터 엄청난 혼란에 빠지게 될 것입니다.

"교수님, 인문학 데이터를 전 세계와 연결하시려면 무조건 시맨틱 웹 국제 표준인 `"**RDF**"`를 쓰셔야 합니다!"
"아닙니다! 요새 IT 실무에서는 낡고 느린 방식 대신, 처리 속도가 가장 빠르고 직관적인 `"**Neo4j(네오포제이)**"`를 쓰는 것이 대세입니다!"

분명 똑같이 사물과 사물을 점과 선으로 연결한다고 했는데, 왜 두 가지의 완전히 다른 기술 진영이 서로 자신이 정답이라고 싸우고 있는 것일까요? 코딩을 모르는 인문학자는 대체 어느 쪽을 선택해서 소중한 조선시대 데이터를 설계해야 할까요?

이 혼란은 기술의 우열 때문이 아닙니다. 두 진영이 지식을 바라보고 활용하는 `"**철학(Philosophy)**"`이 완전히 다르기 때문에 발생하는 필연적인 충돌입니다. 우리는 이 두 거인의 사상적 차이를 명확히 이해해야만, 우리의 연구 목적에 맞는 완벽한 지식의 집을 지을 수 있습니다.

## 2. 해결책 제시: 철학자(RDF)와 실용주의 엔지니어(Neo4j)

지식 그래프를 구현하는 두 가지 거대한 아키텍처는 각각 웹의 창시자 팀 버너스리가 이끄는 W3C가 제정한 `"**RDF(자원 기술 프레임워크)**"`와, 산업계의 필요에 의해 탄생한 `"**레이블 속성 그래프(LPG, Labeled Property Graph)**"`입니다. LPG의 대표적인 데이터베이스 프로그램이 바로 우리가 자주 듣게 될 `"**Neo4j**"`입니다.

이 두 세계를 인문학적 비유로 명확하게 대비해 보겠습니다.

### 철학자들의 글로벌 도서관: W3C RDF
`"**RDF**"`는 전 세계의 모든 지식을 하나의 규칙으로 통일하여 서로 완벽하게 연결하겠다는 원대한 꿈을 가진 철학자입니다. 
이 세계에서는 예외가 없습니다. 세상의 모든 지식은 무조건 `"**주어-술어-목적어**"`라는 세 개의 조각, 즉 `"**트리플(Triple)**"`로만 쪼개져야 합니다. 데이터의 연산 속도나 효율성보다는, 내 연구실의 이순신 데이터가 지구 반대편의 위키데이터(Wikidata)와 모순 없이 결합하여 새로운 역사적 사실을 기계가 스스로 알아내는 `"**논리적 추론(Reasoning)**"`과 `"**상호운용성(Interoperability)**"`을 최우선으로 삼습니다.

### 속도에 미친 실용주의 택배 회사: Neo4j (LPG)
반면 `"**Neo4j**"`는 글로벌 지식의 통합이나 철학적 완결성에는 큰 관심이 없는 실용주의 엔지니어입니다. 
그들의 목표는 오직 하나, 우리 연구소 서버 안에 구축된 수십만 명의 당쟁 네트워크를 눈 깜짝할 사이에 뚫고 지나가 최단 경로를 찾아내는 `"**탐색 속도(Traversal Speed)**"`입니다. 무조건 데이터를 세 조각으로 쪼개어 선을 복잡하게 늘리는 대신, 점(Node)이나 선(Edge) 안에 마치 포스트잇을 붙이듯이 이름, 출생년도, 관직명 같은 다양한 정보들을 주머니 속에 욱여넣어 실용성과 연산 속도를 극대화합니다.


## 3. 실전 적용: 이이(율곡)의 데이터를 설계하는 두 가지 방법

이 두 가지 철학이 실제 조선시대 역사 데이터를 코드로 짤 때 어떻게 달라지는지 눈으로 직접 확인해 보겠습니다.

우리가 컴퓨터에게 가르쳐 줄 역사적 팩트는 다음과 같습니다.
**"서인(西人) 강경파인 이이(1536년생)는 김장생의 스승이다."**

### 방법 A: 철학자의 방식 - W3C RDF (Turtle 문법)
RDF는 점(노드) 안에 데이터를 숨기는 것을 결코 허락하지 않습니다. 출생년도나 당파 같은 단순한 정보조차도 무조건 점과 선과 점이라는 세 조각(트리플)으로 길게 늘어뜨려야 합니다. 

```turtle
# 시맨틱 웹의 RDF 방식: 모든 것을 트리플(주어-술어-목적어)로 분해합니다.

# 1. 이이는 김장생의 스승이다. (핵심 관계)
[http://조선.kr/person/이이](http://조선.kr/person/이이) [http://조선.kr/관계/스승이다](http://조선.kr/관계/스승이다) [http://조선.kr/person/김장생](http://조선.kr/person/김장생) .

# 2. 이이의 출생년도는 1536년이다. (주머니에 넣을 수 없으니 새로운 선을 하나 더 긋습니다)
[http://조선.kr/person/이이](http://조선.kr/person/이이) [http://조선.kr/속성/출생년도](http://조선.kr/속성/출생년도) "1536" .

# 3. 이이의 소속 붕당은 서인이다. (당파 정보도 선으로 쪼개어 밖으로 꺼냅니다)
[http://조선.kr/person/이이](http://조선.kr/person/이이) [http://조선.kr/속성/당파](http://조선.kr/속성/당파) "서인" .
```

### 방법 B: 실용주의자의 방식 - Neo4j (Cypher 문법)
Neo4j는 점(노드)이라는 주머니 안에 데이터를 `"**속성(Property)**"`이라는 이름으로 마음껏 쑤셔 넣을 수 있습니다. 덕분에 쓸데없는 잔가지(선)가 사라지고 코드가 훨씬 인간의 사고방식과 비슷해집니다. 

```cypher
// Neo4j의 방식: 인물 노드({ }) 안에 출생년도와 당파를 포스트잇처럼 한 번에 집어넣습니다.

// 1. 이이와 김장생의 노드를 만들고, 이이의 주머니 안에 세부 정보를 넣습니다.
CREATE (a:인물 {이름: "이이", 출생년도: 1536, 당파: "서인"})
CREATE (b:인물 {이름: "김장생"})

// 2. 두 사람을 스승이라는 명확한 선(Edge)으로만 깔끔하게 연결합니다.
CREATE (a)-[:스승이다]->(b)
```

이 두 가지 세계관을 한눈에 비교할 수 있는 표를 제시합니다.

| 비교 항목 | W3C RDF (시맨틱 웹) | Neo4j (레이블 속성 그래프) |
| :--- | :--- | :--- |
| **핵심 철학** | 글로벌 지식의 연결 및 철학적 추론 | 로컬 네트워크의 초고속 분석 및 탐색 |
| **데이터 모델** | 무조건 3조각으로 쪼개는 `"**트리플(Triple)**"` | 노드 안에 정보를 뭉쳐 품는 `"**주머니 구조**"` |
| **시각적 복잡도** | 단순한 속성도 선으로 그어 매우 복잡함 | 속성을 숨겨 핵심 관계망만 깔끔하게 보임 |
| **국제 표준 질의어** | `"**SPARQL**"` (W3C 국제 표준) | `"**Cypher**"` (사실상의 산업계 표준) |
| **인문학적 적합성** | 영구적인 문화유산 아카이빙, 글로벌 개방 | 방대한 당파 네트워크 분석, 최단 거리 탐색 |

## 4. 실무 트러블슈팅 (Street-smart Tips)

디지털 인문학 프로젝트를 총괄하게 될 때, 수많은 연구자들이 "둘 중 어느 시스템이 더 좋습니까? 하나만 확실하게 정해 주십시오!"라고 묻곤 합니다. 

현업 실무의 관점에서 단호하게 경고합니다. **"둘 중 하나만 선택하려는 순간, 여러분의 프로젝트는 반쪽짜리가 됩니다."**

인문학 데이터 프로젝트의 궁극적인 사명은 귀중한 사료를 전 세계 인류의 지식 자산으로 영구히 남기는 것(아카이빙)과, 그 데이터를 재빠르게 연산하여 논문용 통계와 네트워크 지도를 뽑아내는 것(분석) 두 가지입니다. 전자는 `"**RDF**"`가 압도적으로 유리하고, 후자는 `"**Neo4j**"`가 압도적으로 유리합니다.

따라서 최고 수준의 인문학 데이터 파이프라인은 두 세계를 결합하는 `"**하이브리드 전략(Hybrid Strategy)**"`을 취해야 합니다. 데이터의 뼈대는 국제 표준인 `"**RDF**"`로 견고하게 구축하여 전 세계에 개방(LOD)합니다. 그리고 내부에서 복잡한 네트워크 연산을 돌릴 때만, 이 RDF 데이터를 Neo4j로 손실 없이 쑥 빨아들여 초고속으로 분석하는 것입니다. 이 두 거인을 화해시키는 마법 같은 융합 기술은 3.3장에서 아주 상세히 다루게 될 것입니다.

## 5. 요약 및 다음 단계

* 그래프 데이터베이스에는 철학적 완결성을 추구하는 `"**W3C RDF**"`와, 연산 속도와 실용성을 추구하는 `"**Neo4j(LPG)**"`라는 두 명의 거인이 존재합니다.
* RDF는 데이터를 글로벌하게 연결하고 추론(Reasoning)하는 데 최적화되어 있으며, Neo4j는 닫힌 시스템 안에서 복잡한 네트워크망을 초고속으로 탐색(Traversal)하는 데 최적화되어 있습니다.
* 우리의 1차적인 목표는 인문학 데이터를 전 우주적인 지식망에 편입시키는 것이므로, 국제 표준인 `"**RDF**"`의 문법을 먼저 완벽하게 마스터해야 합니다.

두 거인의 철학적 차이를 명확히 이해하셨습니까? 그렇다면 이제 본격적으로 시맨틱 웹의 진정한 주인공, 모든 지식을 세 조각으로 쪼개는 마법사라 불리는 `"**트리플(Triple)**"`의 세계로 깊숙이 잠수해 보겠습니다.
