# 28.3. 공간 추론 실전 2: 다각형 교차 판별 (Polygon Overlay)

## 1. 도입: 점(Point)의 한계와 영토(Polygon)의 등장

우리는 앞선 28.2장까지 지도 위에 수군 진영을 "점(Point)"으로 찍고, 그 점들을 중심으로 반경을 돌려 지원군을 찾는 놀라운 공간 탐색을 해냈습니다. 하지만 인문학적 공간은 바늘 끝처럼 좁은 점 하나로 설명되지 않습니다.

임진왜란 초기, 전라좌수사 이순신이 경상도 해역으로 출전하는 역사적인 장면을 떠올려 보십시오. 
전라좌수영의 관할 구역과 경상우수영의 관할 구역은 거대한 바다와 수많은 섬을 품고 있는 면적, 즉 "**영토(Area)**"입니다. 그리고 이순신 함대의 출전 경로는 여러 점을 이어 나가는 구불구불한 "**선(Path)**"입니다.

만약 여러분이 **"이순신 함대의 이동 경로가 경상우수영의 해상 관할 구역을 지나갔는가(침범했는가)?"**라는 질문을 던진다고 가정해 봅시다. 이 질문은 점과 점 사이의 거리를 재는 공식으로는 절대 풀 수 없습니다. 우리는 기계에게 "선"과 "면"이라는 고차원적인 기하학을 가르치고, 두 도형이 서로 부딪히고 겹치는지 수학적으로 판별하게 만들어야 합니다.

## 2. 해결책 제시: 다각형과 선의 충돌, "**교차 판별(Intersects)**"



W3C의 공간 전문가들은 점(Point)을 넘어선 복잡한 도형들을 표현하기 위해, WKT 문법 안에 "**POLYGON(다각형)**"과 "**LINESTRING(선)**"이라는 위대한 도구를 만들어 두었습니다.

인문학적으로 비유하자면, 지식 그래프 위에 가상의 국경선을 긋고(Polygon), 함대의 항해 일지를 따라 뱃길(LineString)을 그리는 작업입니다. 이 두 도형이 그려지고 나면, 우리는 공간 질의의 궁극기라 불리는 "**교차 판별(Intersects)**" 함수를 사용할 수 있습니다.

이 함수는 텍스트로 된 두 객체를 기하학적으로 분석하여, 단 1미터라도 서로의 영역을 밟고 지나갔다면 "참(True)"을 반환합니다.

| 기하학적 형태 | WKT 문법 예시 | 인문학적 활용 (조선시대) |
| :--- | :--- | :--- |
| **선 (Path)** | `LINESTRING(X1 Y1, X2 Y2, ...)` | 이순신 함대의 출동 경로, 봉수대의 시야선, 파발의 이동 경로 |
| **다각형 (Area)** | `POLYGON((X1 Y1, X2 Y2, ...))` | 경상우수영 관할 해역, 한양 도성의 경계, 특정 당파의 세력권 |
| **교차 판별** | `bif:st_intersects(도형A, 도형B)` | **함대의 항로(선)가 경상우수영 해역(면)을 지나갔는지 완벽하게 증명함** |

## 3. 실전 적용: 함대의 항로가 관할 구역을 침범했는가?

이제 거북이(Turtle) 문법으로 경상우수영의 바다 영토(POLYGON)와 함대의 항로(LINESTRING)를 정의하고, SPARQL 쿼리로 두 공간이 교차하는지 알아내는 추론 코드를 작성해 보겠습니다.

**[데이터 입력: 면(Polygon)과 선(LineString) 정의]**
```turtle
PREFIX geo: [http://www.opengis.net/ont/geosparql#](http://www.opengis.net/ont/geosparql#)
PREFIX joseon: [http://dh.aks.ac.kr/joseon/](http://dh.aks.ac.kr/joseon/)

# 1. 경상우수영의 해상 관할 구역을 "다각형(POLYGON)"으로 선언합니다.
# 꼭짓점 좌표들을 순서대로 연결하여 거대한 면적을 만듭니다.
joseon:경상우수영관할구역 a geo:Feature ;
    geo:asWKT "[http://www.opengis.net/def/crs/OGC/1.3/CRS84](http://www.opengis.net/def/crs/OGC/1.3/CRS84) POLYGON((128.0 34.5, 128.5 34.5, 128.5 35.0, 128.0 35.0, 128.0 34.5))"^^geo:wktLiteral .

# 2. 이순신 함대의 1차 출동 경로를 "선(LINESTRING)"으로 선언합니다.
# 여수(전라좌수영)에서 출발하여 옥포 방향으로 구불구불 나아갑니다.
joseon:제1차출동항로 a geo:Feature ;
    geo:asWKT "[http://www.opengis.net/def/crs/OGC/1.3/CRS84](http://www.opengis.net/def/crs/OGC/1.3/CRS84) LINESTRING(127.7 34.7, 128.2 34.8, 128.6 34.9)"^^geo:wktLiteral .
```

**[공간 교차 질의 (SPARQL)]**
이제 이 두 객체가 서로 겹치는지 묻는 쿼리를 던져봅니다.

```sparql
PREFIX geo: [http://www.opengis.net/ont/geosparql#](http://www.opengis.net/ont/geosparql#)
PREFIX joseon: [http://dh.aks.ac.kr/joseon/](http://dh.aks.ac.kr/joseon/)

# 함대 항로와 관할 구역이 교차하는지 검사합니다.
SELECT ?is_intersecting
WHERE {
    joseon:경상우수영관할구역 geo:asWKT ?area_wkt .
    joseon:제1차출동항로 geo:asWKT ?path_wkt .
    
    # [핵심] Virtuoso의 교차 판별 사투리(bif:st_intersects)를 사용합니다.
    # 두 도형이 교차하면 1(True), 아니면 0(False)을 반환합니다.
    BIND(bif:st_intersects(?area_wkt, ?path_wkt) AS ?is_intersecting)
}
```

기계는 즉시 항로의 선분이 다각형 내부를 뚫고 지나갔음을 수학적으로 계산해 내고 "**1 (True)**"을 반환합니다. 우리는 텍스트 더미 속에서 이순신 함대가 타 관할 구역에 진입했다는 입체적인 역사적 사실을 기계적으로 입명해 낸 것입니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 피눈물: "다각형을 그렸더니 기계가 'Polygon is not closed'라며 파업했습니다!"**

이것은 WKT로 면적(Polygon) 데이터를 짤 때 10명 중 9명의 연구자가 겪는 가장 악명 높은 에러입니다. 
연구원들은 지도를 보며 네 개의 꼭짓점(A, B, C, D)을 정성껏 따서 `POLYGON((A, B, C, D))`라고 입력합니다. 그런데 서버는 이 데이터를 받자마자 "닫히지 않은 다각형"이라며 에러를 뿜어냅니다.

**[승리하는 아키텍트의 뫼비우스 연결술]**
기하학에서 다각형(면)이 되려면 출발했던 점으로 다시 완벽하게 돌아와 선을 묶어주어야 합니다. 인간의 뇌는 네 개의 점을 찍으면 머릿속에서 자동으로 마지막 점과 첫 점을 잇지만, 기계의 뇌는 명시적으로 지시하지 않으면 D점에서 멈춘 채 선을 열어둡니다. 선이 열려 있으면 그것은 면(Area)이 아니라 단순히 꺾인 선(LineString)에 불과하여 에러가 발생합니다.

다각형을 정의할 때의 절대 원칙은 이것입니다. **"시작점과 끝점의 좌표는 토씨 하나 틀리지 않고 완벽하게 동일해야 한다."**
즉, 사각형을 그리려면 4개의 점이 아니라 **5개의 점(A, B, C, D, A)**을 찍어야 합니다. 앞선 코드 예시에서 `128.0 34.5`로 시작한 좌표가 맨 마지막에 다시 `128.0 34.5`로 끝나며 완벽하게 입구를 걸어 잠근 것을 확인하십시오. 이 미세한 마무리가 데이터베이스 폭발을 막는 아키텍트의 마지막 디테일입니다.

## 5. 요약 및 대단원 마무리 (모듈 7의 완성)

* 텍스트에 갇힌 역사적 지리 정보를 복원하기 위해, 점(Point)을 넘어선 선(LineString)과 다각형(Polygon) 형태의 고차원 WKT 기하학을 지식 그래프에 부여해야 합니다.
* "**bif:st_intersects**" 교차 판별 함수를 사용하면, 함대의 이동 경로나 인물의 동선이 특정 관할 구역이나 당파의 세력권을 침범했는지 수학적으로 추론해 낼 수 있습니다.
* 다각형 데이터를 구축할 때는 반드시 "**시작점과 끝점의 좌표를 완벽하게 일치**"시켜 도형을 닫아주어야(Closed) 서버의 에러를 방지할 수 있습니다.
