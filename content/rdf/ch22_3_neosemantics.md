# 22.3. Neosemantics(n10s) 플러그인 실무: RDF 데이터를 Neo4j로 손실 없이 임포트

## 1. 도입: 평행우주를 연결하는 '의미론적 웜홀(Wormhole)'

우리는 지금까지 지식 그래프 인프라의 두 가지 평행우주를 완벽하게 구축했습니다. 
21장에서는 전 세계의 지식망(LOD)과 소통하며 학문적 무결성을 증명하는 **"표준 RDF의 세계(Virtuoso)"**를 열었고, 22장에서는 우리 연구실 내부의 데이터를 빛의 속도로 연산하고 시각화하는 **"속성 그래프의 세계(Neo4j)"**를 열었습니다.

하지만 디지털 인문학 데이터 센터의 총괄 아키텍트라면 여기서 깊은 딜레마에 빠지게 됩니다. 
**"20장에서 Protégé로 수개월간 정성껏 빚어낸 거북이 파일(.ttl)을 Neo4j의 강력한 GDS 알고리즘으로 분석하고 싶은데, 이질적인 두 엔진의 문법 차이 때문에 데이터를 Neo4j용으로 처음부터 다시 짜야 하는가?"**

이 절망적인 고민을 단숨에 해결해 주는 구원자가 바로 **Neosemantics(이하 n10s)** 플러그인입니다. n10s는 Neo4j 엔진 내부에 시맨틱 웹의 유전자(RDF 파서)를 이식하여, 외부의 RDF 데이터를 단 한 톨의 의미 손상 없이 받아들이고, 필요할 때 다시 표준 RDF로 뱉어내는 완벽한 '의미론적 웜홀' 역할을 수행합니다.

## 2. 해결책 제시: 이기종 모델 간의 시맨틱 매핑(Semantic Mapping) 전략

RDF와 Neo4j는 세상을 바라보는 관점이 다릅니다. RDF는 모든 것을 세 토막(S-P-O)으로 쪼개는 반면, Neo4j는 관계(Edge) 자체에 속성을 부여합니다. n10s는 이 두 모델 사이의 충돌을 다음과 같은 지능적인 변환 규칙으로 해결합니다.



| RDF 구성 요소 (W3C 표준) | Neo4j 변환 결과 (n10s 처리) | 인문학적 데이터 보존의 의미 |
| :--- | :--- | :--- |
| **Subject / Object (URI)** | **Node (노드)** | 고유 식별자(`uri` 속성)를 가진 역사적 실체로 온전히 복원됨 |
| **rdf:type (클래스 선언)** | **Label (라벨)** | 노드의 분류 체계(예: `:Person`, `:Book`)로 직관적 렌더링 |
| **Object Property (객체 속성)** | **Relationship (관계 화살표)** | 인물과 장소, 사건을 잇는 방향성 있는 네트워크 링크로 변환 |
| **Datatype Property (데이터 속성)** | **Node Property (노드 내부 속성)** | 이름, 생몰년도 등 화살표로 뺄 필요 없는 포스트잇 정보로 압축 |

이 매핑을 통해 우리는 **"표준에 기반한 영구 보존(RDF)"**과 **"속성 그래프에 기반한 초고속 분석(Neo4j)"**이라는 두 마리 토끼를 모두 잡는 진정한 하이브리드 아키텍처를 완성하게 됩니다.

## 3. 실전 적용 1단계: n10s 엔진 이식과 보안 해제

GDS 플러그인을 설치했던 것과 동일한 방식으로 리눅스 터미널에서 작업을 시작합니다.

**[n10s 라이브러리 설치 및 구성]**
```bash
# 1. Neo4j 플러그인 폴더로 이동합니다.
cd /var/lib/neo4j/plugins

# 2. n10s 공식 깃허브에서 호환되는 버전의 jar 파일을 다운로드합니다.
sudo wget [https://github.com/neo4j-labs/neosemantics/releases/download/5.1.0.1/neosemantics-5.1.0.1.jar](https://github.com/neo4j-labs/neosemantics/releases/download/5.1.0.1/neosemantics-5.1.0.1.jar)

# 3. neo4j.conf 파일을 열어 n10s의 동작을 서버에 승인합니다.
sudo nano /etc/neo4j/neo4j.conf

# 파일 끝부분의 보안 허용 리스트에 n10s.* 를 추가합니다. (기존 GDS 설정 뒤에 쉼표로 연결)
dbms.unrestricted_procedures=gds.*,n10s.*
dbms.security.procedures.allowlist=gds.*,n10s.*

# 4. Neo4j 재시작
sudo systemctl restart neo4j
```

## 4. 실전 적용 2단계: 시맨틱 환경 초기화와 데이터 임포트

이제 웹 브라우저(`http://서버IP:7474`)의 Cypher 입력창에서 웜홀을 열어 데이터를 빨아들일 차례입니다.

### 4.1. 그래프 환경 초기화 및 제약조건 생성
RDF를 받아들이기 전, 빈 캔버스에 "어떤 규칙으로 RDF를 해석할지" 선언해야 합니다. 또한, 동일한 인물(URI)이 두 번 생성되는 참사를 막기 위해 식별자 고유성(Unique Constraint)을 강제해야 합니다.

```cypher
// 1. 노드의 'uri' 속성을 절대 중복될 수 없는 고유 키값으로 지정합니다.
CREATE CONSTRAINT n10s_unique_uri FOR (r:Resource) REQUIRE r.uri IS UNIQUE;

// 2. n10s 초기화: 네임스페이스(Prefix)를 무시하고 깔끔한 이름만 남기도록 설정합니다.
CALL n10s.graphconfig.init({
  handleVocabUris: "IGNORE"
});
```

### 4.2. Turtle(.ttl) 파일 실시간 스트리밍 임포트
모든 준비가 끝났습니다. 20.4장에서 추출하여 리눅스 서버 특정 폴더에 올려둔 `modern_figures_lod_v1.ttl` 파일을 Neo4j로 단숨에 밀어 넣습니다.

```cypher
// 로컬 파일 시스템에 있는 거북이(.ttl) 파일을 파싱하여 그래프로 소환합니다.
CALL n10s.rdf.import.fetch(
  "file:///home/ubuntu/modern_figures_lod_v1.ttl", 
  "Turtle"
);

// 임포트가 잘 되었는지 시각적으로 확인합니다.
MATCH (n) RETURN n LIMIT 50;
```

단 한 번의 쿼리 실행으로, Protégé의 건조한 트리 구조에 갇혀 있던 조선시대 인맥망이 Neo4j의 화려한 방사형 그래프로 완벽하게 부활하는 마법을 목격하게 됩니다.

## 5. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 두통: "화살표 이름이 `ns0__hasOffice` 처럼 너무 지저분합니다!"**

만약 위 4.1. 과정에서 `handleVocabUris: "IGNORE"` 옵션을 주지 않고 초기화했다면, Neo4j 화면에 나타난 노드 라벨과 속성 이름들이 온통 URI의 잔해(Prefix)로 뒤덮이게 됩니다. (예: `http://aks.ac.kr/ontology/hasName` -> `ns0__hasName`)

**[승리하는 아키텍트의 네임스페이스 청소법]**
Neo4j는 어디까지나 우리 연구실의 **'분석용 실험대'**입니다. 연구자의 직관적인 시각화를 방해하는 긴 URI 꼬리표는 과감하게 잘라내는 것이 실무의 정석입니다. 반드시 `init()` 단계에서 `IGNORE` 옵션을 주어 인간이 읽을 수 있는 명칭(Local name)만 남기십시오. 원본 데이터의 엄밀함은 이미 21장의 Virtuoso 서버에 안전하게 보존되어 있으니 걱정할 필요가 없습니다.

**시맨틱 아키텍트의 비명: "데이터가 너무 커서 임포트 중간에 서버가 터집니다 (OOM)!"**

수백만 건의 트리플을 자랑하는 국사편찬위원회의 원천 데이터를 `n10s.rdf.import.fetch`로 한 번에 밀어 넣으면, Neo4j의 트랜잭션 메모리가 한계치를 초과하여 쿼리가 강제 종료됩니다.

**[승리하는 아키텍트의 청크(Chunk) 분할 적재법]**
초대형 데이터를 임포트할 때는 기계가 소화할 수 있도록 데이터를 쪼개어 먹여야 합니다. `init()` 설정 시 **`commitSize`** 파라미터를 추가하여, 1만 건 단위로 데이터를 디스크에 안전하게 새기고 메모리를 비우도록 지시하십시오.

```cypher
CALL n10s.graphconfig.init({
  handleVocabUris: "IGNORE",
  commitSize: 10000  // 10,000 트리플 단위로 트랜잭션을 끊어서 저장
});
```
이 튜닝 하나만으로 수억 건의 데이터도 메모리 터짐 없이 밤새도록 안정적으로 빨려 들어가는 쾌적한 파이프라인이 완성됩니다.

## 6. 요약 및 다음 단계

* **Neosemantics(n10s)**는 W3C 표준인 RDF 트리플 구조를 Neo4j의 속성 그래프 구조로 손실 없이 자동 변환해 주는 필수 브릿지 플러그인입니다.
* 성공적인 데이터 이관을 위해서는 사전에 **식별자 고유성 제약조건(Unique Constraint)**을 생성하고, 가독성을 위한 **네임스페이스 무시(`IGNORE`)** 초기화 작업이 선행되어야 합니다.
* 대용량 인문학 데이터를 임포트할 때는 서버 메모리 폭발(OOM)을 막기 위해 반드시 **`commitSize`** 옵션을 활용하여 트랜잭션을 분할 처리해야 합니다.

축하합니다! 이로써 여러분은 학계의 표준(Protégé, Virtuoso)과 산업계의 첨단 분석 엔진(Neo4j)을 자유자재로 오가며 데이터를 연동하는 인프라를 손에 쥐었습니다. 

하지만 실무 프로젝트를 진행하다 보면 곧장 거대한 벽에 부딪히게 됩니다. Virtuoso와 Neo4j는 완성된 데이터를 **"조회하고 연산하는 엔진"**일 뿐, 여러 연구자가 동시에 접속하여 데이터를 **"생성하고 수정하는 편집 도구"**가 아닙니다.
