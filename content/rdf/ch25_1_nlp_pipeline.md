# 25.1. 파이프라인 아키텍처: 고문헌 OCR ➔ NER ➔ RE

## 1. 도입: 스캔된 이미지 속에 갇혀버린 16세기의 인맥망

디지털 인문학의 궁극적인 꿈은 수백 년간 서고에 잠들어 있던 기록들을 깨워 거대한 지식의 거미줄로 엮어내는 것입니다. 하지만 우리가 박물관이나 규장각에서 건네받는 최초의 사료는 텍스트(Text)조차 아닙니다. 그것은 그저 한지가 스캔된 "**이미지(Image)**", 즉 빛의 명암이 기록된 픽셀의 덩어리일 뿐입니다.

운이 좋아서 누군가 그 이미지를 한글 텍스트로 타이핑해 두었다고 해도 고통은 끝나지 않습니다. 《조선왕조실록》에 기록된 수천만 자의 텍스트 속에서, "선조가 누구를 벌하고, 이순신이 누구와 서신을 교환했는지" 그 관계망을 발라내는 작업은 온전히 연구자의 몫입니다. 수십 명의 학자가 평생을 바쳐 텍스트에 형광펜을 칠하고 엑셀표로 옮겨 적는 이 지난한 작업은, 인문학적 상상력을 발휘할 시간을 앗아가는 거대한 노동의 감옥이었습니다.

이제 우리는 엑셀 칸을 채우는 수작업을 멈추고, 컴퓨터에게 "**글을 읽고 맥락을 이해하는 독해력**"을 가르쳐야 합니다. 스캔된 이미지 속에서 스스로 지식 그래프(RDF)를 뽑아내는 3단계 인공지능 파이프라인을 구축해 보겠습니다.

## 2. 해결책 제시: 딥러닝이 구동하는 "기계 사학자"의 3가지 감각 기관

컴퓨터 공학에서는 비정형 텍스트에서 정형화된 지식을 뽑아내는 이 일련의 과정을 "**정보 추출(Information Extraction)**" 파이프라인이라고 부릅니다. 이 파이프라인은 기계 사학자의 눈과 뇌 역할을 하는 세 가지 핵심 감각 기관으로 이루어져 있습니다.

인문학도의 책상 위에서 벌어지는 형광펜 칠하기 작업에 비유하여 설명해 보겠습니다.

| 추출 파이프라인 | 컴퓨터 공학적 개념 | 인문학적 비유와 작동 원리 |
| :--- | :--- | :--- |
| **1단계: 해독** | **OCR (광학 문자 인식)** | **"기계의 눈"**<br>먹물과 한지가 섞인 이미지 픽셀 덩어리를 분석하여, "이것은 '이' 자고, 저것은 '순' 자다"라고 판독하여 디지털 텍스트로 변환합니다. |
| **2단계: 식별** | **NER (개체명 인식)** | **"형광펜 칠하기"**<br>텍스트를 읽다가 고유명사가 등장하면 카테고리별로 색칠합니다. "이순신"에는 인물(Person) 형광펜을, "전라좌수사"에는 관직(Post) 형광펜을 칠합니다. |
| **3단계: 연결** | **RE (관계 추출)** | **"붉은 실로 연결하기"**<br>형광펜이 칠해진 단어들 사이에 위치한 동사("임명하였다")를 분석하여, 인물과 관직 사이에 "**core:hasPost**"라는 논리적 화살표(트리플)를 생성합니다. |

## 3. 실전 적용: 사료의 문장이 트리플로 변환되는 찰나의 순간

우리에게 《선조실록》의 한 구절이 스캔된 이미지로 주어졌다고 가정해 보겠습니다. 이 파이프라인이 코드를 통해 어떻게 작동하는지 파이썬(Python)의 논리 구조로 살펴보겠습니다.

**[1단계: OCR (텍스트 추출)]**
기계의 눈이 스캔 이미지를 읽고 문자열 변수(String)로 변환합니다.
> 원문 데이터: "선조가 이순신을 전라좌수사로 임명하였다."

**[2단계: NER (개체명 추출 모델 가동)]**
자연어 처리 모델이 문장을 단어 단위로 쪼개어 형광펜을 칠합니다.

```python
# 1. 딥러닝 기반의 자연어 처리 엔진(NER)이 텍스트를 읽어 들입니다.
text = "선조가 이순신을 전라좌수사로 임명하였다."
doc = nlp_model(text)

# 2. 기계가 찾아낸 고유명사(Entity)와 그 종류(Label)를 출력합니다.
for entity in doc.entities:
    print(f"단어: {entity.text} / 종류: {entity.label}")

# [출력 결과]
# 단어: 선조 / 종류: Person (인물)
# 단어: 이순신 / 종류: Person (인물)
# 단어: 전라좌수사 / 종류: Post (관직)
```

**[3단계: RE (관계 추출 및 트리플 연성)]**
이제 기계의 뇌(RE 모델)가 단어 사이의 동사 "임명하였다"를 분석하여 뼈대를 조립합니다.

```python
# 3. 관계 추출(RE) 엔진이 두 개체 사이의 논리적 서술어(Predicate)를 추론합니다.
# 인물(이순신)과 관직(전라좌수사) 사이에 '임명'이라는 맥락이 있으므로, 
# 온톨로지 규칙에 따라 "hasPost" 화살표를 생성합니다.

subject = "[http://dh.aks.ac.kr/joseon/person/이순신](http://dh.aks.ac.kr/joseon/person/이순신)"
predicate = "[http://dh.aks.ac.kr/ontology/core/hasPost](http://dh.aks.ac.kr/ontology/core/hasPost)"
object_node = "[http://dh.aks.ac.kr/joseon/post/전라좌수사](http://dh.aks.ac.kr/joseon/post/전라좌수사)"

# 4. 완벽한 지식 그래프(RDF) 생성!
print(f"<{subject}> <{predicate}> <{object_node}> .")
```

기계는 단 0.1초 만에 책을 읽고, 분석하고, 지식 그래프 서버(Virtuoso)에 꽂아 넣을 완벽한 거북이(`.ttl`) 텍스트를 연성해 냈습니다. 이 파이프라인을 10대의 서버에 물려 한 달을 돌리면, 수백 년 치의 실록 전체가 거대한 지식의 거미줄로 환생하게 됩니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 피눈물: "이순신이 아니라 이슌신으로 추출되었습니다!"**

이 파이프라인의 가장 무서운 점은 "**오류의 연쇄 폭발(Cascading Errors)**" 현상입니다.
가장 첫 단계인 **OCR(광학 문자 인식)**에서 한자나 옛 한글의 획을 잘못 읽어 "이순신"을 "이슌신"으로 판독했다고 가정해 봅시다. 
1. 문장이 오염됩니다 ("선조가 이슌신을...").
2. 2단계의 **NER** 모델은 처음 보는 "이슌신"이라는 단어를 사람 이름으로 인식하지 못하고 그냥 넘어갑니다(형광펜 누락).
3. 3단계의 **RE** 모델은 주어(Person)가 사라졌으니 화살표를 만들지 못하고 에러를 뿜으며 파이프라인 전체가 정지합니다.

앞단(OCR)의 작은 기침 하나가 뒷단(지식 그래프)에서는 치명적인 폐렴으로 번지는 것입니다.

**[승리하는 아키텍트의 파이프라인 방어술]**
실무에서 딥러닝 파이프라인을 설계할 때는, 각 단계 사이에 반드시 "**사전 기반 교정기(Dictionary-based Corrector)**"를 끼워 넣어야 합니다. 
한국학중앙연구원이나 국사편찬위원회에서 이미 확보해 둔 "조선시대 인명 사전 DB"를 파이프라인 중간에 주입하십시오. 기계가 "이슌신"이라고 읽어냈더라도, 다음 단계로 넘어가기 전에 사전을 검색하여 가장 발음/형태가 유사한 표준어인 "이순신"으로 강제 교정(Cleansing)한 뒤 NER 모델로 넘기는 우회로를 만들어야만 오류의 연쇄 폭발을 막을 수 있습니다.

## 5. 요약 및 다음 단계

* 엑셀 칸이 아닌 비정형 역사 원문에서 지식망을 복원하기 위해서는 인공지능 기반의 "**정보 추출 파이프라인**"이 절대적으로 필요합니다.
* 파이프라인은 문자를 판독하는 "**OCR**", 인물과 관직 등의 명사에 이름표를 붙이는 "**NER**", 그리고 그 맥락을 붉은 실로 잇는 "**RE**"의 3단계로 구성됩니다.
* 각 단계는 톱니바퀴처럼 맞물려 있으므로 앞단의 에러가 뒷단으로 전이되는 "**오류의 연쇄 폭발**"을 막기 위한 인문학적 사전(Dictionary) 방어막이 필수적입니다.

이제 우리는 기계에게 텍스트를 읽히고 표면적인 사실을 추출하는 법을 배웠습니다. 
하지만 역사 텍스트는 훨씬 더 교묘합니다. 어떤 문장에서는 "전라좌수사"라고 부르지만, 어떤 문장에서는 "수사(水使)"라고 줄여 부르거나 "통제사"라는 별칭으로 부릅니다. 기계는 이 단어들이 모두 같은 개념이라는 것을 어떻게 깨달을 수 있을까요?
