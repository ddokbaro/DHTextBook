# 21.1. 트리플 스토어의 개념과 서버(Linux) 환경 기반 설정

## 1. 도입: 마우스 클릭(GUI)의 세계에서 텍스트 명령(CLI)의 세계로

지금까지 우리는 친숙한 윈도우(Windows)나 맥(macOS) 운영체제 위에서, 마우스로 버튼을 누르고 폴더를 열며 Protégé를 다루었습니다. 화면에 모든 것이 직관적으로 보이는 이러한 환경을 **"GUI(Graphic User Interface)"**라고 부릅니다. 연구실 책상에 앉아 종묘배향공신의 데이터를 깎고 다듬는 개인 작업에는 이 GUI 환경이 최고입니다.

하지만 완성된 `modern_figures_lod_v1.ttl` 파일을 전 세계와 365일 24시간 끊김 없이 공유하려면, 우리 연구실의 PC 전원을 끄더라도 절대 꺼지지 않는 거대한 컴퓨터, 즉 **"서버(Server)"**가 필요합니다. 

현대 웹 생태계를 지탱하는 서버들의 90% 이상은 윈도우가 아닌 **"리눅스(Linux)"**, 그중에서도 **"우분투(Ubuntu)"**라는 운영체제를 사용합니다. 서버의 세계에는 마우스도, 예쁜 아이콘도 존재하지 않습니다. 오직 검은 바탕에 흰 글씨가 깜빡이는 터미널 창과 키보드 타이핑만으로 기계와 대화하는 **"CLI(Command Line Interface)"**의 세계가 펼쳐집니다. 

인문학도에게 이 검은 화면은 공포의 대상일 수 있습니다. 하지만 거대한 지식 그래프를 배포하는 아키텍트가 되기 위해서는 이 낯선 터미널 창에 접속하여, 지식의 성채(트리플 스토어)를 짓기 위한 튼튼한 콘크리트 바닥을 직접 다져야만 합니다.

## 2. 해결책 제시: 리눅스(Linux) 서버 기초 공사의 3대 요소

AWS(아마존 웹 서비스)나 연구원의 전산실에서 우분투 리눅스 서버를 한 대 할당받았다고 가정해 보겠습니다. 이 텅 빈 깡통 서버에 당장 Apache Jena나 Virtuoso 같은 트리플 스토어를 설치하려 들면 백발백중 에러가 터집니다. 

트리플 스토어라는 거대한 공장을 돌리기 위해서는 다음의 **"3대 기초 공사"**가 선행되어야 합니다.

| 기초 공사 단계 | 인문학적/실무적 비유 | 실행할 주요 리눅스 명령어 |
| :--- | :--- | :--- |
| **① 원격 접속과 패키지 갱신** | 텅 빈 창고의 문을 열고 들어가서, 낡은 공구함의 연장들을 최신 상태로 업그레이드합니다. | `ssh`, `sudo apt-get update` |
| **② 자바(Java) 가상머신 설치** | 트리플 스토어(특히 Apache Jena)라는 외국인 노동자가 일할 수 있도록 통역기를 설치합니다. | `sudo apt-get install openjdk-11-jdk` |
| **③ 방화벽(Firewall) 개방** | 전 세계의 SPARQL 질의가 들어올 수 있도록, 굳게 닫힌 창고의 특정 번호(Port) 문을 활짝 열어둡니다. | `sudo ufw allow 3030` |

이 세 가지 작업만 터미널 환경에서 무사히 마친다면, 트리플 스토어를 올리기 위한 완벽한 무균실 세팅이 끝납니다.

## 3. 실전 적용: Ubuntu 리눅스 서버 기반 설정 가이드

윈도우 PC에서 **"PuTTY"**라는 프로그램이나 맥의 **"터미널(Terminal)"**을 열고, 할당받은 서버의 IP 주소(예: `192.168.0.100`)로 원격 접속(`SSH`)을 시도합니다. 검은 화면에 로그인 프롬프트가 뜨면, 이제 텍스트 명령어로 기초 공사를 시작합니다.

**[작업 1: 최고 관리자 권한 획득과 시스템 업데이트]**
리눅스에서 시스템에 영향을 주는 모든 명령 앞에는 **"내가 최고 관리자(Superuser)다!"**라고 선언하는 `sudo`라는 마법의 단어를 붙여야 합니다.

```bash
# 1. 시스템의 패키지(프로그램) 목록을 최신 상태로 갱신합니다.
sudo apt-get update

# 2. 갱신된 목록을 바탕으로 설치된 프로그램들을 모두 최신 버전으로 업그레이드합니다.
sudo apt-get upgrade -y
```

**[작업 2: Apache Jena 구동을 위한 Java 설치]**
다음 장에서 배울 **Apache Jena Fuseki**는 Java 언어로 만들어진 프로그램이므로, 서버에 Java 실행 환경(JRE/JDK)이 없으면 아예 켜지지도 않습니다.

```bash
# 1. 안정적인 버전인 OpenJDK 11을 설치합니다.
sudo apt-get install openjdk-11-jdk -y

# 2. 설치가 완료되면, 자바 버전을 확인하여 정상적으로 깔렸는지 점검합니다.
java -version
```

**[작업 3: UFW(방화벽) 포트 개방]**
리눅스는 기본적으로 보안을 위해 외부에서 들어오는 모든 문(Port)을 꽉꽉 잠가두고 있습니다. Apache Jena Fuseki는 기본적으로 **"3030번"** 문을 사용하고, Virtuoso는 **"8890번"** 문을 사용합니다. 이 문을 열어주지 않으면, 서버 안에서 스토어가 돌아가고 있어도 밖에서는 절대 접속할 수 없습니다.

```bash
# 1. Jena Fuseki를 위한 3030번 포트를 개방합니다.
sudo ufw allow 3030

# 2. Virtuoso를 위한 8890번 포트도 미리 개방해 둡니다.
sudo ufw allow 8890

# 3. 방화벽 상태를 확인하여 문이 잘 열렸는지 점검합니다.
sudo ufw status
```

이 짧은 타이핑 몇 번으로, 여러분의 리눅스 서버는 거대한 지식 그래프를 품을 수 있는 완벽한 옥토(沃土)로 변모했습니다.

## 4. 실무 트러블슈팅 (Street-smart Tips)

**시맨틱 아키텍트의 절망 1: "교수님, 방화벽(UFW)을 열었는데도 웹 브라우저에서 접속이 안 됩니다!"**

클라우드 환경(AWS EC2, Oracle Cloud 등)을 처음 써보는 대학원생들이 100% 겪는 통곡의 벽입니다. 리눅스 터미널 안에서 `sudo ufw allow 3030`을 치고 성공 메시지를 보았는데도, 집에서 `http://서버IP:3030`으로 접속하면 **"사이트에 연결할 수 없음"**이라는 에러가 뜹니다.

**[승리하는 아키텍트의 2중 방화벽 해제법]**
클라우드 서버는 방어막이 두 겹입니다. 리눅스 운영체제 자체의 방화벽(UFW)이 안쪽 문이라면, AWS나 클라우드 인프라가 제공하는 **"보안 그룹(Security Group)"**이라는 거대한 바깥쪽 철문이 하나 더 있습니다. 
터미널 안에서 아무리 문을 열어도, AWS 웹 콘솔에 로그인하여 해당 인스턴스의 **"인바운드 규칙(Inbound Rules)"** 설정 메뉴에 들어가 **"사용자 지정 TCP, 포트 3030, 소스 0.0.0.0/0(모두 허용)"**을 추가해 주지 않으면 바깥 철문에 막혀 트래픽이 들어오지 못합니다. 반드시 **리눅스 UFW와 클라우드 보안 그룹 양쪽을 모두 열어주어야 합니다.**

**시맨틱 아키텍트의 절망 2: "퇴근하려고 검은 창을 껐더니, 서버도 같이 죽어버렸습니다!"**

트리플 스토어를 터미널에서 성공적으로 실행시키고, 기쁜 마음으로 터미널 프로그램(PuTTY)의 X 버튼을 눌러 창을 끄고 퇴근했습니다. 다음 날 출근해 보니 SPARQL 엔드포인트가 접속 불가 상태가 되어 있습니다. 

CLI 환경에서는 여러분이 실행한 프로그램이 **"현재 열려 있는 터미널 창(세션)"**에 종속되어 돌아갑니다. 창을 닫는 순간 리눅스는 **"아, 주인이 작업을 끝냈구나. 실행 중이던 트리플 스토어도 같이 꺼버리자!"**라고 판단하여 프로세스를 강제 종료(Kill)해 버립니다.

**[승리하는 아키텍트의 백그라운드 실행법]**
프로그램이 내가 퇴근한 뒤에도 24시간 백그라운드에서 돌아가게 만들려면, 명령어 맨 앞에 **`nohup`**(No Hangup: 끊지 마라)을 붙이고, 맨 뒤에 **`&`**(백그라운드 실행) 기호를 붙여야 합니다.
예시: `nohup ./fuseki-server &` 
이렇게 실행하고 터미널 창을 끄면, 리눅스는 여러분이 연결을 끊어도 트리플 스토어를 영원히 살려둡니다. 실무 운영 서버에서 반드시 기억해야 할 생존 기술입니다.

## 5. 요약 및 다음 단계

* 우리가 만든 지식 그래프(.ttl)를 전 세계가 질의할 수 있는 서비스로 배포하려면, GUI 환경의 로컬 PC를 벗어나 **"리눅스(Linux) 기반의 CLI 서버 환경"**을 구축해야 합니다.
* 서버 기초 공사를 위해 터미널에 원격 접속(SSH)하여 **"패키지 업데이트"**, 트리플 스토어 구동을 위한 **"Java 환경 설치"**, 외부 접속을 허용하는 **"방화벽(UFW 및 클라우드 보안그룹) 포트 개방"**을 완수해야 합니다.
* 리눅스 터미널 창을 닫아도 트리플 스토어가 죽지 않고 24시간 서비스되도록 하려면, 반드시 `nohup`과 `&`를 활용한 백그라운드 실행 기술을 숙지해야 합니다.

가장 두렵고 낯선 검은 화면(CLI)의 공포를 이겨내고, 튼튼한 콘크리트 바닥을 성공적으로 다졌습니다. 이제 이곳에 위대한 건축물을 세울 차례입니다.
