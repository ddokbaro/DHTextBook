# 4.3. 기계에게 지식을 써서 보내는 방법: RDF 직렬화(Serialization) 포맷 대관

## 1. 도입: 공중에 떠 있는 지식을 파일로 저장해야 할 때

우리는 앞선 장들을 통해 사물과 사물의 관계를 주어, 술어, 목적어(SPO)의 세 조각으로 해체하고, 이들에게 영원히 변하지 않는 고유한 이름표(`"**URI**"`)를 달아주는 법을 완벽하게 배웠습니다. 이제 여러분의 머릿속에는 조선시대 지식인들의 족보와 당쟁이 복잡하고 아름다운 3차원의 점과 선, 즉 `"**지식 그래프**"`로 둥둥 떠다니고 있을 것입니다.

그런데 여기서 아주 현실적이고 물리적인 공학적 문제에 부딪히게 됩니다. 

"이 허공에 떠 있는 아름다운 3차원의 거미줄(그래프)을, 도대체 어떤 파일 확장자로 저장해서 동료 연구자에게 이메일로 보내거나 서버 데이터베이스에 업로드해야 합니까?"

우리가 엑셀(RDB)을 버렸기 때문에 더 이상 `.xlsx`나 `.csv` 파일에 이 거미줄을 담을 수는 없습니다. 3차원으로 얽힌 점과 선의 네트워크를 컴퓨터 하드디스크에 저장하려면, 이 복잡한 구조를 위에서부터 아래로 한 줄씩 읽을 수 있는 평범한 1차원의 텍스트 문서로 납작하게 눌러 펴는 마법이 필요합니다.

## 2. 해결책 제시: 직렬화(Serialization), 그래프를 한 줄의 텍스트로 펴다

컴퓨터 공학에서는 이처럼 복잡하게 얽힌 메모리상의 데이터 구조를 파일이나 네트워크 전송을 위해 한 줄의 순차적인 텍스트(문자열)로 길게 늘어뜨려 변환하는 과정을 `"**직렬화(Serialization)**"`라고 부릅니다. 

시맨틱 웹의 세계에서도 우리가 만든 세 조각의 레고 블록(트리플)을 텍스트 파일로 저장하기 위한 여러 가지 `"**직렬화 문법(Serialization Formats)**"`이 존재합니다. 지식의 내용(SPO)은 완전히 똑같지만, 그것을 포장하는 박스의 모양만 달라지는 것입니다. 

가장 대표적으로 학계와 산업계에서 사용하는 4대 직렬화 포맷은 다음과 같습니다.
1. **N-Triples (.nt):** 시맨틱 웹의 쌩얼(민낯). 기계가 읽기 가장 좋은 가장 순수한 형태의 원시 포맷
2. **Turtle (.ttl):** 인문학 연구자와 온톨로지 엔지니어들이 가장 사랑하는 직관적인 압축 포맷
3. **JSON-LD (.jsonld):** 현대 웹 개발자들이 열광하며, 구글(Google) 검색 엔진이 가장 사랑하는 최신 포맷
4. **RDF/XML (.rdf):** 가장 오래된 전통의 강자이나, 인간이 읽기에는 끔찍한 구시대의 유산

이 네 가지 포맷이 동일한 역사적 사실을 어떻게 다르게 표현하는지 직접 눈으로 확인해 보겠습니다.

## 3. 실전 적용: 4대 직렬화 포맷 대격돌

우리가 표현할 역사적 사실은 단 하나입니다. 
**"이이(P00123)의 이름(label)은 율곡이다."**

### 1. 지식의 기초 해부학: N-Triples (`.nt`)
N-Triples는 어떠한 기교나 압축도 허용하지 않는 가장 정직한 포맷입니다. 오직 `<주어URI> <술어URI> <목적어URI> .` 이라는 완벽한 3단 구조만을 강제합니다. 컴퓨터가 파싱(Parsing)하기에는 세상에서 가장 완벽하지만, 인간이 손으로 치기에는 너무나도 가혹합니다.

```ntriples
# 띄어쓰기와 마침표로만 구분되는 가장 순수하고 잔혹한(?) 형태
[http://조선.kr/person/P00123](http://조선.kr/person/P00123) [http://www.w3.org/2000/01/rdf-schema#label](http://www.w3.org/2000/01/rdf-schema#label) "율곡" .
```

### 2. 연구자들의 가장 친한 친구: Turtle (`.ttl`)
위의 N-Triples를 보며 여러분은 "저렇게 긴 주소를 매번 다 손으로 쳐야 합니까?"라며 경악하셨을 것입니다. 그래서 나온 포맷이 바로 터틀(Turtle)입니다. `"**접두사(Prefix)**"`라는 치트키를 사용하여, 길고 지루한 `http://조선.kr/person/` 이라는 공통 주소를 `조선:` 이라는 단 두 글자로 극단적으로 압축해 줍니다. 인문학자가 직접 데이터를 구축할 때 압도적인 효율성을 자랑합니다.

```turtle
# N-Triples의 무식함을 접두사(Prefix)로 우아하게 압축한 형태
@prefix 조선: [http://조선.kr/person/](http://조선.kr/person/) .
@prefix rdfs: [http://www.w3.org/2000/01/rdf-schema#](http://www.w3.org/2000/01/rdf-schema#) .

조선:P00123 rdfs:label "율곡" .
```

### 3. 웹 개발자와 구글의 총아: JSON-LD (`.jsonld`)
현대의 IT 산업계는 무겁고 오래된 XML을 버리고, 가볍고 빠른 `"**JSON**"` 포맷으로 통일되었습니다. JSON-LD는 일반적인 JSON 데이터 구조 안에 `@context`라는 시맨틱 의미 부여 마법을 걸어, 일반 웹 데이터를 순식간에 링크드 오픈 데이터(LOD)로 변신시키는 현대의 가장 강력한 무기입니다.

```json
{
  "@context": {
    "이름": "[http://www.w3.org/2000/01/rdf-schema#label](http://www.w3.org/2000/01/rdf-schema#label)"
  },
  "@id": "[http://조선.kr/person/P00123](http://조선.kr/person/P00123)",
  "이름": "율곡"
}
```

### 4. 끔찍한 과거의 유산: RDF/XML (`.rdf`)
초창기 학자들은 당시 유행하던 범용 마크업 언어인 XML을 사용했습니다. 하지만 꺾쇠 `< >` 태그가 너무 많아서 코드가 뚱뚱해지고, 인간의 눈으로 읽고 수정하기가 거의 불가능에 가깝습니다. 지금은 구형 시스템과 통신할 때만 억지로 씁니다.

```xml
<rdf:RDF xmlns:rdf="[http://www.w3.org/1999/02/22-rdf-syntax-ns#](http://www.w3.org/1999/02/22-rdf-syntax-ns#)"
         xmlns:rdfs="[http://www.w3.org/2000/01/rdf-schema#](http://www.w3.org/2000/01/rdf-schema#)">
  <rdf:Description rdf:about="[http://조선.kr/person/P00123](http://조선.kr/person/P00123)">
    <rdfs:label>율곡</rdfs:label>
  </rdf:Description>
</rdf:RDF>
```

| 직렬화 포맷 | 확장자 | 인간의 가독성 | 주요 사용처 및 특징 |
| :--- | :--- | :--- | :--- |
| **N-Triples** | `.nt` | 하 (너무 장황함) | 기계적인 대용량 데이터 덤프(Dump) 및 시스템 간 초고속 전송 |
| **Turtle** | `.ttl` | 최상 (매우 직관적) | 연구자가 직접 온톨로지를 설계하고 데이터를 검수, 편집할 때 |
| **JSON-LD** | `.jsonld` | 상 (구조적임) | 웹 개발자에게 데이터를 넘겨주거나 API를 개발할 때 |
| **RDF/XML** | `.rdf` | 최하 (매우 끔찍함) | 과거의 낡은 레거시 시스템과 통신할 때만 억지로 사용함 |

## 4. 실무 트러블슈팅 (Street-smart Tips)

디지털 인문학 프로젝트를 진행하며 웹사이트를 구축할 때, 인문학 연구팀과 외주 IT 개발팀 사이에 100% 확률로 엄청난 싸움이 벌어지는 지점이 있습니다.

인문학 연구팀은 배운 대로 자랑스럽게 `"**Turtle(.ttl)**"` 파일로 조선시대 인물망 데이터를 수십만 건 만들어서 개발자에게 넘깁니다. 그러면 일반적인 웹 개발자들은 코드를 열어보고 비명을 지릅니다. "교수님! 이 띄어쓰기와 마침표로 범벅된 해괴한 텍스트 파일은 도대체 뭡니까? 저희는 이런 데이터를 웹사이트에 연동할 줄 모릅니다!" 

이때 여러분이 "이 무식한 개발자야, 이것이 시맨틱 웹의 표준 Turtle이다!"라고 화를 내시면 프로젝트는 파국으로 치닫습니다. 

일반적인 IT 개발자들은 `"**JSON**"`이라는 언어밖에 모릅니다. 따라서 지식 그래프를 다루는 시맨틱 아키텍트는 철저한 `"**이중화 전략**"`을 취해야 합니다. 
우리 연구실 내부에서 데이터를 정제하고 뼈대를 잡을 때는 직관적인 `"**Turtle(.ttl)**"`을 사용합니다. 하지만 이 데이터를 최종적으로 웹 서비스로 내보내거나 개발자에게 전달할 때는, 파이썬이나 포맷 변환 도구를 통해 버튼 한 번 눌러서 반드시 `"**JSON-LD**"` 포맷으로 직렬화하여 넘겨주십시오. 

이 작은 포맷 변환 하나가 개발자들의 야근을 막아주고, 여러분의 인문학 데이터가 구글 검색 엔진 최상단에 노출되도록 만들어 주는 궁극의 실무 비급입니다.

## 5. 요약 및 다음 단계

* 공중에 떠 있는 3차원의 지식 그래프를 파일로 저장하기 위해 1차원의 텍스트로 변환하는 과정을 `"**직렬화(Serialization)**"`라고 합니다.
* 3단 구조의 원리를 가장 정직하게 보여주는 기초 모델은 `"**N-Triples(.nt)**"`이지만, 연구자가 직접 눈으로 읽고 편집할 때는 압축률이 좋은 `"**Turtle(.ttl)**"` 포맷이 절대적으로 유리합니다.
* 완성된 지식 데이터를 현대 웹 생태계에 배포하거나 IT 개발자와 협업할 때는 반드시 `"**JSON-LD**"` 포맷으로 변환해야 합니다.

자, 이제 우리는 기계가 오해하지 않도록 무의미 식별자(ID)를 부여하는 법도 배웠고, 그 내용을 어떤 텍스트 포맷으로 예쁘게 저장하여 개발자에게 넘겨주어야 하는지도 모두 통달했습니다.

그렇다면 이제 진짜 본격적인 데이터 작성으로 들어가 보겠습니다. 앞선 코드에서 보았던 "이름이 무엇이다(`rdfs:label`)"와 같은 이 복잡한 술어(Predicate)의 뼈대들을 우리 연구실에서 밑바닥부터 다 새로 발명해야 할까요?

전혀 그렇지 않습니다! 다음 챕터인 **[4.4. 지식의 재사용: 국제 표준 온톨로지(RDFS, SKOS, FOAF) 활용법]**에서는, 전 세계의 천재들이 이미 만들어 놓은 레고 블록의 도면들을 공짜로 빌려와서 우리의 조선시대 데이터를 순식간에 글로벌 규격으로 조립하는 놀라운 방법을 전수해 드리겠습니다.
