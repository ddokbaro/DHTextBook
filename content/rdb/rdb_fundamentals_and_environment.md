# RDB 개론과 다기종 실습 환경 구축: 서버리스부터 클라우드까지

앞서 우리는 구글 스프레드시트 환경에서 시트를 분리하고 함수로 연결해 보는 '사전 정규화'를 통해, 평면적 데이터가 관계형 모델로 진화할 때 발휘되는 압도적인 위력을 체감했습니다. 이제 VLOOKUP 함수의 한계를 넘어, 수백만 건의 역사 데이터를 0.01초 만에 결합하고 통제하는 진정한 `"**관계형 데이터베이스 관리 시스템(RDBMS)**"`의 세계로 진입할 차례입니다.

과거 데이터베이스 교육의 가장 큰 진입 장벽은 무거운 온프레미스 서버를 세팅하거나 복잡한 로컬 설치 과정에서 발생하는 수많은 에러(데몬 충돌, 환경 변수 꼬임 등)였습니다. 정작 SQL 논리는 배워보지도 못한 채 설치 과정에서 지쳐 포기하는 인문학도들이 부지기수였습니다. 
이 장에서는 이러한 인프라의 고통을 완벽히 제거하고, 학생의 수준과 목적에 맞춰 즉각적으로 실습할 수 있는 `"**현대적 RDB 교육 환경의 4단계 진화 모델**"`을 심층 분석합니다.

---

## 1. 1단계: 웹 기반 샌드박스 (설치 제로의 즉각적 SQL 실습)

데이터베이스 개론 수업이나 순수하게 SQL 질의어 문법 자체에 집중하고 싶을 때, 로컬 설치를 완전히 배제하는 웹 샌드박스(Web Sandbox)는 최적의 솔루션입니다.

* **DB Fiddle (db-fiddle.com):** MySQL 8.x, PostgreSQL 등 최신 엔진을 브라우저상에서 즉시 컴파일해 줍니다. 
* **교육적 활용 (LMS 연동):** 교수자는 이 샌드박스의 출력 결과를 `<iframe>` 태그를 이용해 강의 노트에 직접 임베딩할 수 있습니다. 
* **⚠️ 치명적 주의사항 (환경의 휘발성):** 샌드박스는 임시 스토리지를 사용하므로 새로고침을 하면 작성한 쿼리가 모두 소멸됩니다. 반드시 `"**저장(Save)**"` 버튼을 눌러 고유 URL을 해시로 기록하는 습관을 들여야 합니다. 또한, 무료 계정의 코드는 공개되므로 미발표 학술 데이터나 민감한 개인정보를 올리는 것은 엄격히 금지됩니다.

## 2. 2단계: 파일 기반 데이터베이스 (SQLite와 DB Browser)

웹 샌드박스는 편리하지만 데이터의 물리적 저장성(Persistence)을 배울 수 없습니다. 거대한 백그라운드 서비스(데몬)를 구동하는 오버헤드 없이 데이터 저장의 원리를 가르치기 위해 우리는 `"**SQLite**"`로 전환합니다.

### 2.1 서버리스(Serverless)와 제로 구성의 미학
SQLite는 네트워크 포트를 열고 대기하는 데몬이 없습니다. 데이터베이스 전체 구조(테이블, 인덱스 등)가 컴퓨터 내의 `"**단일 크로스 플랫폼 파일(.db 또는 .sqlite)**"` 하나에 모두 담깁니다. USB에 담아 교수에게 제출하거나 GitHub에 커밋하는 것이 일반 텍스트 파일처럼 쉽습니다.

### 2.2 DB Browser for SQLite (DB4S) 시각화 도구
SQL 명령어 창이 낯선 학생들을 위해 `"**DB Browser for SQLite**"`라는 오픈소스 GUI 도구를 결합합니다.
학생들은 이 도구의 마법사를 통해 클릭 몇 번으로 테이블을 생성(DDL)할 수 있습니다. 가장 위대한 교육적 효과는, 시각적으로 테이블을 설계한 후 하단의 로그 패널을 통해 도구가 백그라운드에서 어떤 `CREATE TABLE` 구문을 생성했는지 확인하고 `"**역공학(Reverse-engineering)**"`을 통해 SQL 구조를 자연스럽게 체득하게 된다는 점입니다.

* **⚠️ 치명적 주의사항 (동적 타이핑의 유연함):** 일반적인 MySQL은 정수형(Integer) 컬럼에 텍스트를 넣으면 에러를 뱉지만, SQLite는 이를 종종 유연하게 수용해버립니다(Dynamic Typing). 이 유연함에 길들면 향후 엄격한 엔터프라이즈 환경으로 넘어갔을 때 치명적 오류를 겪게 되므로, 데이터 제약 조건에 대한 명시적 교육이 동반되어야 합니다.

## 3. 3단계: 로컬 경량화 스택 (클라이언트-서버 데몬의 이해)

파일 기반 DB를 마스터했다면, 이제 실제 엔터프라이즈 환경과 동일한 클라이언트-서버 데몬 아키텍처를 로컬 컴퓨터에 구성해야 합니다. 과거에는 Bitnami 인스톨러가 학계의 표준이었으나, 2025/2026년을 기점으로 완전 유료화(Bitnami Secure) 정책으로 변경됨에 따라 우리는 커뮤니티 주도의 `"**XAMPP(Windows)**"`와 `"**MAMP(macOS)**"`로 완전히 회귀합니다.

### 3.1 5분 만에 끝나는 XAMPP 로컬 서버 구축 (Windows)
1. **설치:** Apache Friends에서 XAMPP를 다운로드하여 `C:\xampp` 경로에 설치합니다 (권한 오류 방지를 위해 Program Files 경로는 피합니다).
2. **데몬 구동:** XAMPP 제어판에서 MySQL(MariaDB) 모듈의 `Start` 버튼을 누릅니다. 
3. **트러블슈팅 (포트 충돌):** 만약 `3306` 포트가 기존에 설치된 다른 DB에 의해 점유되어 데몬이 즉시 종료(Crash)된다면, 제어판의 `xampp-portcheck.exe`를 사용하여 네트워크 충돌을 확인하고 포트 번호를 `3307` 등으로 우회해야 합니다.
4. **접속:** 데몬이 켜지면 `Admin` 버튼을 눌러 웹 기반 GUI인 `phpMyAdmin`으로 즉시 접속하여 실습을 시작합니다.

## 4. 4단계: 퍼블릭 클라우드 데이터베이스와 프리 티어의 함정

커리큘럼의 후반부, 혹은 졸업 포트폴리오를 위해 학생들은 결국 로컬을 벗어나 글로벌 클라우드 제공자(Hyperscaler)의 RDB 인스턴스를 구축해야 합니다. 그러나 "무료"라는 말 뒤에는 치명적인 과금 폭탄의 함정이 도사리고 있습니다.

* **AWS RDS:** 12개월간 매월 750시간을 무료로 제공합니다. 그러나 최근 도입된 고성능 `gp3` 스토리지는 **무료 티어 대상이 아닙니다**. 생성 마법사에서 반드시 스토리지 유형을 `"**gp2**"`로 수동 전환해야 과금을 피할 수 있습니다.
* **GCP Cloud SQL:** 30일 단기 트라이얼만 제공하므로, 학기 내내 쓰려면 교수가 Google Education Grants 바우처를 신청하여 배포해야 합니다.
* **Azure SQL Database:** 매월 10만 vCore 초를 평생 제공합니다. 한도 도달 시 서버가 `"**자동 일시중지(Auto-pause)**"`되어 과금을 완벽히 방어하므로 학생용으로 최적입니다.
* **Oracle Autonomous Database:** 평생 2개의 인스턴스를 주지만, `"**7일 연속 접속이 없으면 중지되고 90일 후 영구 삭제**"`되는 끔찍한 리소스 회수 정책이 있습니다. 주기적으로 접속하여 타이머를 초기화해야만 공든 탑이 무너지지 않습니다.

## 5. 최종 완성: 범용 클라이언트 도구(DBeaver)와 보안 통제 ★

이기종(MSSQL, MySQL, SQLite, Cloud DB 등) 폴리글랏 시대에 데이터베이스마다 전용 관리 도구(SSMS, Workbench 등)를 설치하는 것은 비효율의 극치입니다. 

우리는 JDBC(Java Database Connectivity) 기반으로 전 세계 100여 개의 DB에 모두 연결할 수 있는 완벽한 범용 오픈소스 클라이언트, `"**DBeaver**"`를 교육 표준으로 채택합니다. (저사양 윈도우 PC의 경우 극도로 가벼운 네이티브 앱인 `"**HeidiSQL**"`을 병행합니다.)

### 5.1 운영 사고 방지를 위한 거버넌스 세팅 (Connection Type)
DBeaver가 실무에서 강력한 이유는 완벽한 환경 통제 기능 때문입니다. 
클라우드에 있는 운영 데이터베이스에 연결할 때 속성을 `"**Production**"`으로 지정해 보십시오. DBeaver의 창 전체가 붉은색으로 물들며 경각심을 줍니다. 나아가 `Confirm SQL execution` 기능을 활성화하면, `DELETE`나 `UPDATE` 같은 치명적 데이터 변형 쿼리를 실행할 때 반드시 확인 팝업을 띄우게 하여 인문학자들의 치명적인 오작동을 원천 봉쇄해 줍니다.

---

RDB의 역사부터 서버리스, 로컬 스택, 클라우드를 거쳐 범용 클라이언트 연결까지 완벽한 환경 세팅이 끝났습니다. 이제 도구의 칼날을 세웠으니, 다음 장에서는 우리가 가진 인문학 원시 데이터(플랫 파일, CSV)를 이 데이터베이스 엔진 내부로 어떻게 밀어 넣는지, 그리고 그 과정에서 겪게 될 **'인코딩(UTF-8 BOM)'의 끔찍한 에러들을 어떻게 트러블슈팅**하는지 실무 파이프라인으로 진입하겠습니다.
