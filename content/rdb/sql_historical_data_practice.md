# 한국학 데이터 추출 실습: 패턴 매칭(LIKE)과 문자열 함수 활용

지금까지 우리는 엑셀의 플랫 데이터를 논리적으로 분해하여(정규화), 데이터베이스라는 엄격한 창고에 안전하게 적재(임포트)했습니다. 데이터베이스의 뼈대를 세우고 데이터를 밀어 넣는 고된 엔지니어링 작업이 끝났으니, 이제 이 지식의 창고에서 우리가 원하는 역사적 진실을 캐낼 차례입니다.

이 장에서는 SQL의 꽃이라 불리는 `"**SELECT (조회)**"` 명령어와 `"**WHERE (조건)**"` 절을 무기로 삼아, 수만 건의 조선시대 인물 사료 속에서 특정 가문을 추적하고, 텍스트의 패턴을 매칭하며, 결측치(미상)를 다루는 본격적인 인문학 데이터 마이닝을 시작합니다.

## 1. 텍스트 검색의 마법: 패턴 매칭 연산자 `LIKE`

인문학 데이터는 텍스트가 주를 이룹니다. "본관이 덕수 이씨인 사람"처럼 정확히 일치하는 값(`=`)을 찾는 것은 쉽지만, "이름이 '순'으로 시작하는 사람"이나 "역임 관직 중에 '수사(水使)'라는 단어가 포함된 사람"을 찾으려면 어떻게 해야 할까요? 

이때 사용하는 것이 바로 텍스트의 일부만으로도 데이터를 낚아채는 `"**LIKE 연산자**"`와 `"**와일드카드(Wildcard)**"` 기호입니다.



### 1.1 `%` (퍼센트): "무엇이든, 몇 글자든 상관없다"
`%` 기호는 0개 이상의 모든 문자를 대체하는 만능열쇠입니다. 디지털 인문학 텍스트 검색에서 가장 압도적인 빈도로 사용됩니다.

* **전방 일치 (Prefix Match):** 성씨가 '이'씨인 모든 인물 찾기
  ```sql
  SELECT 인물ID, 이름, 생몰년 
  FROM person_tb 
  WHERE 이름 LIKE '이%';
  ```
  *(결과: 이순신, 이이, 이항복 등이 모두 검색됩니다. '이' 뒤에 몇 글자가 오든 상관하지 않습니다.)*

* **부분 일치 (Substring Match):** 본관 데이터에 '안동'이라는 지명이 포함된 모든 가문 찾기
  ```sql
  SELECT 본관ID, 본관성씨 
  FROM clan_tb 
  WHERE 본관성씨 LIKE '%안동%';
  ```
  *(결과: '안동권씨', '신안동김씨', '구안동김씨' 등 앞뒤로 어떤 글자가 있든 '안동'이 포함되면 모두 추출됩니다.)*

### 1.2 `_` (언더바): "정확히 한 글자만 비워둔다"
`%`가 무한한 길이를 허용한다면, `_` 기호는 `"**정확히 한 글자(1 Character)**"`만을 대체합니다. 사료의 형태가 정형화되어 있을 때 매우 강력합니다.

* **특정 글자수 강제:** 이름이 외자(1글자)인 '이'씨 성의 인물 찾기 (예: 이황, 이이)
  ```sql
  SELECT 인물ID, 이름 
  FROM person_tb 
  WHERE 이름 LIKE '이_';
  ```
  *(결과: '이이', '이황'은 검색되지만, 두 글자인 '이순신'은 `_` 한 칸의 규칙을 어겼으므로 검색되지 않습니다.)*

## 2. 사료 텍스트의 가공: 문자열 함수 (String Functions)

데이터베이스에 저장된 텍스트가 항상 연구자가 원하는 형태로 예쁘게 잘려 있지는 않습니다. 이때 우리는 SQL이 제공하는 문자열 함수를 사용하여 쿼리 결과창에서 텍스트를 즉각적으로 자르고, 붙이고, 변형할 수 있습니다. 

### 2.1 문자열 추출: `SUBSTRING()`
조선시대 인물 데이터에서 '이름' 컬럼의 맨 앞 한 글자(성씨)만 따로 분리해서 통계를 내고 싶을 때 사용합니다.

```sql
-- 이름 컬럼의 1번째 글자부터 딱 1글자만 잘라내어 '성씨'라는 임시 이름표(Alias)를 붙임
SELECT 
    이름, 
    SUBSTRING(이름, 1, 1) AS 성씨 
FROM person_tb;
```
*(참고: SQLite나 Oracle에서는 `SUBSTR()`로 줄여 쓰기도 하는 방언의 차이가 존재합니다.)*

### 2.2 텍스트의 치환: `REPLACE()`
과거에 입력된 사료 데이터 중, 행정구역 개편이나 학계의 표기법 통일로 인해 특정 단어를 일괄적으로 바꾸어 출력해야 할 때 사용합니다. 원본 데이터를 물리적으로 훼손(`UPDATE`)하지 않고, 화면에 보여줄 때만 화장(Makeup)을 고치는 안전한 방법입니다.

```sql
-- 출력 시 '한성부'라는 텍스트를 발견하면 모두 '서울'로 바꾸어 출력하라
SELECT 
    인물ID, 
    REPLACE(출신지, '한성부', '서울') AS 현대_출신지 
FROM person_tb;
```

### 2.3 문자열의 길이 계산: `LENGTH()` / `CHAR_LENGTH()`
입력된 사료의 품질을 검증(Data Cleansing)할 때 유용합니다. 예를 들어, 인물 이름은 보통 2~4글자여야 하는데, 데이터 입력 보조원의 실수로 이름 칸에 긴 설명이 들어가 버린 오류 데이터를 찾아낼 수 있습니다.

```sql
-- 이름의 길이가 5글자를 초과하는 비정상적인 데이터만 색출
SELECT 인물ID, 이름 
FROM person_tb 
WHERE CHAR_LENGTH(이름) > 5;
```

## 3. 침묵의 텍스트, '미상(Unknown)'을 다루는 법: `IS NULL`

인문학 데이터베이스에서 가장 철학적인 개념은 바로 `"**NULL**"`입니다. 숫자 0도 아니고, 공백 텍스트(`''`)도 아닙니다. NULL은 **"아직 알려지지 않았거나, 존재하지 않는다(미상)"**는 완벽한 무(無)의 상태를 의미합니다.

초보 연구자들은 생년월일이 없는 인물을 찾기 위해 다음과 같은 치명적인 실수를 범합니다.
```sql
-- [에러가 나지는 않지만 0건이 검색되는 논리적 오류]
SELECT * FROM person_tb WHERE 생년 = NULL;
```
NULL은 값이 아니므로 등호(`=`) 연산자로 비교할 수 없습니다. "알 수 없음은 알 수 없음과 같다"라는 철학적 명제가 컴퓨터 세계에서는 거짓(False)으로 처리되기 때문입니다. 따라서 미상의 데이터를 추적할 때는 반드시 전용 연산자인 `"**IS NULL**"`을 사용해야 합니다.

```sql
-- 생년 기록이 소실된(NULL인) 인물만 추출
SELECT 이름, 본관 
FROM person_tb 
WHERE 생년 IS NULL;

-- 반대로 생년 기록이 명확히 존재하는 인물만 추출
SELECT 이름, 생년 
FROM person_tb 
WHERE 생년 IS NOT NULL;
```

## 4. 요약

* `"**LIKE '%패턴%'**"`: 텍스트의 위치에 상관없이 원하는 단어가 포함된 사료를 낚아채는 가장 강력한 투망입니다.
* `"**문자열 함수(SUBSTRING, REPLACE)**"`: 원본 데이터를 건드리지 않고, 출력 창에서 텍스트를 예쁘게 재단하는 가위와 풀입니다.
* `"**IS NULL**"`: 사료의 멸실과 역사적 미상을 컴퓨터의 언어로 필터링하는 절대 규칙입니다.

하나의 테이블에서 텍스트를 지지고 볶는 훈련을 마쳤습니다. 그러나 진정한 인문학 지식베이스의 위력은 흩어져 있는 테이블들을 논리적으로 다시 결합할 때 발휘됩니다.
