# CSV/TXT 데이터 임포트 실무와 인코딩(UTF-8 BOM) 트러블슈팅

공들여 설계한 빈 테이블에 생명력을 불어넣을 시간입니다. 우리는 앞서 정제한 엑셀 데이터를 CSV(쉼표 분리)나 TSV(탭 분리) 형태의 플랫 파일로 저장한 뒤, DBeaver나 HeidiSQL의 `"**데이터 임포트(Import) 마법사**"`를 통해 RDB로 쏟아붓게 됩니다.

그러나 이 적재(Load) 과정은 결코 버튼 한 번으로 끝나지 않습니다. 윈도우(Windows) 운영체제와 한글 엑셀이 만들어내는 환장의 콜라보레이션은, 멀쩡하던 인문학 사료를 기괴한 외계어로 둔갑시키거나 알 수 없는 에러를 뿜어내며 여러분의 영혼을 파괴할 것입니다. 이 장에서는 임포트 실무의 기본과 함께, 가장 악명 높은 `"**인코딩(Encoding) 및 BOM 트러블슈팅**"`을 완벽하게 마스터합니다.

## 1. DBeaver를 활용한 데이터 임포트 기본 워크플로우

DBeaver에서 CSV 데이터를 테이블에 밀어 넣는 표준 절차는 다음과 같습니다.

1. **대상 테이블 준비:** 대상이 되는 빈 테이블을 우클릭하고 `데이터 가져오기(Import Data)`를 선택합니다.
2. **소스 포맷 선택:** `CSV`를 선택하고 준비된 원시 데이터 파일을 불러옵니다.
3. **컬럼 매핑(Mapping) ★:** 가장 중요한 단계입니다. CSV 파일의 첫 번째 줄(헤더)에 있는 이름과 데이터베이스 테이블의 컬럼명이 정확히 1:1로 일치하는지 확인해야 합니다. 만약 CSV에는 '생몰년'으로 되어 있는데 DB에는 'birth_year'로 되어 있다면, 마법사 화면에서 수동으로 짝을 지어주어야 합니다.
4. **실행 및 롤백(Rollback):** `Start`를 누르면 적재가 시작됩니다. 만약 단 하나의 행(Row)이라도 데이터 타입이 맞지 않으면(예: 정수형 컬럼에 텍스트 유입), DBeaver는 즉시 에러를 띄우고 지금까지 들어간 데이터를 모두 취소(`"**롤백, Rollback**"`)하여 데이터의 무결성을 지켜줍니다.

## 2. 첫 번째 절망: 한글 깨짐과 인코딩(Encoding)의 충돌

임포트를 마친 후 테이블을 조회했을 때, '이순신'이 'ÀÌ¼ø½Å'이나 '' 같은 정체불명의 기호로 깨져 있다면 `"**인코딩(Encoding) 충돌**"`이 발생한 것입니다.



컴퓨터는 문자를 저장할 때 숫자로 변환하여 저장하며, 이 변환 규칙을 인코딩이라고 합니다. 
* **EUC-KR (또는 CP949):** 과거 윈도우와 한글 엑셀이 기본적으로 사용하던 구형 한국어 전용 규격입니다.
* **UTF-8:** 전 세계의 모든 언어와 고어(古語), 심지어 이모지(Emoji)까지 완벽하게 호환하는 `"**현대 데이터베이스의 글로벌 절대 표준**"`입니다.

**[해결책]** 디지털 인문학 데이터베이스의 인코딩 셋(Charset)은 무조건 `"**UTF-8 (또는 utf8mb4)**"`이어야 합니다. 한글이 깨졌다면, 엑셀에서 파일을 저장할 때 그냥 `CSV (쉼표로 분리)`를 누른 것입니다. 반드시 `다른 이름으로 저장`에서 `"**CSV UTF-8 (쉼표로 분리)**"` 옵션을 선택하여 저장한 후 다시 임포트해야 합니다.

## 3. 숨어있는 암살자: 윈도우 메모장의 BOM (Byte Order Mark)

"분명히 엑셀에서 UTF-8로 저장했는데도 에러가 납니다!"
가장 많은 인문학도가 여기서 데이터베이스 학습을 포기합니다. 에러 로그를 자세히 살펴보면, 데이터 전체가 아니라 `"**첫 번째 컬럼의 이름(Header)**"`을 인식하지 못한다는 기괴한 메시지가 출력됩니다.

> `Error: Column 'ï»¿person_id' does not exist in target table.`

분명 내 CSV 파일의 첫 번째 글자는 `person_id`인데, 기계는 앞에 `ï»¿`라는 보이지 않는 유령 문자가 붙어 있다고 우깁니다. 이 유령의 정체가 바로 `"**BOM (Byte Order Mark)**"`입니다.

### 3.1 BOM의 정체
마이크로소프트(Windows) 프로그램들(엑셀, 메모장)은 텍스트 파일을 UTF-8로 저장할 때, "이 파일은 UTF-8 형식입니다"라는 것을 운영체제에 몰래 알려주기 위해 파일의 맨 앞단에 눈에 보이지 않는 3바이트의 특수 기호(`EF BB BF`)를 몰래 삽입합니다. 

문제는 RDBMS(MySQL, SQLite 등)와 클라이언트 도구들은 이 친절한(?) 윈도우의 서명을 이해하지 못하고, 이를 첫 번째 컬럼 이름의 일부로 오독(Misread)해 버린다는 것입니다. 그 결과 컬럼 매핑이 완전히 어긋나며 임포트가 장렬하게 실패합니다.



## 4. 완벽한 트러블슈팅: BOM 없는 UTF-8 구출 작전

이 치명적인 문제를 우아하게 타파하려면, 윈도우의 엑셀이나 기본 메모장을 버리고 개발자용 텍스트 에디터를 사용하여 `"**BOM을 수동으로 제거**"`해야 합니다.

### 4.1 Notepad++ (노트패드 플러스플러스) 활용법
저사양 윈도우 PC에서도 가볍게 돌아가는 최고의 구원자입니다.
1. 엑셀에서 저장한 CSV 파일을 Notepad++로 엽니다.
2. 상단 메뉴에서 `[인코딩(Encoding)]`을 클릭합니다.
3. `"**UTF-8(BOM 없음)로 변환 (Convert to UTF-8 without BOM)**"`을 선택합니다.
4. 저장(Ctrl+S) 후 DBeaver에서 다시 임포트를 시도하면, 기적처럼 모든 데이터가 0.1초 만에 쏟아져 들어갑니다.



### 4.2 VS Code (Visual Studio Code) 활용법
최근 디지털 인문학 코딩 교육에서 가장 많이 쓰이는 에디터입니다.
1. VS Code로 CSV 파일을 엽니다.
2. 화면 우측 하단의 상태 표시줄에 있는 `UTF-8 with BOM`이라는 글자를 클릭합니다.
3. 상단에 뜨는 명령 팔레트에서 `인코딩하여 저장(Save with Encoding)`을 선택합니다.
4. 목록에서 `"**UTF-8**"` (뒤에 with BOM이 안 붙은 순수 UTF-8)을 선택하여 덮어씌웁니다.

## 5. 요약: 데이터 파이프라인의 안전 수칙

데이터 임포트 과정에서 마주치는 수많은 에러는 여러분의 잘못이 아닙니다. 이기종 시스템(Windows와 DB 엔진) 간의 규격 충돌일 뿐입니다. 다음 세 가지 수칙만 기억하십시오.

1. 엑셀의 친절함을 믿지 마라.
2. 데이터베이스의 언어는 무조건 `"**UTF-8**"`이다.
3. 임포트 전, 반드시 개발자 에디터(Notepad++)를 열어 `"**BOM을 암살**"`하라.

이제 창고(데이터베이스)에 우리의 귀중한 인문학 사료가 안전하게 적재되었습니다. 다음 파트인 **[Part 5. SQL 데이터 제어와 이기종 방언의 이해]**에서는, 이렇게 밀어 넣은 데이터를 자유자재로 지휘하고 추출하는 `"**SQL 질의어(Query)**"`의 세계로 본격적인 항해를 시작하겠습니다.
