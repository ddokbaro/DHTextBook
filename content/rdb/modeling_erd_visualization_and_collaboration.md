# ERD 시각화 도구의 선택과 협업 워크플로우: ERDCloud와 Draw.io 활용

지금까지 우리는 정규화(Normalization) 원칙과 템포럴(Temporal) 모델링 등을 통해 인문학 사료를 해체하고 조립하는 논리적 훈련을 거쳤습니다. 그러나 이 복잡한 구조를 머릿속으로만 기억하거나 텍스트(SQL)로만 나열한다면, 방대한 디지털 인문학 프로젝트를 며칠 안에 미궁 속에 빠뜨리게 될 것입니다.

건축가가 집을 짓기 전 설계도를 그리듯, 데이터베이스를 구축하기 전에는 반드시 `"**ERD(Entity Relationship Diagram, 개체 관계도)**"`를 그려야 합니다. ERD는 단순한 그림이 아니라, 인문학 전공자, 데이터 엔지니어, 웹 개발자가 서로의 언어 장벽을 허물고 소통하게 만들어 주는 `"**프로젝트의 공용어(Lingua Franca)**"`입니다. 이 장에서는 현대 학계와 업계에서 가장 강력한 지지를 받는 두 가지 ERD 도구의 특성과 이상적인 협업 워크플로우를 심층 분석합니다.

## 1. ERD: 보이지 않는 데이터에 형상을 부여하다

ERD는 크게 세 가지 시각적 요소로 구성됩니다.
1. **엔티티(Entity, 개체):** 인물, 관직, 고을처럼 데이터를 담는 네모 상자(테이블)입니다.
2. **속성(Attribute):** 이름, 생년, 품계처럼 엔티티 상자 안에 적히는 구체적인 정보들입니다.
3. **관계(Relationship):** 상자와 상자를 잇는 선입니다. 1:1, 1:N, N:M 등 개체 간의 논리적 연결을 까마귀 발(Crow's foot) 모양의 기호 등으로 표현합니다.



수백 줄의 SQL 코드나 엑셀 시트로는 전체 데이터의 맥락을 파악하기 어렵지만, 잘 그려진 ERD 한 장은 이순신(인물)이 어떻게 전라좌수사(관직)와 연결되고, 그 관직이 어떻게 임진왜란(사건)과 이어지는지 직관적인 통찰을 제공합니다.

## 2. 실시간 협업의 최강자: ERDCloud (erdcloud.com)

디지털 인문학 연구팀은 대개 지리적으로 분산되어 있으며(서울의 연구자와 대전의 개발자 등), 기술적 배경도 제각각입니다. 이때 가장 빛을 발하는 도구가 바로 국내 기술로 개발된 웹 기반 시각화 도구인 `"**ERDCloud**"`입니다.



### 2.1 주요 실무 기능
* **실시간 동시 편집 (Real-time Collaboration):** 구글 문서(Google Docs)를 사용할 때처럼, 여러 팀원이 동시에 하나의 ERD 캔버스에 접속하여 테이블을 조작할 수 있습니다. 
* **의사소통의 즉시성:** 캔버스 내부에 채팅 기능이 내장되어 있습니다. "관직 테이블의 품계 컬럼을 VARCHAR가 아니라 INT로 바꾸는 게 어떨까요?"라고 채팅을 치며 그 자리에서 선을 긋고 수정할 수 있습니다.
* **다양한 DBMS 렌더링 지원:** MySQL, Oracle, MSSQL 등 타겟 데이터베이스 엔진을 선택하면, 해당 엔진의 문법에 맞는 DDL(데이터 정의어) 코드를 그림으로부터 즉시 자동 생성해 줍니다.

ERDCloud는 초기 기획 단계에서 연구진 전원이 모여 아이디어를 발산하고 데이터 구조의 합의(Consensus)를 이끌어내는 `"**브레인스토밍 및 구조 확정 단계**"`에 가장 최적화되어 있습니다.

## 3. 역공학(Reverse Engineering)과 학술 시각화: Draw.io (diagrams.net)

ERDCloud가 실시간 설계에 강점이 있다면, `"**Draw.io (현재 diagrams.net)**"`는 세계에서 가장 널리 쓰이는 범용 다이어그램 도구로서, 논문 작성과 기존 데이터베이스 분석에 압도적인 위력을 발휘합니다.

### 3.1 역공학(Reverse Engineering)의 마법
이미 누군가 구축해 둔 공공 데이터베이스나 기존 연구 데이터를 분석해야 할 때, 그 거대한 구조를 처음부터 손으로 다시 그리는 것은 엄청난 낭비입니다. 

Draw.io는 텍스트로 된 SQL 코드를 그림으로 즉시 변환해 주는 `"**역공학 기능**"`을 제공합니다. 
1. 기존 데이터베이스(예: SQLite, DBeaver)에서 테이블 생성 구문(`CREATE TABLE ~`)을 복사합니다.
2. Draw.io 메뉴에서 `[Insert] -> [Advanced] -> [SQL]`을 클릭합니다.
3. 복사한 SQL 코드를 붙여넣기만 하면, 복잡했던 텍스트 코드가 단 1초 만에 깔끔하게 정돈된 테이블 상자와 관계 선(ERD)으로 변환되어 캔버스에 나타납니다.



### 3.2 퍼블리싱(Publishing)과 폐쇄망 지원
Draw.io는 오픈소스이며 오프라인 데스크톱 앱을 지원합니다. 보안이 엄격하여 외부 인터넷이 차단된 대학 연구실의 폐쇄망 환경에서도 완벽하게 작동합니다. 또한 구글 드라이브(Google Drive)나 깃허브(GitHub)와 완벽하게 연동되어 파일 버전을 관리하기 쉬우며, 학술 진흥 재단 결과 보고서나 KCI 등재지 논문에 삽입할 고해상도 벡터 이미지(SVG, PDF)를 추출하는 데 타의 추종을 불허합니다.

## 4. 이상적인 인문 데이터 연구팀의 협업 워크플로우

성공적인 프로젝트를 위해 두 도구를 다음과 같은 워크플로우로 결합하여 사용하는 것을 권장합니다.

1. **Phase 1 (구조 스케치 및 합의):** 프로젝트 초기, 인문학자와 개발자가 `"**ERDCloud**"`에 모여 뼈대를 잡습니다. 화상 회의를 켜두고 실시간으로 테이블을 생성, 분리, 병합하며 논리적 정규화를 마칩니다.
2. **Phase 2 (물리적 구현 및 명세서 작성):** 합의된 ERD를 바탕으로 물리적 데이터베이스(MySQL, SQLite)를 생성하고, 이전 장에서 배운 `"**테이블 기술 명세서(Data Dictionary)**"`를 엑셀로 상세히 기록하여 맥락을 채웁니다.
3. **Phase 3 (문서화 및 논문 투고):** 프로젝트가 성숙하고 데이터베이스 구조가 완전히 고정(Freeze)되면, 완성된 DB에서 DDL을 추출해 `"**Draw.io**"`로 역공학합니다. 다이어그램의 색상과 배치를 논문 규격에 맞게 아름답게 다듬은 뒤 고해상도 이미지로 출력하여 학술 성과물로 배포합니다.

이러한 체계적인 시각화 및 협업 파이프라인이 정착될 때, 연구팀은 비로소 특정 개인의 기억에 의존하지 않고 시스템으로 굴러가는 진정한 디지털 인문학 연구소로 거듭나게 됩니다.
