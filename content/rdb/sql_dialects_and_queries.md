# SQL 기초와 이기종 방언(Dialects)의 이해

데이터베이스의 구조를 설계(Part 3)하고, 파이프라인을 통해 원시 사료를 밀어 넣었다면(Part 4), 이제 남은 것은 이 방대한 지식의 창고에서 내가 원하는 데이터만을 빠르고 정확하게 건져 올리는 일입니다. 

이때 컴퓨터와 대화하기 위해 사용하는 언어가 바로 `"**SQL(Structured Query Language, 구조화된 질의어)**"`입니다. SQL은 단순한 컴퓨터 명령어가 아니라, 복잡하게 얽힌 관계형 모델 속에서 인문학적 질문을 논리적 명제로 번역하는 `"**수학적이고 철학적인 도구**"`입니다. 이 장에서는 SQL이 가진 독특한 언어적 특성과, 데이터베이스 제품마다 미묘하게 달라지는 '방언(Dialects)'의 정체를 해부합니다.

## 1. SQL의 미학: 절차가 아닌 '결과'를 선언하라 (Declarative Language)

디지털 인문학에 입문하며 파이썬(Python)이나 R을 먼저 배운 학생들은 SQL을 처음 접할 때 큰 인지적 부조화를 겪습니다. 파이썬이 `"**어떻게(How)**"` 할 것인지를 한 줄 한 줄 지시하는 절차적 언어(Procedural Language)라면, SQL은 내가 `"**무엇(What)**"`을 원하는지만을 선언하는 `"**선언적 언어(Declarative Language)**"`이기 때문입니다.



예를 들어, "1592년에 임용된 정3품 이상의 무관 명단"을 파이썬 코드로 짠다면 다음과 같은 지난한 절차가 필요합니다.
1. 임용 데이터를 맨 윗줄부터 끝까지 반복해서 읽어라. (For loop)
2. 만약(If) 연도가 1592년이고 품계가 정3품 이상이면,
3. 빈 리스트에 그 사람의 이름을 추가해라.

하지만 SQL의 세계에서는 이러한 절차를 지시할 필요가 없습니다. 그저 다음과 같이 우아하게 `"**조건(집합)을 선언**"`하기만 하면 됩니다.

```sql
SELECT 인물_이름 
FROM 임용_테이블 
WHERE 임용_연도 = 1592 
  AND 품계_코드 >= '정3품';
```

데이터베이스 엔진 내부의 옵티마이저(Optimizer)가 이 선언문을 읽고, 인덱스를 탈지 전체를 뒤질지 스스로 가장 빠른 경로를 계산하여 0.01초 만에 결과를 던져줍니다. 즉, 인문학자는 복잡한 알고리즘을 고민할 필요 없이 `"**데이터의 논리적 조건(집합론)**"`에만 집중하면 되는 것입니다.

## 2. 데이터베이스의 바벨탑: SQL 방언(Dialects)

SQL은 1970년대 IBM에서 개발된 이후, 전 세계의 표준화 기구에 의해 `"**ANSI SQL**"`이라는 국제 표준 문법으로 제정되었습니다. 
이상적인 세계라면 모든 데이터베이스 시스템(Oracle, MSSQL, MySQL, SQLite)이 이 표준 문법 하나만으로 100% 호환되어야 합니다. 그러나 현실의 데이터베이스 생태계는 구약성서의 바벨탑처럼 언어가 뿔뿔이 흩어져 있습니다. 이를 `"**SQL 방언(Dialects)**"`이라고 부릅니다.



### 2.1 방언은 왜 탄생했는가?
마이크로소프트, 오라클 등 각 벤더(Vendor)들은 시장 점유율을 높이기 위해 표준(ANSI SQL)에는 없는 자신들만의 강력하고 독창적인 편의 기능들을 엔진에 추가하기 시작했습니다. 
* 마이크로소프트의 SQL Server는 `"**T-SQL(Transact-SQL)**"`이라는 방언을 씁니다.
* 오라클은 `"**PL/SQL**"`이라는 방언을 씁니다.
* 오픈소스 진영의 MySQL과 SQLite 역시 문자열 처리나 날짜 계산에서 자신들만의 독자적인 문법을 발전시켰습니다.

## 3. 인문학도를 좌절시키는 방언의 실무적 차이

하나의 데이터베이스(예: 로컬 SQLite) 환경에서만 쿼리를 작성하다가, 클라우드 환경(예: Azure의 MSSQL)으로 프로젝트를 이관할 때 쿼리가 작동하지 않아 밤을 새우는 일이 비일비재합니다. 

대표적으로 조선시대 사료를 다룰 때 가장 많이 쓰이는 `"**문자열 결합(String Concatenation)**"`을 예로 들어보겠습니다. "덕수이씨 이순신"이라는 하나의 문자열을 만들기 위해 성씨와 이름을 합치는 쿼리는 엔진마다 모두 다릅니다.

* **표준 ANSI & SQLite:** 파이프 두 개(`||`)를 사용합니다.
  ```sql
  SELECT 본관 || ' ' || 이름 AS 풀네임 FROM 인물_테이블;
  ```
* **마이크로소프트 (MSSQL):** 엑셀이나 프로그래밍 언어처럼 덧셈 기호(`+`)를 사용합니다.
  ```sql
  SELECT 본관 + ' ' + 이름 AS 풀네임 FROM 인물_테이블;
  ```
* **MySQL / MariaDB:** 전용 함수인 `CONCAT()`을 사용해야만 합니다.
  ```sql
  SELECT CONCAT(본관, ' ', 이름) AS 풀네임 FROM 인물_테이블;
  ```

이 외에도 게시판의 페이지를 나누는 페이징 처리(`LIMIT` vs `TOP` vs `OFFSET`), 현재 날짜를 가져오는 함수(`SYSDATE` vs `GETDATE()` vs `NOW()`) 등에서 뼈아픈 파편화가 존재합니다.

## 4. 요약 및 다음 단계

SQL 방언의 존재를 모르는 초학자들은 구글링이나 ChatGPT가 짜준 SQL 코드를 자신의 DBeaver에 복사해 넣었다가 원인 모를 문법 에러(Syntax Error)를 만나고 극심한 좌절에 빠집니다. 

디지털 인문학 프로젝트를 수행하는 우리는 항상 자신이 지금 `"**어떤 데이터베이스 엔진(방언) 위에 서 있는지**"`를 명확히 인지해야 하며, 가급적 특정 엔진에 종속되지 않는 `"**표준 ANSI SQL**"`을 작성하려는 습관을 들여야 합니다.

이제 SQL의 철학과 방언의 존재를 이해했으니, 다음 장에서는 데이터베이스를 조작하는 두 가지 핵심 뼈대인 **DDL(데이터 정의어)과 DML(데이터 조작어)**의 구조를 상세히 해부하고, 우리가 자주 사용하는 MSSQL과 MySQL 간의 치명적인 방언 차이를 실무 쿼리로 직접 비교 분석해 보겠습니다.
