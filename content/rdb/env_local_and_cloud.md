# 클라이언트-서버 데몬의 이해: XAMPP 로컬 스택 및 클라우드 프리 티어의 함정

앞선 장에서 우리는 파일 하나로 끝나는 SQLite의 극단적인 가벼움을 경험했습니다. 그러나 현대의 거대한 디지털 인문학 아카이브나 엔터프라이즈 애플리케이션은 단일 파일로 구동되지 않습니다. 수천 명의 사용자가 동시에 접속하여 데이터를 읽고 쓰기 위해서는, 보이지 않는 곳에서 네트워크 요청을 처리하는 거대한 백그라운드 프로그램이 필요합니다. 이를 `"**데몬(Daemon)**"`이라고 부릅니다.

학생들은 궁극적으로 데이터베이스 엔진이 데몬으로 작동하며 TCP/IP(예: 포트 3306)를 통해 통신하는 `"**클라이언트-서버(Client-Server) 아키텍처**"`를 반드시 다루어야 합니다. 이 장에서는 로컬 컴퓨터에 서버 데몬을 올리는 XAMPP 스택과, 글로벌 클라우드 서비스의 무료 티어(Free Tier) 뒤에 숨겨진 치명적인 과금 함정들을 낱낱이 파헤칩니다.



## 1. 로컬 경량화 스택: Bitnami의 몰락과 XAMPP의 귀환

과거 학계에서는 Apache, MySQL, PHP를 한 번에 설치해 주는 'Bitnami(비트나미)' 인스톨러가 절대적인 표준이었습니다. 그러나 2025/2026년을 기점으로 Broadcom에 인수된 Bitnami가 소프트웨어 배포 모델을 수익성 위주로 재편하며 무료 버전을 중단하고 `"**Bitnami Secure**"`라는 유료 장벽을 세웠습니다.

이에 따라 대학의 한정된 예산과 학생들의 무료 실습 환경을 위해, 우리는 커뮤니티 주도의 오픈소스 생태계인 `"**XAMPP(Windows용)**"`와 `"**MAMP(macOS용)**"`로 완전히 회귀해야 합니다.

### 1.1 5분 만에 끝나는 XAMPP 로컬 서버 구축 (Windows 기준)

학생들이 윈도우 환경에서 5분 이내에 로컬 MariaDB/MySQL 서버 데몬을 구축하는 표준 절차는 다음과 같습니다.

1. **설치 경로의 주의점:** Apache Friends 사이트에서 XAMPP를 다운로드하여 설치할 때, 윈도우의 엄격한 권한 제어를 피하기 위해 `C:\Program Files`가 아닌 `"**C:\xampp**"` 경로에 직접 설치하도록 강제해야 합니다.
2. **서비스 초기화:** 설치 후 `xampp-control.exe`를 실행합니다. 여러 모듈 중 `MySQL` 옆의 `Start` 버튼을 누르면 `mysqld.exe` 데몬이 백그라운드에서 초기화되며 3306 포트를 개방합니다.
3. **네트워크 포트 트러블슈팅:** 만약 데몬이 켜지자마자 즉시 종료(Crash)된다면, 이미 컴퓨터에 설치된 다른 데이터베이스가 3306 포트를 점유하고 있기 때문입니다. 제어판의 `xampp-portcheck.exe`를 통해 포트 충돌을 확인하고, 설정(my.ini)에서 포트를 `3307` 등으로 우회해야 합니다.
4. **시각적 클라이언트 접속:** 데몬이 정상 작동하면 `Admin` 버튼을 클릭하여 웹 브라우저 기반의 GUI 도구인 `phpMyAdmin`에 즉시 접속하여 실습을 진행할 수 있습니다.

이 과정을 통해 학생들은 완벽하게 격리된 자신의 컴퓨터 안에서 실제 기업의 데이터베이스 서버와 100% 동일한 데몬 라이프사이클을 통제해 보게 됩니다.

## 2. 퍼블릭 클라우드 데이터베이스: 프리 티어(Free Tier)의 치명적 함정

로컬 환경에 익숙해진 학생들은 학기 말 포트폴리오 프로젝트를 위해 외부에서도 접속할 수 있는 퍼블릭 클라우드(AWS, GCP, Azure, Oracle)로 눈을 돌리게 됩니다. 글로벌 벤더들은 학생들을 끌어들이기 위해 무료 계층(Free Tier)을 제공하지만, 이 '무료'라는 단어 뒤에는 예측 불가능한 `"**과금 폭탄과 리소스 강제 삭제**"`라는 끔찍한 함정이 도사리고 있습니다.



각 클라우드 벤더별 교육적 주의사항을 완벽하게 숙지해야 합니다.

### 2.1 Amazon Web Services (AWS) RDS: 스토리지 클래스의 함정
* **제공량:** 가입 후 12개월 동안 매월 750시간의 마이크로 인스턴스와 20GB의 스토리지를 제공합니다.
* **⚠️ 치명적 함정:** 최근 AWS는 성능이 개선된 새로운 `gp3` 스토리지를 기본값으로 도입했습니다. 문제는 이 `"**gp3 스토리지가 무료 티어 적용 대상에서 완전히 제외**"`되어 있다는 점입니다. 인스턴스 생성 마법사에서 스토리지 유형을 반드시 구형인 `"**gp2**"`로 수동 전환하지 않으면 가입 즉시 비용이 청구됩니다.

### 2.2 Microsoft Azure SQL Database: 학생을 위한 최고의 안전장치
* **제공량:** 구독 유지 시 평생 동안 매월 100,000 vCore 초의 서버리스 컴퓨팅과 32GB 스토리지를 제공합니다.
* **💡 교육적 장점:** 서버리스(Serverless) 모델의 특성상, 학생이 할당된 10만 초를 모두 소진하면 데이터베이스가 자동으로 일시 중지(Auto-pause)됩니다. 이는 금전적 여유가 없는 학생들을 초과 과금으로부터 완벽하게 보호해 주는 `"**가장 훌륭한 안전장치**"`입니다. (단, 'Azure for Students Starter' 계정으로는 생성할 수 없으므로 일반 무료 계정이나 상위 대학생 인증으로 가입해야 합니다.)

### 2.3 Oracle Cloud (OCI) Autonomous Database: 극단적인 자원 회수
* **제공량:** 'Always Free(평생 무료)'로 2개의 강력한 자율운영 데이터베이스와 20GB의 스토리지를 제공합니다. 성능 면에서는 가장 압도적입니다.
* **⚠️ 치명적 함정:** Oracle은 자원 낭비를 막기 위해 극도로 공격적인 리소스 회수 정책을 폅니다. 데이터베이스에 `"**7일 연속 접속이 없으면 시스템이 자동으로 정지**"`되며, 비활성화 상태로 `"**90일이 경과하면 경고 후 영구 삭제**"`해 버립니다. 주기적으로 접속하여 타이머를 리셋하지 않으면 학기 중반에 프로젝트 전체가 증발하는 대참사를 겪게 됩니다.

### 2.4 Google Cloud Platform (GCP) Cloud SQL: 휘발성 트라이얼
* **제공량:** 12개월 프리 티어 대신, 최고 사양의 Enterprise Plus 인스턴스를 30일 동안만 무료로 제공합니다.
* **⚠️ 치명적 함정:** 30일이 지나면 강제 중지되며 영구 삭제됩니다. 한 학기 내내 사용하려면 교수가 'Google Cloud Education Grants'를 신청하여 학생들에게 바우처 코드를 분배해야 하므로, 졸업 후 포트폴리오 호스팅 용도로는 부적합합니다.

## 3. 요약 및 다음 단계

이제 학생들은 자신의 로컬 컴퓨터에 백그라운드 서버 데몬을 안전하게 올릴 수도 있고, 클라우드의 무료 인프라를 과금 폭탄 없이 프로비저닝(Provisioning)할 수 있는 완벽한 통제력을 갖추었습니다.

하지만 서버를 구축하는 것은 절반의 완성에 불과합니다. 운영 서버에서 쿼리를 조작하다가 실수로 데이터를 날려버리지 않으려면 어떻게 해야 할까요? 다음 장에서는 윈도우, 맥OS, 리눅스를 가리지 않고 세상의 모든 데이터베이스에 접속할 수 있는 가장 완벽한 범용 클라이언트, **"DBeaver와 HeidiSQL의 아키텍처 및 보안 세팅"**으로 나아가 보겠습니다.
