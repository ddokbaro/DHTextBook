# 시트(Sheet) 분리와 VLOOKUP/INDEX-MATCH를 통한 관계형 연결의 '아하 모먼트'

앞선 장에서 우리는 하나의 엑셀 셀(Cell) 안에 인물의 여러 관직과 출신지를 쉼표로 나열하는 `"**플랫 데이터(Flat Data)**"` 방식이 얼마나 끔찍한 데이터 관리의 재앙을 불러오는지 확인했습니다. 

이제 우리는 복잡한 관계형 데이터베이스(RDB) 프로그램을 당장 설치하는 대신, 우리에게 가장 친숙한 구글 스프레드시트(또는 엑셀) 위에서 관계형 데이터 모델을 직접 흉내 내 볼 것입니다. 엉켜있는 데이터를 논리적으로 분해하고 함수로 다시 연결하는 이 `"**사전 정규화(Pre-normalization)**"` 과정을 통해, 여러분은 RDB가 왜 위대한 발명품인지 마음 깊이 깨닫는 `"**아하 모먼트(Aha-moment)**"`를 맞이하게 될 것입니다.

## 1. 분해의 예술: 엔티티(Entity) 도출과 시트(Sheet) 쪼개기

데이터베이스 설계의 제1원칙은 **"성격이 다른 정보는 반드시 분리한다"**입니다. 앞서 보았던 이순신, 원균의 플랫 데이터를 자세히 살펴보면, 크게 세 가지의 완전히 다른 정보 그룹(이를 컴퓨터 공학에서는 '엔티티'라고 부릅니다)이 섞여 있음을 알 수 있습니다.

1. **사람 자체에 대한 불변 정보** (이름, 생몰년, 본관)
2. **관직 자체에 대한 불변 정보** (관직명, 품계, 소속)
3. **어떤 사람이 어떤 관직을 거쳐 갔다는 '사건' 정보** (임용)



우리는 하단의 시트 탭(Tab)을 추가하여 이 세 가지 정보를 물리적으로 완전히 쪼개버릴 것입니다. 

### Step 1: `인물_시트` (Person Master)
| 인물ID | 이름 | 생년 | 몰년 | 본관 |
| :--- | :--- | :--- | :--- | :--- |
| P001 | 이순신 | 1545 | 1598 | 덕수이씨 |
| P002 | 원균 | 1540 | 1597 | 원주원씨 |

### Step 2: `관직_시트` (Office Master)
| 관직ID | 관직명 | 품계 | 문무구분 |
| :--- | :--- | :--- | :--- |
| O001 | 정읍현감 | 종6품 | 종방 |
| O002 | 삼도수군통제사 | 종2품 | 서반 |
| O003 | 전라좌도수군절도사 | 정3품 | 서반 |

## 2. 기계의 언어로 이름 짓기: 고유 식별자(ID)의 부여

위의 분리된 시트에서 가장 주목해야 할 점은 `"**인물ID**"`와 `"**관직ID**"`라는 새로운 열(Column)이 생겼다는 것입니다. 

동명이인(예: 조선시대에 '이순신'이라는 무관은 여러 명 존재했습니다)을 이름표 하나로 구별하려 들면 기계는 반드시 혼란을 겪습니다. 또한, 관직명은 시대에 따라 이름이 미묘하게 바뀌기도 합니다. 따라서 변하지 않는 절대적인 기준점이 필요한데, 이것이 바로 데이터베이스에서 말하는 `"**기본 키(Primary Key, PK)**"`입니다. 우리는 이 규칙을 스프레드시트에 도입하여 `P001`, `O002` 같은 고유 기호를 부여했습니다.

## 3. 관계(Relation)의 동적 결합: VLOOKUP 함수

이제 사람과 관직을 쪼개놓았으니, "이순신이 삼도수군통제사가 되었다"라는 역사적 사건을 기록할 차례입니다. 이를 위해 세 번째 시트인 `임용_교차_시트`를 만듭니다.

### Step 3: `임용_교차_시트` (Junction Table)
| 임용ID | 인물ID | 관직ID | 
| :--- | :--- | :--- | 
| H001 | P001 | O001 | 
| H002 | P001 | O003 | 
| H003 | P001 | O002 | 
| H004 | P002 | O002 | 



기록은 매우 간결해졌지만, 인간이 읽기에는 암호문 같아 불편합니다. 이때 스프레드시트의 마법인 `"**VLOOKUP(혹은 INDEX와 MATCH의 조합)**"` 함수를 사용합니다. 

`임용_교차_시트` 옆에 '이름'과 '관직명' 열을 임시로 만들고 다음의 함수를 입력합니다.
* 이름 가져오기: `=VLOOKUP(B2, '인물_시트'!A:E, 2, FALSE)`
* 관직명 가져오기: `=VLOOKUP(C2, '관직_시트'!A:D, 2, FALSE)`

기계는 `P001`이라는 코드를 들고 `인물_시트`로 달려가 "이순신"이라는 텍스트를 실시간으로 물고 돌아옵니다. 이것이 바로 관계형 데이터베이스에서 가장 중요한 개념인 `"**조인(JOIN)**"` 연산과 완벽하게 동일한 작동 원리입니다.

## 4. 진정한 '아하 모먼트(Aha-moment)'

이렇게 시트를 쪼개고 ID로 연결해 둔 상태에서, 앞서 우리가 플랫 데이터에서 겪었던 3대 재앙을 다시 마주해 봅시다.

1. **완벽한 통계 도출:** "삼도수군통제사를 역임한 사람은 몇 명인가?" 
   -> `임용_교차_시트`에서 관직ID가 `O002`인 행(Row)의 개수만 세면 됩니다(결과: P001, P002 2명). 복잡한 텍스트 분절 작업 없이 피벗 테이블(Pivot Table) 클릭 한 번에 통계가 나옵니다.
2. **기적적인 유지보수(Update):** 학계의 고증이 바뀌어 '삼도수군통제사'를 '수군통제사'로 이름을 바꿔야 합니다. 
   -> 수백 명의 임용 기록을 뒤질 필요가 없습니다. 오직 `관직_시트`의 `O002` 행에 있는 텍스트 단 하나만 '수군통제사'로 수정하십시오. VLOOKUP 함수로 연결된 수백 명의 임용 시트 기록이 0.1초 만에 동시에 변경됩니다. 갱신 이상(Update Anomaly)이 원천적으로 소멸하는 순간입니다.

우리는 방금 스프레드시트의 함수를 이용해 데이터베이스의 **제1~제3 정규화(Normalization)**를 흉내 내었습니다. 
하지만 VLOOKUP 함수는 데이터가 수만 건으로 늘어나면 엑셀을 멈추게 만들고, ID를 강제하는 제약 조건(Constraint) 기능이 없어 누군가 오타를 내면 여전히 데이터가 무너집니다.

바로 이 한계를 극복하고, 수억 건의 데이터를 0.01초 만에 오류 없이 조인(JOIN)하기 위해 탄생한 전용 소프트웨어가 바로 우리가 배울 `"**관계형 데이터베이스(RDBMS)**"`입니다. 관계형 모델의 위대함을 체감했으니, 이제 본격적으로 진짜 RDB의 역사와 그 환경 구축의 세계로 뛰어들어 보겠습니다.
