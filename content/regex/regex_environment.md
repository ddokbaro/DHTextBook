# 데이터 전처리 환경 구축과 데이터 포맷

디지털 환경에서 수집된 방대한 텍스트 문서들은 기계가 즉각적으로 분석할 수 있는 상태가 아닙니다. 컴퓨터는 인간처럼 문맥을 읽고 의미를 추론하지 못하기 때문입니다. 비정형의 자연어 텍스트를 기계가 연산할 수 있는 정형 데이터로 깎아내고 변환하는 일련의 과정을 **“데이터 전처리”**(Data Preprocessing)라고 합니다.

이 데이터 전처리를 수행하기 위해 인문학자를 비롯한 모든 데이터 분석가가 반드시 익혀야 하는 가장 강력하고 절대적인 무기가 바로 **“정규표현식”**(Regular Expression, Regex)입니다. 

이 장에서는 정규표현식이 기계적 텍스트 처리의 기본이 되는 이유를 밝히고, 이를 활용하기 위한 최적의 소프트웨어 환경 구축 방법, 그리고 기계가 데이터를 읽어 들이는 기본 포맷인 CSV와 TSV의 구조를 실제 예시와 함께 상세히 탐구합니다.

## 1. 기계적 처리의 기본, 정규표현식을 사용해야 하는 이유

정규표현식은 복잡한 문자열 속에서 특정한 형태나 규칙을 가진 문자열을 찾아내기 위해, 그 규칙을 수학적이고 기계적인 패턴으로 정의하는 **“형식 언어”**입니다. 

그렇다면 왜 우리는 단순한 찾기/바꾸기 기능을 넘어 이 복잡한 형식 언어를 배워야만 할까요? 그 이유는 인간의 인지 방식과 컴퓨터의 연산 방식 사이의 좁힐 수 없는 간극을 해결해야 하기 때문입니다.

### 1.1 의미 기반 검색의 한계와 패턴 매칭의 필요성
다음과 같은 역사적 텍스트가 있다고 가정해 봅시다.

> “**이순신(李舜臣, 1545~1598)은 조선시대 전라좌도 수군절도사를 역임한 무신이다. 임진왜란이 나자 옥포·노량에서 연승했다. 충무공은 1593년 삼도수군통제사가 되었다.**”

인간은 위 문단을 읽을 때 “**이순신**”과 “**충무공**”이 동일한 인물을 지칭한다는 사실을 사전 지식을 통해 즉각적으로 인지합니다. 하지만 컴퓨터에게 이순신과 관련된 모든 문장을 추출하라고 명령하기 위해 검색창에 “**이순신**”을 입력하면, 컴퓨터는 “**충무공**”이라는 단어가 포함된 중요한 문장을 철저하게 누락해 버립니다. 기계는 단어의 의미가 아니라 오직 글자의 형태(바이트 값)만을 대조하기 때문입니다.

이때 정규표현식을 사용하면 “**이순신**”과 “**충무공**”을 동시에 찾으라는 논리적 조건(`이순신|충무공`)을 부여할 수 있습니다. 정규표현식은 기계가 이해하지 못하는 인간의 맥락을 기계가 철저히 연산할 수 있는 논리적 규칙으로 번역해 주는 가장 원초적인 통역관입니다.

### 1.2 대규모 데이터의 일괄 구조화
데이터 분석을 위해서는 수백, 수천 편의 시나 소설 텍스트를 일정한 데이터베이스 형태로 만들어야 합니다. 예컨대 1,000편의 시 데이터가 있을 때, 컴퓨터가 빈도 분석을 수행하려면 시의 모든 행(Row)마다 고유한 ID와 작가명을 분리하여 일괄적으로 붙여주어야 합니다. 인간이 수작업으로 이를 수행하면 엄청난 시간 소요와 치명적인 오류가 발생하지만, 정규표현식을 활용하면 단 한 줄의 패턴식만으로 수만 줄의 데이터를 눈 깜짝할 사이에 빠르고 정확하게 구조화할 수 있습니다. 

이처럼 데이터의 노이즈를 제거하고 원하는 정보를 추출하여 일정한 형식으로 조립하는 과정의 90% 이상이 정규표현식을 통해 이루어집니다. 정규표현식의 숙달 없이 기계적 데이터 분석을 논하는 것은 불가능에 가깝습니다.

## 2. 엑셀의 한계와 텍스트 에디터의 필요성

일반적으로 표 형태의 데이터를 다룰 때 가장 친숙한 프로그램은 마이크로소프트 엑셀(Excel)입니다. 그러나 텍스트 데이터를 전처리하는 단계에서 엑셀을 사용하는 것은 매우 부적절하며, 정보 공학적으로 다음과 같은 뚜렷한 한계를 지닙니다.

1.  **메모리 과부하와 성능 저하:** 엑셀은 텍스트 편집이 아닌 회계 연산과 서식 적용에 특화된 프로그램입니다. 수만 줄에 달하는 대용량 텍스트 데이터를 엑셀에 붙여넣으면 메모리 점유율이 급증하여 프로그램이 극심하게 버벅거리거나 강제 종료되는 현상이 빈발합니다.
2.  **정규표현식 엔진의 부재:** 엑셀의 기본 찾기/바꾸기 기능으로는 기계적인 패턴 매칭 알고리즘을 구동할 수 없습니다. 

따라서 대용량 텍스트 처리에 최적화되어 있고 정규표현식 엔진을 자체적으로 내장한 **“텍스트 에디터”**(Text Editor)를 필수적으로 사용해야 합니다.

### 2.1 데이터 전처리용 텍스트 에디터 추천
* **노트패드++ (Notepad++):** 2003년에 개발된 이래 윈도우 환경에서 가장 널리 쓰이는 무료 에디터입니다. 가벼운 구동 환경과 정규표현식 지원, 다양한 플러그인 확장성 덕분에 데이터 편찬에 최적화되어 있습니다.
* **엠에디터 (EmEditor):** 세계에서 가장 가볍고 빠르다고 평가받는 에디터로, 수백 기가바이트(GB)에서 테라바이트(TB) 급의 초거대 텍스트 파일도 지연 없이 열어 편집할 수 있습니다. (무료 및 유료 버전 존재)
* **Mac OS:** 맥 운영체제 사용자의 경우 기본적으로 내장된 텍스트 에디터 앱에서도 정규표현식을 훌륭하게 지원하므로 이를 적극 활용할 수 있습니다.

## 3. 텍스트 에디터 최적화 세팅 가이드

정규표현식을 오류 없이 작성하고, 보이지 않는 데이터의 구조를 시각적으로 통제하기 위해 텍스트 에디터(노트패드++ 기준)에서 다음 세 가지 설정을 반드시 활성화해야 합니다.

1.  **자동 줄바꿈 (Word Wrap):** `보기 > 자동 줄바꿈` 메뉴를 선택합니다. 이 설정을 켜지 않으면 개행(Enter)이 될 때까지 텍스트가 오른쪽으로 무한히 길어지므로, 창 사이즈에 맞게 텍스트를 접어서 한눈에 파악할 수 있도록 만듭니다.
2.  **공백과 탭의 시각화:** `보기 > 기호 보기 > 공백과 탭 표시`를 선택합니다. 빈 화면처럼 보이는 공간이라도 기계의 입장에서는 완전히 다른 데이터입니다. 이 기능을 켜면 스페이스바를 누른 띄어쓰기는 **“주황색 점”**으로, 탭(Tab) 키를 누른 공간은 **“화살표(→)”**로 시각화됩니다. 탭은 데이터의 열을 구분하는 핵심 기호이므로 띄어쓰기와 명확히 구분되어야 합니다.
3.  **정규표현식 찾기 모드:** `Ctrl + F`를 눌러 찾기 창을 열쇠, 하단의 찾기 모드에서 **“정규표현식”** 라디오 버튼을 선택합니다. 또한 영문 대소문자를 엄격히 구별하는 **“대소문자 구분”**과 커서 위치와 상관없이 문서 전체를 검색하는 **“되돌이 검색”** 체크박스를 켜두어야 완벽한 전처리가 가능합니다.

## 4. 기계가 읽는 데이터의 형태: CSV와 TSV 완벽 이해

정규표현식을 사용해 텍스트를 전처리하는 궁극적인 목적은, 길게 늘어진 비정형 문장들을 기계가 열(Column)과 행(Row)으로 명확히 인식할 수 있는 데이터베이스 테이블 형태로 변환하는 것입니다. 이때 가장 널리 쓰이는 표준 텍스트 포맷이 바로 **CSV**와 **TSV**입니다. 

입문자들이 두 포맷의 차이와 한계를 명확히 이해할 수 있도록 구체적인 예시를 통해 비교해 봅니다.

### 4.1 범용성의 CSV (Comma-Separated Values)
**CSV**는 파일 이름이 암시하듯 데이터의 각 열(항목)을 **“쉼표(Comma, `,`)”**를 사용하여 구분하는 텍스트 포맷입니다. 웹상의 수많은 공공 데이터가 이 형식으로 배포됩니다.

```text
문헌번호,저자명,도서명,발행연도
101,조지 오웰,1984,1949
102,프란츠 카프카,동물농장,1945
```
위 데이터를 엑셀 등에서 불러오면 기계는 쉼표를 기준으로 네 개의 칸(열)을 정확히 나누어 표로 만듭니다. 구조가 매우 단순하여 호환성이 뛰어납니다.

**CSV의 치명적인 한계와 이스케이프(Escape) 처리:**
그러나 만약 데이터 본문 내용 자체에 이미 쉼표가 포함되어 있다면 어떤 일이 벌어질까요?

```text
문헌번호,저자명,도서명,금액
103,토머스 모어,유토피아,15,000원
```
기계는 `15,000원`이라는 하나의 값 내부에 있는 쉼표를 “**새로운 열을 나누라는 신호**”로 오인해 버립니다. 결과적으로 원래 네 개의 열이어야 할 데이터가 `103` | `토머스 모어` | `유토피아` | `15` | `000원` 이라는 다섯 개의 열로 산산조각 나며 데이터베이스가 붕괴됩니다.

이 오류를 막기 위해 CSV는 쉼표가 포함된 문자열 데이터를 반드시 **“쌍따옴표”**로 감싸주어야 하는 엄격한 규칙(이스케이프 처리)을 가집니다.

```text
문헌번호,저자명,도서명,금액
103,토머스 모어,유토피아,"15,000원"
```

### 4.2 텍스트 친화적인 TSV (Tab-Separated Values)
디지털인문학에서 다루는 역사 문헌, 소설, 기사 데이터에는 본문 내용 중에 수많은 쉼표가 등장합니다. 모든 쉼표를 쌍따옴표로 통제하는 것은 전처리 과정에서 엄청난 공학적 비용을 유발합니다. 

이를 우회하기 위해 가장 권장되는 포맷이 **TSV**입니다. TSV는 데이터의 열을 **“탭(Tab, `\t`)”** 기호로 구분합니다.

```text
문헌번호	저자명	도서명	금액
103	토머스 모어	유토피아	15,000원
```
일반적인 자연어 텍스트 문장 한가운데에 탭(Tab) 기호가 쓰이는 일은 거의 없습니다. 따라서 TSV를 사용하면 데이터 내부에 쉼표가 아무리 많아도 구분자와 충돌하지 않으므로 쌍따옴표로 감쌀 필요가 없어 파일 관리가 압도적으로 직관적이고 쾌적해집니다. 우리가 엑셀에서 표를 복사하여 텍스트 에디터에 붙여넣을 때 각 칸이 탭으로 벌어져 있는 이유도 엑셀의 기본 클립보드 복사 형태가 TSV이기 때문입니다.

## 5. 데이터 분리와 무결성 유지 원칙

### 5.1 텍스트 나누기 기능을 통한 TSV/CSV 변환
텍스트 에디터에서 정규표현식으로 정제를 마친 TSV(또는 CSV) 데이터를 엑셀로 복사해 올 경우, 데이터가 각 열로 나뉘지 않고 A열 한 칸에 모두 뭉쳐서 들어가는 경우가 발생합니다.
이때는 당황하지 말고 엑셀의 데이터 분리 기능을 사용해야 합니다.
1.  데이터가 모여 있는 전체 열(A열 등)을 선택합니다.
2.  상단 메뉴에서 `데이터 > 텍스트 나누기`를 클릭합니다.
3.  `구분 기호로 분리됨`을 선택하고 다음으로 넘어갑니다.
4.  원본 데이터가 TSV라면 **“탭”**을, CSV라면 **“쉼표”**를 체크한 뒤 마침을 누르면 기계가 구분자를 인식하여 데이터를 각 셀로 완벽하게 분할해 줍니다.

### 5.2 데이터베이스 절대 금기 사항: 셀 병합 금지
엑셀로 데이터를 다룰 때 인문학 연구자들이 시각적 편의를 위해 흔히 저지르는 가장 치명적인 실수는 바로 **“행 합치기”** 혹은 **“열 합치기”**(셀 병합) 기능의 사용입니다.

기계적 관점에서 데이터베이스의 각 행(Row)과 열(Column)은 독립적이고 완전한 데이터 셋입니다. 인간의 눈에는 셀을 병합하여 같은 작가명을 하나로 묶어두면 깔끔해 보일 수 있습니다. 하지만 컴퓨터 시스템이 이 병합된 표를 읽어 들일 때, 병합된 첫 번째 셀만 값을 가진 것으로 간주하고 나머지 셀들은 “**아무것도 없는 공백 데이터(Null)**”로 인식해 버립니다. 

따라서 기계 학습이나 통계 분석을 위한 원천 데이터를 구축할 때는 값이 중복되더라도 **“반드시 모든 행과 열에 값을 개별적으로 채워 넣어야 하며, 어떠한 경우에도 셀 병합을 수행해서는 안 됩니다”**.
