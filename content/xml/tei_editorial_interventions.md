# 원전의 전사와 편집자적 개입

오랜 세월을 견뎌온 아날로그 문헌을 디지털 텍스트로 옮기는 전사(Transcription) 과정은 결코 기계적인 타이핑 작업이 아닙니다. 원본 텍스트에는 필사자의 실수로 인한 오탈자가 존재하며, 세월의 흔적으로 글자가 지워지거나 훼손된 부분도 있습니다. 때로는 저자가 직접 줄을 그어 지우고 행간에 새로운 글자를 써넣은 흔적도 발견됩니다.

양심적인 문헌학자는 원본의 물리적 상태를 있는 그대로 보존하는 동시에, 독자의 이해를 돕기 위해 오류를 바로잡고 텍스트를 복원해야 하는 딜레마에 빠집니다. TEI는 이러한 딜레마를 해결하기 위해, 원본의 상태와 편집자의 학술적 개입(Editorial Interventions)을 하나의 XML 문서 안에 모순 없이 병기할 수 있는 강력한 태그 세트를 제공합니다.

## 1. 교정과 정규화: `<choice>`를 활용한 다중 해석

과거의 인쇄본 교감에서는 지면의 한계로 인해 원본의 오기(誤記)를 각주로 빼거나 편집자의 수정본만을 본문에 실어야 했습니다. 그러나 TEI는 `"**<choice>**"` 요소를 통해 원본의 형태와 편집자의 수정 형태를 텍스트의 동일한 위치에 나란히 공존시킵니다. 



`<choice>` 내부에서는 개입의 성격에 따라 다음 두 가지 쌍을 엄격히 구분하여 사용합니다.

### 1.1 오기의 교정: `<sic>`과 `<corr>`
명백한 오류를 수정할 때 사용합니다.
* `"**<sic>**"` (sic): 원본에 기록된 형태가 명백한 오류임에도 불구하고, 원본에 쓰인 그대로(as is) 전사했음을 나타냅니다.
* `"**<corr>**"` (correction): 편집자가 판단한 올바른 교정 형태를 나타냅니다.

**[마크업 예시]**
```xml
<p>
    이순신 장군이 
    <choice>
        <sic>한산도</sic>
        <corr>한산대첩</corr>
    </choice>
    에서 대승을 거두었다.
</p>
```
*디지털 환경에서는 이 마크업을 통해 일반 독자에게는 `<corr>`(한산대첩)을 보여주고, 원본 연구자에게는 토글 버튼을 통해 `<sic>`(한산도)을 보여주는 동적인 독서 환경을 구축할 수 있습니다.*

### 1.2 표기의 정규화: `<orig>`와 `<reg>`
단순한 오류가 아니라, 시대적 관행이나 지역적 방언으로 쓰인 단어를 현대의 표준적인 철자법으로 통일(정규화)할 때 사용합니다.
* `"**<orig>**"` (original): 원본의 철자나 표기 형태를 보존합니다.
* `"**<reg>**"` (regularization): 현대적 관행에 맞게 정규화된 형태를 나타냅니다.

**[마크업 예시]**
```xml
<p>
    <choice>
        <orig>뎨일</orig>
        <reg>제일</reg>
    </choice>
    좋은 방책이다.
</p>
```

## 2. 사본의 물리적 훼손과 복원

고문헌의 가장 큰 특징은 보존 상태에 따른 텍스트의 결락입니다. TEI는 훼손의 정도와 편집자의 판독 가능성에 따라 태그를 세분화합니다.

### 2.1 판독이 불확실할 때: `<unclear>`
글자가 희미하거나 얼룩이 져서 읽을 수는 있지만 그 확신이 떨어질 때 사용합니다. `@reason` 속성으로 불확실한 이유를, `@cert`(certainty) 속성으로 편집자의 확신 정도를 명시할 수 있습니다.
```xml
<p>사신의 이름은 김<unclear reason="water_damage" cert="low">종</unclear>서이다.</p>
```

### 2.2 완전히 유실되었을 때: `<gap>`
텍스트가 물리적으로 완전히 파손되었거나, 편집자의 의도에 의해 전사를 생략했을 때 사용하는 `"**빈 요소**"`입니다. `@reason`과 함께 `@extent`(범위) 속성을 사용하여 유실된 분량을 기록합니다.
```xml
<p>그날 밤 <gap reason="torn_page" extent="3 words"/> 사건이 발생했다.</p>
```

### 2.3 편집자가 텍스트를 보충할 때: `<supplied>`
`<gap>`이나 원본의 누락으로 인해 텍스트가 비어있지만, 편집자가 문맥이나 다른 판본을 참고하여 논리적으로 글자를 채워 넣었을 때 사용합니다.
```xml
<p>그날 밤 <supplied reason="context">은밀한</supplied> 사건이 발생했다.</p>
```

## 3. 필사자의 수정 흔적 기록



초고나 필사본에는 저자나 필사자가 직접 글자를 긋고 지우거나, 행간에 새로운 글자를 끼워 넣은 물리적 흔적이 고스란히 남아있습니다. 이는 텍스트의 성립 과정을 보여주는 매우 중요한 `"**발생론적 데이터**"`입니다.

### 3.1 삭제와 추가: `<del>`과 `<add>`
* `"**<del>**"` (deletion): 원본에서 줄이 그어지거나 긁어내어 삭제된 흔적을 표시합니다.
* `"**<add>**"` (addition): 원본의 텍스트에 추가로 삽입된 글자나 구절을 표시합니다. `@place` 속성을 사용하여 이 글자가 행간(`supralinear`)에 적혔는지, 여백(`margin`)에 적혔는지 물리적 위치를 정확히 기록할 수 있습니다.

**[마크업 예시]**
```xml
<p>
    그는 <del rend="strikethrough">어제</del> 
    <add place="supralinear">오늘 아침</add> 한양으로 떠났다.
</p>
```

## 4. 약어와 축약형의 확장

서양의 중세 필사본이나 동아시아의 초서체 사료에서는 지면을 아끼기 위해 관습적인 약어(Abbreviation)를 빈번하게 사용합니다. 편집자는 독자를 위해 이 약어를 풀어서 확장(Expansion)해 주어야 합니다.

이 역시 `<choice>` 요소의 묶음 안에서 `"**<abbr>**"`과 `"**<expan>**"`의 쌍으로 처리합니다.

```xml
<p>
    문서의 발행 기관은 
    <choice>
        <abbr>한국학</abbr>
        <expan>한국학중앙연구원</expan>
    </choice>
    이다.
</p>
```
이러한 마크업은 문서의 원형을 조금도 훼손하지 않으면서도, 기계가 `<expan>`의 데이터를 읽어들여 `"**한국학중앙연구원**"`이라는 정확한 키워드로 문서를 검색해 낼 수 있도록 만드는 완벽한 상호운용성(Interoperability)을 보장합니다.

결론적으로 TEI의 편집적 개입 태그들은 인문학자가 사료를 대하는 고뇌의 흔적을 기계의 뇌 속에 영구히 각인시키는 방법론입니다. 텍스트의 미시적 교정이 완료되었으니, 이어지는 장에서는 유니코드 표준에 존재하지 않는 동아시아 문헌의 치명적 난제, **"비표준 문자와 이체자 처리(Gaiji 모듈)"**의 정보공학적 해결책을 깊이 있게 탐구하겠습니다.
