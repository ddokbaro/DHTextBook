# 어휘 충돌의 해결과 네임스페이스

웰폼드(Well-formed) 규칙을 통해 기계가 문서를 거부하지 않고 읽어 들일 수 있는 물리적 뼈대를 완성했습니다. 그러나 디지털 인문학의 진정한 목표는 파편화된 문서들을 하나로 모아 거대한 지식 생태계를 구축하는 “**데이터 융합(Mashup)**”에 있습니다. 

연구자나 기관마다 자유롭게 태그를 창조할 수 있다는 XML의 강력한 확장성은, 역설적으로 여러 문서를 합칠 때 치명적인 혼란을 야기합니다. 이 장에서는 서로 다른 스키마의 태그들이 충돌하는 “**어휘 충돌(Vocabulary Collision)**” 현상을 이해하고, 이를 정보공학적으로 우아하게 해결하는 “**네임스페이스(Namespace)**”의 심오한 작동 원리를 파헤칩니다.

## 1. 확장성의 역설: 어휘 충돌(Vocabulary Collision)

국립중앙도서관의 고도서 데이터베이스와 국립현대미술관의 회화 데이터베이스를 하나의 통합 검색 시스템으로 융합한다고 가정해 봅시다.

**[국립중앙도서관의 XML 데이터]**
```xml
<작품>
    <제목>홍길동전</제목>
    <저자>허균</저자>
</작품>
```

**[국립현대미술관의 XML 데이터]**
```xml
<작품>
    <제목>몽유도원도</제목>
    <저자>안견</저자>
</작품>
```

각 기관의 내부 시스템에서는 이 태그들이 완벽하게 작동합니다. 그러나 두 데이터가 하나의 시스템으로 통합되는 순간, 컴퓨터가 `<작품>`이나 `<저자>`를 검색할 때 이 태그가 “**텍스트로 된 책**”을 의미하는지 “**캔버스에 그려진 그림**”을 의미하는지 전혀 식별할 수 없는 상태에 빠집니다. 이것이 바로 마크업 언어의 “**어휘 충돌**”입니다.

## 2. 네임스페이스(Namespace): 소속의 명확화

이러한 어휘 충돌을 방지하고 데이터의 상호 운용성을 보장하기 위해 W3C가 도입한 기술이 바로 “**네임스페이스(Namespace)**”입니다. 네임스페이스는 특정 태그가 지구상의 어느 기관, 혹은 어떤 스키마의 소속인지를 절대적으로 겹치지 않는 “**고유한 식별자**”를 통해 명시하는 문법입니다.



### 2.1 URI (Uniform Resource Identifier)의 활용
전 세계에서 절대 중복되지 않는 고유한 이름을 만들기 위해, XML은 인터넷 주소 형식인 “**URI**”를 차용합니다. 

여기서 초보자들이 가장 많이 하는 오해는 “**해당 인터넷 주소로 접속하면 무언가 다운로드되거나 웹페이지가 열려야 한다**”고 착각하는 것입니다. 네임스페이스에서 사용되는 URI(예: `http://library.go.kr/book`)는 실제 존재하는 웹페이지가 아니어도 무방합니다. 이는 단지 전 세계에서 오직 국립중앙도서관만이 보장하고 책임질 수 있는 “**고유한 식별 문자열(문자표)**”로서 기능할 뿐입니다.

### 2.2 접두사(Prefix)를 활용한 네임스페이스 선언
태그를 작성할 때마다 매번 긴 URI를 적을 수는 없습니다. 따라서 `xmlns`(XML Namespace) 속성을 사용하여, 긴 URI를 짧고 직관적인 “**접두사(Prefix)**”에 연결해 둡니다.

```xml
<통합아카이브 xmlns:도서="[http://library.go.kr/book](http://library.go.kr/book)" 
           xmlns:미술="[http://museum.go.kr/art](http://museum.go.kr/art)">
    <도서:작품>
        <도서:제목>홍길동전</도서:제목>
        <도서:저자>허균</도서:저자>
    </도서:작품>

    <미술:작품>
        <미술:제목>몽유도원도</미술:제목>
        <미술:저자>안견</미술:저자>
    </미술:작품>
</통합아카이브>
```

이제 컴퓨터는 `<도서:작품>`과 `<미술:작품>`을 이름이 완전히 다른 별개의 요소로 엄격하게 분리하여 인식합니다. 어휘 충돌이 완벽하게 해결된 것입니다.

## 3. 기본 네임스페이스 (Default Namespace)

하나의 문서 안에서 대부분의 요소가 동일한 소속을 가진다면, 매번 태그 앞에 `도서:` 같은 접두사를 붙이는 것은 극심한 타이핑 노동이 됩니다. 이때는 특정 문서나 구역 전체의 기본 소속을 지정하는 “**기본 네임스페이스**”를 사용할 수 있습니다.

접두사 없이 `xmlns="URI"` 형태로 선언하면, 해당 요소와 그 자식 요소들은 모두 기본적으로 해당 URI의 소속으로 간주됩니다.

```xml
<도서록 xmlns="[http://library.go.kr/book](http://library.go.kr/book)">
    <작품>
        <제목>홍길동전</제목>
        <저자>허균</저자>
    </작품>
</도서록>
```
이 구역 내부의 `<작품>`, `<제목>`, `<저자>`는 접두사가 없어도 자동으로 도서관의 네임스페이스 소속으로 파싱됩니다.

## 4. 실무 응용: 여러 네임스페이스의 융합 (TEI와 Dublin Core)

디지털 인문학의 실제 아카이브 구축 현장에서는 하나의 문서 안에 여러 국제 표준 스키마를 융합하여 사용하는 경우가 매우 흔합니다. 

가장 대표적인 사례가 텍스트 본문의 구조는 “**TEI(Text Encoding Initiative)**”를 따르고, 문서의 서지 메타데이터(저자, 발행일, 주제 등)는 도서관 정보학의 국제 표준인 “**더블린 코어(Dublin Core, DC)**”를 가져와 혼용하는 방식입니다.

```xml
<TEI xmlns="[http://www.tei-c.org/ns/1.0](http://www.tei-c.org/ns/1.0)" 
     xmlns:dc="[http://purl.org/dc/elements/1.1/](http://purl.org/dc/elements/1.1/)">
    <teiHeader>
        <fileDesc>
            <titleStmt>
                <title>무정(無情)</title>
                <dc:creator>이광수</dc:creator>
                <dc:date>1917</dc:date>
            </titleStmt>
        </fileDesc>
    </teiHeader>
    <text>
        <body>
            <p>형식은 마음이 초연하였다...</p>
        </body>
    </text>
</TEI>
```

이 고도화된 마크업 코드를 해석해 보겠습니다.
1. 루트 요소인 `<TEI>`에 `xmlns="http://www.tei-c.org/ns/1.0"`이라는 **기본 네임스페이스**가 선언되었습니다. 따라서 접두사가 없는 `<teiHeader>`, `<text>`, `<body>`, `<p>` 등은 모두 TEI 표준 문법으로 인식됩니다.
2. 동시에 `xmlns:dc="http://purl.org/dc/elements/1.1/"`라는 **접두사 네임스페이스**가 선언되었습니다.
3. 이를 통해 메타데이터 구역에서 `<dc:creator>`와 `<dc:date>`를 사용함으로써, 이 정보가 단순한 텍스트가 아니라 전 세계 도서관 시스템이 널리 인식하는 더블린 코어 표준의 저자 및 날짜 정보임을 기계에게 명확하게 선언한 것입니다.

이처럼 네임스페이스는 파편화된 인문학적 데이터를 글로벌 지식망(Semantic Web)에 편입시키고, 다른 학문의 데이터베이스와 자유롭게 소통하게 만드는 “**디지털 문헌학의 외교관**” 역할을 수행합니다.

형식적 엄밀성을 갖추는 문법과 소속을 명확히 하는 과정이 모두 끝났습니다. 이어지는 장에서는 이 뼈대의 구조(어떤 요소가 누구의 부모가 되어야 하는지, 순서는 어떠해야 하는지)를 가장 강력하게 통제하는 최초의 유효성 검증 문서, “**DTD(Document Type Definition)**”의 세계로 진입하겠습니다.
