# LLM을 활용한 마크업 프롬프팅 기법과 환각 통제

앞서 우리는 마크업의 패러다임이 수작업 전사에서 `"**AI 초안 생성 및 인간 검수**"`로 진화했음을 확인했습니다. 거대 언어 모델(LLM)은 문맥을 이해하고 개체명을 식별하는 데 탁월한 능력을 발휘하지만, 기계에게 "이 텍스트를 XML로 만들어줘"라고 단순하게 지시하면 결과는 참혹할 것입니다.

LLM은 본질적으로 확률에 기반하여 다음 단어를 예측하는 모델이므로, 연구자가 설계한 엄격한 DTD/XSD 스키마를 무시하고 자기 마음대로 태그를 지어내거나 심지어 원본 텍스트의 내용을 바꿔버리는 `"**환각(Hallucination)**"` 현상을 일으킵니다. 

이 장에서는 인문학자의 학술적 의도를 기계가 한 치의 오차 없이 수행하도록 지시하는 `"**마크업 프롬프트 엔지니어링(Markup Prompt Engineering)**"`의 핵심 공식과, 원본 데이터의 무결성을 지키는 환각 통제 실무를 다룹니다.

## 1. 프롬프트 구조화의 3원칙

LLM에게 고품질의 XML 마크업을 얻어내기 위해서는 마치 컴퓨터 프로그래밍을 하듯 프롬프트를 구조화해야 합니다. 극도의 효율성을 추구하는 실무 현장에서는 다음 3원칙을 반드시 지켜야 합니다.

1. **페르소나(Persona) 부여:** 모델에게 "너는 한국 고문헌 분석 및 TEI XML 마크업의 최고 전문가이다"라는 역할을 부여하여 출력의 도메인을 고정합니다.
2. **화이트리스트(Whitelist) 통제:** 사용 가능한 태그의 목록을 정확히 지정하고, 그 외의 태그는 절대 생성하지 못하도록 막습니다.
3. **Few-shot 예시 제공:** 백 마디의 설명보다 한 번의 정확한 `"**입출력 쌍(Input-Output Pair)**"` 예시를 보여주는 것이 AI의 포맷 일관성을 유지하는 데 압도적으로 유리합니다.

## 2. 실전 프롬프트 템플릿 (개체명 마크업)

조선시대 사료의 텍스트에서 인물명(`<persName>`)과 관직명(`<roleName>`)을 추출하여 마크업하는 실전 프롬프트 구조입니다.

**[마크업 시스템 프롬프트 예시]**
```text
당신은 한국 고문헌 텍스트 분석 및 TEI XML 마크업 전문가입니다.
주어진 원문 텍스트에서 인물명과 관직명을 식별하여 다음 규칙에 따라 인라인 마크업을 수행하십시오.

[마크업 규칙]
1. 인물의 이름(성, 이름, 자, 호 포함)은 반드시 <persName> 태그로 감싸시오.
2. 인물의 관직명, 신분, 칭호는 반드시 <roleName> 태그로 감싸시오.
3. 위 두 가지 태그 외에는 어떠한 XML 태그도 새로 만들거나 사용하지 마시오.

[예시]
입력: 영의정 류성룡이 임금께 아뢰기를
출력: <roleName>영의정</roleName> <persName>류성룡</persName>이 임금께 아뢰기를

입력: 충무공 이순신 장군은 전라좌수사가 되어
출력: <persName>충무공</persName> <persName>이순신</persName> <roleName>장군</roleName>은 <roleName>전라좌수사</roleName>가 되어

[작업 대상 원문]
(여기에 마크업할 텍스트를 입력합니다)
```

이러한 `"**Few-shot 프롬프팅**"` 기법은 기계가 예시의 패턴을 모방하게 만듦으로써, 우리가 설계한 구조(`persName`, `roleName`)에서 단 1mm도 벗어나지 않도록 통제하는 가장 강력한 수단입니다.

## 3. 치명적인 환각(Hallucination)과 통제 실무 ★

디지털 문헌학에서 LLM을 사용할 때 발생하는 환각은 크게 두 가지 유형으로 나뉩니다. 이 두 가지를 통제하지 못하면 AI가 생성한 데이터는 폐기물에 불과합니다.

### 3.1 제1유형: 원문 훼손 (텍스트 변형)
가장 위험한 환각입니다. LLM이 마크업을 수행하면서 원문에 있는 오탈자를 마음대로 '교정'해 버리거나, 어려운 한자어를 쉬운 말로 '번역'하여 텍스트의 길이나 내용을 바꾸어 버리는 현상입니다. 

* **통제 프롬프트:** `"**규칙 0: 입력된 원문 텍스트의 글자, 띄어쓰기, 문장 부호는 단 하나도 수정, 추가, 삭제하지 마시오. 원본의 무결성을 100% 유지한 상태에서 태그만 덧붙이시오.**"`

### 3.2 제2유형: 비표준 태그의 창조 (스키마 위반)
프롬프트에 `<persName type="king">`을 쓰라고 지시했음에도, LLM이 문맥을 보고 임의로 `<king>`이나 `<monarch>`라는 존재하지 않는 태그를 창조하여 마크업하는 현상입니다. 이는 웰폼드(Well-formed) 규칙과 XSD 유효성을 즉각적으로 파괴합니다.

* **통제 프롬프트:**
  `"**경고: 사전에 허락된 태그 목록([persName, roleName]) 이외의 태그를 임의로 지어내어 사용하는 것을 엄격히 금지합니다. XML 응답 외에 어떠한 부연 설명도 출력하지 마시오.**"`

## 4. 메타데이터(teiHeader) 추출 프롬프팅

단순한 본문 태깅을 넘어, 복잡한 `<teiHeader>`를 구성하기 위해 산문 형태의 텍스트에서 정형 데이터를 추출할 때도 LLM은 강력한 도구가 됩니다. 

"이 책은 1920년에 최남선이 창간한 개벽이다"라는 텍스트를 주면, LLM은 이를 JSON이나 XML 구조로 정확히 분해해 냅니다. 이때 가장 중요한 것은 `"**XML 템플릿(Template) 제공**"`입니다.

**[teiHeader 생성 프롬프트 예시]**
```text
다음 문헌 설명을 분석하여, 아래에 제공된 <teiHeader> 템플릿의 빈칸(____)을 정확한 데이터로 채워 넣으시오.
원문에 없는 정보는 임의로 지어내지 말고, 빈칸을 삭제하시오.

[템플릿]
<teiHeader>
    <fileDesc>
        <titleStmt>
            <title>____</title>
            <author>____</author>
        </titleStmt>
        <sourceDesc>
            <bibl>
                <date when="____">____</date>
            </bibl>
        </sourceDesc>
    </fileDesc>
</teiHeader>
```
위와 같이 뼈대를 미리 던져주면, LLM은 훌륭한 파서(Parser)의 역할을 수행하여 필요한 데이터만 정확한 위치에 꽂아 넣습니다.

결론적으로, 디지털 문헌학자가 LLM과 소통하는 프롬프트 엔지니어링은 단순한 '질문 던지기'가 아니라, 기계의 자유도를 극도로 억압하여 내가 설계한 구조망(Schema) 안으로 데이터를 정확히 흘려보내는 `"**정보 제어 기술**"`입니다. 

이어지는 장에서는 이렇게 생성된 수백, 수천 개의 AI 초안 XML 파일들을 인간이 어떻게 효율적으로 검증하고, 기계적 오류를 찾아내어 미시적으로 교정하는지 그 구체적인 검수(Validation) 워크플로우를 살펴보겠습니다.
