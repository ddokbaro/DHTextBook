# 본문 구조와 시맨틱 태깅: `<index>`를 활용한 개체명 식별과 데이터베이스 색인화 전략

앞서 우리는 잡지의 거시적 계층 구조(`<level1~3>`)와 메타데이터(`<biblioData>`)의 상속 원리를 살펴보았습니다. 그러나 디지털 인문학의 진정한 위력은 텍스트 내부(Body)에 숨겨진 역사적 사실들을 기계가 읽고 분석할 수 있도록 의미를 부여하는 `"**시맨틱 태깅(Semantic Tagging)**"`에서 발휘됩니다.

일반적으로 텍스트 내의 인물, 장소, 책 이름 등을 식별하는 작업을 개체명 인식(NER)이라고 부릅니다. 이 장에서는 `ma_001.xml`(대한자강회월보) 샘플 데이터를 해부하여, 국사편찬위원회가 어떻게 범용 TEI 가이드라인의 복잡성을 걷어내고 `"**<index>**"`라는 독자적이고 효율적인 태그를 통해 거대 데이터베이스 색인화를 달성했는지 분석합니다.

## 1. TEI 개체명 모듈의 복잡성과 NIKH의 대안

서구 중심의 TEI 가이드라인은 개체명을 태깅하기 위해 매우 정교하고 방대한 태그 세트를 제공합니다. 인물은 `<persName>`, 장소는 `<placeName>`, 기관은 `<orgName>`, 책 이름은 `<title>`(또는 `<bibl>`) 등을 사용해야 합니다.

이 방식은 의미론적으로는 완벽하지만, **수십 명의 입력 조교가 수백만 자의 텍스트를 수작업으로 마크업해야 하는 거대 편찬 프로젝트**에서는 치명적인 약점을 가집니다. 입력자가 수많은 태그의 종류와 문법을 완벽히 숙지해야 하므로 교육 비용이 급증하고, 태그를 혼동하여 사용하는 휴먼 에러가 빈발하게 됩니다.



국사편찬위원회(`history.dtd`)는 이 딜레마를 해결하기 위해 수십 개의 태그를 외울 필요 없이, 오직 `"**<index>**"`라는 단일 태그 하나만을 사용하고 그 성격을 `@type` 속성으로 구분하는 고도로 실용적인 정보공학적 결단을 내렸습니다.

## 2. `ma_001.xml` 해부: 직관적 시맨틱 태깅의 실제

제공된 `ma_001.xml`의 데이터, 특히 잡지의 해제(Explanation)를 담고 있는 `<biblioExplanation>` 영역을 살펴보면 이 직관적인 태깅 전략이 어떻게 구현되어 있는지 명확히 확인할 수 있습니다.

**[ma_001.xml의 실제 마크업 사례]**
```xml
<content>
    <paragraph>
        <index type="이름">梁允玉</index>
        <index type="이름">梁益洙</index>
        <index type="이름">梁龍典</index>
        <index type="이름">金泰熙</index>
        ...
        <index type="이름">尹志善</index>
        <index type="이름">洪榮龍</index>
    </paragraph>
</content>
```

### 2.1 단일 태그, 다중 속성 (Single Tag, Multiple Types)
입력자는 어떤 개체명이 등장하든 무조건 `<index>` 꺾쇠를 엽니다. 그리고 그것이 사람인지, 책 이름인지, 사건인지에 따라 `@type="이름"`, `@type="서명"`, `@type="사건"` 등으로 직관적인 속성값을 부여합니다. 
이는 복잡한 영문 TEI 태그(`<persName>`)보다 한국인 작업자에게 훨씬 직관적(`type="이름"`)이므로 작업 속도를 비약적으로 향상시키고 마크업의 일관성을 100% 보장합니다.

### 2.2 메타데이터 영역과의 분리
본문 속 개체명을 추출할 때는 `<index>`를 쓰지만, 헤더(`<biblioData>`) 영역에서 저자를 명시할 때는 `<author><name>高在國</name></author>`처럼 전통적인 서지학 태그를 씁니다. 이는 "본문에 등장하는 인물(Index)"과 "이 글을 쓴 주체(Author)"를 정보공학적으로 완벽히 격리하여 검색의 혼선을 막는 정교한 설계입니다.

## 3. 데이터베이스 색인화(Indexing) 전략 ★

국사편찬위원회가 이 태그의 이름을 `<index>`(색인)로 명명한 데에는 관계형 데이터베이스(RDB) 및 검색 엔진(ElasticSearch, Solr 등)과의 연동을 염두에 둔 거대한 빅픽처가 숨어 있습니다.

아날로그 잡지의 맨 뒷장에는 항상 '인명 색인', '서명 색인' 페이지가 존재하여 독자가 원하는 정보의 페이지를 찾을 수 있게 돕습니다. 디지털 공간에서 `<index>` 태그는 이 역할을 기계적으로 자동화합니다.

### 3.1 역인덱스(Inverted Index) DB의 자동 구축
웹 서비스 개발자는 파이썬(`lxml`)이나 SQL(XQuery)을 활용하여 수백만 건의 XML 문서에서 다음과 같은 단 한 줄의 쿼리만 실행하면 됩니다.

```xpath
//index[@type='이름']/text()
```

이 쿼리를 통해 추출된 "梁允玉(양윤옥)", "金泰熙(김태희)" 등의 데이터는 즉시 RDB의 `"**통합 색인 테이블(Index Table)**"`로 적재됩니다. 
결과적으로 사용자가 '한국사데이터베이스' 포털 검색창에 "김태희"를 입력했을 때, 서버는 무거운 전체 XML 본문을 뒤지는 풀텍스트 검색(Full-text Search)을 수행하지 않고, 가벼운 색인 테이블만을 조회하여 0.1초 만에 "대한자강회월보에 김태희가 등장합니다"라는 결과를 반환하게 됩니다. 

이것이 바로 구조화된 XML 텍스트가 `"**관계형 데이터베이스(RDB)와 결합하여 퍼포먼스를 극대화**"`하는 가장 모범적인 정보공학적 파이프라인입니다.

결론적으로 한국근현대잡지자료의 `<index>` 태그는 학술적 엄밀성을 추구하는 TEI의 복잡성을 덜어내고, 대량의 사료를 가장 빠르고 정확하게 데이터베이스화(DB-friendly)하려는 국가 기관의 치열한 고민이 담긴 위대한 커스터마이징의 산물입니다.

본문의 시맨틱 태깅 전략을 마스터했으니, 이어지는 장에서는 아날로그 잡지의 가장 큰 특징인 '물성(시각적 형태)'을 디지털로 복원하는 **"매체 전환의 흔적 보존: `<illustGroup>`을 통한 이미지 매핑과 `<emph>` 처리"** 메커니즘을 낱낱이 해부해 보겠습니다.
