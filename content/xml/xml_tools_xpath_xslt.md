# XPath/XQuery 빌더와 XSLT 디버깅 환경 세팅

완벽한 스키마 바인딩과 실시간 유효성 검사를 통해 무결점의 XML 데이터를 구축했다면, 이제 이 데이터를 바탕으로 원하는 정보를 추출하고 시각화할 차례입니다. 

일반적인 환경에서는 데이터를 추출하기 위해 파이썬(Python) 스크립트를 짜거나 복잡한 터미널 명령어를 입력해야 합니다. 그러나 디지털 문헌학의 최강자인 Oxygen XML Editor는 에러 검증뿐만 아니라, 데이터를 추출하는 `"**XPath/XQuery 엔진**"`과 HTML로 변환하는 `"**XSLT 프로세서**"`를 소프트웨어 내부에 완벽하게 내장하고 있습니다. 이 장에서는 Oxygen을 완벽한 통합 개발 환경(IDE)으로 활용하는 시각적 툴 체인 세팅법을 다룹니다.

## 1. 직관적인 데이터 추출: XPath/XQuery 빌더

Oxygen 화면의 상단(또는 좌측 패널)을 보면 `"**XPath 입력창**"`이 기본적으로 자리 잡고 있습니다. 이곳은 문서 전체를 관통하여 내가 원하는 데이터 조각(Node)만을 1초 만에 핀셋처럼 뽑아내어 보여주는 마법의 공간입니다.

### 1.1 실시간 쿼리 실행과 하이라이팅
작업 중인 XML 문서를 열어둔 상태에서, 상단 XPath 창에 다음과 같이 앞서 배운 경로 탐색 코드를 입력하고 엔터(Enter)를 칩니다.

```xpath
//persName[contains(@ref, 'P001')]
```

* **결과 패널(Results Panel):** 화면 하단에 쿼리 조건(ID가 P001인 인물명)을 만족하는 모든 노드의 목록이 리스트 형태로 즉각 출력됩니다.
* **실시간 하이라이팅:** 하단 목록 중 하나를 클릭하면, 방대한 원문 텍스트 내에서 해당 인물이 등장하는 정확한 위치로 커서가 이동하며 붉은색으로 `"**하이라이팅(Highlighting)**"`됩니다.

### 1.2 TEI 네임스페이스 자동 인식의 편리함
파이썬(lxml)으로 파싱할 때 우리를 가장 괴롭혔던 것이 바로 `xmlns="http://www.tei-c.org/ns/1.0"`과 같은 기본 네임스페이스 문제였습니다. 파이썬에서는 별도의 딕셔너리를 만들어 주입해야 했지만, Oxygen의 XPath 빌더는 현재 열려 있는 문서의 루트 네임스페이스를 `"**자동으로 인식**"`합니다. 따라서 복잡한 접두사 설정 없이 직관적으로 쿼리를 날려 데이터를 검증할 수 있습니다.

## 2. 변환 시나리오(Transformation Scenario) 구축

XPath로 데이터를 잘 뽑아냈다면, 이제 앞서 작성한 `.xsl` (XSLT) 파일을 원본 XML에 덮어씌워 인간이 읽을 수 있는 웹페이지(HTML)로 렌더링을 테스트해 볼 차례입니다. Oxygen에서는 이를 `"**변환 시나리오(Transformation Scenario)**"`라고 부릅니다.

### 2.1 시나리오 생성 및 원클릭 변환
1. 원본 XML 문서를 연 상태에서 상단 메뉴의 `Document` > `Transformation` > `"**Configure Transformation Scenario(변환 시나리오 구성)**"`를 클릭합니다.
2. `New` 버튼을 눌러 `XML transformation with XSLT`를 선택합니다.
3. **XML URL:** 현재 열려 있는 원본 파일(`currentFileURL`)을 지정합니다.
4. **XSL URL:** 미리 작성해 둔 XSLT 파일(예: `tei_to_html.xsl`)의 경로를 지정합니다.
5. **Output 탭:** 변환된 결과물이 저장될 경로(예: `output.html`)를 지정하고, `"**Open in Browser(브라우저에서 열기)**"` 옵션에 체크합니다.

시나리오를 저장하고 빨간색 ▷(Play) 버튼을 누르면, Oxygen은 즉각적으로 XSLT 연산을 수행한 뒤 내 컴퓨터의 크롬(Chrome)이나 엣지(Edge) 브라우저를 자동으로 실행하여 렌더링된 아름다운 HTML 결과물을 눈앞에 펼쳐줍니다. 

## 3. 오류 추적의 끝판왕: XSLT 디버거(Debugger) 투시경 ★

XSLT 코드를 작성하다 보면, 에러는 나지 않는데 HTML 화면에 엉뚱한 텍스트가 출력되거나 테이블이 찌그러지는 논리적 오류(Logical Error)가 발생하기 마련입니다. 머릿속으로만 변환 과정을 상상하는 것은 한계가 있습니다. 이때 Oxygen의 우측 상단에 있는 `"**XSLT Debugger 퍼스펙티브(Perspective)**"` 버튼을 클릭하면 에디터의 화면이 3단으로 분할되는 환상적인 디버깅 룸으로 진입합니다.



### 3.1 3단 분할 뷰의 구조
* **좌측 창:** 원본 XML 데이터
* **중앙 창:** 변환 규칙을 담은 XSLT 스크립트
* **우측 창:** 실시간으로 생성되고 있는 HTML 결과물

### 3.2 스텝 바이 스텝 (Step Into / Step Over) 추적
디버그 모드에서 F5(Step Into) 키를 한 번씩 누를 때마다, XSLT 변환 엔진이 전체 코드를 한 번에 실행하지 않고 `"**단 한 줄씩만 천천히 실행**"`합니다. 

* 중앙 창에서 `<xsl:for-each>` 반복문을 도는 동안, 좌측 창에서는 현재 처리 중인 XML 노드에 하이라이트가 켜지고, 우측 창에서는 `<tr>`, `<td>` 태그가 한 줄씩 실시간으로 타이핑되어 나타납니다.
* 우측 상단의 `"**Variables(변수)**"` 패널을 보면 현재 XPath가 어떤 값을 물고 있는지, 위치값(`position()`)은 몇 번인지 그 속살이 투명하게 공개됩니다.

이 디버깅 투시경을 활용하면, 아무리 복잡하게 얽힌 다중 템플릿 매칭(Template Matching) 코드라도 "어느 줄에서 값이 누락되었는지" 100% 확실하게 찾아내어 교정할 수 있습니다.

결론적으로 Oxygen XML Editor는 텍스트를 입력하는 타자기를 넘어, 데이터의 뼈대를 세우고(XSD), 살을 붙이며(Author Mode), 혈관을 연결하고(XPath), 최종적인 생명체로 렌더링(XSLT)하는 과정을 하나의 생태계 안에서 완벽히 통제하는 `"**디지털 인문학의 우주선(Spaceship)**"`입니다.
