# XPath 기초: 노드 탐색과 경로 표현식

XML 문서가 수백만 줄에 달하는 거대한 데이터베이스로 성장했을 때, 우리가 원하는 단 하나의 정보(예: “**1920년에 발행된 개벽 잡지의 모든 필자 이름**”)를 어떻게 추출할 수 있을까요? 

관계형 데이터베이스(RDB)에 SQL이 있다면, XML의 나무(Tree) 구조에는 “**XPath(XML Path Language)**”가 있습니다. XPath는 복잡하게 얽힌 XML 노드(Node)들 사이를 자유롭게 항해하며 특정 데이터를 핀셋처럼 집어내는 강력한 경로 탐색 언어입니다. 이 장에서는 XPath가 XML을 바라보는 시각인 노드의 개념을 이해하고, 가장 기본적이면서도 강력한 경로 표현식과 기초 필터링 기법을 학습합니다.

## 1. XPath의 시각: 7가지 노드(Node)

XPath는 XML 문서를 단순한 텍스트의 나열로 보지 않고, 여러 종류의 “**노드(Node)**”가 결합된 거대한 트리(Tree)로 인식합니다. 데이터를 정확히 타겟팅하려면 내가 찾고자 하는 것이 어떤 종류의 노드인지 명확히 알아야 합니다.



디지털 문헌학 실무에서 주로 다루는 4가지 핵심 노드는 다음과 같습니다.
1. **문서 노드(Document Node):** XML 문서 전체를 감싸는 보이지 않는 최상위 뿌리입니다. (루트 요소와는 다릅니다.)
2. **요소 노드(Element Node):** `<기사>`, `<필자>`와 같은 태그 쌍을 의미합니다.
3. **속성 노드(Attribute Node):** 요소 내부에 존재하는 `id="P001"`과 같은 메타데이터입니다.
4. **텍스트 노드(Text Node):** 태그 사이에 기입된 실제 문자열 데이터입니다.

## 2. 경로 표현식 (Path Expressions)

디렉터리 구조에서 파일을 찾듯, XPath는 슬래시(`/`) 기호를 사용하여 노드 사이를 이동합니다. 가장 빈번하게 사용되는 5가지 핵심 기호를 국사편찬위원회 **한국근현대잡지자료** 스키마 예시와 함께 살펴보겠습니다.

### 2.1 `/` (절대 경로: Root에서 시작)
슬래시 하나로 시작하는 경로는 문서의 가장 처음(루트)부터 자식 노드를 향해 순차적으로 한 계층씩 내려가야 함을 엄격하게 강제합니다.

```xpath
/근현대잡지자료/level1/level2/기사
```
* **해석:** 문서의 최상단에서 `<근현대잡지자료>`를 찾고, 그 바로 아래 자식인 `<level1>`, 그 자식인 `<level2>`, 그리고 그 자식인 `<기사>` 요소만을 정확히 찾아냅니다. 중간에 계층을 하나라도 건너뛰면 데이터를 찾지 못합니다.

### 2.2 `//` (상대 경로: 깊이 무관 탐색)
실무에서 가장 파괴적이고 유용하게 쓰이는 기호입니다. 슬래시 두 개는 **“현재 위치에서부터 그 아래로 얼마나 깊이 숨어있든 상관없이, 이름만 일치하면 모두 찾아라”**라는 명령입니다.

```xpath
//필자
```
* **해석:** 문서 내의 계층과 무관하게, 이름이 `<필자>`인 모든 요소 노드를 한꺼번에 추출합니다.

```xpath
/근현대잡지자료/level1//제목
```
* **해석:** `<level1>` 아래에 존재하는 모든 `<제목>`을 찾습니다. 그것이 `<level2>`의 자식이든, `<level3>`의 자식이든 상관없이 모조리 긁어옵니다.

### 2.3 `.` (현재 노드) 와 `..` (부모 노드)
리눅스(Linux)의 디렉터리 이동 명령과 완벽히 동일합니다.
* `.`: 현재 탐색 중인 노드 자신을 가리킵니다.
* `..`: 현재 노드의 직계 부모(한 단계 위) 노드로 이동합니다.

### 2.4 `@` (속성 노드 탐색)
요소(Element)가 아니라 속성(Attribute)의 값을 추출하고 싶을 때는 반드시 골뱅이(`@`) 기호를 태그명 앞에 붙여야 합니다.

```xpath
//level1/@잡지명
```
* **해석:** 문서 내의 모든 `<level1>` 요소를 찾은 뒤, 그 요소들이 가지고 있는 `잡지명`이라는 **속성의 값(Value)**들만 추출합니다. (예: "개벽", "소년" 등)

## 3. 기초 조건 필터링: 대괄호 `[]` (Predicates)

경로 표현식만으로는 수만 개의 기사 중 “**내가 원하는 특정 기사**”만 골라낼 수 없습니다. 특정 조건을 만족하는 노드만을 걸러내는 거름망 역할을 하는 것이 바로 대괄호(`[]`), 즉 “**서술어(Predicates)**”입니다. 대괄호는 항상 필터링하고자 하는 노드의 이름 바로 뒤에 붙습니다.

### 3.1 순번(Index) 필터링
XPath의 순번은 프로그래밍 언어들처럼 0부터 시작하지 않고 **1부터 시작**합니다.

```xpath
//기사[1]
```
* **해석:** 문서 전체에서 첫 번째로 등장하는 `<기사>` 요소 하나만 추출합니다.

```xpath
//level1/level2[last()]
```
* **해석:** `last()` 함수를 대괄호 안에 사용하여, 각 `<level1>` 내부의 마지막 `<level2>`(마지막 호수) 데이터만 추출합니다.

### 3.2 속성값(Attribute Value) 필터링
가장 널리 쓰이는 조건문입니다. 내부의 속성이 특정 값을 가지고 있는지 검사합니다.

```xpath
//level1[@잡지명="개벽"]
```
* **해석:** 수많은 `<level1>` 요소 중에서, `잡지명` 속성의 값이 정확히 `"개벽"`인 요소만 필터링하여 가져옵니다.

### 3.3 자식 요소(Child Element) 존재 여부 필터링
내부에 특정 자식 요소가 존재하는지, 혹은 그 자식 요소가 특정 값을 가지는지 검사할 수 있습니다.

```xpath
//기사[필자]
```
* **해석:** `<기사>` 요소들 중에서, 내부에 `<필자>`라는 자식 요소를 단 하나라도 가지고 있는 기사만 추출합니다. (무명 기사는 제외됩니다.)

```xpath
//기사[필자="이광수"]
```
* **해석:** `<기사>` 요소들 중에서, 자식인 `<필자>` 요소의 텍스트가 정확히 `"이광수"`인 기사만 추출합니다.

우리는 이 장을 통해 XML 트리를 횡단하는 가장 기초적인 나침반(`//`, `@`)과 거름망(`[]`)을 손에 쥐었습니다. 그러나 현실의 인문학 데이터는 “**나를 기준으로 내 앞에 있는 형제 요소**”나 “**내 조상 노드**”를 찾아야 하는 등 훨씬 다차원적인 탐색을 요구합니다. 

이어지는 장에서는 XPath 항해술의 꽃이라 불리는 **“축(Axes)을 활용한 다차원 관계 탐색”** 기술의 심연으로 들어가 보겠습니다.
