# DTD 설계의 기초: 요소(ELEMENT) 선언과 빈도 제어

앞선 장에서 다룬 웰폼드(Well-formed) 규칙은 파서(Parser)가 문서를 읽기 위한 **"물리적 생존 조건"**에 불과합니다. 그러나 디지털 인문학 데이터베이스를 구축할 때, 우리는 훨씬 더 엄격한 학문적 규칙을 기계에게 가르쳐야 합니다. 예를 들어, **"모든 잡지 기사에는 반드시 제목이 있어야 한다"**거나 **"저자는 1명 이상이어야 한다"**와 같은 논리적 제약입니다.

이러한 내용적 엄밀성을 통제하는 최초의 스키마(Schema) 언어가 바로 **"DTD(Document Type Definition)"**입니다. DTD를 통과한 문서는 비로소 **"유효한(Valid) 문서"**로 격상됩니다. 이 장에서는 DTD 설계의 뼈대인 요소(`<!ELEMENT>`) 선언법과, 자식 요소의 등장 횟수를 정밀하게 통제하는 **"빈도 제어 연산자"**를 실습과 함께 심층 해부합니다.

## 1. DTD의 연결과 선언

XML 문서가 특정 DTD의 규칙을 따른다고 선언하려면, 문서 최상단(XML 선언부 직후)에 문서 형식 선언(`<!DOCTYPE>`)을 기입해야 합니다.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE 잡지 SYSTEM "magazine.dtd">
<잡지>
    ...
</잡지>
```
위 코드는 **"이 문서의 루트 요소는 <잡지>이며, 문법 규칙은 외부 파일인 magazine.dtd에 정의되어 있다"**라고 파서에게 지시하는 것입니다. 이제 우리는 `magazine.dtd` 파일 안에 들어갈 법률(규칙)을 제정해야 합니다.

## 2. 요소 선언(ELEMENT)의 기본 문법

DTD에서 새로운 요소를 정의할 때는 `<!ELEMENT>`라는 키워드를 사용합니다. 그 뒤에 요소의 이름과, 그 요소가 품을 수 있는 내용 모델(Content Model)을 괄호 안에 명시합니다.

```dtd
<!ELEMENT 요소명 (내용모델)>
```

### 2.1 내용 모델(Content Model)의 종류
1. **자식 요소 지정:** 괄호 안에 다른 요소의 이름을 적으면, 그 요소가 자식으로 들어와야 함을 의미합니다. (예: `<!ELEMENT 잡지 (기사)>`)
2. **#PCDATA:** 요소 내부에 다른 태그(자식)가 아니라, 순수한 텍스트(문자열)만 들어갈 수 있을 때 사용합니다. 반드시 괄호 안에 기입해야 합니다. (예: `<!ELEMENT 제목 (#PCDATA)>`)
3. **EMPTY:** 빈 요소(`<이미지/>` 등)를 정의할 때 사용합니다. 괄호를 쓰지 않습니다. (예: `<!ELEMENT 이미지 EMPTY>`)
4. **ANY:** 어떠한 내용이든 다 들어갈 수 있습니다. (구조를 강제하는 DTD의 목적에 부합하지 않아 실무에서는 거의 쓰지 않습니다.)

## 3. 빈도 제어 연산자: 구조의 통제

자식 요소를 지정할 때, 단순히 이름만 나열하면 기계는 **"반드시 순서대로, 딱 1번씩만 등장해야 한다"**고 인식합니다. 하지만 인문학 데이터는 그렇게 단순하지 않습니다. 주석은 없을 수도 있고, 저자는 여러 명일 수 있습니다. 이를 통제하기 위해 DTD는 5가지의 강력한 제어 연산자를 제공합니다.



### 3.1 순서 연산자: `,` (Sequence)
쉼표는 자식 요소들이 **"반드시 명시된 순서대로"** 나타나야 함을 강제합니다.
```dtd
<!ELEMENT 기사 (제목, 저자, 본문)>
```
* **해석:** `<기사>` 내부에는 반드시 `<제목>`, `<저자>`, `<본문>`이 순서대로 딱 한 번씩만 등장해야 합니다. 순서가 바뀌거나 누락되면 유효성(Valid) 검사에서 탈락합니다.

### 3.2 선택 연산자: `|` (OR)
수직선(파이프) 기호는 제시된 요소 중 **"반드시 하나만 선택"**해야 함을 강제합니다.
```dtd
<!ELEMENT 날짜 (양력 | 음력)>
```
* **해석:** `<날짜>` 요소 안에는 `<양력>`이나 `<음력>` 중 하나만 올 수 있습니다. 둘 다 오거나 둘 다 없으면 안 됩니다.

### 3.3 수량 연산자: `?` (0번 또는 1번)
물음표는 해당 요소가 **"생략되거나, 최대 1번만 나타날 수 있음"**을 의미합니다. 즉, **"선택적(Optional) 요소"**를 지정할 때 씁니다.
```dtd
<!ELEMENT 책 (제목, 부제?, 저자)>
```
* **해석:** `<부제>`는 없어도 되지만, 있다면 2개 이상 쓸 수 없습니다. `<제목>`과 `<저자>`는 연산자가 없으므로 반드시 1번씩만 와야 합니다.

### 3.4 수량 연산자: `*` (0번 이상, 무한대)
별표(Asterisk)는 해당 요소가 **"아예 없어도 되고, 몇 번이든 무한대로 반복되어도 좋음"**을 의미합니다.
```dtd
<!ELEMENT 본문 (문단, 주석*)>
```
* **해석:** `<문단>` 뒤에 `<주석>`이 없어도 통과되며, `<주석>`이 100개 있어도 통과됩니다.

### 3.5 수량 연산자: `+` (1번 이상, 무한대)
더하기 기호는 해당 요소가 **"반드시 최소 1번은 등장해야 하며, 그 이상 무한히 반복될 수 있음"**을 의미합니다.
```dtd
<!ELEMENT 논문 (제목, 저자+)>
```
* **해석:** 논문에는 유령 저자가 있을 수 없으므로 `<저자>`가 아예 없으면 치명적 오류입니다. 그러나 공저자가 있을 수 있으므로 여러 번 반복되는 것은 허용됩니다.

## 4. 실전 마크업 스키마 설계 (Practicum)

지금까지 배운 연산자를 종합하여, 국사편찬위원회의 근현대잡지자료를 데이터베이스화하기 위한 DTD 구조를 설계해 보겠습니다.

**[상황적 요구사항]**
1. 최상위 루트는 `<잡지>`이다.
2. 잡지는 반드시 1개의 `<서지정보>`를 먼저 가지고, 그 뒤에 최소 1개 이상의 `<기사>`를 가져야 한다.
3. 서지정보는 `<발행일>`, `<잡지명>`, 그리고 생략 가능한 `<권호>`로 이루어진다.
4. 기사는 `<제목>`, 최소 1명 이상의 `<필자>`, 그리고 텍스트인 `<본문>`이나 이미지만 있는 `<원본스캔>` 중 하나를 선택해서 가져야 한다.

**[DTD 설계 코드 (`magazine.dtd`)]**
```dtd
<!ELEMENT 잡지 (서지정보, 기사+)>

<!ELEMENT 서지정보 (발행일, 잡지명, 권호?)>
<!ELEMENT 발행일 (#PCDATA)>
<!ELEMENT 잡지명 (#PCDATA)>
<!ELEMENT 권호 (#PCDATA)>

<!ELEMENT 기사 (제목, 필자+, (본문 | 원본스캔))>
<!ELEMENT 제목 (#PCDATA)>
<!ELEMENT 필자 (#PCDATA)>
<!ELEMENT 본문 (#PCDATA)>
<!ELEMENT 원본스캔 EMPTY>
```

이렇게 정밀하게 짜인 DTD 파일 하나가 있다면, 수십 명의 인문학 전공자들이 동시에 텍스트 마크업 작업을 수행하더라도 데이터의 구조적 뼈대가 절대 흔들리지 않는 견고한 아카이브를 구축할 수 있습니다. 

요소를 통한 구조의 통제법을 완벽히 마스터했습니다. 이어지는 장에서는 요소에 종속된 메타데이터인 **"속성(Attribute)"**을 강제하고 제어하는 문법, **"ATTLIST"** 선언부로 진입하겠습니다.
