# 문법적 엄밀성: 웰폼드(Well-formed)의 조건

과거 웹의 부흥을 이끌었던 HTML은 대단히 관대한 언어였습니다. 태그를 열어놓고 닫지 않거나, 속성값에 따옴표를 생략해도 웹 브라우저는 어떻게든 오류를 무시하고 사용자에게 화면을 렌더링해 주었습니다. 그러나 이러한 관대함은 데이터의 논리적 구조를 서서히 붕괴시켰고, 결국 컴퓨터가 텍스트의 맥락을 이해하지 못하게 만드는 원인이 되었습니다.

XML(eXtensible Markup Language)은 이러한 관대함을 철저히 배격합니다. XML 파서(Parser)는 단 하나의 문법적 오류만 발견해도 즉시 분석을 멈추고 시스템에 “**치명적 오류(Fatal Error)**”를 보고합니다. 이 장에서는 인문학적 데이터가 기계에게 거부당하지 않고 온전한 트리(Tree) 구조로 인정받기 위해 반드시 지켜야 하는 최소한의 물리적 생존 조건, 즉 “**웰폼드(Well-formed, 잘 짜인 문서)**”의 5대 절대 규칙을 심층적으로 다룹니다.

## 1. 웰폼드(Well-formed)란 무엇인가?

디지털 문헌학에서 XML 문서를 평가하는 기준은 크게 두 가지 단계로 나뉩니다.

1. **웰폼드(Well-formed):** 문서가 XML의 기본 문법(태그 작성법, 트리 구조 규칙 등)을 완벽하게 준수했는가를 따지는 “**형식적 엄밀성**”입니다. 이 조건을 통과하지 못하면 기계는 문서 자체를 읽어 들이지 못합니다.
2. **유효성(Valid):** 웰폼드를 통과한 문서가 사전에 정의된 특정 학문적 설계도(DTD, XSD 등)의 규칙(예: `<기사>` 태그 안에는 반드시 `<날짜>`가 있어야 한다)까지 준수했는가를 따지는 “**내용적 엄밀성**”입니다. (이는 다음 장에서 다룹니다.)

따라서 웰폼드는 XML 문서가 컴퓨터 생태계에 존재하기 위한 가장 기초적이고 절대적인 헌법과도 같습니다.

## 2. 잘 짜인 문서의 5대 절대 규칙

XML 파서가 문서를 파싱할 때 검사하는 5가지 핵심 규칙은 다음과 같습니다. 이 중 단 하나라도 어긋나면 문서는 붕괴합니다.

### 2.1 단 하나의 루트(Root) 요소
모든 XML 문서는 나무의 기둥처럼, 문서 전체의 데이터를 감싸는 최상위 요소인 “**루트 요소**”를 오직 하나만 가져야 합니다. 뿌리가 여러 개인 나무는 존재할 수 없습니다.

**[오류 예시: 루트 요소가 2개인 경우]**
```xml
<잡지명>개벽</잡지명>
<발행년도>1920</발행년도>
```

**[수정 완료: 단일 루트 요소로 감싼 경우]**
```xml
<근현대잡지자료>
    <잡지명>개벽</잡지명>
    <발행년도>1920</발행년도>
</근현대잡지자료>
```
위와 같이 `<근현대잡지자료>`라는 단 하나의 루트 요소가 전체 문서를 묶어주어야만 컴퓨터는 하나의 완결된 데이터베이스로 인식합니다.

### 2.2 시작 태그와 종료 태그의 완벽한 짝
XML에서 스스로 닫히는 빈 요소(Empty Element)를 제외한 모든 요소는 반드시 꺾쇠괄호(`< >`)로 시작하여 슬래시가 포함된 꺾쇠괄호(`</ >`)로 닫혀야 합니다.

* **오류:** `<인물>이순신` (닫는 태그 누락)
* **오류:** `이순신</인물>` (여는 태그 누락)
* **정상:** `<인물>이순신</인물>`
* **정상 (빈 요소):** `<이미지 url="photo.jpg"/>` (끝에 `/`를 넣어 스스로 닫음을 명시)

### 2.3 교차(Overlapping) 금지와 철저한 포함 관계
디지털 문헌 마크업에서 가장 빈번하게 발생하면서도 가장 치명적인 오류입니다. XML 요소들은 반드시 “**나중에 열린 태그가 먼저 닫혀야 한다(LIFO: Last In, First Out)**”는 포함 관계의 절대 원칙을 지켜야 합니다. 부모와 자식의 경계가 엇갈리는 것을 “**교차(Overlapping)**”라고 부릅니다.

**[오류 예시: 태그의 교차]**
```xml
<문장>이순신은 <지명>한산도</문장>에서 싸웠다.</지명>
```



위의 코드에서 파서는 `<문장>`이라는 부모 요소 안에 `<지명>`이라는 자식 요소가 생겼다고 인식합니다. 그런데 자식인 `<지명>`이 닫히기도 전에 부모인 `</문장>`이 먼저 닫혀버립니다. 이렇게 되면 컴퓨터는 누가 누구의 내부에 존재하는지 위계 구조(Hierarchy)를 그릴 수 없게 되어 즉시 파싱을 중단합니다.

**[수정 완료: 철저한 포함 관계]**
```xml
<문장>이순신은 <지명>한산도</지명>에서 싸웠다.</문장>
```

### 2.4 대소문자의 엄격한 일치
컴퓨터의 메모리 상에서 대문자와 소문자는 완전히 다른 아스키(ASCII) 코드값을 가집니다. 따라서 여는 태그와 닫는 태그의 대소문자가 1바이트라도 다르면 짝을 잃은 것으로 간주합니다.

* **오류:** `<Person>홍길동</person>`
* **오류:** `<PERSON>홍길동</person>`
* **정상:** `<person>홍길동</person>`

이러한 엄격함 때문에 실무에서는 휴먼 에러를 방지하기 위해 태그 이름을 소문자로 통일하거나, 낙타 표기법(CamelCase, 예: `<personName>`)을 사용하는 등 팀 내부의 명확한 컨벤션(Convention)을 세우는 것이 중요합니다.

### 2.5 속성값의 인용 부호 필수 사용
요소의 시작 태그 내부에 들어가는 모든 “**속성(Attribute)**”의 값은 예외 없이 큰따옴표(`" "`) 또는 작은따옴표로 둘러싸여야 합니다. (디지털 인문학계의 일반적인 코딩 표준은 큰따옴표를 사용하는 것입니다.)

* **오류:** `<기사 id=M001>` (인용 부호 누락)
* **정상:** `<기사 id="M001">`

HTML에서는 속성값에 공백이 없다면 따옴표를 생략해도 웹 브라우저가 알아서 처리해 주었지만, XML 파서는 이러한 모호함을 절대 용납하지 않습니다. 데이터베이스 쿼리 연산 시 문자열(String)의 시작과 끝을 정확히 통제하기 위함입니다.

## 3. 엄밀성이 가져다주는 인문학적 가치

초보 연구자들은 이러한 XML의 융통성 없는 깐깐함에 종종 피로감을 호소합니다. 그러나 이 “**무관용 원칙**”이야말로 수십, 수백 년간 인류의 지적 자산을 에러 없이 보존하게 해주는 가장 강력한 방패입니다. 

문서가 웰폼드(Well-formed) 규칙을 통과했다는 것은, 그 데이터가 파이썬(Python) 파서든, 거대 데이터베이스(MSSQL, Oracle)든, 수백 년 뒤에 발명될 그 어떤 연산 장치든 100% 동일하고 투명한 논리적 트리 구조로 읽힐 수 있음을 정보공학적으로 보증받았다는 뜻입니다.

기본적인 체력을 다지는 웰폼드 규칙을 마스터했으니, 이제 서로 다른 연구 기관의 데이터베이스가 하나로 결합할 때 발생하는 충돌 문제를 해결하는 기술, “**네임스페이스(Namespace)**”의 심오한 세계로 넘어가 보겠습니다.
