# 실무 팁: 정규표현식을 활용한 일괄 치환과 다중 커서를 이용한 반복 태깅

디지털 문헌학 프로젝트를 진행하다 보면, AI가 초안을 훌륭하게 뽑아주었음에도 불구하고 연구자가 직접 수백, 수천 개의 동일한 태그를 반복해서 수정하거나 씌워야 하는 가혹한 순간이 반드시 찾아옵니다. 

예를 들어, 수백 줄의 목록에서 이름 양옆에 일일이 `<persName>` 꺾쇠를 치고 있다면, 여러분은 컴퓨터의 능력을 1%도 활용하지 못하고 있는 것입니다. 이 장에서는 며칠이 걸릴 단순 반복 작업을 단 5초 만에 끝내버리는 VS Code의 두 가지 마법, `"**다중 커서(Multi-cursor)**"`와 `"**정규표현식(Regular Expression, Regex)**"` 활용법을 마스터합니다.

## 1. 공간을 지배하는 마법: 다중 커서 (Multi-cursor)

보통 텍스트 에디터에서 커서(깜빡이는 선)는 단 하나만 존재합니다. 하지만 VS Code에서는 화면 곳곳에 수십 개의 커서를 동시에 배치하고, 키보드를 한 번 두드릴 때마다 모든 커서에서 똑같이 글자가 타이핑되게 만들 수 있습니다.



### 1.1 `Alt + Click` : 원하는 위치에 커서 심기
가장 직관적인 방법입니다. 키보드의 `Alt` 키(Mac은 `Option`)를 누른 상태에서 텍스트의 원하는 곳들을 마우스로 클릭해 보십시오. 클릭한 횟수만큼 커서가 늘어납니다.
* **실무 활용:** 불규칙하게 흩어진 5명의 인물 이름 앞에 커서를 5개 찍어놓고, `<persName>`을 한 번만 타이핑하여 동시에 태그를 엽니다.

### 1.2 `Ctrl + D` : 동일한 단어 연쇄 선택 ★
마크업 실무에서 가장 많이 쓰이는 환상적인 단축키입니다. 
특정 단어(예: '이광수')를 드래그한 뒤 `Ctrl + D` (Mac은 `Cmd + D`)를 누를 때마다, 문서 아래쪽에 있는 다음 '이광수'가 차례대로 추가 선택되며 다중 커서가 생성됩니다. 
* **실무 활용:** 문서 전체에 등장하는 특정 인물의 이름을 모두 선택한 뒤, 양옆 화살표 키(`←`, `→`)를 눌러 텍스트 양끝으로 커서를 빼고 `<persName>` 태그를 한 번에 씌웁니다.

### 1.3 `Shift + Alt + Drag` : 수직 블록 커서
목록 형태로 정리된 데이터에 규칙적으로 태그를 씌울 때 사용합니다. `Shift`와 `Alt`를 동시에 누른 채로 마우스를 아래로 드래그하면, 세로로 길게 이어진 수십 개의 커서가 생성됩니다.
* **실무 활용:** 엑셀에서 복사해 온 100줄짜리 연표 데이터의 맨 앞줄을 세로로 긁어 `<date>` 태그를 단숨에 타이핑합니다. (이후 `End` 키를 눌러 맨 끝으로 이동해 `</date>`를 닫습니다.)

## 2. 패턴을 지배하는 마법: 정규표현식 (Regex) 기초

다중 커서가 '눈에 보이는 곳'을 칠하는 물리적인 기술이라면, `"**정규표현식(Regex)**"`은 텍스트의 '패턴'을 찾아내어 기하급수적인 연산을 수행하는 정보공학의 꽃입니다.

VS Code에서 `Ctrl + F` (찾기) 또는 `Ctrl + H` (찾기 및 바꾸기) 패널을 열고, 입력창 우측의 `"**.* 아이콘(Use Regular Expression)**"`을 클릭하면 정규표현식 모드가 켜집니다.



### 2.1 핵심 메타 문자 (Meta-characters)
글자 그대로를 찾는 것이 아니라, 글자의 '종류'를 기호로 찾습니다.
* `\d` : 숫자 1개 (예: `\d\d\d\d` = 1920, 1592 등 4자리 숫자)
* `\w` : 문자나 숫자 1개 (단어)
* `.*` : 모든 문자의 무한한 반복 (어떤 내용이든 상관없음)

### 2.2 캡처 그룹(Capture Group)과 치환(`$1`) ★
정규표현식 마크업의 핵심은 내가 찾은 텍스트를 `"**기억**"`했다가 치환할 때 `"**재사용**"`하는 것입니다. 찾을 내용에 괄호 `()`를 치면 컴퓨터는 그 내용을 기억하며, 바꿀 내용에서 `$1`, `$2` 등으로 순서대로 불러올 수 있습니다.

## 3. 실전 DH 마크업 시나리오 (Regex Practicum)

이 놀라운 기능이 실제 아카이브 구축 현장에서 어떻게 쓰이는지 확인해 봅시다.

### 3.1 시나리오 1: 대괄호 안의 이름을 태그로 변환하기
OCR을 거친 원시 텍스트나 조교가 정리한 한글 파일에 `[최남선]`, `[이광수]`처럼 이름이 대괄호로 묶여 있습니다. 이를 모두 `<persName>` XML 태그로 치환해야 합니다.

* **찾을 내용 (Find):** `\[(.*?)\]`
  * *해석: `[` 와 `]` 사이에 있는 임의의 문자열 `(.*?)`을 찾아서 1번 그룹 `()`으로 캡처하라.*
* **바꿀 내용 (Replace):** `<persName>$1</persName>`
  * *해석: 찾은 문자열의 껍데기를 버리고, 캡처해 둔 알맹이(`$1`)를 `<persName>` 태그로 감싸라.*

**결과:** `[최남선]` -> `<persName>최남선</persName>`으로 문서 내의 수백 개 데이터가 1초 만에 변환됩니다.

### 3.2 시나리오 2: 날짜 형식의 정규화 (Normalization)
문서에 "1920년 3월 1일"이라는 텍스트가 널려 있습니다. 이를 TEI 표준인 `<date when="1920-03-01">` 형태로 정규화하여 씌워야 합니다.

* **찾을 내용:** `(\d{4})년 (\d{1,2})월 (\d{1,2})일`
  * *해석: 4자리 숫자(연도)를 1번 그룹에, 1~2자리 숫자(월)를 2번 그룹에, 1~2자리 숫자(일)를 3번 그룹에 캡처하라.*
* **바꿀 내용:** `<date when="$1-$2-$3">$1년 $2월 $3일</date>`
  * *주의: 이 예시는 월/일이 두 자리(03)로 완벽히 맞춰져 있을 때 유효하며, 한 자리일 경우 패딩(Padding) 스크립트가 추가로 필요할 수 있습니다.*

### 3.3 시나리오 3: 엉켜있는 속성값 정리
AI가 환각을 일으켜 `<person id="P001">`처럼 TEI 표준(`xml:id`)을 어기고 마음대로 `id` 속성을 써버렸습니다.

* **찾을 내용:** `<person id="(.*?)">`
* **바꿀 내용:** `<person xml:id="$1">`

결론적으로, VS Code의 다중 커서와 정규표현식은 인문학자의 소중한 시간과 체력을 지켜주는 궁극의 방패이자 창입니다. 이 기술을 손에 쥐는 순간, 수십만 자의 아날로그 텍스트가 한 줌의 데이터 찰흙처럼 유연하게 느껴질 것입니다. 

이로써 데이터를 설계하고, 기계와 협업하여 편찬하며, 툴을 통해 이를 극도로 효율화하는 [Level 2] 8장의 여정이 모두 끝났습니다. 이제 다음 장에서는 지금까지 배운 모든 지식을 총동원하여, 한국학중앙연구원과 국사편찬위원회가 구축한 실제 사료의 뱃속을 갈라보는 **"9장. 한국 인문학 데이터 마크업 케이스 스터디"**로 벅찬 발걸음을 내딛겠습니다.
