# 거시 구조와 편년체 사료의 데이터 모델링: `<level1~5>`를 활용한 왕-년-월-일-기사의 5단 위계 구조와 ID 부여 규칙 분석

잡지나 단행본이 '공간적' 편집물이라면, 동아시아의 기록 문화를 대표하는 실록(實錄)은 철저하게 '시간적' 흐름을 따르는 `"**편년체(編年體)**"` 사료입니다. 472년이라는 장구한 세월 동안 매일매일 발생한 국가의 모든 사건을 기록한 조선왕조실록을 디지털 데이터베이스로 구축하는 것은, 곧 `"**거대한 다원적 시간을 정보공학적으로 모델링하는 작업**"`이었습니다.

이 장에서는 국사편찬위원회가 제공한 조선왕조실록 원시 데이터(`2nd_wda_111.xml`, `2nd_wka_135.xml` 등)를 정밀하게 해부하여, 실록 특유의 시공간을 어떻게 5단의 위계 구조(`<level>`)로 제어하고 있는지, 그리고 그 식별자(ID) 안에 어떠한 치밀한 암호가 숨겨져 있는지 분석합니다.



## 1. 편년체 사료의 5단 위계 모델링

서구의 범용 TEI 가이드라인(`<div>`)만으로는 왕조의 연대기적 구조를 통제하기 어렵습니다. 국사편찬위원회의 통합 DTD는 조선왕조실록의 뼈대를 다음과 같은 `"**5단 위계 구조**"`로 강제 할당했습니다.

1. **`<level1>` (왕대):** 특정 왕의 실록 전체 (예: 태조실록, 세종실록)
2. **`<level2>` (년):** 재위 연도 (예: 세종 11년)
3. **`<level3>` (월):** 해당 연도의 특정 월
4. **`<level4>` (일):** 해당 월의 특정 일자
5. **`<level5>` (기사):** 그날 발생한 개별 사건(기사) 단위

### 1.1 계층의 플래트닝(Flattening) 기법 ★
그러나 제공된 세종실록 11년 샘플(`2nd_wda_111.xml`)을 살펴보면, 매우 흥미로운 정보공학적 기법이 발견됩니다.

**[2nd_wda_111.xml의 뼈대 구조]**
```xml
<level2 id="wda_111">
    <front> ... 세종 11년 메타데이터 ... </front>
    <text> ... </text>
    
    <level5 id="wda_11112029_001">
        <front> ... 개별 기사 메타데이터 ... </front>
        <text>
            <content>
                <paragraph>○辛丑/設宴于內殿。 使臣進錫鍍金瑪瑠帶...</paragraph>
            </content>
        </text>
    </level5>
</level2>
```
XML 트리 상에서 `<level3>`(월)과 `<level4>`(일) 태그가 생략되고, `<level2>` 바로 아래에 `<level5>`가 직접 병렬로 나열되어 있습니다. 
이는 컴퓨터가 문서를 파싱할 때 트리가 너무 깊어지는(Deep Nesting) 연산 과부하를 막기 위해, 중간 계층의 태그를 걷어내는 `"**플래트닝(Flattening)**"` 최적화를 수행한 것입니다. 

그렇다면 생략된 '몇 월 며칠'이라는 정보는 어디로 갔을까요? 바로 기사의 주민등록번호인 `"**id 속성**"` 안으로 완벽하게 흡수되었습니다.

## 2. 식별자(ID)에 숨겨진 완벽한 암호 체계

조선왕조실록 데이터베이스 시스템의 가장 위대한 설계는 바로 개별 기사(`<level5>`)에 부여된 `"**ID 부여 규칙(Naming Convention)**"`에 있습니다. `id="wda_11112029_001"`이라는 짧은 문자열을 역공학(Reverse Engineering)으로 해독해 보겠습니다.



* **`wda` (3자리): 왕대 코드.** (`waa`: 태조, `wda`: 세종, `wka`: 중종 등)
* **`1` (1자리): 편찬본 종류.** (일반적으로 `1`은 정족산본/태백산본 기반의 정통 실록을 의미하며, 광해군일기처럼 중초본/정초본이 나뉠 경우 이 숫자가 변합니다.)
* **`11` (2자리): 재위 연도.** (세종 11년)
* **`12` (2자리): 월.** (12월)
* **`0` (1자리): 윤달 식별자.** (`0`은 평달, `1`은 윤달을 의미하여 동아시아 태음력의 한계를 기계적으로 제어합니다.)
* **`29` (2자리): 일.** (29일)
* **`_001` (4자리): 기사 순번.** (해당 일자의 첫 번째 기사)

### 2.1 ID 체계가 RDB 검색에 미치는 위력
이 치밀한 고정 자릿수(Fixed-length) ID 규격은, XML이 관계형 데이터베이스(RDB) 테이블로 이관되었을 때 압도적인 성능을 발휘합니다. 

만약 개발자가 "세종 시대의 모든 윤달 기사만 뽑아라"라는 쿼리를 작성한다면, 무거운 XML 본문이나 `<date>` 태그를 뒤질 필요가 없습니다. RDB에서 `SELECT * FROM sillok WHERE id LIKE 'wda_____%1%_%;'` 와 같이 ID 컬럼의 특정 자릿수만 매칭하는 것만으로 0.01초 만에 데이터를 추출할 수 있습니다. 
구조적 위계(XML)와 검색 효율(RDB)을 동시에 만족시키는 완벽한 식별자 설계입니다.

## 3. 총서(總序) 등 예외 구조의 유연한 수용

실록은 편년체이지만, 왕의 즉위 전 가계도나 배경을 설명하는 총서(總序) 부분은 연/월/일의 시간 개념이 존재하지 않습니다. 국사편찬위원회의 통합 DTD는 이러한 예외를 어떻게 처리했을까요?

**[2nd_waa_000.xml 태조실록 총서 샘플]**
```xml
<level1 id="waa">
    <level2 id="waa_000"> <front>
            <biblioData><title><mainTitle>總序</mainTitle></title></biblioData>
        </front>
        <level3 id="waa_000001">
            <front>
                <biblioData>
                    <title><mainTitle>태조 이성계 선대의 가계...</mainTitle></title>
                </biblioData>
            </front>
        </level3>
    </level2>
</level1>
```
시간이 없는 총서의 경우, 연도 자리에 `"**000**"`이라는 더미(Dummy) 코드를 삽입하여 시스템 에러를 방지했습니다. 또한 월/일이 없으므로 `<level4>`, `<level5>`로 내려가지 않고 `<level3>`에서 개별 기사를 마무리하는 유연함을 보여줍니다.

결론적으로 조선왕조실록의 `<level>` 구조와 ID 체계는 470여 년의 장구한 역사적 시공간을 현대 컴퓨터 과학의 알고리즘 위로 완벽하게 올려놓은 정보공학적 예술 작품입니다. 

거시적인 시간의 틀을 확인했으니, 이어지는 장에서는 이 뼈대 안에서 간지(干支), 명나라 연호, 서기 등 복잡하게 얽혀 있는 동아시아의 다원적 시간을 어떻게 1차원 데이터로 정규화했는지 그 치열한 흔적을 탐구하는 **"다원적 기년법의 정보공학적 정규화: `<dateOccured>`"** 파트로 진입하겠습니다.
