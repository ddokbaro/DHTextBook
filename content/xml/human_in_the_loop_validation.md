# 인간-기계 협업: AI 초안의 논리적 모순 검증과 미시적 교정 팁

거대 언어 모델(LLM)을 활용한 정교한 프롬프팅으로 XML 초안(Draft)을 얻어냈다고 해서 데이터 편찬이 끝난 것은 결코 아닙니다. LLM은 본질적으로 문맥을 확률적으로 예측하는 텍스트 생성기일 뿐, 인문학적 진실을 판별하는 검증기가 아니기 때문입니다. 

AI는 종종 꺾쇠(`< >`)를 빼먹는 초보적인 문법 실수를 저지르기도 하고, 역사적 배경지식이 부족하여 동명이인을 같은 사람으로 묶어버리는 치명적인 논리적 오류를 범하기도 합니다. 따라서 현대 디지털 문헌학에서 데이터의 품질을 결정짓는 최종 관문은 결국 `"**인간 전문가의 검수(Human-in-the-loop)**"`입니다. 이 장에서는 AI가 남긴 오류의 흔적을 기계적, 논리적으로 색출하고 미시적으로 교정하는 핵심 실무를 다룹니다.



## 1. 1차 관문: 기계적 문법 검증 (Well-formedness & Schema)

AI가 생성한 XML 텍스트를 눈으로 한 줄씩 읽으며 꺾쇠가 제대로 닫혔는지 확인하는 것은 가장 미련한 방식입니다. 기계가 만든 오류는 우선 기계의 힘(Validator)을 빌려 단숨에 잡아내야 합니다.

### 1.1 계층의 교차(Overlapping Hierarchy) 색출
LLM이 가장 자주 저지르는 XML 문법 오류는 태그의 열고 닫는 순서가 꼬이는 `"**계층 교차**"` 현상입니다. 

**[AI가 자주 범하는 오류 예시]**
```xml
<p>
    이때 <roleName>영의정 <persName>류성룡</roleName></persName>이 아뢰기를...
</p>
```
이러한 데이터는 Oxygen XML Editor나 VS Code의 XML 플러그인에 복사해 넣는 즉시 붉은색 밑줄과 함께 에러가 출력됩니다. 편집기의 **"문서 서식 지정(Format Document)"** 기능을 실행하면, 웰폼드(Well-formed)가 깨진 정확한 줄 번호(Line number)를 즉각적으로 찾아낼 수 있습니다.

### 1.2 스키마(XSD/Schematron) 기반 일괄 검증
태그가 정상적으로 닫혔다 하더라도, 우리가 앞서 설계한 TEI 가이드라인 규칙에 맞는지 확인해야 합니다.
예를 들어 `<date>` 태그 안에 반드시 `@when` 속성을 넣으라고 프롬프트로 지시했음에도 AI가 이를 누락했다면, Schematron 검증기를 돌려 속성이 누락된 모든 `<date>` 노드들의 목록을 패널에 띄우고 일괄적으로 교정해야 합니다.



## 2. 2차 관문: 논리적, 문헌학적 모순 검증

문법적 오류가 모두 해결되었다면, 이제 XML 문서로서의 자격은 갖춘 것입니다. 그러나 진정한 인문학적 검수는 지금부터 시작입니다. 기계는 절대로 텍스트 이면에 숨겨진 `"**역사적 컨텍스트(Context)**"`를 이해하지 못합니다.

### 2.1 동명이인과 개체명 정규화(Normalization)의 오류
역사 인물 간의 사회 연결망(SNA)을 구축하기 위해 종묘배향공신 데이터를 마크업한다고 가정해 봅시다. 원문에 "김공(金公)"이라는 지칭이 등장했을 때, AI는 단순히 이를 `<persName>김공</persName>`으로 태깅할 것입니다. 

그러나 문헌학자는 이 텍스트가 작성된 연도, 발화자의 정치적 파벌 등을 종합적으로 고려하여 이 "김공"이 특정 인물임을 식별해 내야 합니다. 

**[인간 편집자의 미시적 교정]**
```xml
<p><persName>김공</persName>이 말하기를...</p>

<p><persName ref="[http://people.aks.ac.kr/front/dirSer/ppl/pplView.aks?pplId=PPL_6JOc_A1545_1_0009675](http://people.aks.ac.kr/front/dirSer/ppl/pplView.aks?pplId=PPL_6JOc_A1545_1_0009675)">김공(金公)</persName>이 말하기를...</p>
```

### 2.2 복합 관직명과 형태소의 오독
한문 사료를 번역한 텍스트에서 AI는 종종 관직명과 인물명을 엉뚱하게 분리합니다. 예를 들어 "병조판서겸지의금부사(兵曹判書兼知義禁府事)"와 같은 복합 직함을 AI가 이해하지 못하고 `<roleName>병조판서</roleName> 겸 <roleName>지의금부사</roleName>`로 분절해 버릴 수 있습니다. 인간 검수자는 이러한 파편화된 태그를 하나로 묶어 원래의 사료적 의미를 복원해야 합니다.

## 3. 효율적인 미시 교정을 위한 실무 팁

수만 건의 태그를 교정할 때 생산성을 극대화하는 노하우입니다.

1. **정규표현식(Regex)의 적극 활용:** 특정 오태깅 패턴이 반복된다면, 편집기의 검색/치환 기능에 정규표현식을 적용하여 수백 개의 오류를 단 한 번의 클릭으로 일괄 교정(Batch Replace)하십시오.
2. **프롬프트 재조정 (Feedback Loop):** AI가 특정 유형의 오류(예: 특정 관직명을 계속 놓치는 현상)를 반복적으로 낸다면, 이를 인간이 모두 수작업으로 고치려 하지 마십시오. 그 즉시 작업을 멈추고 프롬프트의 예시(Few-shot)를 수정하여 **AI에게 다시 초안을 뽑아내게 하는 것**이 전체 작업 시간을 획기적으로 단축시킵니다.
3. **편집자의 주체성:** 원문에 치명적인 오기가 있어 교감이 필요한 경우, AI의 결과물에 얽매이지 말고 과감하게 `<choice>`, `<sic>`, `<corr>` 등의 교감 태그를 직접 삽입하여 비판적 교감본(Critical Edition)을 완성하십시오.

결론적으로, 전자문서와 하이퍼텍스트의 세계에서 AI는 압도적인 속도로 데이터를 퍼 나르는 조수일 뿐입니다. 그 데이터가 학술적 진실에 부합하는지 판별하고, 파편화된 텍스트에 생명력(Link)을 불어넣어 인류의 지식 네트워크로 편입시키는 최종 설계자이자 책임자는 바로 `"**인간 문헌학자**"`입니다.
