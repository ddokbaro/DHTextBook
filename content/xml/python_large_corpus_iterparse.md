# 대용량 역사 코퍼스 메모리 제어: iterparse

우리가 앞서 배운 `etree.parse()` 메서드는 사용하기에는 매우 직관적이고 편리하지만, 치명적인 구조적 한계를 가지고 있습니다. 바로 하드디스크에 있는 XML 문서의 **모든 내용을 한꺼번에 컴퓨터의 주 메모리(RAM)에 올려 거대한 트리(Tree) 객체를 생성한다**는 점입니다. 이를 `"**DOM(Document Object Model) 방식**"`이라고 부릅니다.

일반적인 문집이나 짧은 논문 데이터라면 이 방식이 문제 되지 않습니다. 그러나 국사편찬위원회의 **조선왕조실록**이나 **승정원일기**처럼 원본 텍스트 파일 하나가 수 GB에 달하는 초거대 코퍼스(Corpus)를 `etree.parse()`로 읽어 들이면 어떻게 될까요? 파이썬은 이 텍스트를 객체로 변환하기 위해 원본 용량의 3~4배에 달하는 15GB 이상의 RAM을 순식간에 집어삼키며, 결국 `"**메모리 초과(Out of Memory)**"` 에러를 내뿜고 서버를 다운시키게 됩니다.

이 장에서는 이러한 물리적 한계를 극복하고, 무한대의 용량을 가진 XML 파일도 끄떡없이 처리해 내는 마법과도 같은 `"**이벤트 기반 스트리밍(Event-driven Streaming)**"` 파싱 기법을 탐구합니다.

## 1. 패러다임의 전환: 스트리밍 파싱

거대한 책을 읽을 때 책 전체를 머릿속에 한 번에 집어넣는 사람은 없습니다. 한 페이지를 읽고 필요한 정보를 메모한 뒤, 그 페이지의 내용은 머릿속에서 지우고 다음 페이지로 넘어가는 것이 정상입니다. 



이와 똑같은 원리로 작동하는 함수가 바로 `lxml` 라이브러리의 `"**iterparse()**"`입니다. `iterparse()`는 문서를 메모리에 한 번에 올리지 않고, 파일의 첫 줄부터 끝 줄까지 물 흐르듯 순차적으로(Stream) 읽어 내려갑니다. 그러다가 연구자가 지정한 특정 태그(예: `<기사>`)가 **닫히는 순간(End Event)**, 그 태그 내부의 데이터만 임시로 메모리에 올려 우리에게 전달해 줍니다.

## 2. `iterparse`의 기초 활용법

`iterparse()`는 반복문(`for`)과 결합하여 사용되며, 매 반복마다 `(이벤트 종류, 요소 객체)`의 쌍을 반환합니다.

```python
from lxml import etree

# 1. 파일 경로와 이벤트를 발생시킬 대상 태그 지정
# 'end' 이벤트는 해당 태그가 닫힐 때(</기사>)를 의미합니다.
context = etree.iterparse('massive_history_corpus.xml', events=('end',), tag='기사')

article_count = 0

# 2. 문서를 스트리밍하며 <기사> 태그가 닫힐 때마다 요소를 획득
for event, elem in context:
    article_count += 1
    
    # 기사 내부의 제목 요소 탐색
    title = elem.findtext('제목')
    
    # 1000번째 기사마다 로그 출력
    if article_count % 1000 == 0:
        print(f"{article_count}번째 기사 처리 중... 제목: {title}")
```
이 코드를 실행하면 파이썬은 수 GB의 파일을 읽으면서도 메모리 점유율을 극도로 낮게 유지하며 엄청난 속도로 데이터를 스캔해 냅니다.

## 3. [핵심 실무] 메모리 누수(Memory Leak)의 함정과 완벽한 해제

초보 개발자들이 `iterparse()`를 사용할 때 가장 많이 겪는 비극은, 이 함수를 썼음에도 불구하고 결국 메모리 초과 에러가 발생한다는 것입니다. 

그 이유는 `iterparse()`가 태그를 던져주기는 하지만, **우리가 명시적으로 지우지 않으면 파이썬은 혹시 몰라 그 노드들을 계속해서 백그라운드 트리(Tree)에 매달아 두기 때문**입니다. 따라서 우리는 정보를 다 빼먹은 요소(Element)를 가차 없이 쓰레기통에 버려주는 `"**메모리 해제(Clear)**"` 작업을 반드시 수행해야 합니다.

### 3.1 가장 완벽한 메모리 해제 패턴 ★
단순히 `elem.clear()`를 호출하는 것만으로는 부족합니다. 루트(Root) 노드가 계속해서 자식들의 빈 껍데기를 쥐고 있기 때문입니다. 이전 형제 노드(Previous Sibling)들과의 연결 고리까지 완전히 끊어버리는 아래의 코드는 대용량 XML 처리의 `"**바이블(Bible)**"`과도 같은 패턴입니다.

```python
from lxml import etree

context = etree.iterparse('massive_history_corpus.xml', events=('end',), tag='기사')

# 빠른 탐색을 위해 iterparse 객체를 튜플 언패킹으로 순회
for event, elem in context:
    
    # --- [1단계: 필요한 데이터 추출 및 RDB/CSV 저장] ---
    article_id = elem.attrib.get('ID')
    title = elem.findtext('제목')
    
    # (이곳에 DB에 데이터를 Insert하는 코드가 들어갑니다)
    
    # --- [2단계: 메모리 완벽 해제 (핵심)] ---
    # 1. 요소 내부의 텍스트와 자식 노드들을 메모리에서 삭제
    elem.clear()
    
    # 2. 부모 노드 입장에서, 이미 처리가 끝난 이전 형제 노드들과의 연결을 삭제
    while elem.getprevious() is not None:
        del elem.getparent()[0]

# 3. 루트 노드의 메모리까지 최종 정리
del context
```

### 3.2 왜 이렇게까지 지워야 하는가?
`<기사>` 태그 하나를 처리하고 `elem.clear()`를 하면 그 기사의 내용은 지워지지만, 이 기사를 감싸고 있는 최상위 `<조선왕조실록>` 태그는 여전히 남아있습니다. 파이썬은 문서가 끝날 때까지 루트 태그를 닫을 수 없으므로, 수십만 개의 빈 `<기사>` 껍데기들이 계속해서 루트에 매달려 메모리를 갉아먹게 됩니다.

위의 `while elem.getprevious() is not None:` 구문은 **"내 앞서 지나간 형제들은 이미 처리가 끝났으니 부모의 호적에서 파내어 메모리에서 영구히 삭제하라"**는 가장 안전하고 강력한 정보공학적 조치입니다.

결론적으로 `iterparse`와 철저한 메모리 해제 패턴을 결합하면, 일반적인 개인용 노트북에서도 국회도서관 전체 규모의 XML 데이터를 거뜬히 파싱하고 분석할 수 있는 막강한 컴퓨팅 파워를 얻게 됩니다. 

거대한 데이터의 바다를 건너는 법을 배웠으니, 이어지는 마지막 장에서는 파싱한 XML 데이터를 최신 데이터 과학의 언어인 `"**Pandas 데이터프레임(DataFrame)**"`으로 변환하여 통계 및 네트워크 분석을 준비하는 실무 파이프라인을 구축하겠습니다.
