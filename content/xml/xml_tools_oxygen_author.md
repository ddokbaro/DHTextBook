# DH 학계의 표준 도구: Oxygen의 철학과 가독성을 극대화하는 Author 모드

앞서 우리는 AI가 생성한 마크업 초안을 인간 연구자가 어떻게 검증하고 교정해야 하는지, 그 `"**인간-기계 협업(Human-in-the-loop)**"`의 패러다임을 확인했습니다. 그러나 메모장이나 단순한 텍스트 에디터로 수만 줄에 달하는 XML 코드를 열어놓고 인간이 직접 오류를 찾아내는 것은 불가능에 가깝습니다. 

전 세계의 거대한 디지털 인문학(DH) 프로젝트, 특히 TEI 컨소시엄을 이끄는 학자들은 코딩 전문 소프트웨어 대신 `"**Oxygen XML Editor**"`라는 유료 상용 소프트웨어를 사실상의 학계 표준 도구로 채택하여 사용하고 있습니다. 이 장에서는 단순한 편집기를 넘어선 Oxygen의 설계 철학과, 인문학자의 가독성을 극대화하여 텍스트 교감의 질을 높이는 `"**Author 모드(Author Mode)**"`의 위력을 심층 해부합니다.

## 1. Oxygen XML Editor의 철학: XML을 위한 완벽한 IDE

개발자들에게 최고의 툴로 꼽히는 VS Code나 IntelliJ는 파이썬(Python), 자바(Java) 등 범용 프로그래밍 언어를 위해 설계되었습니다. 반면, Oxygen은 오직 `"**XML 생태계(XML Ecosystem)**"` 하나만을 위해 20년 이상 벼려진 장인의 도구입니다.

단순히 텍스트에 색깔을 입혀주는 것을 넘어, DTD/XSD 스키마를 실시간으로 추적하여 오타를 막아주고, 복잡한 XPath 연산과 XSLT 변환, 심지어 네이티브 XML 데이터베이스(eXist-db)와의 직접 연동까지 하나의 화면 안에서 모두 해결하는 완벽한 `"**통합 개발 환경(IDE, Integrated Development Environment)**"`을 제공합니다. 이것이 예산이 부족한 인문학 프로젝트들조차 기꺼이 라이선스 비용을 지불하며 Oxygen을 고집하는 이유입니다.

## 2. 텍스트 모드(Text Mode)의 인지적 한계

Oxygen은 문서를 편집할 때 화면 하단에 두 가지 주요 뷰(View) 탭을 제공합니다. 기본 화면인 `"**Text 모드**"`는 우리가 흔히 아는 꺾쇠(`< >`) 태그와 원문 텍스트가 뒤섞인 날것의 코드 화면입니다.

기계적인 구조를 파악하거나 일괄 치환(Find/Replace)을 할 때는 Text 모드가 유리합니다. 그러나 다음과 같은 텍스트를 인문학자가 교정한다고 상상해 보십시오.

```xml
<p>
    이때 <roleName>영의정</roleName> <persName ref="#P001">류성룡</persName>이 
    <date when="1592-04-13">임진년 4월</date>에 아뢰기를...
</p>
```
사료의 길이가 길어지고 태그가 복잡하게 중첩될수록(Tag Soup), 편집자의 눈은 원본 텍스트의 맥락(Context)을 놓치고 태그의 스펠링에만 매몰되는 `"**인지적 과부하(Cognitive Overload)**"`를 겪게 됩니다. 역사적 진실을 판별해야 할 학자가 기계적인 '타이피스트'로 전락하는 순간입니다.

## 3. 가독성의 혁명: Author 모드 (Author Mode) ★

이러한 인문학자의 고충을 완벽하게 해결하기 위해 Oxygen이 도입한 혁신적인 인터페이스가 바로 `"**Author 모드**"`입니다. 



Author 모드 탭을 클릭하는 순간, 복잡한 꺾쇠 태그들은 마법처럼 화면에서 사라지고 MS Word나 한글(HWP) 문서처럼 깔끔하게 서식이 적용된 텍스트만이 나타납니다. 

### 3.1 워드 프로세서와 같은 직관적 편집 (WYSIWYG)
Author 모드에서는 태그를 직접 타이핑할 필요가 없습니다. 텍스트를 마우스로 드래그한 뒤, 단축키나 우클릭 메뉴를 통해 `<persName>`을 선택하면 백그라운드에서 자동으로 XML 태그가 감싸집니다. 
이는 AI가 1차로 생성한 마크업 초안을 눈으로 쓱 훑어 내려가며, 내용적 모순이나 오류를 발견했을 때 직관적으로 텍스트를 수정할 수 있는 최적의 환경을 제공합니다.

### 3.2 CSS 기반의 시각화 제어 (Visual Authoring)
Author 모드가 단순히 태그를 숨기기만 하는 것은 아닙니다. Oxygen은 웹 디자인에 쓰이는 `"**CSS(Cascading Style Sheets)**"` 기술을 XML 편집기에 직접 도입했습니다. 연구자는 간단한 CSS 코드를 작성하여 XML 태그에 시각적 속성을 부여할 수 있습니다.

**[Author 모드 전용 CSS 예시]**
```css
/* 인물명은 파란색 굵은 글씨로 표시 */
persName {
    color: blue;
    font-weight: bold;
}

/* 관직명은 회색 이탤릭체로 표시 */
roleName {
    color: gray;
    font-style: italic;
}

/* 태그의 속성값(예: ref="#P001")을 마우스 오버 시에만 툴팁처럼 표시 */
persName:before {
    content: "[" attr(ref) "] ";
    font-size: 0.8em;
    color: red;
}
```
이러한 CSS를 Oxygen에 연결해 두면, 인문학자는 푸른색으로 빛나는 글자만 보고도 직관적으로 "아, 이것은 인물명으로 잘 태깅되었구나"라고 인식할 수 있습니다. 

## 4. TEI 프레임워크와의 완벽한 융합

Oxygen이 DH 학계의 압도적 지지를 받는 또 다른 이유는 `"**TEI 프레임워크(Framework)**"`를 소프트웨어 내부에 기본적으로 탑재하고 있기 때문입니다. 

새로운 문서를 생성할 때 'TEI P5' 템플릿을 선택하면, 방대한 TEI 가이드라인 스키마가 즉시 백그라운드에 연동됩니다. Author 모드에서 엔터(Enter) 키를 누르기만 해도, 현재 커서 위치에서 문법적으로 허용되는 TEI 태그 목록(예: `<p>` 안에서는 `<name>`, `<date>` 등)만을 드롭다운 메뉴로 영리하게 추천해 줍니다. 

결론적으로 Oxygen의 Author 모드는 **"기계의 언어(XML)"**와 **"인간의 언어(가독성 높은 텍스트)"** 사이의 거리를 완벽하게 좁혀주는 훌륭한 다리입니다. 인문학자는 이 시각적 환경 덕분에 코딩의 스트레스에서 벗어나, 텍스트 본연의 학술적 의미망을 교직(交織)하는 데 자신의 지적 역량을 100% 집중할 수 있습니다.

이어지는 장에서는 가독성 확보를 넘어, 데이터의 무결성을 기계적으로 검증해 내는 **"스키마(XSD/Schematron) 바인딩 및 실시간 유효성 검사 100% 활용법"**을 집중적으로 탐구하겠습니다.
