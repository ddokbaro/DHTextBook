# XPath 내장 함수와 다중 조건 필터링

앞서 우리는 경로 표현식(`/`, `//`)과 축(Axes)을 통해 거대한 XML 트리 구조 속에서 원하는 노드의 위치를 정확히 타겟팅하는 항해술을 마스터했습니다. 그러나 실제 디지털 인문학 연구에서는 단순히 노드를 찾는 것을 넘어, “**이광수가 쓴 기사가 총 몇 편인가?**”를 세거나, “**제목에 '독립'이라는 단어가 포함된 모든 기사**”를 검색해야 하는 고차원적인 질의(Query)가 필요합니다.

이러한 복잡한 요구사항을 해결하기 위해 XPath는 프로그래밍 언어에 버금가는 강력한 “**내장 함수(Built-in Functions)**”와 논리 연산자를 제공합니다. 이 장에서는 실무에서 가장 빈번하게 사용되는 핵심 함수들과 다중 조건 결합 기법을 심층적으로 해부합니다.

## 1. 텍스트 노드의 직접 추출: `text()`

초보자들이 XPath를 작성할 때 가장 많이 겪는 혼란은 “**요소 자체를 가져오는 것**”과 “**요소 안의 글자만 가져오는 것**”의 차이를 구분하지 못하는 데서 발생합니다.

* `//제목`: 이는 `<제목>무정</제목>`이라는 **XML 태그(요소) 전체**를 덩어리째 반환합니다.
* `//제목/text()`: 이는 태그 껍데기를 모두 버리고, 그 안에 들어있는 `"**무정**"`이라는 **순수한 문자열(텍스트 노드)**만을 추출합니다.

**[실무 활용 예시]**
```xpath
//기사[@기사ID="A001"]/본문/text()
```
* **해석:** 기사 ID가 "A001"인 요소를 찾아, 그 내부의 `<본문>` 태그를 벗겨내고 순수한 본문 텍스트 데이터만을 데이터베이스나 화면으로 전송합니다.

## 2. 문자열 부분 검색 함수: `contains()` 와 `starts-with()`

관계형 데이터베이스(RDB)의 SQL 문법 중 `LIKE '%단어%'`와 정확히 동일한 역할을 수행하는, 디지털 문헌학 검색 시스템의 핵심 엔진입니다.

### 2.1 `contains(대상, "찾을문자열")`
대상의 텍스트(또는 속성값) 안에 특정 문자열이 **일부라도 포함**되어 있다면 참(True)을 반환합니다.

```xpath
//기사[contains(제목, "독립")]
```
* **해석:** `<기사>` 요소들 중에서, 자식인 `<제목>`의 텍스트 안에 `"**독립**"`이라는 단어가 포함된 모든 기사를 찾아냅니다. ("조선독립선언", "독립의 의지" 등 모두 검색됨)

```xpath
//인물[contains(@직업, "소설")]
```
* **해석:** 직업 속성값에 `"**소설**"`이 포함된 모든 인물("소설가", "단편소설작가" 등)을 추출합니다.

### 2.2 `starts-with(대상, "시작문자열")`
문자열이 반드시 특정 단어로 **시작**할 때만 참을 반환합니다. 

```xpath
//필자[starts-with(text(), "김")]
```
* **해석:** 필자의 이름이 `"**김**"`으로 시작하는 모든 사람(김구, 김소월 등)을 찾아냅니다. (주의: 여기서는 `text()` 함수를 `starts-with`의 인자로 결합하여 사용했습니다.)

## 3. 노드의 통계와 수량 산출: `count()`

인문학 데이터의 정량적 분석(Quantitative Analysis)을 위해 절대적으로 필요한 함수입니다. 이 함수는 노드 자체가 아니라, **조건을 만족하는 노드의 “개수(숫자)”**를 정수형으로 반환합니다.

```xpath
count(//기사[필자="최남선"])
```
* **해석:** 문서 전체를 뒤져 필자가 `"**최남선**"`인 `<기사>` 요소가 총 몇 개인지 숫자로(예: 42) 반환합니다.

```xpath
//잡지[count(기사) > 10]
```
* **해석:** 수많은 `<잡지>` 요소 중에서, 내부에 포함된 `<기사>` 자식 요소의 개수가 `"**10개 초과**"`인, 즉 기사가 풍부하게 수록된 잡지만을 필터링하여 추출합니다.

## 4. 위치 기반 필터링 심화: `position()` 과 `last()`

앞서 대괄호 안에 숫자를 넣어 순번을 찾는 법(`[1]`)을 배웠습니다. 이를 더 유연하게 통제하는 함수들입니다.

* **`position()`:** 현재 탐색 중인 노드의 순번을 반환합니다. 범위 연산에 매우 유용합니다.
  ```xpath
  //기사[position() <= 3]
  ```
  * **해석:** 문서에 등장하는 기사 중 `"**1번부터 3번까지의 기사**"`만 추출합니다. (페이지네이션이나 미리보기 구현에 필수적입니다.)

* **`last()`:** 동일한 부모를 가진 형제 노드들 중 **가장 마지막 노드**의 순번을 반환합니다.
  ```xpath
  //level1/level2[last() - 1]
  ```
  * **해석:** 각 `<level1>` 묶음에서 `"**끝에서 두 번째**"`에 위치한 `<level2>` 요소를 정확히 찾아냅니다.

## 5. 다중 조건의 결합: 논리 연산자 (`and`, `or`, `not()`)

실제 연구 질의(Query)는 단일 조건으로 끝나지 않습니다. 대괄호(`[]`) 서술어 내부에 논리 연산자를 사용하여 여러 개의 촘촘한 그물망을 칠 수 있습니다.

### 5.1 `and` (교집합: 모두 만족)
```xpath
//기사[발행년도="1920" and contains(제목, "개벽")]
```
* **해석:** 발행년도가 1920년이면서, **동시에** 제목에 "개벽"이 포함된 기사만 추출합니다.

### 5.2 `or` (합집합: 하나라도 만족)
```xpath
//인물[직업="시인" or 직업="소설가"]
```
* **해석:** 직업이 시인이거나 소설가인 인물을 모두 추출합니다.

### 5.3 `not()` (여집합: 부정)
함수 형태로 사용되며, 괄호 안의 조건이 **거짓일 때만 참을 반환**합니다. (특정 데이터를 배제할 때 씁니다.)

```xpath
//기사[not(필자)]
```
* **해석:** 내부에 `<필자>` 요소가 **존재하지 않는** 기사(즉, 무기명 기사)만을 찾아냅니다.

```xpath
//기사[not(contains(제목, "광고"))]
```
* **해석:** 제목에 "광고"라는 단어가 **포함되지 않은** 순수한 기사들만 필터링합니다.

XPath의 경로 탐색, 다차원 축(Axes) 횡단, 그리고 내장 함수를 활용한 정밀 필터링까지, 우리는 이제 XML 데이터를 자유자재로 해체하고 조립할 수 있는 완벽한 메스를 쥐게 되었습니다. 

이어지는 장에서는 이렇게 찾아낸 원석 같은 데이터들을 조합하여 인간이 읽기 편한 HTML 웹페이지나 아름다운 PDF 문서로 변환해 내는 마법, **“XSLT(eXtensible Stylesheet Language Transformations)”**의 세계로 진입하겠습니다.
