# 거시 위계 구조 분석: <level1~3>을 활용한 권호 및 기사 분할의 의도와 분산형 메타데이터 상속

잡지나 신문과 같은 정기간행물은 일반적인 단행본(Book)과는 완전히 다른 차원의 복잡성을 지닙니다. 하나의 잡지사(종수) 아래에 수십 년간 발행된 수백 개의 호수(Issue)가 존재하고, 다시 그 호수 안에는 수십 편의 개별 기사(Article)와 광고, 삽화들이 포함됩니다.

이러한 다층적 구조를 평면적인 데이터베이스에 구겨 넣으면 필연적으로 정보의 맥락이 유실됩니다. 앞서 우리는 국사편찬위원회의 `history.dtd`가 TEI의 범용적인 `<div>` 대신 번호가 명시된 `"**<level>**"` 태그를 도입했음을 확인했습니다. 이 장에서는 실제 사료인 `ma_045.xml`(학풍) 샘플을 해부하여, 이 계층 구조가 어떻게 작동하며 메타데이터를 효율적으로 상속시키는지 그 정보공학적 아키텍처를 분석합니다.

## 1. 정기간행물의 3단 분할: `<level1>` ~ `<level3>`

국사편찬위원회는 아날로그 잡지의 물리적 형태를 디지털 세계에 완벽하게 대응시키기 위해 트리(Tree) 구조의 3단 분할을 강제했습니다. 



실제 `ma_045.xml` 데이터의 뼈대를 살펴보면 이 구조가 얼마나 명쾌하게 설계되었는지 알 수 있습니다.

```xml
<level1 id="ma_045">
    <front> ... 학풍(잡지명) 메타데이터 ... </front>
    
    <level2 id="ma_045_0010">
        <front> ... 1948년 10월호(발행정보) 메타데이터 ... </front>
        
        <level3 id="ma_045_0010_0010">
            <front> ... (卷頭言)學問의 權威를 爲하여 (기사명) ... </front>
            <text> ... 기사 본문 ... </text>
        </level3>
        
        <level3 id="ma_045_0010_0090">
            <front> ... 兩班制度論 (기사명/필자) ... </front>
            <text> ... 기사 본문 ... </text>
        </level3>
    </level2>
</level1>
```

이러한 엄격한 ID 부여 방식(`ma_045` -> `ma_045_0010` -> `ma_045_0010_0090`)은 XML이 훗날 관계형 데이터베이스(RDB) 테이블로 변환될 때 기본 키(Primary Key)와 외래 키(Foreign Key)로 즉각 작동하도록 설계된 철저한 `"**데이터베이스 친화적(DB-friendly)**"` 구조입니다.

## 2. 분산형 메타데이터 설계: `<front>`와 `<biblioData>` ★

TEI 문서의 가장 큰 특징 중 하나는 문서 전체의 서지 정보를 최상단의 `<teiHeader>`라는 거대한 하나의 바구니에 모두 담아둔다는 것입니다. 그러나 여러 호수와 수천 개의 기사가 병합된 잡지 자료에서 이 방식을 취하면, 헤더가 비대해져 관리가 불가능해집니다.

이를 해결하기 위해 국편의 DTD는 메타데이터를 담는 `"**<biblioData>**"` (TEI의 teiHeader에 해당) 요소를 각각의 `<level>` 계층마다 분산하여 배치하는 전략을 취했습니다.

### 2.1 Level 1: 거시적 서지 정보
가장 상위인 `<level1>`의 `<front>`에는 이 잡지 전체를 관통하는 불변의 정보만이 기록됩니다.
```xml
<level1 id="ma_045">
    <front>
        <biblioData type="목차제공잡지">
            <title><mainTitle>학풍</mainTitle></title>
            <binderPeriod begin="1948-10-01" end="1950-06-01"/>
        </biblioData>
    </front>
```

### 2.2 Level 2: 호수별 간행 정보
`<level2>`의 `<front>`에는 해당 호수의 구체적인 간행일과 발행처가 기록됩니다.
```xml
    <level2 id="ma_045_0010">
        <front>
            <biblioData>
                <title><mainTitle volume="1948년 10월(통권 1호, 제1권 제1호)">
                    학풍 1948년 10월(통권 1호, 제1권 제1호)
                </mainTitle></title>
                <publication>
                    <dateIssued date="1948-10-01">1948년 10월 1일</dateIssued>
                </publication>
            </biblioData>
        </front>
```

### 2.3 Level 3: 미시적 기사 정보
가장 말단인 `<level3>`의 `<front>`에는 개별 기사의 제목과 필자(저자)가 기록됩니다.
```xml
        <level3 id="ma_045_0130_0090">
            <front>
                <biblioData>
                    <title><mainTitle>兩班制度論</mainTitle></title>
                    <creator>
                        <author><name>高在國</name></author>
                    </creator>
                </biblioData>
            </front>
```

## 3. 정보공학의 정수: 객체 지향적 상속 (Inheritance)

왜 이렇게 정보를 쪼개놓았을까요? 이는 현대 컴퓨터 공학의 `"**객체 지향 프로그래밍(OOP)**"`에서 쓰이는 `"**상속(Inheritance)**"`의 개념을 XML 마크업에 그대로 구현한 것입니다.

만약 한 연구자가 검색 엔진에서 "兩班制度論(양반제도론)"이라는 기사를 검색해 냈다고 가정해 봅시다. 이 기사(Level 3) 자체의 메타데이터에는 이 글이 언제, 어느 잡지에 실렸는지 적혀있지 않습니다. 
그러나 컴퓨터 프로그램(XPath)은 트리를 역추적(`parent::`)하여 다음과 같이 정보를 동적으로 조합해 냅니다.

1. **내 정보 (Level 3):** 제목 "兩班制度論", 필자 "高在國"
2. **부모 정보 상속 (Level 2):** 발행일 "1948년 10월 1일"
3. **조부모 정보 상속 (Level 1):** 잡지명 "학풍"

**최종 조합된 검색 결과:** `"**학풍 1948년 10월호 (1948-10-01 발행) - 兩班制度論 (고재국 지음)**"`

이러한 분산형 메타데이터 구조는 개별 기사마다 잡지명과 발행일을 중복해서 타이핑하는 엄청난 낭비와 휴먼 에러를 원천적으로 제거하며, 데이터베이스의 용량을 획기적으로 줄여주는 가장 우아한 아키텍처입니다.

결론적으로 한국근현대잡지자료의 `<level>`과 `<biblioData>` 설계는 종이 매체가 가진 맥락(Context)을 컴퓨터의 논리 구조로 완벽하게 치환해 낸 디지털 문헌학의 걸작입니다. 

거시적 뼈대와 메타데이터의 유전 법칙을 확인했으니, 이어지는 장에서는 이 뼈대 안쪽, 즉 본문 텍스트 내에서 인물과 서명을 뽑아내는 **"본문 구조와 시맨틱 태깅: `<index>`를 활용한 개체명 식별"**의 세계를 해부하겠습니다.
