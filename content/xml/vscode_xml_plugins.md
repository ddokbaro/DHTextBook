# VS Code를 가벼운 XML IDE로 변신시키는 필수 확장 플러그인 설정

앞서 살펴본 Oxygen XML Editor가 인문정보학 학계의 든든한 상용 표준이라면, 마이크로소프트(Microsoft)가 개발한 오픈소스 에디터인 `"**VS Code(Visual Studio Code)**"`는 압도적인 확장성을 무기로 그 뒤를 바짝 쫓고 있는 가장 강력한 대안입니다. 

라이선스 비용의 부담이 큰 대학원생이나 소규모 독립 연구 프로젝트에서 VS Code는 최고의 선택지입니다. 하지만 VS Code는 기본적으로 범용 텍스트 에디터이므로, 이를 Oxygen처럼 훌륭한 `"**XML 통합 개발 환경(IDE)**"`으로 사용하기 위해서는 우리가 직접 뼈대에 살을 붙이는 `"**확장 플러그인(Extensions)**"` 튜닝 작업이 필수적입니다.

## 1. 확장 플러그인 마켓플레이스 진입

VS Code를 실행한 후, 좌측 사이드바에 있는 4개의 블록 모양 아이콘인 `"**Extensions(확장)**"` 메뉴를 클릭하거나 단축키(`Ctrl+Shift+X` / Mac: `Cmd+Shift+X`)를 누르면 전 세계 개발자들이 만들어 올린 수십만 개의 플러그인 마켓플레이스에 진입할 수 있습니다. 

이곳에서 검색창을 이용해 다음의 필수 플러그인들을 설치(Install)합니다.

## 2. 텍스트 편찬을 위한 필수 플러그인 3선 ★

디지털 문헌학자의 작업 속도와 정확성을 Oxygen 수준으로 끌어올려 줄 3대 핵심 플러그인입니다.



### 2.1 코어 엔진: `XML by Red Hat`
단연코 VS Code XML 환경의 심장이라고 할 수 있는 플러그인입니다. 세계적인 오픈소스 기업인 Red Hat이 개발 및 유지보수하고 있습니다.
* **주요 기능:** * XML 문법 하이라이팅(색상 부여)
  * 태그 자동 완성 및 문서 포맷팅(`Shift+Alt+F`)
  * **[핵심]** DTD 및 XSD 스키마 바인딩을 통한 `"**실시간 유효성 검사(Real-time Validation)**"` 지원

### 2.2 생산성 극대화: `Auto Rename Tag`
마크업 과정에서 태그의 이름을 바꿔야 할 때(예: `<p>`를 `<lg>`로 변경), 여는 태그를 수정하면 저 멀리 떨어져 있는 닫는 태그(`</lg>`)까지 `"**동시에 자동으로 변경**"`해 주는 마법 같은 플러그인입니다. 
수만 줄에 달하는 역사 사료를 다룰 때, 짝이 맞지 않는 태그 오류(Mismatched tags)를 원천적으로 차단해 주는 엄청난 생산성 도구입니다.

### 2.3 쿼리 투시경: `XPath` (by DotJosh Johnson)
VS Code 에디터 내부에서 즉각적으로 XPath 쿼리를 날려볼 수 있게 해주는 플러그인입니다.
* 설치 후 `Ctrl+Shift+P`(명령 팔레트)를 열고 `XPath: Evaluate`를 실행한 뒤 쿼리를 입력하면, 문서 내에서 해당 조건을 만족하는 노드들을 즉시 하이라이팅하여 추출해 줍니다. (Oxygen의 XPath 빌더 역할을 대체합니다.)

## 3. Red Hat XML을 활용한 스키마 바인딩 실무

플러그인 설치가 끝났다면, 이제 Oxygen에서 했던 것과 동일하게 내가 설계한 규칙(Schema)을 문서에 강제하는 바인딩 작업을 수행해 보겠습니다.

`XML by Red Hat` 플러그인은 W3C 표준인 `<?xml-model ?>` 처리 명령을 완벽하게 인식합니다. 문서의 최상단에 다음과 같이 스키마 경로를 입력해 주십시오.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<?xml-model href="schemas/tei_all.xsd" type="application/xml" schematypens="[http://www.w3.org/2001/XMLSchema](http://www.w3.org/2001/XMLSchema)"?>
<TEI xmlns="[http://www.tei-c.org/ns/1.0](http://www.tei-c.org/ns/1.0)">
    </TEI>
```



### 3.1 실시간 에러 검출 (Problems 패널)
이제 규격에 맞지 않는 태그를 입력하거나 필수 속성을 누락하면, VS Code 화면 하단의 `"**Problems(문제)**"` 탭에 에러 목록이 실시간으로 쏟아지며 해당 코드 아래에 붉은색 물결밑줄이 그어집니다. 마우스를 올리면 Red Hat 엔진이 "이 요소는 이곳에 올 수 없습니다"라는 구체적인 XSD 위반 사유를 알려줍니다.

## 4. VS Code 환경의 장단점 요약

* **장점:** 100% 무료이며, 구동 속도가 매우 가볍고 빠릅니다. 또한 Git(버전 관리)과의 연동이 예술적인 수준이므로, 여러 명의 연구자가 GitHub를 통해 문서를 공동 편찬하는 환경에 최적화되어 있습니다.
* **단점:** Oxygen의 `Author 모드`와 같이 태그를 완전히 숨겨주는 완벽한 WYSIWYG 뷰를 제공하지는 않습니다. (태그의 바다를 맨눈으로 항해해야 합니다.)

결론적으로, 약간의 인지적 불편함을 감수하고 필수 플러그인들을 단단하게 무장한다면, VS Code는 자본의 장벽 없이 누구나 최상급의 디지털 인문학 데이터를 편찬할 수 있게 해주는 가장 민주적인 도구입니다. 

이어지는 장에서는 이 범용 에디터의 진정한 숨겨진 무기, 수백 개의 오탈자와 잘못된 태그를 단 1초 만에 일괄 교정해 내는 `"**정규표현식(Regex)과 다중 커서(Multi-cursor)의 마법**"`에 대해 심층적으로 탐구하겠습니다.
