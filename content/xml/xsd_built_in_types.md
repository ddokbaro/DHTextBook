# XSD 내장 데이터 타입(Built-in Data Types) 총망라

XML Schema(XSD)가 DTD를 밀어내고 디지털 아카이브의 새로운 표준이 된 가장 결정적인 이유는, 프로그래밍 언어 수준의 강력하고 세밀한 “**내장 데이터 타입(Built-in Data Types)**”을 제공하기 때문입니다. 

W3C 표준은 세상의 데이터를 표현하기 위해 19개의 “**원시 타입(Primitive Types)**”과, 이로부터 파생된 25개의 “**파생 타입(Derived Types)**” 등 총 44개의 데이터 타입을 규정하고 있습니다. 이 장에서는 XSD가 제공하는 모든 데이터 타입을 범주별로 빠짐없이 리스트업하고, 디지털 인문학 실무에서 자주 사용되는 핵심 타입(⭐ 표기)의 활용법을 상세히 해부합니다.



## 1. 문자열 및 텍스트 타입 (String Types)

텍스트를 기반으로 하는 인문학 자료 마크업에서 가장 널리 사용되는 범주입니다. 공백 처리 방식이나 명명 규칙에 따라 세분화됩니다.

* ⭐ **`xs:string`**: 가장 기본적인 문자열입니다. 띄어쓰기, 줄바꿈(엔터), 탭(Tab) 기호 등을 입력한 원본 그대로 모두 보존합니다. 본문 텍스트나 기사 내용 전체를 묶을 때 사용합니다.
* ⭐ **`xs:token`**: `xs:string`에서 파생된 타입으로, 문자열 앞뒤의 불필요한 공백을 제거하고, 내부의 연속된 공백이나 줄바꿈을 단일 공백으로 압축합니다. 검색의 정확도를 높여야 하는 “**주제어**”, “**인명**”, “**지명**” 등에 매우 적합합니다.
* **`xs:normalizedString`**: 줄바꿈이나 탭 기호만 공백으로 치환하고, 띄어쓰기는 그대로 둡니다.
* **`xs:language`**: `en`, `ko`, `fr-FR` 등 국제 표준(RFC 3066)에 맞는 언어 코드만을 허용합니다.
* ⭐ **`xs:ID`**: XML 문서 전체에서 절대 중복될 수 없는 고유 식별자(ID)를 지정합니다. 숫자로 시작할 수 없습니다.
* ⭐ **`xs:IDREF`**: 다른 요소에 부여된 `xs:ID` 값을 참조(가리킴)하는 데이터 타입입니다.
* **`xs:IDREFS`**: 공백으로 구분하여 여러 개의 `IDREF`를 동시에 참조할 수 있습니다.
* **`xs:Name` / `xs:NCName`**: XML 요소 이름의 명명 규칙(숫자 시작 불가, 공백 불가 등)을 따르는 문자열만 허용합니다. (`NCName`은 콜론을 포함할 수 없습니다.)
* **`xs:NMTOKEN` / `xs:NMTOKENS`**: 요소 이름 규칙과 유사하나 숫자나 마침표로 시작할 수 있는 이름 토큰입니다.
* **`xs:ENTITY` / `xs:ENTITIES`**: DTD에서 선언된 외부 개체(Entity)를 참조할 때 사용합니다.

## 2. 숫자 타입 (Numeric Types)

연산이 가능하고 범위 비교가 필요한 숫자 데이터를 엄격하게 통제하는 타입들입니다. 

* ⭐ **`xs:integer`**: 소수점이 없는 순수한 정수(Integer)만을 허용합니다. 페이지 수, 발행 호수 등에 사용됩니다.
* ⭐ **`xs:decimal`**: 소수점을 포함할 수 있는 십진수 실수입니다. 화폐 단위나 정밀한 측정값을 기록할 때 씁니다.
* **`xs:float` / `xs:double`**: 부동 소수점(Floating-point) 숫자입니다. `double`이 `float`보다 더 크고 정밀한 값을 표현합니다.
* **`xs:int` / `xs:long` / `xs:short` / `xs:byte`**: `xs:integer`에서 파생된 타입들로, 컴퓨터 메모리 크기에 따라 허용되는 숫자의 최댓값/최솟값이 다릅니다. (예: `byte`는 -128부터 127까지만 허용)
* **`xs:positiveInteger`**: 1 이상의 양수만 허용합니다. (0 불가)
* **`xs:nonNegativeInteger`**: 0을 포함한 양수만 허용합니다. (음수 불가)
* **`xs:negativeInteger`**: -1 이하의 음수만 허용합니다. (0 불가)
* **`xs:nonPositiveInteger`**: 0을 포함한 음수만 허용합니다. (양수 불가)
* **`xs:unsignedLong` / `xs:unsignedInt` / `xs:unsignedShort` / `xs:unsignedByte`**: 음수 부호(`-`)를 허용하지 않는 절대적인 양수 데이터 타입들입니다.

## 3. 날짜 및 시간 타입 (Date and Time Types)

역사학과 문헌학 데이터베이스에서 **가장 극적인 혁신**을 가져다준 타입입니다. 문자로 적힌 날짜를 기계가독형의 수학적 연대기로 변환해 줍니다. W3C는 ISO 8601 국제 표준 표기법을 강제합니다.

* ⭐ **`xs:date`**: `YYYY-MM-DD` 형식만을 허용합니다. (예: `1920-06-25`)
* ⭐ **`xs:gYear`**: `YYYY` 형식으로 연도만 입력받습니다. (예: `1920`). 한국사 데이터베이스에서 특정 사건이 발생한 “**년도**”만을 추출해 마크업할 때 가장 강력한 유효성 검사 도구가 됩니다.
* ⭐ **`xs:dateTime`**: `YYYY-MM-DDThh:mm:ss` 형식으로 날짜와 시간을 동시에 기록합니다. `T` 문자로 날짜와 시간을 구분합니다. (예: `2026-02-22T01:32:00`)
* **`xs:time`**: `hh:mm:ss` 형식으로 시간만 기록합니다.
* **`xs:gYearMonth`**: `YYYY-MM` 형식으로 연도와 월까지만 기록합니다. (특정 월간지의 발행월 기록에 적합합니다.)
* **`xs:gMonthDay`**: `--MM-DD` 형식으로 매년 반복되는 특정 기념일(월과 일)을 기록합니다.
* **`xs:gDay`**: `---DD` 형식으로 특정 일자만 기록합니다.
* **`xs:gMonth`**: `--MM` 형식으로 특정 월만 기록합니다.
* **`xs:duration`**: 두 시간 사이의 간격(기간)을 `PnYnMnDTnHnMnS` 형식으로 기록합니다. (예: `P2Y6M`은 2년 6개월을 의미합니다.)

## 4. 기타 특수 및 이진 데이터 타입

웹 생태계와의 호환성 및 파일 첨부를 위해 고안된 타입들입니다.

* ⭐ **`xs:boolean`**: 오직 `true`, `false`, `1`, `0` 등 4가지 값 중 하나만 가질 수 있는 논리값입니다. (예: `<완간여부>true</완간여부>`)
* ⭐ **`xs:anyURI`**: 인터넷 주소(URL)나 URN 등 고유 식별자 체계의 문법을 준수하는 값만 허용합니다. 외부 이미지 경로(`http://...`)나 연결 개방형 데이터(LOD)의 외부 자원을 링킹할 때 필수로 사용됩니다.
* **`xs:base64Binary`**: 이미지, 음성, PDF 파일 등의 아날로그 데이터를 Base64 방식으로 인코딩한 문자열 데이터입니다. XML 문서 내부에 사진 파일을 직접 삽입할 때 사용합니다.
* **`xs:hexBinary`**: 데이터를 16진수 형태로 인코딩한 문자열입니다.
* **`xs:QName`**: 네임스페이스 접두사가 포함된 정식 이름(Qualified Name) 형식을 강제합니다. (예: `dc:title`)
* **`xs:NOTATION`**: DTD에 선언된 NOTATION(문서를 여는 외부 응용 프로그램 정보)을 참조합니다.

## 5. 내장 데이터 타입의 인문학적 가치

단순히 글자를 타이핑하는 것을 넘어, 위에서 열거된 44개의 타입을 통해 데이터의 본질을 규정하는 행위는 디지털 문헌학의 수준을 한 차원 끌어올립니다.

`<발행년도>일천구백이십년</발행년도>`라는 텍스트는 인간에게는 읽히지만 기계는 시간순으로 정렬할 수 없습니다. 그러나 스키마에서 발행년도를 `xs:gYear`로 엄격하게 통제해 두면, 연구자는 강제적으로 `<발행년도>1920</발행년도>`라고 마크업해야 하며, 컴퓨터는 이 데이터를 통해 1919년과 1921년 사이에 존재했던 문헌들을 즉각적으로 검색하고 시계열 그래프로 시각화해 냅니다.

이처럼 XSD의 내장 데이터 타입은 인문학적 사실(Fact)을 기계의 논리(Logic)로 치환해 주는 가장 정밀하고 확실한 정보공학적 거름망입니다.
